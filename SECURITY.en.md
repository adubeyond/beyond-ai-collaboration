# Security Policy

**English** | [简体中文](SECURITY.md)

## Supported versions

Security reports are accepted for the latest public release. Unpublished candidates, historical snapshots, and independently modified derivatives do not have a promised support or remediation timeline.

## Reporting a vulnerability

Do not disclose the following in a public Issue, Pull Request, discussion, or log:

- Exploitable vulnerability details.
- Passwords, tokens, cookies, private keys, certificates, or connection strings.
- Real servers, production environments, customer data, or internal network information.

After GitHub Private Vulnerability Reporting is enabled, use **Security → Report a vulnerability** in the repository.

If that entry is not available, email [adubeyond@qq.com](mailto:adubeyond@qq.com) with the subject `[BEYOND Security]`. Do not disclose reproduction steps, exploit code, credentials, or sensitive logs in a public Issue.

Maintainers will make a practical effort to protect the privacy of good-faith reporters and affected people. A maintainer directly involved in a report should recuse themselves when another qualified reviewer is available.

## Suggested report contents

- Affected version or commit range.
- Issue category and potential impact.
- A redacted minimal reproduction condition.
- Suggested mitigation or repair direction.
- Whether the issue has been disclosed elsewhere.

Receiving a report does not confirm a vulnerability or promise a fixed response time. Maintainers will first verify impact, reproducibility, and disclosure boundaries before deciding on remediation and release.
