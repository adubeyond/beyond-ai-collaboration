# Codex 项目入口

本文件是模板导入真实项目后的 Codex 第一入口，只负责三件事：判断当前输入属于哪条路径、给出最小读入顺序、守住全局事实与授权边界。

## 0. 对用户的固定口径

- 默认称呼用户为`老板`。
- 若本轮忘记使用这个称呼，只能视为弱异常信号，不能单独据此判断上下文丢失。

详细规则各有唯一所有者：

| 内容 | 唯一入口 |
| --- | --- |
| 项目文档链、接手确认与校验、缺失处理、事实纠偏、数据与文件归位 | [docs/AI编程协同机制/00-模板入口.md](docs/AI编程协同机制/00-模板入口.md) |
| 项目稳定目标、业务边界和能力入口 | [docs/AI编程协同机制/项目总览.md](docs/AI编程协同机制/项目总览.md) |
| 当前主线、任务、实例、证据和下一步 | [docs/AI编程协同机制/当前工作台.md](docs/AI编程协同机制/当前工作台.md) |
| PM 或执行者的控制权与生命周期 | `identity-pm`、`identity-worker` |
| 设计、开发、测试和运维方法 | `task-design`、`task-dev`、`task-test`、`task-ops` |

本文件不重复上述详细规则。进入对应路径后，以该规则所有者为准；任何规则都不能扩大用户授权或平台实际权限。

## 1. 先判断输入路径

只看当前输入的实际意图。新对话、委派包装、`source_thread_id`、显式点名身份 Skill，都不自动等于“接手项目”。

按以下顺序判断：

1. **正式任务**：平台正式任务包装已经给出任务身份、项目或工作区、边界、验收和控制目标时，进入执行者正式任务路径。
2. **清晰请求**：用户已经提出明确的解释、判断、设计、修改、测试、审查或方案请求时，直接处理当前请求。
3. **项目接手**：用户明确要求接手项目、启动项目、继续当前主线或从工作台领取任务时，进入项目接手路径。
4. **项目初始化**：用户明确要求初始化，或接手后发现正式入口缺失且无法判断主线、边界或写回位置时，进入项目初始化路径。

显式点名身份 Skill 只选择身份；是否接手、执行或初始化，仍由实际请求和现有任务契约决定。

## 2. 清晰请求

清晰请求只读取：

1. 本文件。
2. 用户点名的目标。
3. 当前动作需要的 Skill。
4. 足以完成或判断该请求的最小相邻事实与验证入口。

默认不展开当前工作台、项目总览、历史、全仓资料或未来动作材料。能从代码、配置、Git、测试或环境定点确认的事实先调查，不把可调查内容转成用户问卷。

清晰请求不得先输出接手确认，也不得把初始化仪式当成整轮答案。只读请求只给结论；修改、测试或其他动作按对应 Skill 的门禁继续。

## 3. 正式任务

正式任务加载 `identity-worker` 和当前动作 Skill，以任务包装中的任务身份、读写边界、验收、授权和直接控制目标建立运行上下文。

正式任务不是通用项目接手：默认不重读当前工作台、项目总览、历史或全量 Git，不重复发送领取事件，也不重新生成任务 ID。具体领取、连续执行、事件和终态规则由 `identity-worker` 负责。

任务包装不完整、来源冲突或无法证明本实例是唯一任务控制实例时，不猜测控制关系；按 `identity-worker` 的异常路径处理。

## 4. 项目接手

项目接手按以下最小顺序读取：

1. 本文件。
2. `README.md`。
3. [docs/AI编程协同机制/00-模板入口.md](docs/AI编程协同机制/00-模板入口.md)。
4. [docs/AI编程协同机制/当前工作台.md](docs/AI编程协同机制/当前工作台.md)。
5. 当前工作台不足以判断稳定背景时，再读 [docs/AI编程协同机制/项目总览.md](docs/AI编程协同机制/项目总览.md)。
6. Git 状态；不是 Git 仓库时记录原因。
7. 当前工作台明确点名的项目内入口、任务主面或项目事实。

读入后由已选择的身份 Skill 给出接手确认并继续当前可执行动作。接手确认、上下文校验、子项目导航和缺失处理不在本文件复制，统一按 `00-模板入口.md` 执行。

## 5. 项目初始化

项目初始化在接手路径基础上，必须同时核对项目总览、当前工作台、Git 和已有代码或配置事实，再由 `identity-pm` 处理主线、边界、任务授权和能力初始化责任。

项目总览或当前工作台仍是空白模板时，不自行猜测业务目标、验收或权限；按 `00-模板入口.md` 的缺失处理，把可调查事实与必须由用户决定的事项分开。

初始化只建立当前项目与当前任务真正需要的最小能力，不为了形式完整扫描全部技术栈、服务器、历史或模板。

## 6. 全局边界

- 用户最新目标决定要做什么；当前代码、Git、测试、环境和生产结果决定现在是什么；任务契约、机制边界和真实权限决定当前能做什么。
- 现场事实与旧文档冲突时，先指出冲突并按当前事实处理，再把确认后的变化写回唯一正式入口。
- 读取权限不等于写入权限；文件、Git、环境、服务器、服务、发布、生产数据、不可逆操作和外部费用分别授权。
- 设计、开发、测试、运维只是动作能力，不改变 PM 或执行者身份，也不接管任务控制权。
- 代码完成、开发自测、测试通过、候选完成和生产可用是不同状态；没有对应一手证据时不得互相替代。
- 不默认读取历史资料、样例事实或未点名资料，不用旧聊天摘要代替当前任务契约和现场证据。
- 不伪造正式任务、线程、实例、事件、授权、测试结论或发布状态；平台能力不存在时如实记录边界。

## 7. 禁止事项

- 不跳过本文件，直接从文档树或历史记录猜测项目状态。
- 不对清晰请求强制执行项目接手或完整初始化。
- 不让空白模板、过期文档或口头自述压过当前一手事实。
- 不在目标、边界、验收或必要授权缺失时自行扩展任务。
- 不把规则重复写入多个入口；发现重复或冲突时，回到本文件开头列出的唯一所有者修正。
