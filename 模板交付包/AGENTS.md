# Codex 初始化入口

本文件是未来项目在 Codex 中的首入口。Codex 初始化先读这里，再进入项目文档链；不要直接从 `docs/AI编程协同机制/00-模板入口.md` 开始。

## 1. 对用户的固定口径

- 默认称呼用户为`老板`。
- 若本轮忘记使用这个称呼，只能视为弱异常信号，不能单独据此判断上下文丢失。
- 判断上下文是否正常，仍要同时看：当前主线、边界、Git 状态、下一步是否判断正确。

## 1.1 接手校验

新对话若属于“接手项目、接手任务、继续当前主线、领取任务、启动项目”这类接手场景，先按最小路径读入，再给轻回执，不直接开工。

新对话本身不等于接手场景。用户已经提出清晰的判断、设计、修改、测试、审查或方案请求时，即使需要先读取仓库事实，也只在内部完成当前请求所需的最小读入，然后直接处理；不得输出`接手确认`，不得把轻回执当成整轮答案。只有用户明确要求接手、启动、继续主线或领取任务时，才进入本节轻回执。

由其他 Codex 任务创建、委派，或消息中带有`source_thread_id`、委派包装，也不自动构成接手；接手判定只看包装内的实际用户输入。实际输入是清晰任务时直接处理，不能因为存在来源任务就先给轻回执。

最小读入只允许：

1. 本文
2. `README.md`
3. `docs/AI编程协同机制/当前工作台.md`；若当前工作台不足以判断主线、边界或任务背景，再补读 `docs/AI编程协同机制/项目总览.md`
4. Git 状态；非 Git 仓库记录原因

默认只回四项：

```text
接手确认：
- 模式：
- 当前主线：
- 当前边界：
- 当前下一步：
```

`模式`记录项目当前运行形态，不记录智能体身份或动作技能。`PM 总控`、`执行者`、`设计`、`开发`、`测试`、`运维`都不是这里的工作模式。

若当前工作台和项目总览仍是未填写的模板占位，且代码、Git、测试或环境中也没有可确认的真实项目事实，固定按空白新项目处理：

```text
接手确认：
- 模式：使用模板（新项目待初始化）
- 当前主线：尚未定义，不得自行猜测
- 当前边界：只核验现有入口与 Git，不分派、不开发、不修改项目文件
- 当前下一步：由 PM 或项目负责人先补齐项目总览和当前工作台，再建立任务授权
```

空白新项目的“下一步”必须点名 [项目总览.md](docs/AI编程协同机制/项目总览.md) 和 [当前工作台.md](docs/AI编程协同机制/当前工作台.md) 两个正式写回位置，不能只写“补充信息”“等待任务”或“稍后初始化”。只有两处已有真实项目事实时，才按实际主线、边界和下一步给回执，不得继续套用空白项目口径。

这四项必须来自刚读到的动态事实，不能把“下一步先去读文档”当成合格回执。

出现以下任一情况时，再升级补充校验：

- 没有称呼用户为`老板`
- 当前主线、当前边界或当前下一步回答含糊
- 当前主线、当前边界或当前下一步与刚读到的动态事实冲突
- 直接跳去分派、开发、测试、验收或新建文件
- 用户明确要求复核读入链

升级校验只补四项：

```text
补充校验：
- 进入路径：
- Git 状态：
- 写回位置：
- 当前校验码：
```

没有完成轻回执前，不进入分派、开发、测试、验收或新建文件。

轻回执是启动校验，不是等待点。若当前工作台已有可执行任务、任务控制实例或明确授权，完成轻回执后必须在同一轮继续领取和执行；只有红灯条件成立时才暂停。

## 1.2 长对话漂移自检

长对话中，若出现以下任一情况，先暂停推进，先做一次上下文自检：

- 没有称呼用户为`老板`
- 当前主线、当前边界或当前下一步回答明显变空、变泛
- 用户明确质疑“你是不是忘了前文”
- 准备直接跳去分派、开发、测试、验收或新建文件，但当前判断不稳

自检只回四项：

```text
上下文自检：
- 你怎么称呼用户：
- 当前主线：
- 当前边界：
- 当前下一步：
```

若这四项里有两项以上与当前动态事实不符，先重新读取最小路径，再继续；不要硬接着做。

## 2. 完整项目初始化（按需升级）

本节不是每个新对话、每个动作 Skill 或每次任务恢复的默认读入链。只有用户明确要求初始化项目，或接手最小链仍不足以确定项目主线、边界、正式入口和写回位置时，才升级到本节。清晰任务继续按用户目标定点读取；同一任务内部切换动作时继承任务运行上下文，只补新动作需要的事实，不重新执行本节。

1. 本文
2. [README.md](README.md)
3. [docs/AI编程协同机制/00-模板入口.md](docs/AI编程协同机制/00-模板入口.md)
4. [docs/AI编程协同机制/项目总览.md](docs/AI编程协同机制/项目总览.md)
5. [docs/AI编程协同机制/当前工作台.md](docs/AI编程协同机制/当前工作台.md)
6. Git 状态；非 Git 仓库记录原因
7. 当前工作台明确指定的机制、模板、项目事实或子项目文档入口

若当前工作台点名了某条子项目线的项目内入口，例如子项目自己的 `docs/README.md`，先按该入口继续读取；不要跳过它，直接在子项目文档树里盲找。读到该入口后，应继续拿到该项目线的默认任务主面和接手后默认动作，而不是停在“已理解项目”。
若该项目线的项目内入口还提供了场景化阅读顺序，优先选与本轮最贴近的最小场景继续，不默认把所有场景都读一遍。

## 3. 禁止事项

- 不跳过本文，直接把项目文档当第一入口。
- 不默认读取历史资料、样例事实或未点名资料。
- 不因称呼正常就误判为上下文正常；仍要检查主线、边界、证据和下一步。
