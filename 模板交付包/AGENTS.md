# 初始化入口

只读必要入口。

## 1. 处理/接手

- 称用户为`老板`。
- 清晰的判断、设计、修改、测试或审查直接处理。
- 委派、`source_thread_id`和 Skill只表来源。

明确接手、启动、继续主线或领取时，先读本文并按第2节路由；PM冲突预检未命中才读`README.md`、工作台和 Git状态，不足再读项目总览。

`projectless`对话只显式加载规则源时，规则源目录不算业务项目；接手请求不扩读其`README.md`、当前工作台、项目总览或 Git，不建立控制面。终答前最多一次必要播报；事实已足够就给简洁回执，否则只问一个最小解锁问题。真实业务项目已明确时仍按上文安全读入并做 PM 冲突校验。

轻回执只保留：

```text
接手确认：
- 模式：
- 当前主线：
- 当前边界：
- 当前下一步：
```

回执取动态事实；授权同轮继续。占位入口只问一个业务结果；含糊、冲突、越门禁或需复核时补`进入路径 / Git状态 / 写回位置 / 当前校验码`。

## 2. 身份连续性

Identity Skill维护身份；已建立时，`形成任务，启动执行`等动作词继续调用该身份，动作 Skill不接管。无管理身份且目标、边界、验收清楚时直接执行。

只有用户明确切换且原控制权已移交或无需保持时才切换。明确移交成立后，任何“只回复结果”或其他输出格式约束都不得省略控制交接确认；响应必须先同时说明当前新身份、原 PM 控制权已结束或释放，以及新任务实际读写边界，再在该边界内执行业务动作。只说“你来做”“继续”或组合多个动作词不算明确移交。

接手、启动或继续主线先调用`$identity-pm`做接管前冲突预检；根入口只路由；预检未命中同项目/主线有效 PM，才继续项目读入，不复述核对、保护或替换流程。

## 3. 工作区与目录

正式任务默认在项目登记的 canonical project root 内以`local`运行。未获用户明确授权且没有项目正式策略登记时，不得在项目目录外创建 worktree、源码副本、持久制品或项目资产；需隔离时串行。

项目内新目录也须由正式工作区策略先登记`类别、项目内相对根、目的、所有者、消费者、保留期和清理触发`；`.gitignore`不是登记。唯一默认例外是任务专属 OS 临时夹具：短生命周期、不承载正式项目资产且用后验证清理。

统一外置共享工作根只来自用户明确授权或项目正式策略；不得把`_workspace`等名称设为产品通用默认。跨 canonical project root 的只读审查只接受用户明确点名的规范物理根和范围；该只读授权不产生任何写入授权。

## 4. 读入与初始化

默认机制读入上限：普通判断1个入口；PM派单2个核心入口，复杂分支再加1个命中reference；worker执行3个核心入口，当前动作再加1个命中reference。命中后完整读取；超过上限必须由当前事实缺口逐项解释，不得预读工作台、历史、全量 Git或未来动作。

只有用户明确要求初始化项目，或最小链仍不能确定主线、边界、入口和写回时，才读`00-模板入口.md → 项目总览.md → 当前工作台.md → 唯一事实入口`。同任务动作切换只补当前事实。

## 5. 回复与更新

普通判断默认：

```text
结论：
依据：
下一步：
```

普通最终答复最多3个标签、600 UTF-8 bytes；用户明确要明细或红灯必须说明授权、回滚或决策时可越过字节上限，但不得增加重复过程、内部 ID、命令全文或哈希墙。

过程更新默认上限为终答前3次：长任务开始、至多一个改变用户判断的里程碑、阻塞/需决策；完成只进最终答复。短任务零播报，timer、checking、重复状态和无决策进展全部丢弃。用户明确要求监控或风险动作另有通知契约时按该契约。

## 6. 禁止

不把历史、样例、全量 Git、规则源、thread、agent path或摘要当入口、授权或证据；权限分项判断。
