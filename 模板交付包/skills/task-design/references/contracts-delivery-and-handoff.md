# 契约、交付与接力作业包

仅在跨执行线契约、完整阶段设计、实施拆解、接力、设计归位或实施反馈回改时完整读取本文件。

## 复杂设计必须独立落位

符合下列任一情况时，设计不能只存在于聊天、当前工作台摘要或任务卡字段中：

- 一个业务结果涉及多个模块、项目、执行线或两个以上用户检查周期；
- 后续开发、测试、发布或运维需要在不同时间、不同实例中独立读取；
- 涉及共享契约、关键状态流程、权限边界、数据迁移、兼容切换或分阶段发布；
- 设计内容已经长到工作台摘要无法同时说清用户结果、实现、测试和发布路径；
- 用户明确要求方案、设计书、技术方案或独立文档。

活动设计的准确路径、唯一性、版本、创建授权、活动期和历史回收由[项目文档入口](../../../docs/AI编程协同机制/00-模板入口.md)统一定义。任务契约只登记当前活动入口、版本、写入授权、消费者和计划归档位置；任务卡或工作台只保存摘要和链接。本作业包只规定设计正文怎样覆盖用户说明、执行依据与上下游接力。

正文可以按[复杂业务设计文档模板](../../../docs/AI编程协同机制/模板/复杂业务设计文档模板.md)裁剪；模板只提供格式，不保存项目事实。项目已有有效正式设计位置时，是否沿用和怎样登记同样按项目文档入口处理，不为套模板迁移真值。

## 用户层与执行层

复杂设计文档分两层表达：

1. 文档开头是给用户看的说明，用普通中文写清`做成什么 / 实现路径 / 测试路径 / 发布路径 / 明确不做 / 需要用户决定什么`。避免用英文缩写、框架名、类名、字段表和架构图代替解释；不可避免的专业词先给中文含义。
2. 后半部分是给执行者的落地依据，保存模块/文件、复用能力、契约、数据与状态、安全边界、迁移回滚、验证入口和依赖顺序。技术原文需要精确时保留代码标识、接口名和命令。

用户层和执行层描述的是同一方案，不能为了“说人话”省略风险，也不能在技术附录偷偷加入用户层没有说明的新能力或范围。实现、测试和发布路径都是计划，实际结果仍分别由开发、测试和运维证据确认。

## 设计交付覆盖

总设计至少覆盖项目总目标、主链路、总体结构、模块职责、阶段、关键共享对象、主要风险和推进顺序。

阶段设计至少覆盖当前目标、边界、对象、必要契约、验收、风险、前置依赖、落地顺序、交接方向和写回位置。异常路径只按当前规模展开。

跨线设计再补：来源线、目标线、共享对象、接收内容、联调证据和最终拍板人。共享契约只能有一个正式版本，前端、后端和测试不得各存一份。

只冻结当前交付真正涉及的最小契约：

| 类型 | 当前范围需要回答什么 |
| --- | --- |
| API | 路径、方法、请求参数、响应字段、错误语义或错误码、鉴权 |
| 数据 | 字段名、类型、必填项、默认值、状态枚举和必要样例 |
| 前端 | 页面入口、展示字段、加载态、空态、错误态和刷新方式 |
| 文件 | 允许修改、禁止修改、输入输出及生成物位置 |
| 联调 | 来源与目标、Mock或测试数据、验证路径、日志或证据入口 |

不涉及的类型不展开，不为填满契约增加字段或场景。契约缺失时可以继续任务内设计，但不得进入依赖该契约的实现。正式契约需要变化时，先说明变化内容、事实依据、受影响消费者以及兼容和验收影响，并把结果返回原 Worker。需要用户决定的业务语义或验收取舍，由原 Worker在当前正式任务对话直接询问用户；用户答复只影响本任务时，Worker更新唯一任务和设计/契约版本后继续，不经 PM 中转。变化影响跨任务所有权、顺序、合流、共享契约或主线时，Worker带设计锚点立即通知 PM协调受影响范围。决定成立、唯一正式契约更新且受影响实现重新获授权前，原 Worker停止冲突实现，设计 Action不能自行解释为已经放行。

## 开发就绪接口

设计结果不靠“方案已完成”四个字交接。对当前实施范围至少给出：

| 开发需要的输入 | 必须能判定的内容 |
| --- | --- |
| 实现依据 | 当前任务约定、唯一正式设计/契约或本轮直接设计结果；有正式入口时包含适用版本/章节 |
| 实现落点 | 目标模块、入口或文件类型；复用能力、依赖方向和明确不改对象 |
| 行为与契约 | 用户可见结果、输入输出、状态/错误/权限语义、数据不变量和受影响消费者 |
| 工程风险 | 当前涉及的安全、事务/并发、外部失败、资源、配置、可观测性、兼容和迁移边界 |
| 落地顺序 | 前置依赖、跨线先后、迁移/双写/回滚与临时代码退出条件 |
| 验收映射 | 每个范围项对应的可观察标准、验证入口和不覆盖范围 |
| 未知与停止点 | 编码前必须闭合的决定项、实施时可定点核对的事实及其来源 |

轻量局部设计可以压缩为几句话，重大或跨线设计必须指向唯一正式入口；不得要求开发者在多个草案、聊天摘要或不同执行线的契约中自行选一个。设计完整只说明输入足够，不解除用户检查点，也不产生源码、测试、Git、环境或发布授权。

交接前应能把当前范围逐项映射为`设计/契约项 → 目标模块或文件 → 必须保持的行为/不变量 → 验证入口`。某项无法定位实现位置时继续调查；无法给出可判定验证时不能用主观描述替代验收。

## 实施切片

设计结果返回原 Worker并由其依据任务契约、用户检查点和当前授权确认可继续后，才按可验证交付切片，不机械拆成固定分钟数：

```text
目标结果：
涉及位置：
前置依赖：
实现要点：
验证方式：
结果返回原 Worker；直接用户请求由当前智能体交付给用户：
```

拆解只写入任务契约指定且当前任务拥有准确写入授权的唯一任务主面或唯一正式设计入口；任务卡已经承担文件化任务主面时不再视为第三个并列位置。没有对应授权时只随本轮设计结果返回原 Worker。当前工作台承载 PM 的当前主线、跨任务状态和下一步，设计 Action不得把它当成默认写入位置；只有 PM已经决定需要更新主线投影且准确路径写入授权成立时，才由有权控制者写入。只有任务授权已明确新文件路径、用途、使用者、入口和回收方式时，才形成独立实施计划。

## 归位与回改

- 总设计：每个项目或子项目只保留一个正式主设计落点。
- 复杂业务和跨周期阶段设计：写入任务契约按项目文档入口登记的唯一独立设计主文档；任务卡和当前工作台只保存当前版本、摘要和链接，不承载正文。
- 简单、单轮且只由当前执行者消费的阶段设计：可以随任务结果内联，不强制建文件。
- 共享契约：只保留一个正式入口。
- 协同设计：使用当前工作台既有`跨线接力`视图及任务验收入口，不另建协作文档。
- 核心架构：影响系统边界、主链路、模块职责或关键数据流时更新正式技术架构。

实施反馈先返回原 Worker，并区分三类：

1. 代码定位、局部算法或项目约定等实施细节与设计兼容，且不改变用户行为、正式契约、模块/数据所有权、质量目标或验收：由原 Worker在开发边界内解决，不为小调整重开设计。
2. 一手事实证明设计假设错误，或实现必须改变正式设计、共享契约、模块/数据所有权、质量目标、兼容迁移或验收：停止受影响实现，切回设计方法核对事实、消费者和影响；需要持久化时先更新唯一正式入口及适用版本，再恢复开发。
3. 变化进一步影响业务结果、正式任务边界、授权或用户检查点但只作用于当前任务：原 Worker在当前任务对话取得用户决定后直接更新任务版本、授权和控制关系；同时影响其他任务、共享对象、主线或跨任务资源时，再带变化锚点立即交 PM协调受影响范围。

不能让代码静默偏离设计，也不能为了维护旧设计否认代码、运行或性能证据。没有设计/契约写入授权时，交付差异、影响、建议位置和未写原因，不产生第二份临时正式版本。设计 Action不直接改正式任务契约或项目主线。

## 完成与历史归档

设计完成不等于业务任务完成。只要开发、测试、发布或验收仍在消费，独立设计文档就保持活动；停止追加、稳定事实归位、引用修正、移动授权和历史回收全部按[项目文档入口](../../../docs/AI编程协同机制/00-模板入口.md)执行，本作业包不另建第二套门禁。

返回 Worker前，设计侧只负责补齐实际结果、实现/测试/发布证据入口、与原设计的差异、未完成事项和替代入口，不把计划改写成已经发生，也不让已归档文档继续冒充当前设计。

## 返回 Worker与后续方法判定

设计 Action向原 Worker返回：当前结论、唯一正式设计或契约入口、当前版本与正文锚点、本版变化摘要、目标文件或模块、依赖、实现边界、验证入口、明确不做、受影响消费者、残留风险和仍需决定的事项。跨线时再返回共享对象、先后顺序、接收证据和拍板人。原 Worker到达用户检查点时先交付设计并停止；只有检查点允许、开发授权存在且关键缺口已经闭合时，才由同一 Worker选择开发方法，不建立“设计者向开发者移交控制权”的第二条任务链。需要PM知情时Worker只在聚合或立即事件中传递这些锚点和差异，不复制整份设计正文。

设计自检必须覆盖目标—范围—事实—设计—主链路—契约—验收的追溯关系、一致命名、事实/候选分离、范围无夹带、风险维度按实际命中、开发输入可判定和无占位。关键缺口未闭合时继续设计；格式完整、写回完成或已经返回 Worker都不是开发放行证据，设计 Action不能解除用户检查点、扩大授权或宣布任务终态。
