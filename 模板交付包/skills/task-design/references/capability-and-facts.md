# 设计能力与事实作业包

仅在原 Worker 已经选择设计方法，且当前设计必需事实未知、正式入口不存在、证据已经过期、易变事实需要复核，或需要建立、核验、刷新产品设计与契约基线时完整读取本文件。本文件只提供事实调查、核验和写回方法，不是当前项目的产品设计、技术架构或共享契约，也不建立独立身份、决定路径或写入授权。

项目事实、方法和格式必须分开：

- 产品、代码、配置、正式接口/schema、数据、设计稿、测试和运行结果是一手事实或正式原文。
- `项目事实/产品设计与契约基线.md`只在真实项目中登记经过核验、需要跨任务复用的产品流程、业务语义、体验约定、共享业务/交互契约入口和详细业务验收。
- `项目事实/技术架构与核心代码逻辑.md`只登记经过核验的系统边界、质量约束、稳定模块职责、核心链路、数据所有权和核心逻辑；不与产品基线混写。
- `模板/产品设计与契约基线模板.md`和`模板/技术架构与核心代码逻辑模板.md`只提供可裁剪格式，不能作为当前技术或产品事实，也不能因模板存在而自动创建实际文件。

## 事实补足与基线建立

1. 继承原 Worker已经核验的任务目标、非目标、当前放行段、用户检查点、分项授权、事实入口和回源关系。任务或工作台已经点名有效实际入口时直接读取相关章节；尚未点名时先沿项目总览登记入口，只有需要确定标准落点、首次创建或维护边界时才进入项目事实索引。模板不是读取产品事实的路径，不与实际入口或索引并行预读。
2. 读取当前动作最小输入、已有产品/设计/契约正式入口，以及当前目标直接相关的代码、配置、数据和测试；产品语义问题优先进入产品设计事实或正式产品契约，系统边界、模块职责、数据所有权和质量约束问题优先进入架构事实，技术栈与工程规则进入工程事实。只在已暴露当前判断必需依赖时顺序补读另一个事实域。
3. 把材料分成`一手事实 / 有权决定者确认的业务决策 / 候选 / 当前不需要`，不把旧方案、任务预期或用户对技术现状的猜测写成当前事实。
4. 调查代码、配置、接口、测试和现有文档可以回答的技术事实；业务目标、体验取舍或共享契约含义中调查后仍未知的部分形成最小决定项并返回原 Worker，不由设计 Action直接建立用户或 PM决定通道。
5. 只有缺口会改变目标、边界、正式契约或验收时才形成决定项；每次只保留一个会改变方向的最小问题，说明候选、事实来源和影响，可以提供`确认 / 纠正 / 不知道，请继续调查`路径，不得发送项目资料问卷。直接用户请求由当前智能体询问用户；正式任务由原 Worker按任务既有控制关系处理。
6. 有权决定者答复后，把已经确认的业务决策与仍需现场核验的技术事实分开；取得相应证据后，把事实、证据和建议写回内容返回原 Worker。只有原 Worker确认事实确需跨任务复用、唯一入口已经核对且当前任务拥有准确路径写入授权时，才能创建或更新对应实际事实文件；产品基线授权不能推导出架构基线、正式契约或项目总览写入授权。
7. 实际事实文件只记录其事实域拥有的稳定内容、适用范围、正式来源、核验证据、刷新触发、维护方和未知项；已有正式原文只登记链接。达到当前动作最低条件后把结果返回原 Worker，由其按任务契约决定继续设计、停在检查点或选择下一方法。

事实补足不另建业务任务或平行台账，不直接返回 PM 续派，也不绕过原 Worker询问用户。标准事实路径已经确定只解决内容归位，不证明文件存在、内容已核验或产生写入权限；当前任务事实足够且无需跨任务复用时，不为形式完整创建空基线。没有授权时只向原 Worker交付已确认事实、证据、建议位置和尚未写回原因，不扩张为任意文档创建权。

## 事实调查与候选控制

用户已经点名目录或具体问题时，先用文件检索定位入口、契约、实现和测试，只读命中的必要文件。能确认当前事实、差异和验收入口时立即停止；事实仍不足时只列最小缺口，不用全量扫描掩盖问题。

接口路径、字段、状态、模块名、依赖和技术约束必须标注来源。允许用候选结构帮助收敛，但必须同时写明：

- 它是候选，不是正式契约。
- 还缺哪项事实核对。
- 放行前需要什么证据。
- 当前没有加入哪些未要求能力。

候选清楚但仍缺会改变目标、边界、正式契约或验收的事实时，结论保持`继续设计`，不得冻结候选设计或放行开发，也不得以“先做出来再说”绕过事实门禁。不影响这些决定的未知项写成实施前核对，不阻塞当前设计交付。

## 复用与定点复核

已有正式入口和足够新鲜的证据时，复用稳定目标、主流程、设计约定和契约入口，只核对当前目标、受影响字段或状态、验收和命中的易变事实。建议更新内容返回原 Worker；获得准确路径授权并写回后保留核验时间、证据和刷新触发，使后续设计不重复询问已经稳定的项目事实。

项目专用事实只由原 Worker按当前任务授权写入唯一项目事实入口或既有正式契约，不进入通用 Skill，也不复制平行版本。当前设计所需事实已经足够后，把设计结果、证据、剩余缺口和写回现实返回原 Worker；由同一 Worker服从用户检查点和原任务授权决定交付设计、继续设计、选择开发方法或收口，不为事实沉淀制造额外阶段等待。
