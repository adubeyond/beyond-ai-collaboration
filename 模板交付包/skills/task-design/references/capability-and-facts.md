# 设计能力与事实作业包

仅在设计能力`未初始化/需刷新`，或需要建立、核验、刷新产品设计与契约基线时完整读取本文件。

## 初始化顺序

1. 读取项目能力台账、现有产品/设计/契约入口，以及当前目标直接相关的代码、配置、数据和测试。
2. 把材料分成`已确认事实 / 候选事实 / 业务取舍 / 当前不需要`，不把旧方案或用户猜测写成当前事实。
3. 自行调查代码、配置、接口、测试和现有文档可以回答的技术事实；只把业务目标、体验取舍或共享契约含义中调查后仍未知的部分交给用户。
4. 每次只问一个最小引导问题，带候选值、事实来源、影响和`确认 / 纠正 / 不知道，请继续调查`路径；不得发送项目资料问卷。
5. 用户答复后区分用户确认与现场事实，取得一手核验，再写回任务包授权的唯一产品设计与契约基线。
6. 记录目标、主流程、设计约定、唯一契约、验收、事实来源、核验证据和刷新触发；达到当前动作最低条件后沿原任务继续。

初始化不另建业务任务或平行台账，不返回PM续派。标准事实路径已由任务包给出时直接使用；路径、用途、使用者、入口和持续保留方式未授权时只停止写回，不扩张为任意文档创建权。

## 事实调查与候选控制

用户已经点名目录或具体问题时，先用文件检索定位入口、契约、实现和测试，只读命中的必要文件。能确认当前事实、差异和验收入口时立即停止；事实仍不足时只列最小缺口，不用全量扫描掩盖问题。

接口路径、字段、状态、模块名、依赖和技术约束必须标注来源。允许用候选结构帮助收敛，但必须同时写明：

- 它是候选，不是正式契约。
- 还缺哪项事实核对。
- 放行前需要什么证据。
- 当前没有加入哪些未要求能力。

候选清楚但事实尚未闭合时结论保持`继续设计`。不得冻结候选设计或放行开发，也不得以“先做出来再说”绕过事实门禁。

## 刷新与成长复用

设计基线可用时复用稳定目标、主流程、设计约定和契约入口，只刷新当前目标、受影响字段/状态、验收和命中的易变事实。更新后保留核验时间、证据和刷新触发，使后续设计不重复询问已经稳定的项目事实。

项目专用事实只写项目能力档案，不进入通用Skill。初始化或刷新完成后，按原任务授权进入开发或收口，不为能力成长制造额外阶段等待。
