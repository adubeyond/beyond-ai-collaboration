# 设计事实与基线

仅在当前设计需要读取、建立或修正可跨任务复用的产品设计与契约事实时读取。普通局部设计不进入本文件。

## 1. 定点核验

先沿项目或子项目文档入口确认当前专题的正式所有者、适用范围和文档状态。总览或宽泛事实基线负责指路与稳定边界；已经存在更具体的接口、schema、页面、状态或业务契约时，以该契约承载正文，不把内容复制回宽泛基线。

只读取当前目标直接相关的：

- 现有产品/设计/契约入口；
- 用户目标与明确不做；
- 页面、接口、数据和关键业务流程现状；
- 相关代码、配置、测试和一手运行事实。

区分：

- 当前已经存在的事实；
- 本次要解决的设计问题；
- 实施后的方案状态；
- 仍需开发前定点核对的细节。

不能确认的候选不得冒充正式字段、状态或业务规则。

## 2. 写回长期事实

只有后续任务会复用的内容才写回项目事实索引登记的、与当前子项目和专题匹配的现有产品、设计或契约所有者：

- 稳定目标、边界和主流程；
- 设计约定和用户入口；
- 共享契约的唯一正式入口；
- 稳定验收口径；
- 事实来源、最后核验和失效触发。

具体接口字段、状态和错误已经有正式契约时，只登记入口和适用范围。

项目没有现成所有者、当前任务确实需要且拥有写入授权时，才使用项目事实索引的兜底路径；只写已经核验的部分，不复制空模板、不另建初始化任务。当前设计不需要时不创建。

## 3. 变化与复用

已有基线与当前现场一致时直接复用，只更新本次确实改变的事实。现场冲突时以代码、配置、正式契约、测试或运行事实为准，修正受影响内容并保留新的依据。

事实写回后返回原 Worker继续当前任务；直接设计请求则交付给用户。不等待 PM更新能力状态，也不由本 Skill创建任务或状态。
