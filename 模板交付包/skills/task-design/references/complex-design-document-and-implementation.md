# 复杂设计文档与实施衔接

只在复杂业务、跨模块共享契约、多个实施周期、迁移、权限或关键状态流程，用户要求正式设计文档，或者实施反馈需要回改总体设计时完整读取。普通局部设计不进入本文件。

## 1. 唯一活动设计文档

复杂设计不能只留在聊天、工作台摘要或任务卡中。正式任务直接使用任务已经点名的项目/子项目文档入口和事实索引；只有直接请求尚未给出文档入口，或现有入口发生冲突时，才读取[项目文档入口](../../../docs/AI编程协同机制/00-模板入口.md)。然后确定：

```text
已有正式设计入口或唯一新路径
文档服务的业务结果和消费者
谁负责在实施期间更新
何时停止作为活动设计
完成后的合并、归档或只读方式
```

优先复用项目已有设计、架构或契约文档。没有承载者且任务拥有写入授权时才新建；不得使用“最终版、最新版、修订版”等平行文件制造多个真值。

工作台只保存结论和入口，任务线程只保存当前动作与反馈，设计正文只保留一个活动版本。设计文档所在目录只承载设计正文及其直接附件，不作为后续开发、测试、发布或运行证据的通用工作区；这些证据回到当前任务或项目已有的对应所有者。

## 2. 设计正文

复杂设计至少用清楚的语言说明：

- 用户要得到的结果、当前系统行为和明确不做；
- 主链路、模块职责、读写方向和共享对象；
- 接口、字段、状态、错误和兼容约束；
- 实现位置、依赖和推荐顺序；
- 测试入口、关键用例和验收标准；
- 发布、观察和回退路径，或者为什么本次不涉及；
- 已确认事实、候选、风险和仍需决定的唯一问题。

实施切片按可验证结果拆，不按设计、开发、测试角色拆，也不机械切成固定时长：

```text
目标结果 / 涉及位置 / 前置依赖 / 实现要点 / 验证方式 / 完成条件
```

## 3. 与实施连接

设计满足实现门禁且原任务已授权开发时，同一个 Worker切换到开发方法继续，不建立设计交接任务，不等待PM续派。

开发反馈只影响字段、状态或当前顺序时，更新活动设计和唯一契约；影响总边界、主链路、模块职责或技术路线时，先回到设计方法重新裁决，再继续实现。

设计结束时只提供一个可消费入口：正式文档路径、当前适用范围与决定、首个可验证实施结果、仍会阻断实现的未决项。原 Worker继续实施时直接使用该入口；PM或另一个正式任务消费时只传这份最小摘要，不复制设计正文。跨任务关系按03机制处理，设计 Skill不创建任务、不分配Worker，也不承担消息中继。

## 4. 历史回收

仍有开发、测试、发布或验收消费者时，设计文档保持原位并继续作为唯一活动入口。任务完成、取消或被替代后：

1. 把仍有效的目标、契约和架构结论归回各自长期所有者；
2. 修正工作台、项目总览和相关文档中的活动引用；
3. 没有活动消费者时移入项目已有历史入口；
4. 没有移动授权时在原位标明“已关闭，只读历史”，并停止追加过程；
5. 不为归档再创建一份总结或复制正文。

移动、删除和合并仍服从用户授权，不能借归档丢弃尚未验收的设计或有效契约。
