# 测试事实与证据基线

仅在当前验证需要读取、建立或修正可跨任务复用的测试命令、环境、数据边界和验收事实时读取。普通单一断言不进入本文件。

## 1. 最小测试输入

- 业务结果和明确不测范围；
- 验收项、原失败路径和待测对象；
- 当前实现、diff或正式契约；
- 可用测试命令、环境、数据和已知基线失败；
- 允许的副作用与清理边界；
- 当前任务线程或已有测试记录中的证据位置；没有独立记录时由当前结果承载。

用户、项目规则或验收标准明确要求独立测试时，测试方只接收验证所需的原始对象和定点材料，不接收开发者预设结论。

## 2. 定点调查

先从项目或子项目入口定位待测模块；测试命令可以分别由各模块的测试项目、配置、依赖清单、脚本或CI拥有，不要求项目先建立一份统一测试基线。协作机制、角色说明和旧测试报告不能替代当前测试入口。

从测试配置、脚本、CI、相关代码、环境入口和正式验收确认：

- 能直接证明验收项的测试层级和命令；
- 环境、数据、账号和临时对象边界；
- 已知基线失败；
- 当前轮证据位置和清理要求。

能从项目发现的事实不转问用户。业务验收取舍、真实权限或调查后仍无法确定的外部资源，才形成一个最小问题。

## 3. 写回与复用

后续任务会复用的稳定事实写回项目事实索引登记的、与当前子项目和测试层级匹配的现有测试或验收文档；没有单一测试文档时，可以由索引登记多个有明确范围的真实入口。当前轮结果仍留在任务线程或获授权测试记录。记录来源、最后核验和失效触发。

项目没有现成所有者、当前任务确实需要且拥有写入授权时，才使用项目事实索引的兜底路径；不复制空模板、不另建初始化任务。已有基线与现场一致时直接复用；测试入口、环境、数据或验收变化时只更新受影响部分。

稳定基线不能替代当前轮真实测试。
