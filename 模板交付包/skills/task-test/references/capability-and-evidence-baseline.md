# 测试能力与证据基线

## 何时读取

仅在当前验证必需的测试事实未知、正式入口不存在、证据已经过期、易变事实需要复核，或现有测试入口、环境、数据、账号、基线失败和证据去向无法支撑当前动作时完整读取。普通单一断言不进入本文件。

## 最小测试包

由原 Worker 调用测试方法或独立测试助手时，只接收当前验证需要的：

- 任务 ID、业务结果和明确不测范围
- 验收项、原失败路径，以及正式验收/设计/契约的路径、版本和正文锚点
- 当前待测内容、提交/制品哈希/构建 ID或其他稳定版本锚点、已有变更清单或可用 diff
- 正式测试入口、环境、数据和已经由可比一手证据确认的基线失败
- 测试资产、环境、账号、网络、服务、数据和临时对象的分项边界
- 独立性要求、用户检查点、证据写回位置与原 Worker 回传目标

独立测试助手不得接收开发者预设结论或完整聊天历史，只接收最小包、原始制品和验证所需的定点材料；它不因接收测试包取得业务任务控制权。

## 项目专用测试事实

本文件负责补足和沉淀项目专用事实，不复制主文件中的通用测试原则。围绕当前结果实际涉及的范围，定点确认：

模板项目的测试事实域标准落点由项目事实索引确定为`docs/AI编程协同机制/项目事实/测试与验收基线.md`；这只是稳定路由，不表示文件已存在、内容已核验或本轮拥有写入授权，其他项目沿自己的唯一测试事实入口。`docs/AI编程协同机制/模板/测试与验收基线模板.md`只提供可裁剪格式，不保存项目事实。任务或项目文档已经点名有效实际入口时直接使用；只有实际入口缺失、需要确定标准落点、首次创建或维护边界时才进入项目事实索引，不并行预读实际入口、索引和模板。

- 项目正式的单元、组件、契约、集成、端到端、构建、静态检查和发布前验证入口，以及各入口的适用范围、工作目录、参数、预计成本和与 CI 门禁的对应关系。
- 当前支持的运行时、操作系统、浏览器、设备、区域、语言、时区、依赖服务和协议版本；哪些差异会改变裁决。
- 已有测试目录、公共断言、fixture、数据工厂、Mock/桩边界、快照审阅方式和测试资产所有者，避免另造一套基础设施。
- 测试环境、数据库、缓存、队列、对象存储、外部服务、功能开关、时钟和随机源的隔离方式，以及允许使用的账号、数据来源、创建和清理入口。
- 测试进程、子进程、服务、端口、队列消费者和长任务的超时、无进展判定、停止、状态观察与归属明确的清理入口。
- 哪些测试会写数据、调用网络、改变服务、产生费用、接触敏感信息或访问生产，分别需要什么授权、观察、停止和恢复条件。
- 项目正式覆盖阈值、兼容矩阵、安全/性能/可访问性专项入口、Flaky 登记或隔离规则；项目没有正式规则时保持未知，不自行发明数字或流程。
- 测试日志、截图、录屏、报告和其他证据的准确位置、版本锚点、保留时间、脱敏规则、接收者及回收方式。

## 事实补足与基线建立

1. 从待测对象及其相邻测试、包脚本、测试配置、直接依赖、相关 CI 段、环境入口和正式验收定点调查；不为建立“完整测试能力清单”扫描全仓、全部流水线或所有环境。
2. 确定待测提交/制品/构建、正式验收与设计/契约的路径/版本/正文锚点、变更与验收映射、可观察判定标准、测试层级与命令、环境/数据/账号边界、已知基线、证据去向，以及副作用的停止、清理或保留门禁。当前代码、配置、CI和实际命令证据与旧基线冲突时，以当前一手事实裁决并保留冲突来源。
3. 记录事实来源、核验时间和刷新触发；只有事实需要跨任务复用且当前任务拥有准确路径写入授权时，才把稳定事实写入唯一`测试与验收基线`。当前轮动态证据只写任务授权的任务入口或证据位置；没有授权时交付证据、建议位置和尚未写回原因。
4. 只有业务验收取舍、真实权限，或调查后仍无法确定的环境/数据来源才向用户提一个最小问题。
5. 问题包含候选值、来源、影响和`确认 / 纠正 / 不知道，请继续调查`路径；不得把账号、基线失败和证据入口整套改成用户问卷。
6. 事实达到当前验证最低条件后返回原 Worker；同一 Worker 服从用户检查点沿原任务选择测试方法，不返回 PM 重新派单。

## 版本、基线与证据锚定

当前轮证据至少能够定位实际待测提交、制品哈希、构建 ID或等价版本锚点，正式验收/设计/契约路径、版本和正文锚点，相关配置、执行位置、测试入口、环境/关键变体、数据条件、实测值或断言、退出状态、测试创建对象、清理/保留结果和未覆盖范围。时间只有在环境易变、证据有时效或需要区分多轮结果时才记录；不为形式完整堆积无关系统信息或整段原始日志。

“已知基线失败”必须说明失败断言、可比版本、同条件环境、复现结果、首次或最近核验时间以及为何与当前变更无关。只有旧日志、旧任务记录或开发者说明时，它仍是待核验线索；无法建立可比对照时不能把当前失败排除为基线。

证据只能支撑与其对象、版本、验收/设计锚点、环境和覆盖一致的结论。本地 Mock 测试、开发自测、独立测试、CI、联调、预发和生产观察分别标注，不能因为共享同一命令名、报告格式或“全部绿色”而互相替代。待测版本、正式验收或设计/契约正文发生变化时，旧裁决失去当前放行权，只能作为历史对照。

## 独立调用的补读

没有任务运行上下文且输入没有给出清晰目标、断言和对象时，才按项目入口定点补读根`AGENTS.md`、项目点名入口、当前任务和正式验收。Git 仅在版本或变更归属确实影响裁决时读取；不默认展开项目总览、历史任务和旧测试过程。

用户已经明确问“到底过没过”或给出单一断言时，不停在接手确认，直接按核心验证。

## 复用与定点复核

已有正式入口和足够新鲜的证据时，不重新扫描项目或重复询问。后续只核对待测版本、变更范围、环境状态、原失败路径和当前轮证据；稳定基线、缓存报告和成功历史不能替代当前轮真实验证。

触发刷新包括测试入口或CI变化、环境/数据/账号变化、验收契约变化、依赖或运行时变化，以及已有事实超过约定时效。事实冲突时保留来源和时间，不静默选边。
