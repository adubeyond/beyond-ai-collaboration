# 测试能力与证据基线

## 何时读取

仅在正式项目测试能力为`未初始化/需刷新`，或现有测试入口、环境、数据、账号、基线失败和证据去向无法支撑当前动作时完整读取。普通单一断言不进入本文件。

## 最小测试包

由任务控制实例调用时，只接收：

- 任务 ID、业务结果和明确不测范围
- 验收项、原失败路径和待测版本
- diff、变更清单与正式契约
- 测试命令、环境、数据和已知基线失败
- 只读、写入、临时对象和修复边界
- 证据写回位置与任务控制实例回传目标

独立测试实例不得接收开发者预设结论或完整聊天历史，只接收最小包、原始制品和验证所需的定点材料。

## 初始化顺序

1. 定点读取测试配置、脚本、CI、相关代码、环境入口和正式验收，先调查可发现事实。
2. 确定待测版本、变更与验收、测试层级与命令、环境/数据/账号边界、已知基线失败、证据去向和副作用门禁。
3. 记录事实来源、核验时间和刷新触发；稳定事实写入唯一`测试与验收基线`，当前轮动态证据写任务入口或证据索引。
4. 只有业务验收取舍、真实权限，或调查后仍无法确定的环境/数据来源才向用户提一个最小问题。
5. 问题包含候选值、来源、影响和`确认 / 纠正 / 不知道，请继续调查`路径；不得把账号、基线失败和证据入口整套改成用户问卷。
6. 基线达到当前动作最低条件后立即沿原任务测试，不返回 PM 重新派单。

## 独立调用的补读

没有任务运行上下文且输入没有给出清晰目标、断言和对象时，才按项目入口定点补读根`AGENTS.md`、项目点名入口、当前任务和正式验收。Git 仅在版本或变更归属确实影响裁决时读取；不默认展开项目总览、历史任务和旧测试过程。

用户已经明确问“到底过没过”或给出单一断言时，不停在接手确认，直接按核心验证。

## 成长复用

基线已经`可用`且无刷新触发时，不重新扫描项目或重复询问。后续只刷新待测版本、变更范围、环境状态、原失败路径和当前轮证据；稳定基线不能替代当前轮真实验证。

触发刷新包括测试入口或CI变化、环境/数据/账号变化、验收契约变化、依赖或运行时变化，以及已有事实超过约定时效。事实冲突时保留来源和时间，不静默选边。
