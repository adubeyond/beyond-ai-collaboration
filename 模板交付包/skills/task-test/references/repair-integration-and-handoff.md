# 修复回测、候选集成与交接

## 何时读取

当前已出现可复现失败、需要开发修复回测、多个隔离候选、唯一集成、跨实例移交或高风险专项时完整读取。普通单一断言不进入本文件。

## 失败与修复回测

测试动作负责独立判断和证据，任务控制实例始终管理修复循环：

1. 原测试实例取得可复现失败证据，判断更接近实现、设计、契约、环境还是证据问题，并返回任务控制实例。
2. 测试实例不改变契约、任务状态或写入范围，不启动开发实例，也不请 PM 代派。
3. 边界内实现缺陷由任务控制实例自行切回开发，或按既有授权启动一个写入边界明确的开发助手。
4. 修复后，任务控制实例把新版本、diff 和自测结果交回原测试实例。
5. 原测试实例复测原失败路径和必要受影响回归，重新给三态裁决。

独立测试默认复用一个实例，实例失效时最多一个替补。不得新建平行测试任务、开发任务或“返工任务”。修复线自测不能替代任务授权要求的独立测试。

契约、写入边界、真实权限、高风险或修复上限需要改变时，任务控制实例在当前任务对话请用户裁决；资源、实例和跨任务冲突才通知 PM。用户纠偏后更新正式契约与验收，再由原测试实例回归。

## 候选与唯一集成

同一业务结果拆成多个隔离候选时：

- 候选任务只负责原失败路径、定向测试、受影响回归，以及证明候选可集成所需的构建或静态检查。
- 唯一集成任务负责跨候选契约和一次全量或发布级回归，并在最终候选提交或制品上完成发布前验证。
- 涉及安全、数据一致性、迁移、鉴权或其他高风险面时，不得降低安全、数据一致性、迁移或鉴权专项验证强度。
- 只有影响范围无法可靠界定、候选修改全局共享基础或项目正式门禁明确要求时，候选才追加全量测试，并记录重复全量的必要理由。

初始化包点名`候选 / 唯一集成 / 单任务`责任和最终发布门禁。缺少该字段时，任务控制实例按实际变更范围补齐，不退回 PM，也不把“测试越多”直接等同于证据越强。

## 交接与收口

跨实例交接只传最小测试包、原始制品、当前失败和正式证据位置，不传开发者预设结论或整段聊天。测试结论回到任务控制实例，由它按授权自动收口、继续修复或进入运维。

已预授权运维路径时，测试通过可进入发布前检查；未授权生产时不得把“测试通过”解释为允许发布。终态、生命周期和 PM 事件由任务控制实例与身份技能负责，测试动作不另造控制事件。
