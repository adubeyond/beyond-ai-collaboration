# 测试动作

## 身份与边界

测试是 Worker 在当前任务内选择的专业方法，或基础智能体处理直接、清晰验证请求时采用的方法，不建立新智能体，不改变身份、任务 ID、控制权或授权。它只用当前轮证据判断待测结果，裁决固定为`通过 / 不通过 / 不能判断`。

在本方法内，PM 只编译、派发或协调任务，不能替 Worker 运行完整测试；跨任务、共享对象、主线、资源、安全和收口仍由 PM 按身份职责处理。正式任务先由 Worker 完成接单核验，再进入测试；结果返回同一 Worker。直接、清晰的用户测试请求由当前智能体直接交付，不制造不存在的 Worker 或 PM 关系。

测试不定义验收、不修改产品实现、不管理开发修复、不发送任务终态，也不替运维发布。没有独立性要求时，正式任务由同一 Worker、直接请求由当前智能体使用测试方法；确需独立证据时，由实际承接请求的智能体按协作规则使用一个局部测试助手，助手只验证并返回证据，不取得任务控制权。

## 最小读入与路由

由 Worker 调用时，继承已核验的目标与不测范围、正式验收和有效设计/契约锚点、用户检查点、分项授权、待测版本、开发证据、事实入口和回源关系，只补当前验证需要的对象与证据；不重跑接手链，不预读修复或运维材料。当前用户消息也可以成为清晰、直接的测试契约。

这些专业附录同时适用于正式任务和直接请求。正式任务按文中的Worker关系执行；直接请求由当前智能体承担询问、交付和后续动作。不存在的PM、助手或任务关系不补造。

按当前问题选择路径：

1. 测试事实未知、正式入口缺失、证据过期，或要建立、核验、刷新测试与验收基线：读[测试能力与证据基线](references/capability-and-evidence-baseline.md)。
2. 已出现失败、需要修复回测、存在多个隔离候选或跨实例交接：读[修复回测、候选集成与交接](references/repair-integration-and-handoff.md)。
3. 验收复杂、影响范围不清，需要覆盖矩阵、缺陷归因、环境裁决或详细失败包：读[覆盖、归因与裁决](references/coverage-attribution-and-verdict.md)。
4. 单一断言、单文件核对或明确命令：只读点名对象并取得当前轮证据，不读 reference。

初始最多读取一份 reference；场景真实变化后再读下一份。触发后完整读取，同一任务中文件未变化则复用；reference 缺失时只停止依赖它的分支，不猜规则或错误放行。

## 快速断言

目标、期望、比较方式和禁止范围明确时，使用一次能直接证明断言的最小读取或命令，记录实测值、比较结果和必要退出状态后立即裁决。不为“更完整”展开工作台、历史、全仓、无关测试或第二套等价证明；目标不足时只指出一个关键证据缺口。平台明确拒绝当前命令类别时，按根`AGENTS.md`的全局边界立即裁决，不换成等价命令、命令壳或运行时探测继续重试。

用户禁止 Git、网络、服务、部署、生产或数据操作时，不为例行验证读取或操作这些对象；禁止写入不等于自动允许只读。

## 验证门禁与三态

验证前闭合：

- 待测对象和稳定版本锚点；
- 正式验收、设计或契约的路径、版本及可观察判定标准；
- 必验、不测和当前影响范围；
- 测试层级、环境、数据、账号和证据位置；
- 独立性要求，以及文件、网络、服务、进程、临时对象和清理/保留边界。

副作用边界不明时不执行对应测试。版本、验收或契约变化后，旧裁决只作历史对照。

先逐必验项裁决，再合成总结果：

- 任一必验项有当前轮直接反证：`不通过`，同时保留其他未覆盖项。
- 没有失败，但必验项证据不足、对象/版本不明或环境不足：`不能判断`。
- 全部必验项在当前对象、版本、环境和范围内通过，且没有关键未覆盖项：`通过`。

超时、工具错误、空结果和测试设施故障不自动等于产品不通过；只有与验收直接冲突的一手证据才支持`不通过`。

## 核心测试约束

- **判定标准**：先验证用户可观察结果、正式验收和边界契约，不从当前实现反推正确性；永真断言、仅证明调用发生、空测试集或无有效断言的绿色退出不能判通过。
- **对象与证据**：证据必须绑定待测版本、验收锚点、环境、数据和实际覆盖，并确认测试真实执行且因正确原因通过或失败；开发自述、旧日志和旧截图只能作线索。
- **覆盖与层级**：按业务影响和风险选择最低充分层级，先做高信号定向验证，再补真实涉及的失败、边界和回归；单一样例、局部静态核查或单元测试不能冒充更大范围、联调或生产证据。
- **复用与替身**：复用项目正式测试入口、fixture、数据工厂和公共断言。Mock 或桩必须保留真实契约，不能替掉被测核心行为制造假通过。
- **稳定与归因**：控制时间、随机、并发、缓存、网络和共享状态；不得重跑到绿、无限重试、固定等待、扩大超时或放宽断言掩盖 Flaky、污染和失败。
- **测试资产**：测试代码、脚本、fixture、快照和配置只有准确路径获得写入授权时才可修改；不得删除/跳过用例、改期望、扩大容差或无审阅更新快照使候选通过。
- **副作用与残留**：测试产生的数据、账号、文件、进程、服务、消息、缓存、费用或环境变化必须有授权、观察、停止和清理/保留责任；无一手清理证据时不能写“已清理”。

复杂覆盖、证据强度、缺陷归因、Flaky、超时、候选集成和完整失败包由对应 reference 承载，只处理当前变化真正命中的风险。

## 正常路径

1. 把验收、设计或契约转成可观察结果与反例，选择能直接暴露当前风险的最小测试层级。
2. 执行高信号定向验证，再按实际影响补必要失败、边界和回归；项目门禁或无法界定影响时才扩大范围。
3. 记录与待测版本、环境和数据对应的实测值、退出码、断言与关键输出，区分本轮回归、可比基线、测试资产和环境问题。
4. 复测修复版本时先跑原失败路径，再按影响补回归；不能用新版本沿用旧裁决。
5. 逐项和总体裁决，限定证据强度、未覆盖、残留及建议流向，只写入获授权的任务或证据入口。

## 失败回流与交付

正式任务的失败证据先返回原 Worker，由它决定切开发、切设计、处理环境或停止；直接请求由当前智能体在现有授权内作出同样判断，未获修复授权时只交付失败事实，不补造 Worker 或返工任务。测试方法和独立测试助手不启动或管理开发，不要求 PM 逐轮代派，也不另建返工任务。修复后，正式任务由 Worker、直接请求由当前智能体核对新版本并再次选择测试方法；需要独立测试时回到原唯一测试助手。

正式任务内决定由 Worker 在当前对话处理，直接请求的决定由当前智能体在用户给定的授权与检查点内处理；只有真实存在PM关系且影响跨任务、共享对象、主线、资源或安全时才交 PM。测试通过也不产生发布、生产或用户可用结论；只有原授权和检查点允许时，实际承接请求的智能体才选择后续方法。

交付先用普通语言说明测的是哪一版、用户关心的结果能否确认、哪里失败或为何不能判断，再给最小证据、实际覆盖、未覆盖、清理/残留和下一流向。用户约定“一次一个断言”“测试完先看”或其他检查点时，到点立即停止，不提前修复、扩大覆盖、进入运维或收口。
