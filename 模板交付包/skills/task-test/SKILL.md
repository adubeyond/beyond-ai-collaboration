# 测试动作

推荐触发句：`测试当前变更`

## 身份与结果

测试是 PM 或执行者调用的动作技能，不是独立身份。它用当前轮一手证据判断设计或实现是否满足验收，只给`通过 / 不通过 / 不能判断`；不接管业务任务、开发修复、PM 状态或运维发布。

清晰的只读断言、证据核对和完成判断也可直接进入本技能。当前输入已经点名目标、断言和禁止范围时，直接验证并裁决，不先升级成项目接手、完整审计或正式测试编排。

## 输入分类与最小读入

由任务控制实例调用时，继承任务运行上下文，只读当前测试包、待测对象、正式验收和最小验证入口；不重跑接手链，不预读未来修复或运维材料。用户当前消息给出的清晰测试请求也是合法测试契约，不要求先补工作台任务行。

先按场景选择 reference：

1. 正式项目动作显示测试能力`未初始化/需刷新`：完整读取[测试能力与证据基线](references/capability-and-evidence-baseline.md)。
2. 测试已失败、需要复现修复回测、多个隔离候选或跨实例交接：完整读取[修复回测、候选集成与交接](references/repair-integration-and-handoff.md)。
3. 验收复杂、影响范围不清、需要覆盖矩阵、缺陷归因、环境故障裁决或详细失败包：完整读取[覆盖、归因与裁决](references/coverage-attribution-and-verdict.md)。
4. 排除以上分支后的单一断言、单文件核对或明确命令，只读点名对象并形成当前轮一手证据，不读取 reference。

初始最多读取一份 reference；真实场景变化后才读下一份，不把多份正文合并预读。被触发的 reference 必须完整读取；缺失时只停止依赖它的分支，核心仍处理普通断言且不得猜规则或错误放行。

## 单一断言快路径

当前消息已经给出文件、期望值、比较方式和禁止范围时，使用一次能直接证明断言的最小读取或命令，记录实测值、比较结果和必要退出状态后立即裁决。

- 区分大小写的单行文本断言，以当前轮原文和序数比较结果作为一手证据；除非编码本身是验收对象或原始读取不能解释，不追加十六进制、字节、字符数或第二套等价证明。
- 用户禁止 Git、网络、服务、部署、生产或数据操作时，不为例行测试真值读取这些对象；禁止写入不自动变成允许只读。
- 不为补充“更完整”证据展开工作台、项目总览、历史、调用方、全仓搜索或无关测试。目标本身不足时只说明唯一证据缺口，再按授权定点补齐。

## 证据与三态裁决

`通过`必须由当前代码、配置或环境对应的一手证据直接支撑；二手摘要、旧日志、旧截图或开发自述不能单独判通过。只有定点文件核对等一手弱证据时，说明未覆盖风险；证据或环境不足时给`不能判断`，不能把超时、工具错误或结果空值直接写成业务`不通过`。

`不通过`只用于当前轮一手证据已经与验收标准直接冲突。测试结论必须同时说明实际流向：自动收口、回任务控制实例修复、回设计补契约、回运维补环境，或因真实红灯请求最小裁决。

## 测试能力初始化安全默认

正式项目需要测试能力初始化时，必须形成或刷新唯一`测试与验收基线`。必需事实和核验未闭合前不得宣布测试通过，也不得执行副作用不明的测试；达到当前动作最低条件后沿原任务继续，不返回 PM 续派。

清晰、局部、零副作用的直接断言允许用`当前消息 + 点名对象 + 当前轮定点证据`形成内联最小测试契约，不强迫普通核对先建设完整项目档案。初始化调查、引导提问、成长写回和稳定事实复用只在初始化分支读取对应 reference。

## 验证门禁与正常路径

验证前闭合：目标与不测范围、待测对象或版本、验收标准、当前轮证据入口和允许的副作用边界。Git 只在版本锚点、变更归属或项目正式门禁确实依赖它时才是必需条件；用户明确禁止时不得擅自补读。

1. 选择能直接证明验收项的最小命令、接口、页面操作或定点核查。
2. 本轮实际取得实测值、退出码、断言和关键输出，区分基线失败与本轮回归。
3. 缺陷修复必须复测原失败路径，并按真实影响补必要回归；普通单一断言不机械扩成五类覆盖。
4. 给出三态裁决、证据、未覆盖风险和实际下一流向；只把结论与证据位置写回获授权入口。

历史回收和旧证据只能作线索。验收标准或关键测试对象缺失时给`不能判断`并指出一个最小补齐动作，不自行发明标准。

## 修复控制权

测试失败后的边界内修复仍属于原业务任务。失败证据返回任务控制实例，由它切回开发或按授权启动开发助手，再把新版本交回原测试实例回测；测试实例不得启动开发、要求 PM 代派、修改任务状态或另建平行返工任务。

涉及契约、写入边界、真实权限、高风险、修复超限或资源冲突时才形成红灯。测试通过后由任务控制实例按原授权收口或进入运维，测试不得把通过自动扩张成发布授权。

## 权限与停止边界

- 不修改实现，不扩大开发、Git、服务、网络、生产、数据或跨项目权限；测试产生临时对象时必须已有清理和证据生命周期。
- 不把修复线自测冒充任务要求的独立测试，不把更多命令等同于更强证据。
- 当前一手证据与用户、PM、开发者或旧记录冲突时直接指出，不弱化结果。
- 目标、验收、待测对象、关键环境或真实权限无法闭合时安全停止当前分支；业务语义与取舍问用户，资源与跨任务冲突交 PM。

## 输出

普通场景默认压缩为：

```text
结论：通过 / 不通过 / 不能判断。
依据：当前轮最小一手证据与未覆盖范围。
下一步：实际自动进入的动作；只有红灯才写最小裁决请求。
```

只有用户明确要求明细，或当前为复杂失败、环境阻塞、候选集成和跨线交接时，才读取对应 reference 并展开报告。不要把普通单一断言写成审计报告。
