# 跨任务关系与正式审查

只在不同正式任务之间已经出现依赖、共享对象、接力或冲突，或者独立审查被建立为正式任务时读取。多个互不依赖的任务同时存在、Worker任务内助手和普通修复不读取。

PM只处理任务之间的关系。任务内部如何调查、切换 Skill、调用助手、修复和复测，继续由原 Worker负责。

## 1. PM视图与负载

当前工作台一个正式任务一行，只保存任务、唯一 Worker/thread、三态、当前进度、阻塞/风险、正式结果和更新时间。

实时进度优先读取对应 Worker线程。PM不要求 Worker暂停或逐命令回报；普通进展不回复纯消费回执，只有真实暂停、完成和跨任务影响进入主线视图。

PM保持可用，不执行长扫描、实现、调试、完整测试、部署等待和长日志整理。

## 2. 并行与共享对象

不同正式工作目录、独立 clone和只读任务可以并行。多个 Worker共享一个目录时，同一时间只允许一个写入者；Git不能隔离同一目录中的实时写入。

当前 Worker留下可辨认的 Git现场并释放写入位置后，下一个 Worker先核对最新现场再继续。等待顺序的任务保持进行中并继续安全动作；暂停任务保存现场后不长期占位。

BEYOND不自动创建 worktree。只有用户明确要求一次性隔离时才使用，并由原任务完成合流。

共享文件、契约、数据库、服务、测试账号、环境、生产对象或外部额度实际重叠时：

1. 只停止会扩大冲突的动作；
2. 确认对象、正式所有者、相关任务、当前真实版本和各自目标；
3. 能按顺序安全完成时由 PM安排先后；
4. 需要改变业务范围、高风险授权或不可逆路径时交给用户；
5. 不依赖该对象的任务继续。

## 3. 跨任务接力

只有一个正式任务的成果确实被另一个正式任务消费时才登记：

```text
来源任务与正式成果
接收任务与下一动作
共享对象及唯一所有者
文件、提交、制品或运行事实
验证入口与关闭条件
```

接收方核对当前事实后回自己的 Worker任务继续。普通 Skill切换、同一 Worker修复回测和只影响当前任务的用户指令不建立接力，也不经过 PM中转。

## 4. 正式独立审查

低风险改动已有匹配机器证据时，不为了形式新增审查任务。核心链路、共享契约、生产数据或发布变更确实需要独立责任和结果时，才建立正式审查任务。

审查任务只接收业务目标、待审文件/diff/提交、验收依据、当前测试证据、已知风险和结果返回位置。

审查分别回答：结果是否符合任务范围与验收；实现、测试、配置或文档本身是否可靠。审查意见返回来源 Worker核验，不自动扩大任务范围、授予新权限或形成项目完成结论。
