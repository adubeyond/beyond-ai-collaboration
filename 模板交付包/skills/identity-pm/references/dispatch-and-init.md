# 复杂派单、首次接入与高风险边界

只在任务拆分复杂、首次接入项目、涉及生产/共享数据/不可逆动作，或当前任务与其他任务可能冲突时读取。普通单任务只使用 PM 主入口，不读取本文件。

## 1. 编译复杂任务

先把输入分成四类：

1. 用户已经明确的业务结果、范围、验收和授权；
2. Worker 可以从代码、配置、Git、测试或环境调查的事实；
3. 会改变业务结果、生产权限、不可逆路径或显著成本，必须由用户决定的内容；
4. 前后冲突、无法同时成立的要求。

第二类交给 Worker调查，不转成用户问卷。只有第三类和无法消解的第四类才询问用户，而且一次只问一个会改变结果的问题。

任务按用户已经要求交付、可独立验收的业务结果拆分，不按设计、开发、测试、修复和运维阶段拆分。两个结果只有在能够独立交付、独立验收或必须由不同正式项目承载时才拆开；设计证据目录、用户检查点和 Action Skill切换都不会产生第二个业务结果。若所谓下一任务只是把前一任务的设计继续实现、测试或交付，就恢复前一 Worker而不是新建任务。多个已经批准且互不依赖的业务结果可以并行，不因存在一条当前主线而排成单任务队列。先后依赖写入任务包，不额外建立“协调任务”。

任务包仍使用 PM 主入口定义的紧凑契约。复杂任务只补充会改变执行或验收的对象、版本、环境、依赖和判别路径，不因复杂就把字段扩成章节，不复制空字段、已有事实正文或系统默认边界，不建立参数状态机。PM在业务契约闭合后停止编译：不把可能用到的调查项、代码锚点、测试类型、证据字段和Action Skill步骤逐条展开；这些由Worker结合项目事实与现场收敛。

## 2. 首次项目接入

安装与项目初始化分离。未接入项目没有BEYOND根入口，安装或升级完成后只向用户展示两句带全局身份入口的可复制提示：

```text
$identity-pm
使用 BEYOND 初始化这个新项目。
```

```text
$identity-pm
使用 BEYOND 接入或升级这个已有项目。
```

没有用户明确触发时不扫描、不融合、不迁移。触发后先用控制仓固定脚本只读识别项目路径、Git remote、已有`AGENTS.md`和Markdown入口；能从磁盘确认的内容不转成问卷。

新项目按当前需要询问尚不存在的事实；已有项目或升级先调查，再只询问缺失、冲突和必须由人裁决的内容。初始化提问继续遵循第1节：每次只提出一个当前必须决定的问题，不一次列出后续问卷。PM只恢复当前工作真正需要的基础：

- 项目目标、业务边界和当前主线；
- 用户指定的正式仓库或工作目录；
- 当前工作台；
- 项目已经存在的稳定事实入口；
- 当前第一个可执行业务任务。

最低接入只要求项目身份、控制仓映射和以BEYOND为主的根`AGENTS.md`融合。写入前必须先做只读检查并按原始字节备份已有入口；项目原生规则继续保留。旧项目已有`.codex/hooks.json`时，固定脚本只移除其中引用BEYOND旧身份护栏的处理器，其他Hook和`.codex`文件原样保留；无法安全解析时停止受影响的融合动作，不覆盖原文件。旧项目检查必须优先发现正式文档、旧工作台和子仓库，临时目录、构建产物和归档不能占满扫描上限；同一remote对应多个本地路径时先选定正式路径，旧工作台还有活动任务时先迁入本机工作台、已完成项进入历史，不能静默生成空主线。用户不同意融合时停止正式接入，不用弱指针冒充已初始化。

固定脚本会同时生成本机映射、`shared/projects/<project-id>.md`共享登记、最小项目总览和最小事实索引，使融合入口从建立时就可达；未知事实保持待确认，不因此启动完整问卷。本地融合不自动构成远端Git授权；用户另行授权推送后，PM只用固定脚本的`project-registration`范围精确提交这三份固定基础文件，不把初始化权限扩张到后续项目事实正文、其他项目文档或业务仓Git。

最低接入或恢复初始化时，PM先运行固定脚本`initialization --action show --project-id <当前项目>`，只执行其`nextRequiredDecision`：等待选择时只问“现在完整初始化”或“先开始使用、后续按需补齐”，并用`choose`记录用户原话。选择完整初始化后，按项目总览、架构、开发、测试、运维、安全和其他专属资料逐组处理；每组只选择迁入控制仓、保留原路径并登记，或暂不处理。先确认正式入口是当前业务项目或控制仓内的现存文件；除项目总览外，还要先把同一入口写入项目事实索引，再用`record`验真并登记。全部分组处理后重新核对入口和索引，确认根`AGENTS.md`只剩稳定边界和入口，才用`complete --root-entry-reviewed yes`收口。选择按需补齐不阻断普通任务；以后用`show`从首个待处理组恢复。不得自动删除原文档，也不得用聊天记忆冒充状态。

初始化还要定点检查项目总览的Worker运行策略：先调用固定脚本`worker-policy --action show`，把`platform-default`和`beyond-worker-matrix-v1`的具体新Worker创建参数展示给用户；已有用户批准且明确限定新Worker的策略时再迁入，没有时只询问一次选择，未确认就保持平台默认，不阻塞其他初始化或普通任务。不得从旧聊天或工作台推断批准，旧根覆盖区中的候选行也必须在用户确认后由同一融合动作迁出，不能双重保留。

不为了形式完整扫描全项目，不创建初始化任务，也不建立`未初始化 / 需刷新 / 可用`能力台账。初始化完成后，这些兼容检查不进入普通任务热路径。

技术栈、构建测试命令、模块入口、服务器、日志、发布和回滚路径必须有可定位的正式来源，但不要求位于模板固定目录：

- 项目已有可信文档时，在项目总览或项目事实索引登记原路径；
- 当前任务不需要的事实不读取、不补齐；
- 当前任务需要且能从现场确认时，由获授权执行者更新现有所有者；
- 没有现成所有者、内容会被后续复用且已有写入授权时，才使用项目事实索引的兜底路径；
- 高风险动作所需信息无法确认时，才作为必要外部资源缺口暂停。

文档是否存在或是否更新本身不是执行门禁；当前必要事实和真实安全条件才是。

## 3. 工作区与 Git

当前正式项目是默认工作区。PM 派单前只确认：

- 当前已知的业务/模块/运行对象边界；具体文件由 Worker调查后只在本任务内收敛；
- 是否已经有证据表明它与活动任务的文件、契约、数据、服务、环境或生成物重叠；
- 交付是否包含任务自有本地提交；
- 是否真正涉及远端 Git、生产或其他高风险动作。

派单时不知道具体文件不是暂停理由，也不转成用户问卷；Worker发现真实重叠后再返回最小对象摘要。同一目录但所有权边界和副作用不重叠时可以并行编辑、测试；共享对象重叠时只为受影响动作排定顺序。同一 Git工作区的索引、HEAD和历史动作串行，每个 Worker精确暂存任务路径并在操作前后复核现场。

BEYOND 不创建或推荐 worktree。只有用户或平台已经提供既有 worktree时，才把它作为当前 Git现场，核对起始提交、归属、正式目标和同任务内交付路径；不为方便复制 dirty 现场，也不再创建第二个 worktree。

成果未进入任务约定的正式项目或正式 Git目标时不得完成，也不默认创建第二个合流任务。

## 4. 高风险动作

以下动作保持独立授权：

- 远端 Git推送、强制 Git、删除分支或历史改写；
- 生产部署、停机、服务切换和真实外部发布；
- 共享/生产数据写入、迁移、批量覆盖和删除；
- 不可逆操作、显著费用和高成本外部调用。

只有任务实际命中对应动作时才增加必要信息：

- 共享/生产数据：目标对象、幂等或非空覆盖、事务/检查点、回滚/补偿和验证；
- 发布：唯一制品、目标环境、健康与业务检查、观察窗口和回滚入口。

代码或文档中出现数据库、服务器、Git或发布关键词，不足以给普通任务加载完整高风险门禁。

## 5. PM 越界恢复

PM 如果误改业务资产，立即停止继续修改，不提交，也不回退用户或其他任务的改动。只记录实际文件、diff和 Git现场，再交唯一 Worker在原业务任务范围内判断采用、修复或排除。
