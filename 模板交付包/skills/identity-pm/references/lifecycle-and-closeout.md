# 异常生命周期与收口作业包

只在 `SKILL.md` 已判定当前输入属于阻塞领取、暂停恢复、乱序/重复/旧版本、实例冲突、`red`、`shared_conflict`、证据不足或复杂收口时完整读取本文件。平台创建回执已完成登记的正常启动、普通通知和证据闭合的终态不读取。

## 1. 双状态与事件信封

业务状态固定为`待排期/可执行/进行中/已暂停/候选完成/已完成/阻塞`；实例状态固定为`待领取/执行中/等待事件/待回收/已关闭/失联`。`验证中`表示当前动作为测试，`待验收`迁移为业务`候选完成`，不得用一个状态同时表示业务进度和实例存活。

事件 ID使用`<任务 ID>:<任务版本>:<执行回合>:<序号>`，事件包含：

```text
任务 ID / 任务版本 / 执行回合 / 事件类型 / 时间
实际实例 ID / 会话或线程定位
业务状态 / 实例状态
授权或共享契约变化
完成、剩余、一手证据与正式写回
Git、服务、数据当前真值
下一步 / 需要 PM 裁决
```

同一事件传输失败只能用原 ID和完全相同的正文重试，事件 ID与正文一一对应。PM 按事件 ID和任务版本幂等消费：已消费事件不重复改状态、启动实例或收口；同一事件 ID出现不同正文时登记事件冲突，不把后到正文解释成“修订”；旧版本只作证据。序号跳跃、双实例、来源或双状态冲突时标记`待补证据`，停止自动覆盖。

## 2. 阻塞领取与异常恢复

以下场景使用阻塞领取：来源不明、用户或平台直接恢复、重复实例、共享写入未隔离，或任务包明确要求登记后才能动作。

处理阻塞`claimed/resumed`：

1. 只核对任务 ID、版本、回合、序号、来源 thread ID、项目/工作区和冲突实例。
2. 字段完整、来源与待领取任务一致且无冲突时，下一实际平台动作直接返回登记结果。
3. 回源前不读项目文件、不重载任务包、不推演后续事件、不统计整链耗时。
4. 字段缺失或存在双实例/工作区冲突时保持`可执行/已暂停`，形成资源红灯，不启动内部助手替代。

暂停任务使用快速恢复：只读原任务行、最后已消费事件、任务主面当前结论和本轮必须刷新的 Git、服务、数据、授权等易变事实。目标、边界、验收和稳定入口未变时不重新规划、不扫全项目、不重建任务包、不重复提问。

用户或平台直接开启执行对话时沿用原任务 ID并补录新执行回合；不重启仍在运行的实例，也不倒填不存在的历史事件。实例失联时先停止重复派发，核对唯一工作区和最后一手真值后再决定替补回合。

## 3. 异常事件与按需回源

- `red`：实例保留受影响现场并停止相关动作；PM 读取最小证据后只返回实际裁决。
- `shared_conflict`：先保护共享对象和其他活动任务，只暂停冲突动作；完成所有权、兼容或串行裁决后再恢复。
- `yellow/shared_notice`：本身不是阻塞事件；若后续证据证明已形成共享冲突，再升级为新事件，不回写旧事件含义。
- 重复事件：返回已有消费事实或保持静默，不重复改变业务状态。
- 乱序事件：不猜丢失步骤；核对最后已消费序号和发送端证据，只补缺口，不新建替代任务。
- 旧任务版本：只保留为证据，不覆盖新版本状态、实例或授权。

平台回源失败时记录原事件 ID待重试；不要求来源任务换 ID或长期轮询。正常事件不生成性能报告，除非用户或测试任务明确要求。

## 4. 终态真值核对

消费`paused/candidate_completed/completed/failed`前，定点核对：

- 来源是否为已登记正式任务 thread ID，任务版本与执行回合是否一致。
- 任务主面、实例登记、最后事件与 PM 控制快照能否互相解释。
- 验收证据是否可读，最终消息是否把候选完成冒充已采纳。
- Git、服务/进程、数据、环境和发布现实是否与事件表述一致。
- 事件点名的正式文档、契约、发布记录或证据是否已写回；未点名范围不扩张核对。

证据缺口只能形成限定采纳、退回或待补证据，不让已释放实例长期等待。终态已经投递时，需要返工只能沿同一任务 ID增加执行回合并生成该回合的新事件 ID；不得要求原实例撤回终态、修订同一事件 ID或继续原执行回合。

生产交付额外核对任务起始基线、授权目标主线、当前生产实际版本、尚未归并的生产补丁、可执行回滚版本和验证对象生命周期。生产成功不等于目标主线已包含；无法解释的生产差异不得宣告完成。

## 5. 收口裁决

只使用一手证据：真实命令、测试、日志、截图、接口响应、Git diff或外部记录；摘要和口头说明不能替代。

收口主体独立记录：

- `自动`：预授权低风险任务满足全部机器验收后完成。
- `PM`：共享契约、关键链路或约定任务由 PM 按证据裁决。
- `用户`：仅用于生产数据、不可逆操作、真实资费、重大业务取舍或用户明确保留事项。

裁决结果只用：`采纳 / 限定采纳 / 退回 / 阻塞`。输出：

```text
采纳什么：
不采纳什么：
当前状态：
下一步：
```

样例通过不等于真实业务完成，结构通过不等于语义通过。终态发送后实例释放；普通收口不发纯消费回执。退回通过新输入或新执行回合唤醒，不用回执制造记账回合。

## 6. 阶段切换

进入新阶段前核对上阶段采纳/未采纳范围、已完成任务和证据回收、下一阶段主稿与任务主面、阻塞与允许继续事项、Git 分支和未提交/未跟踪关键文件。缺下一阶段入口、任务主面、历史去向或 Git 状态时，只判为切换准备中；不受影响的调查和回收仍可继续。
