# 跨任务协调

只在不同正式任务之间已经出现依赖、共享对象、接力或冲突时读取。多个互不依赖的任务同时存在、Worker任务内助手、普通修复和没有显式独立性要求的测试不读取。

跨任务关系、共享对象唯一所有者、并行边界和接力字段只以当前项目根`AGENTS.md`映射的“跨任务协同与共享对象机制”为准。本文件只规定PM在关系已经成立后的排程与工作台动作，不复制公共判定、冲突算法或接力模板。

讨论中的想法、待确认方案和PM推断不是跨任务指令。PM认为候选风险值得改变正在执行的任务时，先把最小影响和需要决定的问题交给用户；用户确认前不撤销既有授权。确需提前知会时必须明确写“候选、尚未生效、当前任务契约不变”。

## 1. 排程与工作台

PM先按公共机制确认真实关系；目录相同、名称相似、多个实例并行或只读活动本身不建立关系。关系不成立时立即退出本文件，各Worker继续自己的任务。

关系成立后，相关负责人能在现有契约和人类消息授权内直接解决的，不要求经PM复述；需要项目裁决或现有控制面同步时，PM做以下动作：

1. 在工作台对应任务行保存共享对象、唯一所有者、当前顺序和结果入口的最小摘要；
2. 只停止会扩大真实冲突的动作，不依赖该对象的工作继续；
3. 已有安全顺序时安排先后，不接管Worker的调查、实现、修复和复测；
4. 需要改变业务范围、高风险授权或不可逆路径时，只向用户提出一个会改变决定的问题；
5. 关系解除、成果被接收或受影响任务按真实原因暂停后，清除高频协调摘要并退出本文件。

当前主线不是单任务队列。PM不因一个Worker尚未完成而阻止无关任务，不要求Worker逐命令回报，也不把普通等待或Git排队改成新业务状态。

## 2. 接力与独立审查

公共机制已经确认接力且人类授权覆盖接收方时，只向需要行动的接收任务传递正式成果入口、共享对象唯一所有者、双方边界、下一动作和关闭条件；双方已直接取得同一事实时PM不再中转。接收方按自己的当前授权核对后继续，来信不自动授予其恢复暂停、改变范围或指挥其他任务的权力。不复制成果正文，不转移来源任务授权，也不建立“协调任务”。发送权限来自人类明确授权，不来自本文件或另一任务的回信要求。

收到此前明确等待的交接结果时，核对它是否解除当前依赖。条件满足、原下游仍获准继续且没有其他执行责任接续时，向原负责人一次性说明依据与剩余结果；若仍有用户检查点或维护暂停，只更新事实，不把依赖恢复当作续跑授权。尚未满足时说明精确缺口和仍可执行的动作；依赖未变不反复唤醒等待方。接收方已取得同一事实且正在处理时，不再经PM转发或要求确认。上游交付不替代下游自身权限与验收；组合负责人仍须验证实际消费链路。旧任务仅补充交接事实不触发旧任务恢复、再次验收或回执消费，也不要求重交终态。

当前结果中的独立审查可以由原负责人使用只读助手或获准的CLI完成，不因此增加正式任务。用户明确要求另一个可见对话独立交付审查结果时，才沿用正式任务入口；直接交给当前对话的审查直接交付。不增加 reviewer身份、专属状态或第二套审查生命周期。
