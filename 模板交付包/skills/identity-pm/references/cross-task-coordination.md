# 跨任务协调

只在不同正式任务之间已经出现依赖、共享对象、接力或冲突时读取。多个互不依赖的任务同时存在、Worker任务内助手、普通修复和没有显式独立性要求的测试不读取。

PM只处理任务之间的关系。任务内部如何调查、切换 Skill、调用助手、修复和复测，继续由原 Worker负责。

讨论中的想法、待确认方案和 PM推断不是跨任务指令，不能成为其他任务的新前置、暂停条件、范围变化或授权变化。PM认为候选风险值得改变正在执行的任务时，先把影响和需要决定的问题交给用户；用户确认前不撤销既有授权。

确认后的跨任务变化只传四项：决定来源、受影响任务或对象、准确变化、生效时间。确需提前知会候选时必须明确写“候选、尚未生效、当前任务契约不变”，接收方不得据此暂停或改变执行。

## 1. PM视图与负载

当前工作台一个正式任务一行，只保存任务、唯一 Worker/thread、三态、当前进度、阻塞/风险、正式结果和更新时间。

实时进度优先读取对应 Worker线程。PM不要求 Worker暂停或逐命令回报；普通进展不回复纯消费回执，只有真实暂停、完成和跨任务影响进入主线视图。

## 2. 并行与共享对象

不同正式工作目录、独立 clone和只读任务可以并行。同一目录内，文件/模块所有权明确、共享对象不重叠且测试或运行副作用隔离时，也可以并行编辑和验证；目录相同本身不是冲突。

同一 Git工作区的索引、HEAD或历史动作串行。执行者在`add / commit / merge / rebase / checkout / reset`前核对现场，只精确暂存任务路径；等待 Git操作的任务保持进行中并继续无冲突动作。

BEYOND不创建或推荐 worktree。用户或平台已经提供的既有 worktree只作为当前 Git现场处理，不再创建第二个 worktree或合流任务。

共享文件、契约、数据库、服务、测试账号、环境、生产对象或外部额度实际重叠时：

1. 只停止会扩大冲突的动作；
2. 确认对象、正式所有者、相关任务、当前真实版本和各自目标；
3. 能按顺序安全完成时由 PM安排先后；
4. 需要改变业务范围、高风险授权或不可逆路径时交给用户；
5. 不依赖该对象的任务继续。

## 3. 跨任务接力

只有一个正式任务的成果确实被另一个正式任务消费时才登记：

```text
来源任务与正式成果
接收任务与下一动作
共享对象及唯一所有者
文件、提交、制品或运行事实
验证入口与关闭条件
```

接收方核对当前事实后回自己的 Worker任务继续。普通 Skill切换、同一 Worker修复回测、任务内助手和只影响当前任务的用户指令不建立接力，也不经过 PM中转。

用户明确要求独立审查时，按普通业务结果使用一个 Worker任务和既有测试/验收方法，不增加 reviewer身份、专属状态、自动触发条件或审查生命周期。
