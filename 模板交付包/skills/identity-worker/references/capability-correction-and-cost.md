# 项目能力、纠偏与成本作业包

仅在项目能力`未初始化/需刷新`、用户纠正或重新规划、准备高成本动作或高成本重试时完整读取本文件。

## 项目能力初始化

1. 核对项目能力台账中的状态、唯一初始化责任、正式事实路径、最近核验和刷新触发。
2. 本实例承担责任时按`定点调查 → 候选事实 → 必要确认 → 一手核验 → 正式写回 → 解锁`执行；已有其他责任实例时消费已确认部分、登记依赖并继续不受影响动作。
3. 优先从代码、配置、脚本、测试、Git、环境和既有文档发现技术事实。只有业务取舍、真实权限或调查后仍未知的事实才询问用户。
4. 每次只问一个最小问题，带候选值、来源、影响和`确认 / 纠正 / 不知道，请继续调查`路径；不得让用户补一整张技术清单或设计内部文档路径。
5. 用户答复后区分用户确认与现场事实，写回任务包授权的唯一项目能力档案；必要时向 PM 发送`shared_notice`，但不等待消费回执。
6. 达到当前动作最低条件后立即解锁并沿同一任务继续；不得重新领取、另建初始化任务或返回 PM 续派。

初始化不能扩大文件、Git、服务器、生产、数据、不可逆或外部费用授权。项目专用事实只进项目事实文件，不能写入通用 Skill。初始化结果不另建平行台账；动态责任由 PM 控制面维护，执行者只回传事实和证据。

## 纠偏与重新规划

用户纠正、缩小范围、暂停或要求重新规划时，先编译：

```text
继续有效：
已经作废：
新增要求：
受影响验收：
正式回写：
下一安全动作：
```

完成编译前不做新的文件写入或高成本动作。纠偏属于当前任务输入，不回 PM 二次决断；只有资源、实例、跨任务冲突或授权外扩张才形成控制红灯。暂停时停止继续产生外部影响的动作，按异常生命周期作业包收口。

## 任务级进度与高成本动作

在既有任务主面或运行上下文维护一张进度板：`业务终态、已完成、当前项、关键证据、未完成、下一高成本动作`。进入里程碑、推翻验收、用户询问进度或准备高成本动作时给短摘要，不为进度另建文件。

高成本动作包括长时间浏览器/数据/构建任务、真实服务器动作、付费或限量接口、批量写入和不可快速撤销的操作。执行前核对输入、正式契约或样本、环境参数、预算、可观察证据和停止条件。阈值只能来自任务授权、正式契约、资源限制或已观察基线；事实不足时先做低成本测量，不得发明耗时、超时、重试、并发或数量阈值。

同一路径首次出现长超时、无进展或不可解释结果后，下一步先增加快照、计时、日志、最小样本或检查点，定位最早偏差。新的高成本重试必须说明新增的证据能力，以及如何区分成功、失败和无进展；不得只改超时或重试次数后盲目重跑。
