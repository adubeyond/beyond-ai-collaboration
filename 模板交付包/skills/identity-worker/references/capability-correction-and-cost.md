# 项目事实、用户纠偏与高成本动作

只在当前任务需要补充或修正稳定项目事实、用户改变当前任务，或准备真实高成本动作时读取。

## 1. 维护项目事实

项目事实只保存跨任务仍会复用的当前有效知识，例如技术栈、工程命令、模块入口、测试方法、环境、服务器、日志、发布和回滚路径。

1. 定点读取项目事实索引登记的实际入口，并用代码、配置、Git、测试或运行现场核对。
2. 已有正式文档正确时直接复用；不完整但不影响当前任务时继续业务。
3. 当前任务确认稳定变化且拥有写入授权时，优先更新原事实所有者。
4. 没有现成所有者、内容确实会被复用时，才使用项目事实索引的兜底路径。
5. 现场与旧文档冲突时先按现场处理，再修正受影响事实和直接引用。

稳定事实文档不保存当前分支、提交、worktree、任务版本、执行回合、候选状态、单轮测试结果和过程流水。这些内容留在 Git、任务线程或对应证据记录；长期事实只登记仍有效的结论和必要入口。

事实应能看出适用范围、来源、最后核验和失效条件，但不要求每条结论重复相同字段。密码、私钥、Token、Cookie、验证码等秘密值不得写入。

没有事实写入授权时，继续当前允许的业务动作，并在结果中说明已经确认的事实、建议写回位置和未写原因。不维护`未初始化 / 需刷新 / 可用`状态，也不为补事实另建初始化任务。

## 2. 处理用户纠偏

用户纠正方向、缩小范围、解除检查点或改变验收时，立即区分仍然有效、已经替代、新增要求和受影响验收，然后按最新指令继续当前放行段。

只影响本任务时由 Worker直接处理，不回 PM二次审批。影响其他任务、共享对象、项目主线、生产授权或不可逆边界时，只停止受影响动作并向 PM发送最小影响摘要；用户已经明确的决定不变成待 PM批准。

用户要求在当前节点确认时，交付本段真实结果并等待，不提前执行下一段。

## 3. 高成本动作

长时间浏览器/数据/构建任务、真实服务器操作、付费或限量接口、批量写入和难以快速撤销的操作，在执行前只核对：

- 输入、目标和实际授权；
- 当前环境、对象和资源限制；
- 可以观察成功、失败和卡点的证据；
- 停止条件、预算以及必要回滚或补偿。

同一目标、授权和环境没有变化时，后续同类动作复用已经核验的稳定事实，只刷新进程、锁、版本、数据量、服务状态等会变化且与本次动作直接相关的锚点。不为每次尝试重建“生产上下文”、重新抄写完整预检或另建证据包；原证据仍有效时直接引用，新增证据只记录本次变化和结果。

阈值来自任务约定、正式事实、资源限制或已观察基线，不由 Worker凭空设置。第一次长时间无进展或结果无法解释后，下一次尝试必须增加日志、快照、计时、最小样本或检查点等区分证据；不能只增加超时、次数或原样重跑。
