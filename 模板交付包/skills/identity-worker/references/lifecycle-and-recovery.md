# 异常生命周期与恢复作业包

仅在阻塞领取、暂停恢复、重复实例、来源或路由冲突、事件投递失败、异常终态或退回重开时完整读取本文件。标准创建型任务和普通终态使用核心快路径，不读取本文件。

## 阻塞领取与恢复

以下情况使用阻塞领取：来源不明、用户或平台直接恢复、重复实例、共享写入未隔离，或任务包明确要求登记后动作。

1. 从任务包取得任务 ID、版本、执行回合、项目/工作区、边界和直接 PM 目标；缺身份三元组或可消费目标时形成控制红灯，不自造标识。
2. 使用平台线程消息能力向包装实际`source_thread_id`发送唯一`claimed`或`resumed`。
3. 当前提示未暴露自身 thread ID 时使用核心规定的信封占位，不编造 UUID。
4. 发送后结束当前回合并等待一次实际结果；收到登记或裁决后直接执行，不补发`started`、不重新规划、不扫描全项目。
5. 已登记实例仍有效时唤醒原实例；只有实例失效才按授权进入新执行回合，不并行创建替代控制实例。

输入没有平台正式包装、只有内部 agent path、协作子智能体身份或普通聊天来源，却要求承担整个业务任务时，停止领取并形成资源红灯。局部助手仍只向正式任务控制实例回报。

## 事件幂等、冲突与投递失败

事件 ID 按任务既定规则生成，且与事件正文一一对应；只有同一事实、同一正文的传输失败重试才沿用同一 ID。事件一旦成功投递就不可撤回、修订或用同一 ID补发不同正文。PM返回`已消费`只更新本地最后事件；若`已拒绝/待补证据`发生在非终态事件后，仍可在原任务补齐。若发生在终态已成功投递后，原实例已经释放，必须由新的外部输入沿用任务 ID并增加执行回合；不得唤醒原回合继续、复用原事件 ID或把第二份正文称为事件修订。

遇到以下任一情况停止自动覆盖并向 PM 发送`shared_conflict`或`red`：双控制实例、任务版本倒退、事件序号或状态矛盾、来源 thread 无法归属、共享写入边界冲突。只停止受影响动作；其他安全且已授权路径继续。

终态投递失败时保留原事件 ID和待重试正文。先确认平台消息能力、实际直接来源和安全等价投递路径；仍不可用时把缺口写入最终结果并释放，不把已经发生的业务结果反向改成未发生，不改发另一种终态。

## 暂停、退回与恢复

用户暂停时停止可能继续产生外部影响的动作，安全保存或恢复现场，把任务主面业务状态记为`已暂停`，发送`paused`后释放。恢复时沿用任务 ID、正式上下文和既有证据开启新执行回合。

PM或用户在实例释放后退回属于新的外部输入：沿用任务 ID，增加执行回合，保留原证据并只刷新变化事实。即使平台仍能向旧 thread 发送消息，也只能把它作为新执行回合，不能让已结束回合恢复运行。平台无法唤醒原实例时由后续实例承接；不得让原实例为了可能退回而长期挂起。

## 终态真值核对

发送`paused/candidate_completed/completed/failed`前定点核对：

- 业务状态与实例状态分开。
- 正式任务主面、受影响子项目状态和验收证据一致。
- Git、服务、进程、环境、数据和生产表述与当前现实一致。
- 不能同步写回的入口明确列为未完成，不能用聊天结论冒充正式状态。
- 当前实例只发送一个终态；投递后立即最终答复并释放。
