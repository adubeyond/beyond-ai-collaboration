# 领取与恢复任务

只在用户明确要求当前 Worker从工作台领取、恢复或继续一个具体任务时读取。平台正式任务包装、清晰直接请求和普通项目接手不读取；普通项目主线接手由 PM负责。

## 1. 找到唯一任务

1. 定点读取当前工作台的正式任务表，只选择用户明确点名的业务结果。
2. 任务已经登记正式 Worker thread时，优先回到原线程，不在当前对话建立第二个控制 Worker。
3. 没有正式任务但用户已经把一个明确结果直接交给当前 Worker时，按直接用户任务执行，不伪造任务台登记或 PM关系。
4. 任务无法唯一确定、原 Worker是否仍在写入无法确认，或两个来源声称控制同一结果时，只停止可能重叠的写入并交 PM协调。

## 2. 恢复当前上下文

只确认当前执行必需的内容：业务结果、范围、验收、用户检查点、正式工作目录、当前进度、已有成果与证据、唯一暂停原因和恢复条件。

可以从代码、配置、Git、测试或环境调查的事实由 Worker调查。只有会改变业务结果、用户检查点或真实安全边界的缺口才询问用户。

同一目录只有文件、共享对象或运行副作用实际重叠时才等待 PM安排受影响动作；边界不重叠时可以并行编辑和验证。共享 Git工作区的索引、HEAD或历史动作串行；BEYOND 不创建或推荐 worktree。

恢复优先使用原任务线程、最新 Git和运行现场，只刷新已经变化的事实。不重新初始化、不扫描全项目、不重新填写任务包，也不重复调查已经有一手证据的内容。

## 3. 接手后继续

用一句话向用户确认当前承担的业务结果、正式工作目录和下一动作。用户已经要求继续且当前检查点允许时，在同一轮开始执行，不把接手说明变成等待点。

回复与收口使用 Worker 主入口；暂停、回源失败和原线程客观不可恢复时才读取生命周期 reference。本文件不定义第二套状态或输出格式。
