# 接手、领取与回复作业包

仅在用户明确要求接手项目、继续当前主线、从工作台领取任务，或需要完整失败/交接格式时完整读取本文件。平台正式任务包装和清晰的当前请求不读取本文件。

## 接手最小路径

先遵守根`AGENTS.md`。默认只读取：根`AGENTS.md`、`README.md`、当前工作台或其点名入口、Git状态或不可用原因。完成后给轻回执：

```text
接手确认：
- 模式：
- 当前主线：
- 当前边界：
- 当前下一步：
```

四项必须来自动态事实。用户同时要求“接手后继续领取/执行”时，轻回执后在同一轮继续领取判断，不能把回执当整轮终点。

只有称呼遗漏、主线/边界/下一步含糊或冲突、准备越过回执直接写入，或用户明确要求复核读入链时，才补`进入路径、Git状态、写回位置、当前校验码`。长对话判断发虚时按根入口做上下文自检，不扩展成全项目扫描。

## 从工作台领取

1. 只领取当前工作台中与指定执行线匹配、优先级最高且状态可执行的任务；用户未指定执行线时取全局最高优先级可执行项。
2. 任务行已有实例 ID时只允许该实例继续；写`待领取`时才登记当前真实实例。
3. 核对业务结果、读写边界、验收、允许操作、红灯条件和写回位置。实现方案、契约和测试方法可在任务授权内调查形成，不因尚待设计而拒绝领取。
4. 没有匹配任务、创建文件去向未授权，或关键目标/边界/验收无法确定时明确不能领取，不发明任务或实例 ID。
5. 任务行字段完整时不要求用户重复补材料；历史任务、旧证据和口头摘要只能作线索，不能覆盖当前代码、Git、测试和环境事实。

领取后的动作顺序为：确认正确实例 → 初始化最小运行上下文 → 运行授权自动路径 → 按证据收口。设计级只读任务可以只交设计包，不强迫进入实现。

## 回复与失败交付

接手并领取后优先输出：

```text
领取结果：
交付内容：
证据与风险：
下一步：
```

只有交给 PM 验收或正式回写时才补任务 ID、实例 ID、修改/证据位置、验证方式和写回位置。

不能继续时只说：

```text
我现在不能继续，因为 <唯一关键原因>。
已确认 <当前事实>。
下一步需要 <PM/用户> 决定或补充 <最小事项>。
```

需要完整失败包时使用：`失败原因、已完成、未完成、已验证、残留风险、建议下一步、回到哪一层`。不要用失败包复述整段过程，也不要把任务内可修复问题包装成 PM红灯。
