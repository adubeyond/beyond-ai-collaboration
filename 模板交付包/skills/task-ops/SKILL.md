# 运维动作

## 1. 定位

`task-ops`是软件运维专业方法：Worker加载后形成当前任务中的运维工程师专业能力，正式结果回到同一个 Worker；直接请求由当前基础智能体在授权内检查或操作并交付，不制造任务身份；PM只管理任务、发布顺序、共享资源和证据验收，PM不得读取本 Skill并直接操作环境。

运维负责本地预检、环境与运行检查、发布、恢复、回滚和获授权的 Git/资源收口。测试通过不自动取得生产、Git、数据、停机或不可逆权限。

普通代码任务自己的本地提交是开发连续交付，不进入本 Skill。只有当前主要动作已经变成本地合并、PR、推送、分支处理、遗留 worktree或其他独立 Git资源收口时，才使用这里的 Git路径。

运维裁决使用`可以继续 / 不能继续 / 只能确认当前范围`。这是当前运维动作的判断，不是任务状态；业务状态仍由原 Worker使用`进行中 / 已暂停 / 已完成`。

## 2. 最小读入

正式任务继承 Worker已经确认的业务结果、范围、验收、目标环境、授权和前序证据，不重新接手项目。直接请求已经点名对象、环境和边界时，只读取根规则、目标现状与必要入口，不要求补工作台任务行。PM不得因运维动作词进入本 Skill。

按当前场景最多先选一条：

1. 需要读取、建立或修正服务器、服务、日志、部署或回滚长期事实：完整读取[运行事实与部署手册](references/capability-and-runbook.md)；
2. 真实生产发布、版本收敛、跨任务热修或发布后生产真值：完整读取[生产发布与版本收敛](references/production-release-and-convergence.md)；
3. 本地合并、PR、推送、分支处理，或者用户明确要求处理既有 worktree：完整读取[Git 与遗留 worktree 资源收口](references/git-worktree-and-resource-closeout.md)；
4. 运行故障、日志排障、服务恢复、回滚、发布失败或环境阻塞归因：完整读取[故障恢复、证据与失败交付](references/incident-recovery-and-evidence.md)；
5. 单文件、单记录、单值或明确命令的静态预检：定点核验后裁决，不读取 reference。

场景真实变化后再读下一份；同一任务已读且文件未变化时不重复读取。reference缺失只停止依赖它的分支，不妨碍仍能安全完成的只读检查。

## 3. 运行事实与真实目标

先从项目或子项目运维入口定位当前环境、服务和发布对象的正式所有者。优先复用已有服务器总表、环境说明、部署脚本、服务配置和专项 runbook；没有承载者、当前确实需要且拥有写入授权时才使用项目事实兜底路径。

长期事实和单次现场必须分开：

- 长期事实：环境角色、主机/别名、域名、目录、服务、端口、日志、凭据来源、标准部署与回滚路径；
- 单次事实：本次来源提交/制品、实际目标、当前运行版本、健康状态、发布结果、观察和回滚证据。

真实连接、发布、重启、恢复或数据动作前，必须重新确认本次目标环境与主机身份、实际运行落点、权限、当前版本和回滚入口。旧 IP、旧别名解析、旧目录或文档状态不能替代现场核验；多份文档冲突时停止受影响动作，以当前现场确认唯一所有者并修正引用。

项目 runbook 中出现 worktree 只说明旧流程或可选工具，不构成创建授权。BEYOND 不自动创建 worktree；只有用户明确要求时才进入该分支。

## 4. 预检与执行

用户只要求核对点名文件、记录或值时，做一次直接比较并说明证据强度，不升级成完整运维审计。静态记录匹配只证明记录一致；未核验制品、服务或目标环境时不得外推为已经发布、生产可用或可以安全回滚。

执行环境变更前必须闭合：

```text
业务结果和发布/恢复对象
目标环境与当前实际版本
允许操作的服务、配置、数据和停机边界
经过验证的来源提交或唯一制品
健康检查与关键业务验证
可执行回滚及回滚后验证
本次动作已经处于当前授权内；需要长期留存时使用哪个既有记录入口
```

能从项目脚本、配置、服务和现场确认的事实先调查。缺少真实目标、权限、验证或回滚时继续安全预检，并给`不能继续`或`只能确认当前范围`；只有必须由用户决定或授权的事项才问一个最小问题。

任务已预授权相同对象、环境、范围、验证和回滚时，测试通过后由原 Worker直接切换运维，不等待 PM二次激活。执行时：

1. 使用项目当前正式脚本和 runbook，不临场换路径；
2. 发布前核对来源与制品，执行授权范围内的备份或回滚准备；
3. 只操作本次目标，并在同一实际对象上取得健康与业务证据；
4. 失败时停止扩大，按已授权条件回滚并复验；
5. 稳定变化写回唯一事实所有者，单次结果写任务或既有发布/运行记录。

目标连接信息与凭据合法入口可用，并且当前动作已经授权时，Worker自行使用工具执行，不要求用户手工代操作，也不重复索要相同授权。

## 5. 观察、故障与收口

需要跨时间窗口观察时，先取得当前样本，再记录观察对象、已取得样本、通过标准、剩余次数或时间、下次触发和责任实例。必须等待外部时间且当前没有其他安全动作时，原 Worker转`已暂停`并在同一任务恢复；不占用 PM持续轮询，不把一次健康样本写成稳定。

普通日志异常、启动失败和可回滚发布失败由原 Worker在授权内继续定位、恢复和复验，不为此拆新任务或等待 PM。影响其他正式任务、共享环境或发布顺序时才进入跨任务机制；需要新增生产、停机、数据破坏、不可逆或高成本授权时直接向用户提出一个最小问题。

合并、PR、推送、删除分支、清理 worktree和其他资源分别服从当前授权。不静默处理非本任务改动，不用强制 Git掩盖冲突，不因发布成功擅自删除审计链或回滚资源。

## 6. 输出

默认回复：

```text
结论：可以继续 / 不能继续 / 只能确认当前范围
对象：实际环境、服务、版本或记录
依据：本轮最关键的现场、命令和验证结果
变更：实际执行了什么；只读时写未执行
风险：未覆盖范围、观察或回滚状态
下一步：原 Worker继续观察/恢复/收口；直接请求则给用户最小动作
```

简单静态预检压缩为更短的自然语言。只在真实复杂发布、事故、回滚或资源收口时展开明细，不把普通检查写成长篇审计报告。
