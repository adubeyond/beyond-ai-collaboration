# 软件运维动作

## 身份与边界

运维是 Worker 在当前任务内选择的软件运维与发布方法，或基础智能体处理直接、清晰运维请求时采用的方法，不建立新身份，不改变任务 ID、控制权或授权。它处理本地预检、环境与运行检查、发布、恢复、回滚以及获授权的 Git/资源收口。

在本方法内，PM只编译、派发或协调任务，不能替Worker操作环境；跨任务、共享对象、主线、资源、安全和项目收口仍由PM按身份职责处理。正式任务的结果返回同一Worker；直接请求由当前智能体直接交付，不制造不存在的Worker、PM或任务事件。

运维不定义业务验收，不替开发修代码，不替测试宣布通过，也不因测试通过自动取得生产、Git、数据、停机、费用或不可逆权限。

## 唯一运维事实地基

同一项目的运维不能每轮重新猜服务器、目录、服务、命令或回滚路径。正式运维始终复用一条唯一事实链：

- `运行环境与服务器信息`回答“在哪里”：环境、主机、域名、端口、目录、服务、配置、日志和非秘密访问边界。
- `部署发布运行手册`回答“怎么做”：构建与制品、部署顺序、健康与业务验证、停止条件、回滚和恢复。
- `安全与凭据索引`只回答凭据从哪里合法取得、允许谁使用和如何轮换，不保存秘密值。

本次候选、实际运行版本、健康状态、执行结果和回滚结果属于单次任务记录，不反复写进稳定服务器文档。已有有效入口时直接复用，不另建同类文件；入口缺失时如实说明，再按项目事实索引和写入授权建立标准落点，不让用户或每个任务重新选择内部路径。后续只刷新已经变化或当前动作必须复核的易变事实，稳定事实命中刷新触发前不重复调查，但旧文档不能替代高风险动作前的现场核验。

## 三态裁决

裁决固定为`可以继续 / 不能继续 / 只能确认当前范围`，并绑定准确的下一动作、对象和环境，例如“可以继续到预发部署”“不能继续生产切换”“只能确认本地记录一致”。

- `可以继续`只放行点名的下一动作，不等于已经发布、稳定或用户可用。
- `不能继续`说明当前阻断事实、停止范围和最小补齐或恢复动作。
- `只能确认当前范围`说明已经证实什么、尚未证实什么，不把本地、模板、记录、测试或单一环境证据外推。

只有取得与业务结果、生产环境和观察范围匹配的一手证据时，才能确认用户可用；服务存活、健康检查或记录一致本身不够。

## 最小读入与路由

由Worker调用时，继承已核验的目标、环境、对象、候选版本、测试证据、检查点、分项授权、验证与回滚入口，不重跑接手链。先复用项目已经点名且仍有效的唯一服务器信息和部署运行手册；只读当前动作最小输入，未来发布、恢复或Git材料到真实切换时再读。

这些专业附录同时适用于正式任务和直接请求。正式任务按文中的Worker关系执行；直接请求由当前智能体承担询问、交付和后续动作。不存在的PM、助手或任务关系不补造。

按当前问题选择路径：

1. 唯一服务器/运行手册入口未知、缺失、过期、冲突，或确需首次建立和刷新：读[运维能力与部署运行手册](references/capability-and-runbook.md)。
2. 真实生产发布、五个版本锚点、跨任务热修、发布后真值或生产验证对象：读[生产发布与版本收敛](references/production-release-and-convergence.md)。
3. 分支合并、PR、推送、worktree/任务分支关闭或资源回收：读[Git、worktree 与资源收口](references/git-worktree-and-resource-closeout.md)。
4. 运行故障、日志排障、服务恢复、回滚、环境阻塞或详细失败包：读[故障恢复、证据与失败交付](references/incident-recovery-and-evidence.md)。
5. 本地单文件、单记录或单值静态预检：只读点名对象，不读reference。

初始最多读取一份reference；场景真实变化后再读下一份。触发后完整读取，缺失时只停止依赖它的分支，不猜规则或错误放行。

## 本地只读预检

目标、期望和禁止范围明确时，只做一次能直接证明比较结果的最小读取，说明记录值是否匹配和证据强度后停止。平台明确拒绝当前命令类别时，按根`AGENTS.md`的全局边界停止同类动作，不用等价测试命令、运行时探测或命令壳继续试探。

发布预检只消费已经存在的候选、测试、环境、当前运行版本和回滚证据，不负责补跑开发或测试命令。任一生产放行锚点缺失且已从权威入口确认时立即裁决`不能继续`；不再扫描源码、读取测试正文、重跑测试，或为了行号和引用重复读取已取得的文件。

- 不为补背景展开历史发布、Git、服务、网络、服务器、生产或数据；禁止写入不等于自动允许只读。
- 记录中的哈希或版本匹配只证明记录一致；没有重新计算制品、核对运行时或进入目标环境时，不得写成真实发布已验证。
- 目标不足时只指出一个关键缺口；能够在授权内定点补足时，取得最小充分事实后立即停止。

## 变更门禁与权限

执行变更前必须闭合：目标动作和环境、可追溯候选与当前基线、允许的命令/配置/服务、数据/停机/费用风险、成功与停止断言、当前轮验证、可执行回滚以及临时对象的清理或保留责任。

缺少真实环境、权限、验证或回滚时只能预检或`不能继续`。回滚方案、回滚可执行性和回滚执行授权是不同事实；只有回滚对象、触发条件、范围和责任已经预授权时才可自动回滚。生产、外部服务、数据破坏、删除、强推和其他不可逆动作必须具有对应明确授权，一种权限不能推导另一种。

测试通过后，正式任务只有原任务授权包含下一动作、检查点允许且用户没有保留确认时，Worker才选择运维方法；直接请求只有用户已经明确授权运维动作且没有保留检查点时，才由当前智能体进入。否则只做已授权的发布前检查。任务内决定沿原对话处理；只有真实存在PM关系且影响跨任务、共享对象、主线、资源或安全时才交PM。

## 正常路径

1. 核对当前环境、对象、版本、证据和授权，区分模板、本地、测试、预发与生产。
2. 复用项目正式脚本、运行手册、验证和回滚入口；现场与记录冲突时以当前一手事实裁决。
3. 只执行当前动作获授权的最小步骤，每一步都明确成功断言和停止扩散条件。
4. 在同一对象和当前运行版本上取得健康、关键业务、数据或其他与结论匹配的验证；失败立即停止后续动作。
5. 只有准确路径获得写入授权时才更新项目事实或单次生产记录。不可变制品身份与可变运行真值分开；观察、失败、回滚或恢复后，动态状态必须反映当前现实。
6. 给出三态裁决、证据强度、真实覆盖、残留、清理/保留结果和下一流向。

## 生产、故障与回滚

真实生产发布必须冻结任务起始基线、本次候选、授权目标主线或非Git等价正式入口、当前生产实际版本和可执行回滚版本，并闭合`构建输入 → 不可变制品 → 目标环境 → 运行时实际版本`。任一锚点、差异来源或候选身份不明时不得发布；详细收敛、灰度、观察和生产真值规则进入生产reference。

故障按`停止扩散 → 保存现场与影响 → 恢复或回滚 → 复验业务与数据 → 收口残留`处理。只有运维写入边界内的环境、配置、服务或任务自有资源问题，才可在授权内修正；产品实现、设计、测试资产或业务契约问题在正式任务中把证据返回Worker，由它切换对应方法，直接请求则由当前智能体按既有授权判断是否切换。运维不能借“恢复服务”直接修改业务实现。

## Git与资源收口

合并、PR、推送、分支/worktree删除和资源清理分别服从Git与删除授权。未指定方式时不猜测、不删除、不推送；dirty、归属不明、非本任务或存在活动消费者的对象只报告。危险Git、丢弃改动和非本任务资源清理必须另有明确授权，具体门禁进入Git收口reference。

## 交付与停止

先用人话说明处理的是哪个环境和版本、实际完成什么、是否稳定或已经回滚；用户能否使用只能按匹配证据回答，证据不足时明确写“尚不能确认”。再给绑定下一动作、对象和环境的三态裁决、最小一手证据、未覆盖风险及下一安全动作。

正式任务结果返回同一Worker，由它按身份职责保存任务事件并汇总；运维方法不发送任务终态、不替PM更新工作台。真实生产、停机、数据、不可逆或高成本取舍缺少授权时，由实际承接请求的智能体在当前对话提出一个最小问题。

用户约定“只做预检”“发布前先看”“一次只处理一个资源”或其他检查点时，到点立即停止，不提前发布、回滚、合并、清理或进入下一对象。只有场景真实进入复杂分支时才展开对应reference，不把普通预检写成事故复盘或审计稿。
