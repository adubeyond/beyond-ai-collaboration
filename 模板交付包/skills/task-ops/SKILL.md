# 运维动作

## 1. 定位

`task-ops`是软件运维专业方法：Worker加载后形成当前任务中的运维工程师专业能力，正式结果回到同一个 Worker；直接请求由当前基础智能体在授权内检查或操作并交付，不制造任务身份；PM只管理任务、发布顺序、共享资源和证据验收，PM不得读取本 Skill并直接操作环境。

运维负责本地预检、环境与运行检查、发布、恢复、回滚和获授权的 Git/资源收口。测试通过不自动取得生产、Git、数据、停机或不可逆权限。

普通代码任务自己的本地提交是开发连续交付，不进入本 Skill。只有当前主要动作已经变成本地合并、PR、推送、分支处理、既有 worktree遗留资源或其他独立 Git资源收口时，才使用这里的 Git路径。

用户只要求预检或判断时，运维裁决使用`可以继续 / 不能继续 / 只能确认当前范围`。这是一次判断，不是每个执行步骤都要重复经过的状态；正式任务业务状态仍由原 Worker使用`进行中 / 已暂停 / 已完成`。

SSH入口、规范别名、凭据来源或认证结果已经存在冲突时，在处理该分支前必须完整读取[运行事实与部署手册](references/capability-and-runbook.md)。主入口不保存具体解析方法，不能用模型常识或历史成功替代这次按需读取；完成核对前不得裁决缺少密码或要求用户提供凭据。

## 2. 最小读入

正式任务继承 Worker已经确认的业务结果、范围、验收、目标环境、授权和前序证据，不重新接手项目。直接请求已经点名对象、环境和边界时，只读取根规则、目标现状与必要入口，不要求补工作台任务行。PM不得因运维动作词进入本 Skill。

按当前场景最多先选一条；已经从任务或项目正式入口取得且没有变化的内容不再换一份 reference 重读：

1. 真实生产发布、版本收敛、跨任务热修或发布后生产真值：完整读取[生产发布与版本收敛](references/production-release-and-convergence.md)；
2. 当前运维动作缺少稳定服务器、服务、日志、部署或回滚入口，SSH入口/凭据来源存在冲突或认证异常，或者现场已经证明原入口变化：完整读取[运行事实与部署手册](references/capability-and-runbook.md)；
3. 本地合并、PR、推送、分支处理，或者处理已经存在的 worktree遗留资源：完整读取[Git 与资源收口](references/git-and-resource-closeout.md)；
4. 运行故障、日志排障、服务恢复、回滚、发布失败或环境阻塞归因：完整读取[故障恢复、证据与失败交付](references/incident-recovery-and-evidence.md)；
5. 单文件、单记录、单值或明确命令的静态预检：定点核验后裁决，不读取 reference。

实际发生故障后才读取故障 reference，不为“可能失败”提前加载。场景真实变化后再读下一份；同一任务已读且文件未变化时不重复读取。reference缺失只停止依赖它的分支，不妨碍仍能安全完成的动作。

## 3. 运行事实与真实目标

先从项目或子项目运维入口定位当前环境、服务和发布对象的正式所有者。优先复用已有服务器总表、环境说明、部署脚本、服务配置和专项 runbook；没有承载者、当前确实需要且拥有写入授权时才使用项目事实兜底路径。

长期事实和单次现场必须分开：

- 长期事实：环境角色、主机/别名、域名、目录、服务、端口、日志、凭据来源、标准部署与回滚路径；
- 单次事实：本次来源提交/制品、实际目标、当前运行版本、健康状态、发布结果、观察和回滚证据。

服务器的稳定连接身份使用“环境角色 + 配置中准确的规范别名 + 已核验主机身份”。IP 可以记录为最近一次解析或核验结果，但不能单独充当长期入口；不得自行改写别名大小写或用相似别名代替配置解析。

每个真实发布或恢复任务只建立一次本次生产上下文：

```text
业务结果与发布/恢复对象
目标环境、主机、服务、目录和当前实际版本
正式来源提交与唯一制品
允许操作的服务、配置、数据和停机边界
健康检查、关键业务检查和受影响回归
回滚触发、回滚版本/步骤和回滚后验证
当前授权，以及复用的环境事实和 runbook 入口
```

连接目标时现场确认主机身份和实际运行落点。上下文闭合后保存在当前任务线程或项目已有发布记录中，后续动作直接复用；普通发布不为此新建文档。只有候选制品、目标环境/主机/服务/目录、生产实际版本、授权、验证或回滚发生变化，才刷新受影响项。旧 IP、旧别名解析、旧目录或文档状态不能替代首次现场核验；已经核验且没有变化的事实不重复询问、重读或重新审批。

多份文档或现场互相冲突时只停止受影响动作，以当前现场确认唯一所有者并修正引用，不清空其他已经闭合的上下文。

项目 runbook 中出现 worktree 只说明旧流程或既有现场。BEYOND 不创建或推荐 worktree；只有当前现场已经存在 worktree且确实需要核对、合流或清理时才进入兼容分支。

## 4. 预检与执行

用户只要求核对点名文件、记录或值时，做一次直接比较并说明证据强度，不升级成完整运维审计。静态记录匹配只证明记录一致；未核验制品、服务或目标环境时不得外推为已经发布、生产可用或可以安全回滚。

能从项目事实、脚本、配置、服务和现场确认的生产上下文由Worker自行调查。缺少真实目标、必要权限、验证或回滚时继续安全预检；只有必须由用户决定或授权的事项才问一个最小问题。一次缺口只阻断依赖它的动作，不要求重新确认已经闭合的其他内容。

任务已预授权相同对象、环境、范围、验证和回滚时，测试通过后由原 Worker直接切换运维，不等待 PM二次激活。生产上下文闭合后在一个连续执行段内：

1. 使用项目当前正式脚本和 runbook，不临场换路径；
2. 发布前核对来源与制品，执行授权范围内的备份或回滚准备；
3. 只操作本次目标，并在同一实际对象上取得健康与业务证据；
4. 失败时停止扩大，按已授权条件回滚并复验；
5. 稳定变化写回唯一事实所有者，单次结果写任务或既有发布/运行记录。

目标连接信息与凭据合法入口可用，并且当前动作已经授权时，Worker自行使用工具执行，不要求用户手工代操作，也不重复索要相同授权。SSH入口、凭据来源或认证结果存在冲突时，按第2节加载的运行事实 reference完成核对；该核对尚未完成时不得裁决缺少密码或要求用户提供凭据。具体解析和判定方法只由该reference负责，不在主入口重复维护。

预检、发布、验证和已预授权回滚之间不逐步输出`可以继续`、不回PM、不等待用户重复放行。普通命令失败只更新受影响的版本、服务或验证事实；仍在原授权和回滚边界内时直接停止扩散、定位、恢复或回滚并复验。

## 5. 观察、故障与收口

需要跨时间窗口观察时，先取得当前样本，再记录观察对象、已取得样本、通过标准、剩余次数或时间、下次触发和责任实例。必须等待外部时间且当前没有其他安全动作时，原 Worker转`已暂停`并在同一任务恢复；不占用 PM持续轮询，不把一次健康样本写成稳定。

普通日志异常、启动失败和可回滚发布失败由原 Worker在授权内继续定位、恢复和复验，不为此拆新任务或等待 PM。影响其他正式任务、共享环境或发布顺序时才进入跨任务机制；需要新增生产、停机、数据破坏、不可逆或高成本授权时直接向用户提出一个最小问题。

合并、PR、推送、删除分支、清理 worktree和其他资源分别服从当前授权。不静默处理非本任务改动，不用强制 Git掩盖冲突，不因发布成功擅自删除审计链或回滚资源。

## 6. 输出

正式任务在连续执行段内只保留证据，不逐步骤向用户或PM发送裁决；到达真实暂停、用户检查点或最终结果时才输出。直接预检请求可以立即给一次裁决。

默认回复：

```text
结论：可以继续 / 不能继续 / 只能确认当前范围
对象：实际环境、服务、版本或记录
依据：本轮最关键的现场、命令和验证结果
变更：实际执行了什么；只读时写未执行
风险：未覆盖范围、观察或回滚状态
下一步：原 Worker继续观察/恢复/收口；直接请求则给用户最小动作
```

这个结构用于保存专业结果，不覆盖根入口的用户沟通边界；直接请求的最终答复先按根边界裁剪，再按用户实际需要提供技术证据。

简单静态预检压缩为更短的自然语言。只在真实复杂发布、事故、回滚或资源收口时展开明细，不把普通检查写成长篇审计报告。
