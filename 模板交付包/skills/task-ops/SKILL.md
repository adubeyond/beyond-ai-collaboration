# 运维动作

推荐触发句：`检查运维发布风险`

## 身份与结果

运维是执行者调用的动作技能，不是独立身份。它负责本地预检、环境与运行检查、发布、恢复、回滚和获授权的 Git/资源收口；不替 PM 排发布顺序或宣布项目完成，不因测试通过自动取得生产、Git、数据或不可逆权限。

默认只给三种裁决：`可以继续 / 不能继续 / 只能做到模板层检查`。当前输入只要求点名文件或记录的本地只读预检时，直接取得定点证据并裁决，不升级成真实发布或完整运维审计。

## 输入分类与最小读入

由任务控制实例调用时，继承任务运行上下文，不重新展开项目接手链。只读当前运维包、点名对象、目标环境/制品、验证和回滚入口；未来发布、恢复或 Git 材料在真实切换动作时再读。用户当前消息给出的清晰只读预检也是合法契约，不要求先补工作台任务行。

先按场景选择 reference：

1. 正式项目运维能力`未初始化/需刷新`：完整读取[运维能力与部署运行手册](references/capability-and-runbook.md)。
2. 真实生产发布、生产版本五锚点、跨任务热修、发布后真值或生产验证对象：完整读取[生产发布与版本收敛](references/production-release-and-convergence.md)。
3. 分支合并、提 PR、worktree/任务分支关闭或资源回收：完整读取[Git、worktree 与资源收口](references/git-worktree-and-resource-closeout.md)。
4. 运行故障、日志排障、服务恢复、回滚、环境阻塞归因或详细失败包：完整读取[故障恢复、证据与失败交付](references/incident-recovery-and-evidence.md)。
5. 排除以上分支后的本地单文件、单记录或单值静态预检，只读点名对象，不读取 reference。

初始最多读取一份 reference；真实场景变化后才读下一份，不合并预读未来动作。被触发的 reference 必须完整读取；缺失时只停止依赖该分支，核心仍处理普通本地预检且不得猜规则或错误放行。

## 本地只读预检快路径

当前消息已给出目标文件、期望值和禁止范围时，只读取点名对象并做一次直接比较，说明“记录值匹配/不匹配”和证据强度后停止。

- 不为了补充发布背景读取根入口、项目总览、工作台其他章节、历史发布、Git、服务、网络、服务器、生产或数据；用户禁止某对象时，不把“禁止写入”解释为可例行只读。
- 记录中的哈希或版本匹配只证明静态记录一致，未重新计算制品时必须明确说明；不得外推为真实制品、服务器或生产已验证。
- 目标自身不足以形成裁决时，只指出唯一缺口；用户未禁止且确有必要时才定点补读一个来源。

## 运维能力初始化安全默认

正式项目需要运维能力初始化时，形成或刷新唯一`部署发布运行手册`。稳定手册或当前动作必需事实未闭合前，不得执行真实发布、停服、数据或恢复动作，只能继续安全预检；达到最低条件后沿原任务继续，不返回 PM 续派。

先调查可发现事实，只对生产取舍、真实权限或不可发现环境事实提一个最小引导问题，不能用“请补齐全部信息”的清单代替提问。不得新建一份全字段均为`未发现/待补`的运行手册冒充初始化，不得让用户设计内部文档路径；只问实际服务的项目、仓库或发布对象，不列项目事实索引位置、手册写回目录或允许读取哪个上级目录等内部候选。后续同类发布只刷新易变事实；详细调查、模板、写回和成长复用在初始化 reference 中处理。

## 运维门禁与正常路径

执行变更前必须闭合：目标、环境、可追溯基线、允许命令/配置/服务、数据与停机风险、验证方法和可执行回滚。缺少真实环境、权限、验证或回滚时只能预检或`不能继续`；生产、外部服务、数据删除、强制推送和不可逆操作必须有用户明确预授权。

任务授权包含发布条件时，测试通过后由任务控制实例自动切换运维，不等待 PM 二次激活；没有生产授权、发布对象、可追溯版本或回滚锚点时只做发布前检查。环境资源与跨任务顺序交 PM；真实生产、停机、数据、不可逆或高成本取舍直接问用户一个最小问题，答复后沿原任务继续。

1. 先检查当前状态和证据强度，区分模板、本地、测试、预发与生产。
2. 只按项目已有脚本和正式流程执行获授权动作，不把本地通过写成生产通过。
3. 在同一对象上取得当前轮验证；失败时停止后续动作并保留回滚、版本和资源证据。
4. 更新获授权的项目事实、发布/生产记录或写清未更新原因；只写结论和证据位置，不把长日志塞进工作台。
5. 给三态裁决、真实范围、残留风险和实际流向。

## 生产、共享与 Git 安全默认

真实生产发布必须冻结任务基线、候选提交/制品、授权目标主线、生产实际版本和可执行回滚版本；任一锚点或差异来源不明时不得发布。发现其他任务热修时，来源清楚且可兼容则按事实向直接 PM 发送`shared_notice`，未知或冲突则发送`shared_conflict`并停止受影响动作；详细分类与发布后真值只在生产 reference 处理。

合并、PR、推送、分支/worktree删除和清理分别服从任务 Git 授权。未指定收口方式时不猜测、不删除、不推送；危险 Git、丢弃改动和非本任务资源清理必须另有明确授权。

## 权限与停止边界

- 不执行授权外的文件、Git、服务、网络、服务器、生产、数据、外部费用或不可逆动作。
- 不用模板、旧记录或口头摘要冒充当前环境一手证据；证据冲突时直接指出。
- 不删除审计链、秘密或归属不明资源；临时验证对象必须有清理或实名保留生命周期。
- 环境、权限、配置、证据、回滚或事实冲突无法闭合时停止受影响分支，说明一个最小缺口和应退回的层级。

## 输出

普通场景默认压缩为：

```text
结论：能继续 / 不能继续 / 只能做到模板层检查。
依据：当前环境、对象和最小一手证据。
下一步：当前最小动作；只有红灯才写裁决请求。
```

只有用户明确要求发布清单、运行记录、回滚方案、资源收口或事故明细，或场景真实进入对应复杂分支时，才读取匹配 reference 展开；不要把普通本地预检写成正式事故复盘或审计稿。
