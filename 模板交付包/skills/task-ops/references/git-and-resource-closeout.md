# Git 与资源收口

当前主要动作涉及本地合并、PR、推送、分支处理，或需要处理已经存在的 worktree/历史 Git残留时读取。普通开发、任务自己的本地提交和发布预检不进入本文件。

## 1. 默认 Git 交付

用户指定的正式项目是默认工作区。BEYOND 不创建或推荐 worktree。同一目录内边界不重叠的任务可以并行编辑和验证；同一 Git工作区的索引、HEAD和历史动作串行。

普通本地交付：

1. 核对当前正式项目和已有未提交改动；
2. 只暂存本任务拥有的文件；
3. 运行约定测试；
4. 创建任务自有本地提交；
5. 在正式项目或约定正式 Git目标上核对提交和结果。

推送、PR、非约定分支合并、rebase、reset、stash、强制 Git和删除分支分别服从任务授权。

## 2. 既有 worktree 兼容

只有用户或平台已经提供 worktree时才处理这个现场，不创建、推荐或切换到第二个 worktree。先核对：当前目录和仓库、来源提交与分支、任务归属、未提交/未合并成果、约定正式目标和验证入口。

当前 worktree就是约定正式目标时，按普通 Git交付处理；它只是临时现场时，由原任务在当前授权内完成可追溯合流和正式目标复验。成果未进入正式目标时任务保持`进行中`，不宣布完成，也不另建合流任务。

旧 runbook要求创建“干净 worktree”不改变本规则。需要干净来源时使用项目既有正式分支、独立 clone、制品或构建入口；当前必要来源客观不可用时只停止受影响动作并说明真实缺口。

## 3. 遗留资源处理

处理既有 worktree、分支或未提交资产前先核对归属、Git状态、可达提交、消费者和正式结果：

- 任务自有、clean、无未跟踪/未合并成果，且结果已在正式目标可达：可按已有删除授权清理并复核；
- 存在未归并成果：先由原任务完成合流或保留现场，不自动删除；
- 非本任务、dirty、归属不明或仍有消费者：只报告，不自动 prune/remove；
- 删除分支、丢弃改动、强制推送、远端推送和清理非本任务资源必须有明确授权。

合并或清理后在正式目标重新验证。验证失败时停止清理，保留现场供原任务修复。
