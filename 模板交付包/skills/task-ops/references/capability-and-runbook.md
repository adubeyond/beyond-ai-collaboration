# 运维能力与部署运行手册

## 何时读取

仅在当前动作必需的稳定部署、服务器、服务、日志、验证或回滚事实未知、缺失、过期、互相冲突，或需要建立、核验、刷新部署运行手册时完整读取。普通本地静态预检不进入本文件。

## 当前事实输入与调查

原Worker只传当前动作所需且已经存在的项目、环境、发布对象或制品、生产版本五锚点、权限、验证、回滚、证据去向和副作用边界；不要求为了调用本动作补造一份完整运维包。五锚点中的“授权目标主线”在非 Git 项目映射为权威制品库、发布清单、包版本或其他等价正式版本入口，并明确主线不适用，不能直接删掉该责任。已经确认且未变化的稳定项目事实、服务器事实和标准流程可以复用，但本轮环境、版本、权限、健康和授权必须按风险重新核验。

模板项目的稳定运维事实标准落点由项目事实索引确定为：

- `docs/AI编程协同机制/项目事实/运行环境与服务器信息.md`
- `docs/AI编程协同机制/项目事实/部署发布运行手册.md`
- `docs/AI编程协同机制/项目事实/安全与凭据索引.md`

三者组成唯一稳定事实链：服务器信息保存环境、主机、目录、服务、配置和日志等“在哪里”；部署运行手册保存构建、制品、部署、验证、停止和回滚等“怎么做”；安全索引只保存非秘密的合法来源、最小权限和轮换入口。当前候选、实际运行版本、健康、执行、观察和回滚结果属于“本次发生了什么”，只进入任务主面或任务契约事先登记的唯一单次记录，不复制进稳定事实文件。

这些路径只是稳定路由，不表示文件已经存在、内容已经核验或本轮拥有写入授权。`docs/AI编程协同机制/模板/`中的运行环境、部署发布、安全凭据、发布回滚和故障处理模板只提供可裁剪格式，不保存项目事实。单次发布、回滚或事故记录没有由模板预设的固定事实路径。已有有效实际入口时直接使用；入口缺失、需要确定标准落点、首次创建或维护边界时才进入项目事实索引，不并行预读索引、多个事实文件和全部模板。

首次建立和后续复用遵守：

1. 项目或任务已经点名有效入口时直接沿同一路径读取，不重新命名、复制或为当前任务另建一套。
2. 实际文件缺失时先写明“尚无已登记事实文件”，只定点调查当前动作所需的一手来源；只有准确标准路径获得写入授权时才创建已核验部分，不复制空模板。
3. 建立后，同类运维继续复用这三个稳定入口；服务器、目录、服务、标准命令、日志、验证和回滚步骤只有命中刷新触发才重新调查。
4. 每次高风险动作仍刷新候选、目标环境实际版本、健康、权限、回滚锚点和当前授权；稳定文档不能冒充当前现场。
5. 发现现场与稳定事实冲突时先按现场停止或限定动作，有准确路径写入授权才修正原文件；不得用临时笔记或新路径形成平行真相源。

定点调查部署脚本、CI/CD、服务配置、运行环境、服务器事实、凭据来源边界和历史现场，形成稳定层：

- 发布对象、构建方式与制品入口
- 目标主机、目录、服务和端口
- 标准部署步骤与前置条件
- 健康检查、关键业务验证和日志入口
- 标准回滚锚点、步骤与恢复验证
- 权限、账号和凭据来源边界，不记录秘密

可发现事实自行核对，并区分：

- 稳定事实：服务拓扑、标准目录、正式脚本、日志入口、验证与回滚方法。
- 当前事实：本轮提交或制品、目标环境实际版本、健康状态、权限可用性、回滚锚点和用户授权。
- 待裁决方案：尚未获业务确认的发布窗口、停机、数据处理或高成本选择，不得伪装为事实。

调查后仍缺生产取舍、真实权限或不可发现环境事实时，只问一个最小问题，给出候选值、来源、影响和`确认 / 纠正 / 不知道，请继续调查`路径。用户回答不能替代服务器、服务、Git 和生产现场核验。

没有可复用稳定事实或没有获授权正式路径时，只交付调查证据和未写原因，不创建空占位手册。只有任务明确授予准确文件路径的写入权限时，才更新对应项目事实或运行手册；路径未授权时不得另建平行真相源。正式入口不可达时，只问实际服务哪个项目、仓库或发布对象，不让用户选择内部目录。

## 模板与写回

按场景复用运行环境与服务器信息、部署发布运行手册、单次发布与回滚、运维巡检与故障处理模板。模板只提供格式；稳定事实写入对应项目事实文件，单次发布、事故和长证据写入任务主面或任务契约登记的唯一发布/生产记录，不写回模板源，也不因为模板提到工作台就绕过 PM 的单写边界。

事实达到当前动作的最低条件后沿原任务继续；若用户约定先看预检、先确认发布清单或保留上线验收，则交付检查点并停止，不能以事实闭合代替用户确认。后续只刷新任务起始基线、本次候选、目标主线、生产实际、回滚版本、当前健康和真实授权；服务器、目录、服务、标准命令、日志和回滚步骤只有命中刷新触发才重新核验。

刷新触发包括部署脚本/CI变化、主机或服务变化、运行时/依赖变化、凭据来源变化、验证或回滚口径变化、事实过期及现场证据冲突。变化闭合后，仅在准确路径写入已获授权时同步项目事实、来源和证据时间，不静默覆盖旧来源。
