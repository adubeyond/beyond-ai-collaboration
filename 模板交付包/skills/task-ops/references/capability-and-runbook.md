# 运行事实与部署手册

当前运维动作需要读取、建立或修正服务器、服务、日志、部署和回滚长期事实，或项目纠偏与旧入口、工具要求冲突时读取。普通本地静态预检不进入本文件。

## 1. 定点调查

服务器连接、服务操作、部署、发布或回滚前，先读取当前项目根入口，再按其中的规则所有者进入项目事实索引，定位当前环境、服务和发布对象的唯一正式所有者。组件仓、候选或镜像中的入口须核对其适用范围；相对链接失效时按任务已给的项目路由定位当前所有者，不默认退回候选内的旧规则，也不改写不可变候选。标为历史、上一阶段或只读追溯的说明不作为当前运行入口；总仓环境总表和子项目 runbook 分别承担其明确范围，不复制成第二份真值。

已有纠偏与旧工具要求冲突时，先区分当前授权、目标真实运行依赖与该工具自身的附加条件。工具拒绝只证明该工具路径未满足，不能直接推出任务未获授权或必须恢复旧流程；在原范围内核验当前适用路径。反之，管理员权限或文档纠偏也不能证明替代路径安全可用：来源、真实依赖、目标范围、验证及回退仍须闭合，不伪造证明、不绕过实际权限、不擅改共享控制器。仅真实无法补齐的缺口才阻断受影响动作。

只补当前生产上下文缺少或已经变化的事实。从部署脚本、CI/CD、服务配置、运行环境和真实服务器现场确认：

- 发布对象、构建方式和制品入口；
- 目标环境、主机、目录、服务和端口；
- 标准部署步骤与前置条件；
- 健康检查、关键业务验证和日志入口；
- 标准回滚锚点、步骤与恢复验证；
- 权限、账号和凭据来源边界，不记录秘密。

可发现事实自行核对。已经从当前正式入口取得且没有变化的事实直接复用，不换文档重复确认。调查后仍缺生产取舍、真实权限或不可发现环境事实时，只问一个会改变安全执行的问题。用户回答不能替代服务器、服务、Git和生产现场核验。

## 2. SSH 入口与凭据判定

SSH 入口缺失、冲突或认证异常时，按以下最短路径处理：

1. 从当前事实所有者取得规范别名，保留其准确拼写，不自行改写大小写或换成相似别名；
2. 先用`ssh -G <别名>`展开实际主机、账号、`IdentityFile`、代理和主机校验设置；使用专用配置文件时改用等价的`ssh -F <配置> -G <别名>`，该步骤只解析配置，不建立网络连接；
3. 核对配置指向的密钥、ssh-agent或其他合法凭据入口是否存在，不读取、展示或写入秘密值；当前动作已授权连接时，再用禁止交互式索密的安全探测核验身份与主机；
4. 只有规范入口确实不存在，或准确入口在授权探测后仍因凭据原因失败，才询问缺少的凭据来源或授权。错误别名回退到默认账号、默认密钥或密码提示，不构成“项目没有密码”的证据。

服务器文档保存环境角色、规范别名、主机身份和凭据来源；IP只作为最近一次解析或现场核验结果。地址变化时更新观测值，不让任务绕过规范别名改走散落IP。

## 3. 写回

稳定服务器和环境事实写回项目事实索引登记的现有环境所有者；可复用发布、观察和回滚路径写回匹配当前子项目、服务和环境的现有 runbook。单次发布或事故结果进入对应任务、发布或运行记录。

没有现成所有者、当前任务确实需要且拥有写入授权时，才按项目事实索引的兜底路径创建最小文件；不复制空模板，不另建初始化任务。

## 4. 复用与变化

后续任务直接复用未变化的环境角色、服务器入口、目录、服务、标准命令、日志和回滚步骤。每次真实运维任务首次连接时核对目标主机身份，并建立本次制品、实际运行落点、当前版本、验证、回滚和授权上下文；同一任务后续步骤只刷新实际发生变化的内容。旧 IP、旧别名解析或旧核验时间不能单独证明目标仍未变化，但一次有效现场核验也不因进入下一步骤自动失效。

部署脚本、主机、服务、运行时、凭据来源、验证或回滚路径变化时，只更新受影响内容并保留新的核验时间和依据。
