# 运维能力与部署运行手册

## 何时读取

仅在正式项目运维能力为`未初始化/需刷新`，或稳定部署、服务器、服务、日志、验证和回滚事实不足以支持当前动作时完整读取。普通本地静态预检不进入本文件。

## 初始化包与调查

任务控制实例只传当前动作所需的项目、环境、发布对象/制品、生产版本五锚点、权限、验证、回滚、证据去向和副作用边界。已经确认且未变化的项目总览、服务器事实和标准流程持续复用。

定点调查部署脚本、CI/CD、服务配置、运行环境、服务器事实、凭据来源边界和历史现场，形成稳定层：

- 发布对象、构建方式与制品入口
- 目标主机、目录、服务和端口
- 标准部署步骤与前置条件
- 健康检查、关键业务验证和日志入口
- 标准回滚锚点、步骤与恢复验证
- 权限、账号和凭据来源边界，不记录秘密

可发现事实自行核对。调查后仍缺生产取舍、真实权限或不可发现环境事实时，只问一个最小问题，给出候选值、来源、影响和`确认 / 纠正 / 不知道，请继续调查`路径。用户回答不能替代服务器、服务、Git 和生产现场核验。

没有可复用稳定事实或没有获授权正式路径时，只保留调查证据，不创建空占位手册。正式位置由项目事实索引或任务包确定；索引不可达且当前不是已初始化项目时，只问实际服务哪个项目、仓库或发布对象，不让用户选择内部目录。

## 模板与写回

按场景复用运行环境与服务器信息、部署发布运行手册、单次发布与回滚、运维巡检与故障处理模板。模板只提供格式；真实事实写入项目事实文件、发布记录或生产运行记录，不写回模板源。

手册达到最低条件后沿原任务继续。后续只刷新任务起始基线、本次候选、目标主线、生产实际、回滚版本、当前健康和真实授权；服务器、目录、服务、标准命令、日志和回滚步骤只有命中刷新触发才重新核验。

刷新触发包括部署脚本/CI变化、主机或服务变化、运行时/依赖变化、凭据来源变化、验证或回滚口径变化、事实过期及现场证据冲突。变化闭合后同步项目事实和证据时间，不静默覆盖旧来源。
