# 生产发布与版本收敛

## 何时读取

真实生产发布、五锚点比较、跨任务热修、发布后生产/主线真值，或生产验证对象生命周期任一项出现时完整读取。模板层或本地静态预检不进入本文件。

## 生产版本收敛门禁

进入生产前同时冻结：`任务起始基线 / 本次候选提交或制品 / 授权目标主线或等价正式版本入口 / 当前生产实际版本 / 可执行回滚版本`。非 Git 项目把第三项明确映射为权威制品库、发布清单、包版本或其他正式版本入口，并记录“目标主线不适用”；不能因没有 Git 就少一个权威收敛锚点。用提交祖先、补丁清单、发布清单或制品哈希解释差异；生产实际锚点不可得或差异来源不明时只做只读预检。任务授权必须明确包含当前目标环境和发布动作；用户保留上线确认或约定先看清单时，在执行真实切换前交付检查点并停止。

发布预检从现有正式入口核对上述锚点和既有测试证据；缺一项即可停止生产放行并返回最小补齐动作。预检不运行测试来制造缺失证据，也不通过全仓源码扫描、测试正文或重复带行号读取扩大证明。

候选身份必须形成可复核链：`来源提交或构建输入 → 构建过程/构建 ID → 不可变制品摘要或镜像 digest → 目标环境与发布批次 → 运行时实际版本`。项目已有 release manifest、制品签名、SBOM 或镜像证明时复用并核对，不为凑字段另造；不能证明运行对象就是已测试候选时不得宣布发布通过。不可变制品/发布身份清单只描述构建来源、版本和摘要；当前运行状态、观察进度、失败与回滚结果进入获授权的可变运行真值或单次生产记录。两者可以互相引用，但不得把动态状态塞进不可变清单后反复改写，也不得用恢复旧清单字节把当前状态退回`待验证`等历史快照。

生产存在、但候选与目标主线都没有的补丁逐项归类：

- `候选已等价覆盖`：给代码或行为证据，并在候选制品上回归。
- `本次必须保留`：先兼容合入候选，再重跑受影响验收，不能发布覆盖后再补。
- `其他任务或共享热修`：保留原来源；来源、归属、兼容性清楚时，把来源任务、契约、候选合入提交和回归证据交给任务控制实例，由它按当前协作契约报告共享变化。候选尚未兼容合入并回归前不得发布。
- `未知或冲突`：停止受影响动作并保留生产与回滚锚点，把冲突事实交给任务控制实例处理共享所有权。

共享变化的通知与冲突事件由任务控制实例负责；运维动作只提供事实、证据和停止范围，不自行寻址 PM 或另造事件协议。不受影响的只读预检可以继续。不得把共享热修冒充当前任务私有实现。

## 发布与发布后真值

发布制品必须来自完成收敛的唯一候选，并在同一制品或提交上完成发布前验证。真实发布、停机、数据变更、外部费用和不可逆动作分别受任务授权及用户保留检查点约束；一种权限不得外推为另一种。回滚后再次发布要重新比较生产实际，不沿用失败前旧结论。

涉及配置、schema、数据库迁移、回填、队列格式或外部状态时，发布前必须明确兼容范围、执行顺序、不可逆点和失败后的数据恢复或补偿。优先采用项目既有的向后兼容、扩展后收缩（expand/contract）或等价安全路径；旧版与新版可能并存时必须同时说明双版本读写关系。声称“可以回滚”必须有当前可用的回滚制品、权限、步骤、触发阈值或最晚决策时间、数据恢复/补偿和回滚后验证；高风险场景按项目正式流程在匹配的非生产环境演练，不能用一份旧方案代替本轮可执行性。回滚方案、回滚可执行性和回滚执行授权是三项不同事实：只有对象、触发条件、动作范围和执行责任已经预授权时才可在命中阈值后自动回滚；否则先停止扩散、保存现场并向用户取得最小决定，不得把发布授权外推为回滚授权。

项目采用灰度、金丝雀、滚动、多实例或多区域发布时，发布计划必须给出批次、流量/就绪处理、每批成功断言、观察窗口和停止扩散条件。发现部分节点、实例或区域已经切换而其他部分未切换时，先暂停后续发布，记录各处实际版本、流量状态和已经执行的迁移，再决定继续、回滚或恢复；不得把局部成功写成整体成功。

发布后核对：

1. 生产实际运行提交/制品、服务健康、关键业务和数据结果。
2. 授权目标主线是否包含生产提交，正式接口与发布文档是否对应生产。
3. 跨任务补丁是否已通知、保留来源并有控制面去向。

发布后把本轮指标与发布前基线和项目正式通过标准比较，并覆盖规定的观察窗口；按影响范围检查错误率、延迟、队列、日志/告警、关键业务和数据一致性。项目未定义时间或阈值时不得自行编造，只能交付已经观察的时长、事实和仍未确认范围。

观察窗口超过当前执行回合时，状态只能保持`已发布待验证`或等价候选状态；运维方法在任务主面或已登记生产记录中写明已观察时长、下一观察时间或事件触发、责任实例/责任人、证据入口、失败升级和回滚授权，再把这些事实返回实际承接请求的智能体。正式任务由原Worker按执行者主文件和异常生命周期作业包判断是否满足`paused`、释放当前执行回合及后续同一任务递增回合恢复的条件；直接请求由当前智能体向用户交付暂停现实和恢复触发，不制造正式任务事件。任务契约已经授权监控入口时也可由该入口触发后续观察；不得为了等待窗口长期占用智能体，也不得把排定后续观察写成已经稳定。只有真实存在PM关系且影响共享、资源、主线或生产安全时才立即进入PM，正式任务的普通观察结果按聚合事件消费。

观察完成、发布失败、回滚或恢复后，必须再次核对`不可变发布身份 → 当前运行版本 → 当前状态 → 对应证据`。拥有运行真值准确路径写入授权时，同一动作把动态状态更新为实际结果并保留前一状态与证据入口；没有授权时明确交付“运行现实已变化、记录仍过期”的冲突和建议更新位置，不能宣称生产真值已经收敛。回滚恢复旧制品时可以恢复不可变身份引用，但当前状态应写`已回滚/回滚验证通过/回滚失败`等实际结果，不得恢复为旧发布当时的`已发布待验证`。

生产成功但代码、正式契约或记录未进入授权目标主线或等价正式版本入口时，业务最多`候选完成`；交付列出生产提交或制品、未合流对象、授权缺口和接手入口。合并、推送与 PR 继续服从 Git 分项授权；非 Git 项目核对权威制品库、发布清单、包版本或任务契约登记的等价入口。单次发布的当前候选、执行过程和结果只写入任务主面或任务契约登记的唯一发布/生产记录；工作台只由 PM 在有写入权限时保存阶段摘要和证据链接。只有任务拥有准确路径写入授权时，才更新发布记录或生产真值；否则交付证据位置和未写原因。

## 生产验证对象生命周期

发布前列出将创建或改变的账号、数据行、审计记录、导出物、临时配置和外部资源，并声明`不创建 / 证据取得后自动清理 / 明确保留`。保留项写业务用途、责任方、非秘密标识、证据位置和清理触发；秘密不得进入日志。

验证后只执行已经逐项授权的清理并复核残留。用户约定查看结果后决定保留或清理时，先交付验证证据和对象清单并停止。清理需要额外权限或会破坏审计链时停止自动删除，登记残留和裁决去向。依法或按设计不可删除的审计记录标明责任与期限。缺清理证据或保留责任时，运维只返回“最多候选完成”的限定结论和残留；任务状态与实例生命周期由原Worker按身份职责处理。
