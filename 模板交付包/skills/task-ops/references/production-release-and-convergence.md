# 生产发布与版本收敛

## 1. 何时读取

真实生产发布、来源与生产版本存在差异、跨任务热修或发布后生产真值需要核对时读取。模板层、本地静态预检和普通开发提交不进入本文件。

本文件只补充生产特有判断。目标、授权、验证和回滚已经在当前任务生产上下文闭合时直接复用，不重新建立第二套门禁。

## 2. 一次建立生产上下文

普通单一来源发布先核对四个身份事实：`正式来源提交 / 唯一发布制品 / 当前生产实际版本 / 可执行回滚版本`。再从任务已经确认的范围继承目标环境与服务、允许副作用、健康与关键业务检查、回滚触发和当前授权。

这些内容在当前任务线程或项目已有发布记录中形成一份生产上下文。上下文闭合后，预检、发布、验证和已预授权回滚连续执行，不按步骤重新读取文档、询问用户、回PM或输出中间放行裁决。

只有以下事实实际变化时才刷新对应项：

- 正式来源或制品摘要；
- 目标环境、主机、服务、目录或生产实际版本；
- 允许操作范围、生产/数据/停机授权；
- 健康检查、关键业务检查或受影响回归；
- 回滚版本、步骤、触发或回滚后验证。

一次命令失败、重试或进入下一发布步骤不会自动使全部上下文失效。失败只更新受影响事实；仍在原授权和回滚边界内时，由原Worker停止扩散、定位、恢复或回滚并复验。

## 3. 普通发布与差异收敛

来源提交已经是任务约定的正式Git目标时，不再增加任务起始基线、授权目标主线或另一个合流任务。候选必须是本次正式来源形成的完整制品；不能只替换一个接口或局部文件而绕过同一候选中的其他模块、配置和依赖。

发布前验证与发布后验证绑定同一制品。发布后至少核对实际运行版本、服务健康、关键业务和本次改动真正影响的邻接功能；没有影响的类别不为凑表格机械测试。

只有生产与正式来源确实存在额外差异时，才追查共享热修、分支或未知补丁：

- `候选已等价覆盖`：给出代码或行为证据，并在候选上回归；
- `本次必须保留`：兼容合入候选并重跑受影响验收；
- `其他任务或共享热修`：保留来源，向PM发送一次最小共享影响摘要，不等待纯消费回执；
- `未知或冲突`：只停止受影响的发布动作，保留生产与回滚锚点并进入跨任务协调。

未被差异影响的生产上下文继续有效，不从头重走预检。

## 4. 发布后真值与验证对象

发布后把实际运行版本、健康、关键业务、数据结果和必要发布记录与正式来源对应。生产已经成功但运行内容无法追溯到正式来源时，任务保持`进行中`并完成收敛；只有需要新增高风险授权或必要外部资源时才`已暂停`。

只有本次验证确实会创建或改变账号、数据行、审计记录、导出物、临时配置或外部资源时，才登记其`不创建 / 验证后清理 / 明确保留`。验证后执行已授权清理并复核残留；清理需要新增权限或会破坏审计链时，保留事实并提出一个最小决定，不把无关发布内容重新送审。

普通发布只在任务线程保留结果和证据即可。项目已有发布记录、验收明确要求或当前过程需要跨时间恢复时，才更新对应发布记录；不因进入生产方法自动实例化完整模板。
