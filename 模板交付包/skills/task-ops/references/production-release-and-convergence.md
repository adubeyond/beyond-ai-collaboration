# 生产发布与版本收敛

## 何时读取

真实生产发布、五锚点比较、跨任务热修、发布后生产/主线真值，或生产验证对象生命周期任一项出现时完整读取。模板层或本地静态预检不进入本文件。

## 生产版本收敛门禁

进入生产前同时冻结：`任务起始基线 / 本次候选提交或制品 / 授权目标主线 / 当前生产实际版本 / 可执行回滚版本`。用提交祖先、补丁清单或制品哈希解释差异；生产实际锚点不可得或差异来源不明时只做只读预检。

生产存在、但候选与目标主线都没有的补丁逐项归类：

- `候选已等价覆盖`：给代码或行为证据，并在候选制品上回归。
- `本次必须保留`：先兼容合入候选，再重跑受影响验收，不能发布覆盖后再补。
- `其他任务或共享热修`：保留原来源；来源、归属、兼容性清楚时向实际直接 PM thread ID发送`shared_notice`，说明来源任务、契约、候选合入提交和回归证据，缺项如实待补。候选尚未兼容合入并回归前不得发布。
- `未知或冲突`：向实际直接 PM thread ID发送`shared_conflict`，停止受影响动作并保留生产与回滚锚点。

通知不等待纯消费回执，可继续不受影响的预检。不得把共享热修冒充当前任务私有实现。

## 发布与发布后真值

发布制品必须来自完成收敛的唯一候选，并在同一制品/提交上完成发布前验证。回滚后再次发布要重新比较生产实际，不沿用失败前旧结论。

发布后核对：

1. 生产实际运行提交/制品、服务健康、关键业务和数据结果。
2. 授权目标主线是否包含生产提交，正式接口与发布文档是否对应生产。
3. 跨任务补丁是否已通知、保留来源并有控制面去向。

生产成功但代码、正式契约或记录未进入授权目标主线时，业务最多`候选完成`；事件列出生产提交、未合流对象、授权缺口和接手入口。合并、推送与 PR 继续服从 Git 分项授权。

## 生产验证对象生命周期

发布前列出将创建或改变的账号、数据行、审计记录、导出物、临时配置和外部资源，并声明`不创建 / 证据取得后自动清理 / 明确保留`。保留项写业务用途、责任方、非秘密标识、证据位置和清理触发；秘密不得进入日志。

验证后执行已授权清理并复核残留。清理需要额外权限或会破坏审计链时停止自动删除，登记残留和裁决去向。依法或按设计不可删除的审计记录标明责任与期限。缺清理证据或保留责任时业务只能`候选完成`，但实例仍按终态释放。
