# Git、worktree 与资源收口

## 何时读取

当前动作涉及本地合并、PR、推送、分支/worktree处理、任务资源关闭或历史残留判断时完整读取。普通预检、发布判断或故障恢复不进入本文件。

## 收口契约

任务授权在现有`允许操作`或`收口方式`中说明目标分支、本地合并/提 PR/保留、是否推送，以及 worktree 和任务分支如何处理；不新增独立表格列。创建时登记`自动清理 / 正式保留 / 待裁决`。

终态前清点本任务创建的 worktree、分支、提交和未提交资产：

- 自动清理只适用于对象同时满足`任务自建、工作区 clean、候选提交已合流、已有清理授权、没有活动实例或消费者`。删除后复核 worktree 列表与路径。
- 不满足条件时保留现场并记录`所有者、保留原因、接手入口和清理触发条件`；实例按终态释放，资源进入完成剖面。
- 外部、归属不明、dirty 或 prunable 的 worktree 只报告，不自动 prune/remove；集中治理另走明确 Git 与删除授权。`.gitignore`不能替代生命周期治理，也不能证明目录可删。

终态统一记录：`模式、实际物理根、branch/HEAD、dirty/untracked、候选提交、目标主线已包含/已合并/未合并、保留原因、清理触发`。detached、未提交、未合流或正式资产仍只在 worktree 时，裁决最多为`candidate_completed/testing/blocked`，不得写“主项目已更新/已完成”。

## 分支处理

收口前核对当前轮测试、待合并提交、目标分支、工作区状态和 diff 范围：

- 已授权本地合并：合并后在目标分支结果上重新验证，只清理本任务创建且满足条件的对象。
- 已授权提 PR：准备可审查分支和证据；平台权限可用时创建，否则返回分支、提交和证据入口。
- 已授权保留：保留必要现场，写所有者、入口和后续触发。
- 未指定：不猜测、不删除、不推送；业务记`候选完成`，终态列出未合流对象、现有提交/工作区和 PM 最小裁决。实例进入`待回收/已关闭`，补充策略后沿同一任务 ID 开新执行回合。

合并验证失败时停止清理，保留任务现场供修复。删除分支、丢弃改动、强制推送、远端推送或清理非本任务 worktree 必须有对应明确授权。

普通`本地合并 / 提 PR / 保留`属于 PM 控制面配置，不直接打断用户；删除、丢弃、强推、未授权远端推送或其他高风险取舍才请求用户授权。
