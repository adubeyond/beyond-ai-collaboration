# Git、worktree 与资源收口

## 何时读取

当前动作涉及本地合并、PR、推送、分支/worktree处理、任务资源关闭或历史残留判断时完整读取。普通预检、发布判断或故障恢复不进入本文件。

## 收口契约

任务授权在现有`允许操作`或`收口方式`中分别说明目标分支、本地合并、提 PR、保留、是否推送，以及 worktree 和任务分支如何处理；一种 Git 权限不得推导出另一种。创建时登记`自动清理 / 正式保留 / 待裁决`。用户约定合并前审查、提交前确认、先看 diff 或逐项决定清理时，必须在对应动作前交付检查点并停止。

终态前清点本任务创建的 worktree、分支、提交和未提交资产：

- 自动清理只适用于已有 task-owned 生命周期授权、用户没有保留最终清理确认，且对象同时满足`任务自有、工作区 clean、无未跟踪或未合并内容`、候选提交已安全合流或按正式契约可达、没有活动实例或消费者。删除前解析并核对准确绝对路径；删除后复核 worktree 列表与路径。
- 不满足条件时保留现场并记录`所有者、保留原因、接手入口和清理触发条件`；实例按终态释放，资源进入完成剖面。
- 非本任务、dirty、归属不明或历史 prunable 条目只报告，不自动 prune/remove；集中治理另走明确 Git 与删除授权。

## 分支处理

收口前核对当前轮测试、待合并提交、目标分支、工作区状态和 diff 范围：

- 已授权本地合并：合并后在目标分支结果上重新验证，只清理本任务创建且满足条件的对象。
- 已授权提 PR：准备可审查分支和证据；平台权限可用时创建，否则返回分支、提交和证据入口。
- 已授权保留：保留必要现场，写所有者、入口和后续触发。
- 未指定：不猜测、不删除、不推送；运维只返回未合流对象、现有提交或工作区和所需最小裁决，由原Worker按身份职责决定是否登记`候选完成`、如何处理实例与后续执行回合。运维动作不发送任务终态或直接改变实例生命周期。

合并验证失败时停止清理，保留任务现场供修复。删除分支、丢弃改动、强制推送、远端推送或清理非本任务 worktree 必须有对应明确授权。

已经写入任务契约且没有用户保留检查点的普通`本地合并 / 提 PR / 保留`可以连续执行；没有契约时不得把 PM 角色或旧记录当作授权。删除、丢弃、强推、未授权远端推送、清理非本任务资源或其他高风险取舍必须取得用户明确授权。
