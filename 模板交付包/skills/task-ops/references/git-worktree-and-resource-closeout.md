# Git 与遗留 worktree 资源收口

当前主要动作涉及本地合并、PR、推送、分支处理，或用户明确要求处理既有 worktree/历史残留时读取。普通开发、任务自己的本地提交和发布预检不进入本文件。

## 1. 默认 Git 交付

BEYOND 不自动创建 worktree。用户指定的正式项目是默认工作区，同一项目写入任务串行。

普通本地交付：

1. 核对当前正式项目和已有未提交改动；
2. 只暂存本任务拥有的文件；
3. 运行约定测试；
4. 创建任务自有本地提交；
5. 在正式项目上核对提交和结果。

推送、PR、非约定分支合并、rebase、reset、stash、强制 Git和删除分支分别服从任务授权。

多人分别拥有独立 clone时可以通过分支协作；多个 Worker共享一个目录时不能同时写入。

## 2. 用户明确要求的 worktree

只有用户明确要求并接受合流成本时，才一次性使用 worktree。创建前必须明确并核对：

- 起始提交；
- 任务分支；
- 正式目标；
- 测试和同任务内合流路径；
- 完成后的清理条件。

项目旧 runbook、历史任务或脚本中写有“使用干净 worktree”，不等于用户已经授权创建。没有当前明确要求时，使用正式项目的干净来源与既有构建入口；无法取得可追溯干净来源时停止发布准备并说明缺口，不擅自增加 worktree。

成果未进入正式目标时任务保持`进行中`，不得把临时目录或未跟踪文件写成已完成，也不得另建第二个合流任务。

## 3. 遗留资源处理

处理历史 worktree、分支或未提交资产前先核对归属、Git状态、可达提交、消费者和正式结果：

- 任务自有、clean、无未跟踪/未合并成果，且结果已在正式目标可达：可按已有删除授权清理并复核；
- 存在未归并成果：先完成同任务合流或保留现场，不自动删除；
- 非本任务、dirty、归属不明或仍有消费者：只报告，不自动 prune/remove；
- 删除分支、丢弃改动、强制推送、远端推送和清理非本任务资源必须有明确授权。

合并或清理后在正式目标重新验证。验证失败时停止清理，保留现场供修复。
