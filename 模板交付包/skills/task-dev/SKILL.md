# 开发动作

## 身份与边界

开发是 Worker 在当前任务内选择的专业方法，或基础智能体处理直接、清晰实现请求时采用的方法，不建立新智能体，不改变身份、任务 ID、控制权或授权。在本方法内，PM 只编译、派发或协调任务，不能替 Worker 实现；跨任务、共享对象、主线、资源、安全和收口仍由 PM 按身份职责处理。正式任务先由 Worker 完成接单核验，再在当前放行段内进入开发。开发不替设计改方案，不替测试宣布通过，也不替运维发布。

只读定位、代码解释和改点判断不自动获得写入权。用户只要求结论时，定点调查后停止，不修改文件或发送任务生命周期事件。

## 最小读入与路由

由 Worker 调用时，继承已核验的目标、验收、检查点、分项授权、有效设计/契约、事实入口和回源关系，只读当前实现需要的源码、依赖和验证入口，不重跑接手链。直接、清晰请求在目标、写入边界、结果和验证明确时，可用当前消息作为实现契约；不强制补工作台任务行，也不无目的展开项目总览、历史、全量 Git 或调用方。采用本机制的项目在首次直接写入前，执行根`AGENTS.md`规定的一次最小写入所有权检查；该检查只防止与已有任务静默重叠，不把清晰请求升级成项目接手。检查被拒绝或仍无法排除重叠时只能继续读取必要事实，不得调用写入工具，也不得运行针对拟议改动的构建、测试或运行时验证。

这些专业附录同时适用于正式任务和直接请求。正式任务按文中的Worker关系执行；直接请求由当前智能体承担询问、交付和后续动作。不存在的PM、助手或任务关系不补造。

按当前问题选择路径：

1. 实现必需的工程事实未知、正式入口缺失、证据过期，或要建立、核验、刷新工程开发基线：读[开发能力与工程基线](references/capability-and-engineering-baseline.md)。
2. 跨文件或尚未定位的缺陷、失败、根因、修复循环或回归：读[实现、调试与修复循环](references/implementation-debugging-and-repair.md)；已精确定位的局部问题可走轻量路径。
3. 结构性改动、跨线接力、失败交付或需要完整交付：读[交付、交接与失败包](references/delivery-handoff-and-failure.md)。
4. 普通只读定位：只读点名对象和形成结论所需的相邻来源，交付最小修改点与验证入口，不运行未授权动作。
5. 清晰局部写入：沿现有组织做最小完整改动并定点验证。

轻量请求不读 reference。初始最多读取一份；场景真实切换后再读下一份。触发后完整读取，同一任务中文件未变化则复用；reference 缺失时只停止依赖它的分支，不猜规则或错误放行。

仅核对开发条件、入口或计划且当前段未授权执行时，只读现有事实，不运行版本探测、构建或测试。需要验证时预先选定一条最接近验收的命令，提交后等待结果；平台拒绝当前命令、工具或写入类别时立即按现有证据裁决，不再提交等价测试、运行时探测、命令壳或另一写入工具。

## 写入门禁

写入前闭合：

- 目标结果、明确不做和允许修改的文件或模块；
- 当前消息或唯一正式设计/契约中的实现依据及适用版本；
- 可执行或可替代的验收入口；
- 新文件的路径、用途、使用者、入口和回收方式；
- 权限、数据、Git、依赖和跨项目风险。

存在正式设计或共享契约时，将当前范围最小映射为`设计/契约项 → 目标模块或文件 → 复用能力与不变量 → 验证入口`，不能自行从多份草案或聊天摘要中挑选依据。工作台和历史只能提供线索，不能单独证明当前实例、写入权或有效版本。

信息不足时只形成一个会改变实现的最小决定项。直接请求由当前智能体询问用户；正式任务返回原 Worker，由 Worker 在当前任务内取得用户决定。当前授权包含设计时，正式任务由同一 Worker、直接请求由当前智能体切回设计补齐；不能自行扩大范围。

## 核心工程约束

- **复用与最小改动**：先检查目标附近的现有模块、公共能力、依赖、调用方式和测试；语义与责任一致时复用或小幅扩展，不复制业务规则，也不为假想未来提前抽象。只改当前结果需要的内容，不夹带重构或风格迁移。
- **清晰与注释**：遵守已核验的技术栈、目录、命名、格式化和依赖约定。代码应从结构和命名表达职责；注释只解释无法由代码说清的原因、业务规则、不变量、兼容义务、边界和副作用，并随代码更新。
- **失败与安全**：在真实信任、授权、输入、持久化和状态边界校验并保留可定位错误；不吞异常、伪造成功、拼接可执行内容、关闭安全门禁或泄露敏感信息。
- **契约与设计**：未经授权不改变公开接口、数据、状态、配置默认值、错误语义和调用方行为。现场证据推翻有效设计时停止受影响实现并回到设计，不让代码和旧设计同时冒充正式依据。
- **状态与资源**：按实际风险处理事务、并发、幂等、部分失败、重试、超时、取消、容量和回收；成功、失败和中断路径都要守住数据不变量并释放资源。
- **依赖、配置与文档**：优先使用已有依赖；新增或升级需核对授权、兼容、安全、许可证、锁文件和运行影响。配置、生成物及公开文档只通过正式入口维护，无写入权时交付影响和建议位置。
- **证据与清理**：自测证明实现，不能靠删除/跳过用例、放宽断言或更新期望制造通过。交付前清理无归属的占位、调试、后门、死代码和临时文件；性能判断以当前证据为准。

详细工程事实、修复循环和完整交付要求分别由对应 reference 承载；只检查当前变化真正命中的风险，不机械展开全部清单。

## 实现路径

1. 定点核对目标、有效设计/契约及版本、现有组织、复用能力、风险边界、验证入口和用户已有改动。
2. 选择最小完整改动点，列出明确不改范围；事实推翻设计时先回流设计。
3. 在授权边界内实现；多执行线只写自己的范围，新文件必须已有生命周期。
4. 复读变更，核对必要注释、错误与安全路径、状态与资源、兼容、依赖、配置和消费文档，并清理临时内容。
5. 运行获授权且最接近验收的一条定点自测或必要检查并等待结果；成功后再按证据缺口决定是否需要不同目的的下一项，拒绝后停止该验证分支，不能用版本探测或另一命令替代。确认目标入口真实执行且证据未被削弱，区分基线失败与本轮回归。
6. 正式任务向原 Worker 返回变更与未改范围、设计/契约锚点、复用关系、验证证据、覆盖边界和残留风险；直接请求由当前智能体把同一内容交付用户，不制造任务回源。

## 停止与接力

不静默覆盖用户或其他执行者的修改，不写边界外文件，不从开发授权推断 Git、生产、数据破坏、跨项目或外部权限。目标、写入边界、契约、权限或新文件生命周期无法闭合时停止受影响实现。

实现将改变用户行为、正式契约、核心职责、主链路、关键数据流、数据所有权、质量目标或验收时，正式任务返回原 Worker 并由它切回设计；直接请求由当前智能体在现有授权包含设计时切换设计方法，否则向用户提出一个最小决定项。只有跨任务、共享对象、主线、资源或安全影响才交 PM。

开发自测后，正式任务只有任务授权包含测试、检查点允许且用户未保留代码审阅时，才由同一 Worker 选择测试方法；直接请求只有用户已经明确授权测试且没有保留检查点时，才由当前智能体选择测试方法。否则交付开发结果并停止。开发动作不建立测试实例，不解除检查点，也不把自测、构建或静态检查写成独立测试通过、发布完成或用户可用。

用户约定“先审后改”“一次一个文件”或“改完先看”时，到检查点立即停止。只读结果压缩为结论、最小修改点、验证入口和未执行事项；写入结果先说明当前真实状态，再交付可定位证据，不强制固定标题或内部状态词。
