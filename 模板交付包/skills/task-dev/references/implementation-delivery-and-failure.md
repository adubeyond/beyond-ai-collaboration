# 实现交付与失败证据

只在结构性或多模块改动、需要详细交付，或者当前实现无法完成时完整读取。普通局部修改使用开发主入口的短格式。

## 1. 详细实现交付

至少说明：

```text
实现了什么业务结果
修改了哪些文件、模块、配置或脚本
明确没有修改什么
依据哪份设计或契约
实现所基于的源码版本，以及它与正式目标当前基线的关系
实际运行了什么验证，结果怎样
还有哪些未覆盖风险和回退方向
```

若改变核心模块职责、主链路、关键数据流或代码入口，更新现有技术架构所有者，或者说明本轮没有更新的真实原因。不为交付另建无消费者的总结文档。

## 2. 连接测试

开发交给原 Worker的是可验证实现，不是“代码写完”的口头结论。返回待测对象、行为变化、源码/目标基线关系、完整变更集、直接消费者、验收依据、测试入口和已知风险；原 Worker再按需要切换测试方法。

共享模块或小接口的验证不能只覆盖新增断言：至少覆盖目标行为和已确认受影响的直接消费者。正式目标与当前源码基线不一致时，先在目标基线上复现补丁与必要回归；没有完成这一步时只能交付待移植差异，不能声明发布候选已经闭合。

局部开发助手只向原 Worker返回diff、自检和风险。另一个正式任务确实需要消费实现结果时，按跨任务机制传递正式文件/提交/制品、契约入口和验证入口；开发 Skill不创建接力或改变任务控制权。

## 3. 无法完成时

返回能够继续调查或修复的一手事实：

```text
失败现象与最小复现
已经完成和验证的内容
尚未完成的结果
已经排除的原因
当前最有价值的下一动作
是否存在源码基线、目标版本或完整制品不一致
需要补充的唯一决定、资源或授权
```

普通失败仍回原 Worker继续修复，不改变任务状态。只有原 Worker确认命中真实暂停条件时才暂停；本 Skill不直接找PM、测试或运维重新派单。
