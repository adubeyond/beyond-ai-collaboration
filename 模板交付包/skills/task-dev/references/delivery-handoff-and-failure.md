# 交付、交接与失败包

本文件只在原 Worker 已经选择开发方法，且当前涉及结构性改动、多模块实施、跨线接力或开发动作无法完成时读取。它规定开发结果怎样返回原 Worker，不建立新的交付主体、测试控制实例或任务终态。

## 完整开发交付

结构性改动、多模块实施或明确要求完整交付时，向原 Worker返回实际修改的文件、模块、配置或脚本，本轮明确未改范围，采用的设计与契约依据，验证命令、断言、入口与通过标准，以及未证实事项和回退方向。按当前变更实际涉及的内容同时说明：

- 复用或扩展了哪个既有能力；确需新增实现、公共抽象或依赖时，说明现有能力为何不适用。
- 哪些非显然业务规则、不变量、兼容义务或副作用补充或更新了必要注释；没有这类内容时不制造注释清单。
- 依赖、锁文件、生成物、公开接口、数据/状态语义、配置默认值和迁移兼容是否变化及对应授权。
- 当前结果涉及的信任边界、认证/资源授权、输入与注入防护、最小权限、错误路径和敏感信息怎样处理；安全入口没有实际核验时不能写成“安全通过”。
- 数据不变量、事务/补偿、并发/竞态、幂等、重复执行、部分失败和中断恢复怎样保持；已经发生的数据或外部副作用与代码修复分开说明。
- 外部调用和长任务的超时、取消、重试/退避、容量边界，以及连接、句柄、锁、临时对象和子进程在成功与失败路径如何释放。
- 配置来源、默认值、密钥/开关、环境专用值及日志/指标/追踪的影响；不得把只在开发机手工设置后成立的结果写成可交付。
- 公开API/schema、配置、示例、变更说明、迁移/回滚指引和运维入口是否需要同步；没有准确路径写入授权时列出受影响消费者、建议位置和未写原因。
- 已执行的格式化、静态检查、构建和定点自测，以及未运行入口、当前可比基线失败与本轮回归的区别；同时说明目标测试是否真实执行，测试/快照/阈值是否变化及其授权和理由。
- 已清理或仍有正式归属的临时兼容、`TODO/FIXME`、调试输出、死代码和测试后门。

信息必须可定位、可核验，但不强制固定标题或代码块外形；不适用的内容不机械展开。未取得证据的质量结论不能写成通过，局部成功路径、开发机结果和被削弱的测试也不能替代当前实际涉及的安全、状态、资源和兼容证据。

发现需要改变核心模块职责、主链路、关键数据流或代码入口时，先把事实、影响和设计回改需求返回原 Worker；由同一 Worker按任务授权切回设计方法，触及正式边界、共享契约、验收或其他任务时再按控制关系交 PM。设计决定成立且目标代码与技术架构路径分别获得准确写入授权后，才能实施和写回；没有授权时只返回应更新内容、证据、建议位置和尚未写回原因。

## 返回 Worker与测试方法判定

- 小实现细节随开发结果返回原 Worker；结构、主链路或职责冲突形成设计核对输入，不私自重定义契约。
- 返回原 Worker的是可供测试判断的版本和证据，不是“代码写完”的口头结论；明确测什么、怎么测、什么算通过和剩余风险。
- 原 Worker已经接单、授权包含测试、当前检查点允许继续且用户没有保留代码审阅时，自测后由同一 Worker选择测试方法；开发 Action不能自行建立测试控制、发送测试结论或解除检查点，独立开发助手也只向原 Worker交回结果。

跨线开发确实需要接力时，开发方法向原 Worker返回目标执行线、接收内容、共享契约所有者与版本、读写边界、联调验证、证据入口、写回位置和关闭条件；由原 Worker按既有协作与PM控制关系决定接力，不要求固定交接模板，也不让开发 Action自行创建正式任务或实例。

不得另建无生命周期的协作文档。接力只写入当前任务已有且获准确授权的正式入口或任务授权指定的接力位置；开发 Action不直接把接力结果写成 PM当前工作台已经消费的控制状态，需要控制摘要时由原 Worker回传、PM消费后更新。

## 失败交付

开发动作不能完成时也必须向原 Worker返回可接续结果，说明实际失败原因、已完成和未完成范围、已验证内容、未执行或失败的工程质量入口、可能受影响的数据/状态/资源/消费者、已经发生且尚未恢复的副作用、残留风险、最小安全下一步及所需决定；不强制固定标题、表格或内部状态词。开发动作失败不是业务任务终态，不能替Worker发送`failed`、释放实例或宣布主线失败。

失败包只记录当前轮事实和最小接续动作并返回原 Worker。业务语义、验收取舍、生产权限或不可逆决定需要用户决定时，由 Worker在当前正式任务对话直接询问；资源、实例、跨任务边界、共享对象、主线或安全影响由 Worker交 PM协调。取得有效决定后仍由同一 Worker判断沿原任务继续、切换方法、进入新回合或形成任务终态，开发 Action不建立第二条决定路径。
