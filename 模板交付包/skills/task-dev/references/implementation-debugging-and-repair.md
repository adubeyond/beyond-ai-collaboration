# 实现、调试与修复循环

## 适用范围

只在原 Worker 已经选择开发方法，且当前涉及新增高回归行为、缺陷修复、构建/测试失败、根因排查，或原 Worker需要开发修复助手时读取。本文件只提供实现、调试和修复方法，不建立第二个任务控制实例。

## 实现与证据

- 新增行为、核心逻辑或高风险缺陷优先定位一个能稳定失败的现有验证；当前写入边界明确包含对应测试时，才补最小失败测试。确认失败由目标问题造成，再做最小实现并确认原失败路径转绿。不能通过`skip`、放宽断言/容差、改期望、无审阅更新快照或屏蔽失败，把测试变化冒充产品修复。
- 文档、纯配置、一次性迁移或无法自动化的改动，先定义可观察结果，再用构建、静态检查、定点核查或人工复验替代，并说明未覆盖风险。
- 项目已有失败项必须与本轮新增失败分开；旧失败不能算通过，也不能冒充本轮缺陷。

复现应绑定实际输入条件、待测版本、环境、配置、状态和关键时序。安全、生产数据、不可逆副作用或高成本路径不为追求“真实复现”越过授权；先使用脱敏样本、隔离环境、静态证据、只读日志或最小模拟缩小根因，确需真实动作时返回原 Worker取得对应决定。

## 根因循环

1. 稳定复现并记录实际现象、最小条件、版本/环境和期望与实际差异；无法稳定复现时先把随机、时间、并发、缓存、网络和共享状态作为待区分变量，不原样重跑到偶然变绿。
2. 沿输入来源、信任与授权边界、状态变化、事务/并发边界、资源所有权和调用链定位最早偏差点，同时核对现有校验、转换、错误处理、超时/取消、重试和共享工具是否已经承担该语义。
3. 一次只验证一个根因假设，先取证，再在最早具有正确职责和正式所有权的位置做最小修复；优先修正或扩展现有入口，不在调用方、异常分支或新工具中复制第二套业务规则。
4. 只有兼容旧行为、隔离外部缺陷或保护回滚确实需要临时分支时才增加受控兜底，并明确触发、退出和验证条件；不得用吞异常、伪默认值、重复重试或“失败就返回成功”掩盖根因。
5. 修复涉及持久化、并发、外部调用或长任务时，验证成功、失败、超时、取消、重复执行和中断后的数据不变量、原子/补偿结果及连接、句柄、锁、临时对象和子进程回收；不能只验证理想成功路径。
6. 重跑原失败路径和受影响回归；确认目标测试真实执行且未被削弱，整理重复分支、临时日志、临时权限、调试开关、无效注释和死代码后再跑关键验证。

禁止连续堆叠多个猜测性修复后统一测试，也不得因为已有补丁暂时转绿就保留两套互相竞争的真值。无法定位时交付当前证据、已排除项和下一条最有价值的验证动作，不用“可能是环境问题”提前结束。

调试日志、抓包、转储、数据库快照和追踪只收集定位根因所需的最小信息，按项目规则脱敏并限制存放位置和生命周期；不得把密钥、令牌、个人数据或生产完整载荷写入日志和临时文件。为排障临时关闭鉴权、证书校验、安全策略、事务、超时或错误处理必须有对应高风险授权、隔离与恢复证据，不能作为普通修复手段。

修复已经造成的数据、状态、文件、缓存、队列或外部副作用不等于修改代码。清理、回填、重放、补偿、迁移和生产修复分别需要准确对象与操作授权；没有授权时只返回受影响现实、建议动作、验证和回滚入口，不顺手“修数据”证明代码正确。

普通构建失败、测试失败和边界内实现调整由原 Worker在原任务内连续修复，不因动作切换返回 PM逐轮续派。需要改变契约、越过写入边界、取得真实权限、执行高风险操作，或达到任务契约或风险证据已经明确的修复上限时，开发方法只形成事实、影响和最小决定项并返回原 Worker。用户已经在当前任务对话时由 Worker直接取得任务内决定并按真实授权更新；影响其他任务、共享对象、主线、资源或安全时才交 PM协调。开发方法不直接建立用户或 PM决定通道，也不强制向用户使用内部灯号。

修复与回测服从用户约定检查点。用户要求逐轮查看、一次只改一个文件或当前修复完成后先确认时，交付本轮证据后停止，不提前进入下一轮猜测、扩大修复或切换后续动作。

## 开发修复助手

修复助手必须从原 Worker取得原任务 ID、失败证据、写入边界、用户检查点、交付物、验证入口和关闭条件；任务 ID只用于证明结果归属，不能让助手成为任务控制实例、改变任务契约或取得原 Worker未明确下放的授权。助手只处理对应失败范围。

完成后把 diff、当前轮自测、残留风险和获授权的正式写回位置或未写原因返回原 Worker；由原 Worker根据检查点和测试授权决定是否把新版本交回原测试实例复测。开发助手不控制 tester、不改变任务状态、不解除检查点、不自行启动测试或运维，也不向 PM或用户建立决定通道。

若实际启动者是测试实例、回报要求绕过原 Worker，或控制关系无法核实，写入前只向原 Worker报告控制权冲突并停止受影响动作；无法安全返回原 Worker时不写入。资源、实例、跨任务冲突、业务契约、验收偏好、权限或高风险决定都先返回原 Worker：任务内用户决定由 Worker在当前任务对话取得，跨任务、共享、主线、资源或安全影响由 Worker交 PM协调。助手和开发 Action都不能直接找用户或 PM形成竞争决定。
