# 开发能力与工程基线

## 触发

只在原 Worker 已经选择开发方法，且当前实现必需的工程事实未知、正式入口不存在、证据已经过期、易变事实需要复核，或需要建立、核验、刷新工程开发基线时读取。本文件只帮助原 Worker补足工程事实，不建立独立身份、决定路径或写入授权。普通只读定位和事实已经充分的清晰局部请求不进入本分支。

本reference是**调查、核验与写回方法**，不保存任何项目的真实技术栈或工程规则，也不能作为项目工程基线使用。四类载体必须分开：

- 当前代码、依赖清单、配置、脚本、CI、工具结果和正式文档是一手事实来源。
- 当前任务已经点名的项目级工程事实文件，是本次优先读取的稳定入口。
- 使用本模板项目文档结构时，标准实际入口由项目事实索引确定为`docs/AI编程协同机制/项目事实/工程开发基线.md`；其他项目沿自己的唯一工程事实入口。
- `docs/AI编程协同机制/模板/工程开发基线模板.md`只提供可选格式，不证明实际文件存在，不保存项目事实，也不能解除调查或写入门禁。

入口定位沿根规则和Worker已经选择的项目文档链进行：任务或当前工作台已经点名有效事实文件时直接定点读取；尚未点名但项目总览登记了入口时使用该入口；只有需要确定标准落点、首次创建或维护契约时才进入项目事实索引。不得为寻找“工程基线”并行预读项目总览、项目事实索引和模板。

## 最低可用事实

围绕当前动作定点调查。只有当前任务确实需要跨任务复用且拥有准确路径写入授权时，才形成或刷新唯一工程开发基线：

- 技术栈、运行时和关键依赖版本
- 目标模块、代码入口、职责与受影响契约
- 已有可复用模块、公共组件、内部服务、共享业务规则及其正式所有者和适用边界
- 目录、命名、格式化、静态检查、必要注释、公共接口文档和代码生成约定
- 已批准依赖、依赖新增或升级门禁、锁文件和生成物正式入口
- 信任边界、认证与资源授权所有者，以及输入校验、参数化查询、命令/路径/URL/模板/上传/反序列化等高风险入口的项目安全API和禁止方式
- 错误语义、异常传播、敏感信息、日志级别、指标/追踪、关联标识和重复上报约定
- 配置来源、必填与默认值、环境变量、密钥/证书、功能开关及环境专用值的正式管理入口
- 接口、数据、状态、事务、并发控制、锁、迁移、重试、幂等、补偿和回滚中当前结果实际涉及的规则
- 外部调用、异步任务、批处理和资源使用的超时、取消、重试/退避、并发/容量上限及连接、句柄、锁、临时对象和子进程回收约定
- 金额/精度、时间/时区、区域/编码、排序/分页、缓存一致性等当前结果实际涉及且容易产生隐式错误的语义
- API/schema、配置、示例、变更说明、迁移/回滚指引和运维入口的正式所有者与同步要求
- 开发可修改的测试代码、fixture、快照、覆盖阈值和配置范围，以及项目禁止`skip`、放宽断言或更新快照的审阅门禁
- 安装、构建、运行和开发自检入口；权威测试命令只引用测试事实域
- Git/worktree 稳定约定；当前分支、工作区和写入边界在本轮现场核验
- 验收入口、已知基线失败、事实来源和最后核验时间

不要为了补全整份档案扫描无关仓库，也不为列出“所有可复用能力”遍历全部代码。只闭合当前业务结果所需事实：先从目标模块的导入、调用方、同目录实现、依赖清单、工程配置和测试定位已有轮子与真实约定，足以判断复用、扩展和验证路径后立即停止。稳定约定后续复用，当前版本、依赖、环境、Git 现场和验收入口在相关动作前定点复核。

## 调查与引导

1. 继承原 Worker已经核验的任务目标、非目标、有效设计或契约、当前放行段、用户检查点、分项授权、事实入口和回源关系，定点读取当前动作最小输入、已有工程事实入口、依赖清单、目标源码及其直接导入和调用关系、相邻测试、认证/数据/配置/资源边界、格式化与静态检查入口、生成脚本、相关CI段和既有工程规则；需要定位跨任务事实入口时才按项目事实索引进入对应事实域。
2. 可从代码、命令、配置或环境查证的事实由原 Worker在当前授权内核对。仅核对条件、入口或计划且当前段未授权执行时只读现有事实，不运行版本探测、构建或测试；需要执行时，直接选择最接近当前验收的入口，不用运行时或包管理器版本命令作前置试探。
3. 技术取舍、真实权限或调查后仍无法确定的项目约定形成最小决定项并返回原 Worker，不由开发 Action直接建立用户或 PM决定通道。
4. 一次只保留一个会阻塞当前实现的最小问题，并给出候选值、来源、影响，以及`确认 / 纠正 / 不知道，请继续调查`路径。直接用户请求由当前智能体询问用户；正式任务由原 Worker按既有控制关系处理。
5. 把一手事实、有权决定者确认的业务或工程取舍和候选分开，把事实、证据、决定项和建议写回内容返回原 Worker；未验证事实不写成正式约定，不能用默认猜测解除业务写入门禁。

## 写回与继续

事实足以支持当前实现后，只有事实确需跨任务复用、唯一实际入口已经确认且原 Worker核对任务拥有该准确路径写入授权时，才能创建或更新项目级工程事实文件，记录适用范围、正式来源、最后核验、刷新触发、维护方、未知与例外；已有正式来源时只登记链接和适用边界，不复制第二份原文。没有授权时只向原 Worker交付已确认事实、证据、建议位置和尚未写回原因。

实际工程事实文件达到项目事实最小契约后，是否在项目总览登记能力入口还需要项目总览的单独写入授权；工程基线写入授权不能推导项目总览、当前工作台、业务源码、测试、配置或Git写权限。不得直接修改 PM经营主线的当前工作台。需要其他任务立即消费时，由原 Worker按现有协作契约报告共享变化，开发 Action不另造事件协议；事实结果返回原 Worker后，由同一 Worker根据当前检查点和授权决定继续开发、切回设计或停止。

已有正式入口和足够新鲜的证据时，只引用稳定约定，并核对本次目标代码实际使用的复用能力、信任/状态/资源边界、受影响契约、依赖、生成和文档入口、质量检查及必要现场，把复核结果返回原 Worker；不重建档案、不重复询问用户，也不让过期基线压过当前代码、配置和工具证据。
