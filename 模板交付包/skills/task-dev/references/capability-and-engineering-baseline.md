# 开发能力与工程基线

## 触发

只在正式项目任务依赖的开发能力为`未初始化/需刷新`，或已有工程基线出现刷新触发时读取。普通只读定位和清晰局部请求不进入本分支。

## 最低可用事实

围绕当前动作定点调查并形成或刷新唯一工程开发基线：

- 技术栈、运行时和关键依赖版本
- 目标模块、代码入口、职责与受影响契约
- 编码、依赖、配置和生成物约定
- 安装、构建、运行、正式测试命令及可用环境
- Git/worktree 约定和当前写入边界
- 验收入口、已知基线失败、事实来源和最后核验时间

不要为了补全整份档案扫描无关仓库。只闭合当前业务结果所需字段；稳定事实后续复用，当前版本、依赖、环境、Git现场和验收入口按刷新触发更新。

## 调查与引导

1. 定点读取项目能力台账、依赖清单、目标源码、配置、脚本、CI 和既有工程规则。
2. 可从代码、命令、配置或环境查证的事实由当前实例自行核对。
3. 只有技术取舍、真实权限或调查后仍无法确定的项目约定才问用户。
4. 一次只问一个阻塞当前动作的最小问题，并给出候选值、来源、影响，以及`确认 / 纠正 / 不知道，请继续调查`路径。
5. 未验证事实标为候选，不写成正式约定；不能用默认猜测解除业务写入门禁。

## 写回与继续

事实闭合后，只写任务授权的正式项目事实路径，记录状态、来源、最后核验和刷新触发；不得直接修改 PM 单写的当前工作台。需要其他任务立即消费时发送`shared_notice`，由 PM 更新控制快照；不等待消费回执，沿原业务任务继续。

已有基线为`可用`且没有刷新触发时，只引用正式入口并刷新本次目标代码、受影响契约与必要现场，不重建档案、不重复询问用户。
