# 工程事实与开发基线

只在当前实现需要读取、建立或修正可跨任务复用的技术栈和工程约定时读取。普通局部修改不进入本文件。

## 1. 当前任务需要的事实

先从项目或子项目文档入口定位目标模块的当前开发约定；标为历史、候选、上一阶段或只读追溯的说明不作为默认工程基线。

定点核对：

- 语言、运行时、框架和关键依赖版本；
- 目标模块、入口、职责和调用边界；
- 现有编码、注释、错误处理和复用约定；
- 安装、构建、运行、lint、格式化和测试命令；
- 配置与环境变量名；
- 当前正式项目、Git原则和生成物边界。

事实优先来自目标模块的依赖清单、源码、配置、脚本、CI和当前可运行命令。开发指南只补充这些入口没有表达的稳定约定；与现场冲突时不能压过一手工程事实。能调查的内容不转问用户。

## 2. 写回工程基线

只有后续任务会复用的稳定内容才写回项目事实索引登记的、与当前子项目和模块匹配的工程文档；架构与核心链路写入对应架构事实所有者。记录来源、最后核验和失效触发。

项目没有现成所有者、当前任务确实需要且拥有写入授权时，才使用项目事实索引的兜底路径；只写已经核验的部分，不复制空模板、不另建初始化任务。

已有基线与现场一致时直接复用。依赖、命令或工程约定变化时，只更新受影响内容，不重扫整个项目。

## 3. 开发连续性

工程事实不足但能够从当前项目确认时，Worker先调查、继续实现并在同一任务中补齐事实。只有目标、真实权限或安全执行必需的信息客观无法取得时，才把缺口返回原 Worker裁决。
