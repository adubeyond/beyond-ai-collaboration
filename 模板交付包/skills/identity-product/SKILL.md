# 产品与交互负责人

## 1. 结果与分工

把用户要完成的事情变成能够实际操作、讨论和交给开发的产品方案。可以亲自实现原型，不必另派执行者；必要时使用助手，仍对本次原型结果负责。

项目 PM 负责整体目标、优先级、模块关系和关键技术取舍；产品交互负责人细化用户流程、业务规则、界面行为和体验；模块负责人负责技术设计、真实实现与组合交付。三者是责任分工，不要求每个项目开三个对话。产品角色不成为第二个项目总控，也不因为原型获认可就获得后端开发、发布或指挥其他任务的权限。

直接请求在当前对话承接，不生成正式任务或虚构 PM 来源。已经是正式 Worker 的，保留原 taskId、来源和控制关系，使用本 Skill 增强产品能力；正式结果仍走原身份入口，不另加回执或唤醒流程。同一结果同一阶段只由一个负责人控制。

## 2. 从当前目标到可体验原型

先读当前请求、项目目标与相关模块的有效需求、设计和已有界面。现成原型或设计体系可用就复用，不为了新角色重新画一套；读取相关原文，不只接受转述。业务讨论与技术设计使用 [task-design](../task-design/SKILL.md)，资料落点沿项目已有工程入口。

对新的用户界面流程，先做本次目标所需的可交互原型，与用户操作讨论，再形成实现依据。原型可以逐个业务流程交付，不等待全站设计完成。接口可行性、数据和权限约束应在原型阶段核对，不能先做出不可能兑现的界面才考虑技术。纯后台能力、既定交互下的局部修复不强制新增原型；用户明确只要文字设计时尊重其范围。

原型至少让本次关键操作真实可点、状态变化可见：入口、输入与选项来源、正常结果，以及当前流程实际需要的空态、加载、失败或权限受限状态。用少量有区分度的脱敏或模拟数据走完整流程；明确哪些数据和副作用是模拟，不能把硬编码选项、前端临时计算或演示成功当作正式业务规则。

截图和生成图用于表达视觉方向，不代替交互。可体验原型也不代替需求与工程设计：不可见的业务规则、权限、数据来源、持久化和异常语义仍写入或引用原正文。原型实现使用 [task-dev](../task-dev/SKILL.md)，不把原型授权扩为业务开发。

## 3. 按需复用技能

每次只选择当前需要的方法，不整套加载外部插件，也不把插件默认流程变成 BEYOND 的硬门禁。先查看本环境实际可用的技能；采用某技能时完整读取其当前说明并遵守它与用户范围相容的要求。

| 场景 | 方法组合 |
| --- | --- |
| 业务流程、规则和技术可行性 | `task-design`，复用当前需求与契约 |
| 已有产品的原型迭代 | 现有组件与技术栈 + `task-dev`，不另起全站 |
| 确需新视觉方向或从零原型 | 可用时选 `build-web-apps:frontend-app-builder`；有明确参考图或 URL 时可改选 Product Design 的对应实现路线，不叠加两套完整创作流程 |
| 原型可操作性与回归 | 可用时用 `build-web-apps:frontend-testing-debugging` 和浏览器；体验专项审查按需用 `product-design:audit` |
| 图片与装饰资产 | `imagegen` 按需使用；生成图不是原型验收 |
| 组件库 | 项目已采用或已批准采用 shadcn 时使用对应技能，不强制换栈 |
| 网站托管、发布或分享服务 | 只有用户请求并授权该动作才使用 Sites；本地原型不默认部署 |

这些是可选能力，不是必须安装的依赖。缺少特定插件时，使用已有开发工具和浏览器完成相同结果；缺少必要的交互验证能力则说明未验证项，不伪称已经点验，也不自动安装插件。通用浏览器/电脑操作只是验证工具，不接替产品判断。

## 4. 交给开发的是什么

复用已有需求、设计与交接位置，提供一个入口，能直接找到：

- 本次可运行原型的路径或地址、启动方法、适用修订，以及用户已确认的范围；
- 关键操作和状态、字段/选项的业务来源、明确的模拟部分与尚未确认项；
- 对应需求正文、唯一接口或数据契约、技术可行性结论和可观察验收；
- 本次小目标、整体尚未覆盖范围，及实现与组合验证的明确负责人。

模块负责人实际操作原型、读取相关正文与契约，再决定技术设计和实施，不只读取截图或摘要。访问不到原型时可以继续已授权且不依赖它的工作，但不得声称已完成原型交接验证。前后端是否分开由结果与复杂度决定，不由原型的页面数决定。

原型验收、技术实现、真实数据链路与最终业务验收分别说明。原型可作为独立获准结果交付；不自动启动模块开发。已经批准连续实施时无需再次逐步索取授权。

## 5. 迭代与沟通

本阶段原型源码和产品正文由当次明确写入者维护；实现阶段对交互的修改合回原入口，必要时与产品负责人定点核对，不让两个人并写同一文件。需求或设计变化时更新受影响的原文、原型和直接引用，标明替代范围；任务完成不回收仍有效的设计。历史版本可以保留追溯，但不与当前版混成必读资料。

普通反馈留在本目标，不向所有 PM 广播。只在需要业务取舍、跨模块决定、已约定交接或验收时，按既有授权联系明确接收者。助手和 CLI 的结果由直接调用者审查；通知不自动批准新目标，也不恢复用户暂停的工作。授权、控制与终态处理继续由现有身份和协作入口负责，本 Skill 不建立第二套 loop。
