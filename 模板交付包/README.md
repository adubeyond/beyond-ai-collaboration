# BEYOND 3.0 模板交付包

本目录是可复制到项目中的正式模板。这里只放通用规则、记录表、模板和 Skills 源码，不放过程性资料。

## 1. 启动步骤

Codex 初始化先读根 [AGENTS.md](AGENTS.md)。本文只负责说明正式模板里有哪些内容，不重复展开初始化校验、接手回执和项目文档链细节。

项目真正开始运行时，按 [AGENTS.md](AGENTS.md) 指向进入最小读入链；默认围绕当前工作台判断，只有需要稳定背景时再补读项目总览：

- `00-模板入口.md`
- `当前工作台.md`
- `项目总览.md`（需要稳定背景时再补读）
- Git 状态
- 当前工作台明确指定的内容

禁止默认读取历史资料、样例事实和未明确指定的资料。

若项目总览、当前工作台或历史记录与当前代码、Git、测试、环境结果冲突，以 [00-模板入口.md](docs/AI编程协同机制/00-模板入口.md) 的反驳机制处理，不得顺着旧记录继续执行。

## 2. Skills 入口

`skills/` 是 Skills 源码目录，不代表运行环境已自动安装。使用时二选一：

- 已安装到当前 AI 工具的 Skills 目录：可直接使用 `$identity-pm`、`$task-dev` 等技术入口。
- 未安装：用对应 `SKILL.md` 文件路径显式触发，例如 `skills/identity-worker/SKILL.md`。

命名采用双层规则：技术名保留英文，展示名和日常说法使用中文。不要把 skill 目录名、frontmatter `name`、`$skill` 入口改成中文。

Skills 源码统一要求 `UTF-8 无 BOM`。`SKILL.md` 文件头前不得混入隐藏字符；否则可能出现“文件在、内容对，但只有部分入口能被工具识别”的识别异常。

这里要分清三件事：

- 中文入口：给人看，说明“这个入口是干什么的”。
- 技术入口：给工具看，说明“底层 skill 名是什么”，所以保留英文。
- 当前工具是否能直接调用：看该工具是否已安装并加载，不看这张表。文档里有 `SKILL.md` 文件，不等于运行环境里已经能直接调起。

用户入口分两层：身份入口回答“我是谁、谁负责结果”，动作入口回答“现在做什么”。身份与动作不能互相替代，但可以组合使用；调用动作 Skill 不改变智能体身份。

身份入口只保留两个：

| 中文入口 | 技术入口 | 推荐触发句 | 用途 |
| --- | --- | --- | --- |
| [PM 总控 / 项目经理](skills/identity-pm/SKILL.md) | `$identity-pm` | `以 PM 总控身份接手当前项目` | 接手项目、判断主线、拆任务、验收、回写 |
| [执行者](skills/identity-worker/SKILL.md) | `$identity-worker` | `以执行者身份接手当前任务` | 领取当前工作台任务，在边界内交付结果 |

动作入口按软件工程阶段使用：

| 中文入口 | 技术入口 | 推荐触发句 | 用途 |
| --- | --- | --- | --- |
| [架构/设计](skills/task-design/SKILL.md) | `$task-design` | `进入架构设计` | 需求、架构、接口契约、边界和验收设计 |
| [开发](skills/task-dev/SKILL.md) | `$task-dev` | `开始开发当前任务` | 先判断能不能开工，再按正式设计、正式契约和已确认边界实现 |
| [测试](skills/task-test/SKILL.md) | `$task-test` | `测试当前变更` | 运行验证、记录证据、输出失败交付 |
| [运维](skills/task-ops/SKILL.md) | `$task-ops` | `检查运维发布风险` | 部署、发布、运行检查、故障处理和回滚建议 |

同一个执行者实例可以被指定为任务控制实例，在授权边界内依次调用多个动作 Skill，把一个业务任务连续推进到收口。普通缺陷优先由同一实例从测试切回开发再回测；只有独立验证、并行收益或写入隔离确有需要时才增加实例。是否新增任务只看是否形成独立业务交付物，不按技能数量机械拆分。

PM 是控制面，不是逐环节审批人。任务开始时一次性确定自动执行路径、允许操作与实例、验收证据、收口方式和红灯条件；执行中只有红灯需要等待裁决，黄灯记录并通知但默认继续。

后台助手不是身份入口。它是 PM 总控或执行者为了加速调查、验证、检索而启动的助手实例；后台结论必须回写给主智能体，由主智能体采纳后才进入当前事实。

日常最稳的触发方式是中文自然语言，例如“以 PM 总控身份接手当前项目”“以执行者身份接手前端任务”“进入架构设计”“开始开发当前任务”“测试当前变更”“检查运维发布风险”。需要强制指定 skill 时，再使用英文技术入口或 `SKILL.md` 路径。

本模板不把 slash 命令作为默认入口。`/PM总控`、`/执行者`、`/设计`、`/开发`、`/测试`、`/运维` 只有在具体工具已做好本地映射时才可直接使用；默认仍以中文自然语言、`$identity-pm` 这类技术入口，或对应 `SKILL.md` 路径为准。

若出现“同一批 Skills 里只有部分能调用”的情况，先查编码、文件头、frontmatter、安装副本与加载缓存，不先判断为用户不会触发或纯平台问题。

新增文档必须能挂到本表、当前工作台文件创建登记表，或已有正式入口的下级索引；否则不得创建。

软件工程事实模板不进入默认冷启动链。只有当前工作台、项目总览、PM 或对应动作 skill 明确点名时才读取，避免把服务器、运维、代码细节变成每轮必读负担。

`模板/`只提供格式，不写项目事实。标准项目能力事实按[项目事实索引](docs/AI编程协同机制/项目事实/README.md)落到`项目事实/`；文件尚不存在时，由 PM 在实际使用该能力的原业务任务包中登记确定路径和创建授权，任务控制实例按对应模板创建、核验并继续原任务，不把项目内部事实文件创建再次转问用户。用户明确禁止文档写入时除外。
