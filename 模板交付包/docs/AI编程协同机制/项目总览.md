## 5. 项目能力初始化台账

本表登记可跨任务复用的项目能力入口。PM 在项目首次接入时只建立空表和已知入口；每个业务任务只初始化自动路径实际会使用的能力，不要求为了“完整”先扫描全项目。任务控制实例发现稳定事实后回写正式入口和核验锚点；进入写文件、测试、发布、生产数据等动作前，只刷新对应的易变事实。

本表只保存跨任务稳定结果，不保存当前实例和调查过程。能力结果状态只使用：

- `未初始化`：没有可信正式入口或最低事实。
- `可用`：正式入口、当前能力最低字段和核验证据齐全，可被后续任务复用。
- `需刷新`：稳定入口仍有效，但命中的事实需要重新核验。
- `阻塞`：已确认缺少真实权限、资源或安全条件，当前能力不能使用。
- `不适用`：项目明确不使用该能力。

`调查中/待用户确认/待现场核验`是当前初始化阶段，只写入[当前工作台.md](当前工作台.md)的 PM 单写协调表；当前任务和实例不得进入本稳定表。

| 能力 | 结果状态 | 正式入口或事实来源 | 稳定责任方 | 最后核验与证据 | 动作前刷新触发 | 缺失时的最小初始化动作 |
| --- | --- | --- | --- | --- | --- | --- |
| 项目与规则 | 未初始化 | 根 `AGENTS.md`、项目入口、稳定业务约束 | PM / 项目维护者 |  | 项目入口、边界或规则变化 | 定位唯一入口并登记，不复制整套规则 |
| 设计与契约 | 未初始化 | `项目事实/产品设计与契约基线.md` | PM 冻结方向；任务实例维护事实 |  | 业务口径、共享契约或验收变化 | 按[项目事实索引](项目事实/README.md)授权原任务创建并核验 |
| 开发与技术约定 | 未初始化 | `项目事实/技术架构与核心代码逻辑.md`、`项目事实/工程开发基线.md` | 任务控制实例维护事实 |  | 写文件、依赖或核心链路变化 | 从代码和配置发现，按标准路径创建或更新 |
| 测试与证据 | 未初始化 | `项目事实/测试与验收基线.md` | 任务控制实例 / 测试执行者维护事实 |  | 待测版本、环境、数据或基线变化 | 建立最小验证入口和证据去向，不发明通过标准 |
| Git 与工作区 | 未初始化 | 仓库、分支策略、HEAD、worktree 和分项授权 | PM 冻结授权；任务实例维护现场 |  | 每次写文件、提交、推送、合流或清理前 | 只读核验现实；`add/commit/push/merge`分别授权 |
| 运维与发布 | 未初始化 | `项目事实/运行环境与服务器信息.md`、`项目事实/部署发布运行手册.md` | 任务控制实例 / 运维执行者维护事实 |  | 发布、停启服务或环境变化前 | 按标准路径形成稳定事实；本次版本和现场另行刷新 |
| 安全与凭据 | 未初始化 | `项目事实/安全与凭据索引.md` | PM 冻结边界；任务实例维护非秘密事实 |  | 使用凭据、启动服务、外部调用或生产动作前 | 只登记来源和边界，不复制密钥 |
| 文档与事件 | 未初始化 | 当前工作台、任务主面、证据区、PM 控制目标和事件位置 | PM / 任务控制实例 |  | 新任务、新执行回合或正式入口变化 | 点名任务主面、事件目标和写回责任；不得只留聊天摘要 |

任务授权中的`动作初始化包`引用本表的稳定入口并补充本任务差异，不重复抄录全部项目事实。台账缺项不是停工命令，而是进入引导式初始化：

1. PM 先在当前工作台登记唯一初始化责任任务；任务实例再定点调查代码、配置、脚本、测试、Git、环境和现有正式文档，不把可调查事实转成用户问卷。
2. 只把业务取舍、真实权限或调查后仍无法确定的事实编译成一个最小决策簇，向用户展示候选值、来源和影响，允许`确认 / 纠正 / 不知道，请继续调查`。
3. 当前任务控制实例按[项目事实索引](项目事实/README.md)把答复、事实来源和核验证据写回唯一正式入口；能现场核验的事实不得只靠口头确认。
4. 达到当前动作最低条件后标记`可用`，沿同一任务继续原业务动作，不返回 PM 重新派单。
5. 同一能力同一时刻只有一个由 PM 协调表登记的初始化责任任务；其他任务消费已确认部分或等待，不重复调查和提问。

`可用`不是永久真理。入口消失、依赖或环境变化、用户纠正、真实证据冲突时改为`需刷新`；现场、代码、Git 和测试事实优先于旧台账。
