# BEYOND 项目文档入口

本文是外置控制仓中的项目文档治理入口，不是 Codex 第一入口。先由控制仓根[AGENTS.md](../../AGENTS.md)或业务项目中已经融合的完整入口判断请求路径；只有项目初始化、项目接手发现工作台缺失/冲突或需要处理事实归位、文档创建更新与历史回收，或者当前任务明确点名本文时，才进入这里。

本文只负责四件事：最小读取项目文档、处理文档缺失与事实冲突、确定事实的唯一落点、控制文档创建与历史回收。身份控制、任务调度和设计、开发、测试、运维方法由各自规则所有者负责。

## 1. 最小项目文档链

进入本文后按顺序判断，不并行预读：

1. 尚未读取工作台或当前需要复核时，读取控制仓`local/当前工作台.md`，恢复当前主线、活动任务、阻塞和下一步；[当前工作台](当前工作台.md)只提供初始结构，不承载团队共享真值。
2. 从`local/projects/<project-id>.md`定位当前业务项目。工作台不足以说明稳定目标、业务边界或项目入口时，再读取`projects/<project-id>/项目总览.md`。
3. 只读取工作台或总览为当前问题点名的任务入口、项目内入口、正式契约或项目事实。
4. 当前判断确实依赖版本、改动归属或写入现场时，再检查 Git。
5. 当前判断依赖代码、测试、配置、服务或环境时，只调查对应的一手事实。

前一步已经足够回答或继续时，不进入后一步。历史、完整文档树、全部项目事实和未来动作材料不在默认读入链。

项目或子项目已有自己的文档入口时，入口只需让后续智能体找到：

- 当前业务真值和稳定规则；
- 当前任务或当前工作面；
- 共享契约与跨线依赖；
- 变化应写回的唯一位置。

旧项目不先重建文档体系。已有 README、设计、架构、接口、测试或运维文档能够承担这些职责时，继续复用并在控制仓对应项目总览或[项目事实索引](项目事实/README.md)登记原入口；只有用户确认迁入控制仓，或混写已经造成冲突并获得调整授权时才移动。

既有项目首次导入或升级时，先运行控制仓脚本只读识别当前路径、Git、根/嵌套`AGENTS.md`和Markdown，再按项目总览、架构、开发、测试、运维、安全和其他专属资料逐组向用户展示可迁移内容。每组只能选择迁入控制仓、保留原位置并登记，或暂不处理；不扫描全部历史，也不自动覆盖或删除：

- 根与嵌套 `AGENTS.md`只保留对应目录的稳定边界、特殊风险和事实入口；通用身份、Skill方法、任务状态与暂停/完成规则回到各自所有者；
- 子项目 README、文档导航和事实索引可以指向当前任务与长期事实，但不得要求“工作台先激活”“PM先派单”或按设计/开发/测试/运维固定阶段读取后才能执行一个已经完整授权的正式任务；
- 事实索引或运维入口声明为当前的直接文件如果把同一环境指向不同主机、SSH别名或凭据来源，只核对这些当前入口并交运维方法用配置与现场确认唯一所有者；失效入口退出当前路径，不扫描未被当前入口引用的历史；
- 仍在使用的直接文件链接和标题锚点必须可达；旧任务、旧阶段和失效入口降级为历史，不继续占用当前读取路径。

兼容核对只在初始化、升级或已发现入口冲突时执行。普通任务直接使用任务点名的项目入口，不重复审查整套文档体系。

升级完成不能只靠模型自述：必须用当前不可变版本附带的安装验真脚本，对六个已安装 Skill逐文件对账，并核对控制仓结构、业务项目根`AGENTS.md`完整内核、项目Hook和身份护栏脚本；任一缺失、残留或内容差异都表示升级尚未完成。已有Hook只能备份后合并，BEYOND Hook首次安装或变化后由用户信任一次。项目覆盖和项目原生规则只能保留在各自受管区域。

## 2. 缺失与冲突

文档缺失不等于事实不存在，也不自动构成停工或创建授权。

| 情况 | 处理 |
| --- | --- |
| 当前工作台缺失或仍是空模板 | 从用户目标、已有正式入口和现场事实恢复当前判断；有授权时建立最小工作台，没有授权时直接交付结果并说明缺口 |
| 项目总览缺失 | 当前任务事实足够时继续；确实缺少稳定目标、边界或入口且已有授权时，才创建最小总览 |
| 项目事实文件缺失 | 先查项目是否已有可信的正式文档；没有承载者且当前任务确实需要时，才按项目事实索引的兜底路径补齐 |
| Git、Skill、服务或环境不可用 | 只说明受影响的判断或动作；不把未知伪装成干净、通过或可用 |
| 多份文档互相冲突 | 回到用户当前决定和一手现场核验，确认唯一所有者后修正引用；不选择最方便的一份继续 |

缺失或冲突不影响当前安全动作时，先继续能够验证的部分。只有它会实质改变目标、业务取舍、验收、必要授权或高风险对象时，才暂停受影响的动作。

纠偏时按内容选择依据：

- 用户目标、业务取舍和验收偏好，以用户当前决定为准；
- 当前实现、版本和运行结果，以代码、Git、测试、配置、数据、服务和环境为准；
- 任务范围、写入边界和真实停止条件，以当前任务契约与平台权限为准；
- 项目文档保存已经确认的稳定事实和当前摘要，发生冲突时回到前三类来源核验。

有写入授权时，把确认后的变化写回唯一正式入口并修正必要引用；没有写入授权时，说明结论、依据、建议落点和未写回原因。旧聊天、旧记录和模型判断只能作为线索，不能冒充一手事实。

## 3. 事实归位

同一类真值只保留一个正式所有者：

| 内容 | 正式位置 |
| --- | --- |
| 稳定项目目标、业务边界、项目结构和长期事实入口 | `projects/<project-id>/项目总览.md` |
| 当前主线、活动任务、负责人、三态、进度、阻塞、正式结果和下一步 | `local/当前工作台.md` |
| 跨任务复用的产品、契约、架构、工程、测试、环境、发布和安全事实 | `projects/<project-id>/项目事实/README.md`登记的项目已有正式文档；没有现成所有者时才使用其标准路径 |
| 内部成员共同维护的团队任务、协同事项和结果 | `shared/tasks/`、`shared/collaborations/`；规则见[团队任务与协同](团队任务与协同.md) |
| 当前任务的目标、边界、进展、纠偏、结果和证据入口 | 正式任务线程；只有复杂长期恢复或独立审计任务才展开任务卡 |
| 复杂业务设计正文 | 当前任务唯一设计文档；任务面只保存版本、结论和链接 |
| API、schema、字段、事件和状态机原文 | 项目已有的唯一正式契约文件，其他文档只登记入口和适用范围 |
| 单次测试、发布、回滚、巡检、事故和原始输出 | 对应任务、测试、发布或运行记录 |
| 空白格式 | `模板/`；模板不承载项目事实 |
| 已结束且不再被活动任务消费的长过程 | 项目已有历史入口或`记录/历史任务回收/` |

状态和团队进度只进工作台；稳定知识写对应事实所有者；执行过程留在任务和证据系统。当前提交、候选哈希、单轮测试、任务进度和时间流水不得长期堆在稳定事实文档中。

密码、私钥、Token、Cookie、验证码等秘密值不得写入项目文档。文档只能记录凭据名称、合法来源、使用边界、轮换入口和责任人。

## 4. 创建、更新与回收

优先更新已有正式位置。新建项目文档前只确认：

1. 当前任务会持续需要它，且已有位置无法正确承载；
2. 文件用途、唯一入口、维护责任和活动消费者明确；
3. 目标路径在当前写入边界内；
4. 完成后的合并、归档或删除方式明确。

这些是 PM 或 Worker 根据现场判断的内部条件，不要求用户填写表单。业务取舍、真实权限或调查后仍不能确定的关键项，才形成一个最小问题。

项目事实索引中的领域用于分类，不代表必须建立同名文件。项目已经存在可信的产品、架构、接口、测试或运维文档时，索引到原位置；只有当前任务需要、没有正式承载者并且内容会被后续任务复用时，才使用索引给出的标准路径。

只有变化会影响后续判断、当前执行或正式验收时才写回。普通解释、临时推断、重复进度和可以随时从代码获得的短期信息不强制沉淀。

维护时遵守：

- 工作台只保留当前摘要和入口，不复制 Git、测试、发布或任务流水；
- 稳定事实只保留当前有效结论、适用范围和必要依据；
- 同一任务、设计或契约只保留一个活动主面，不创建“最终版”“最新版”等平行真值；
- 长日志、截图、原始输出和监控明细放入已登记的证据位置；
- 入口移动、改名或拆分时，同步修正仍在使用的直接引用。

任务完成、取消或被替代后，先把仍有效的产品、契约、架构、工程和运维事实归回各自所有者，再处理任务文档。仍有开发、测试、发布或验收消费者时保持原位；没有活动消费者且引用已经修正时，移入已有历史入口。没有移动授权时，在原位标记“已关闭，只读历史”并从当前工作台移除活动入口，不继续追加。

移动、删除和合并文件仍需相应授权，不能借历史回收丢弃尚未验收的证据、有效契约或用户仍依赖的记录。

完成当前文档恢复或纠偏后，返回控制仓根[AGENTS.md](../../AGENTS.md)或业务项目融合入口已经选择的身份或动作路径继续；本文不生成接手话术、身份回复、任务状态或专业执行流程。
