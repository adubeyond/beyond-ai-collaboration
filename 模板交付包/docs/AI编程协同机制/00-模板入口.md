# BEYOND 项目文档入口

本文是项目文档链入口，不是 Codex 第一入口。项目根存在 [AGENTS.md](../../AGENTS.md) 时，先由它判断请求路径；只有进入项目接手、项目初始化，或当前任务确实需要恢复项目事实时，才读取本文。

本文只负责四件事：提供最小项目文档链、处理文档缺失与事实冲突、确定项目事实的唯一落点、约束项目文档的创建与回收。回复方式、身份控制、专业动作、任务生命周期和 Skills 安装排障不在本文定义。

## 1. 最小项目文档链

进入本文后，按当前问题所需的最小范围读取：

1. [当前工作台.md](当前工作台.md)：先恢复当前主线、任务边界、活动状态、证据和下一步。
2. [项目总览.md](项目总览.md)：只有当前工作台不足以说明稳定目标、业务边界、项目结构或能力入口时再补读。
3. 当前工作台明确点名的任务主面、正式设计、共享契约、项目事实或项目内入口。
4. 当前判断依赖版本、改动归属或仓库状态时，再检查 Git；不是 Git 仓库或 Git 不可用时如实记录。
5. 当前判断依赖代码、测试、配置、数据、服务或环境时，只定点调查对应的一手事实。

这是一条分步判断链，不是并行预读清单。必须先完成当前工作台的读取和充分性判断；尚未确认缺少哪项稳定背景前，不得在同一批次预读项目总览。后续每一步同样只在前一步明确暴露当前判断所需缺口时进入。

当前判断需要技术架构、工程开发、测试、环境、发布或安全等能力事实时，按以下顺序选择入口：

1. 当前工作台或任务已经点名有效的实际事实文件时，直接定点读取该文件，不为确认路径再读项目总览或项目事实索引。
2. 尚未点名实际文件，但项目总览可能登记了对应能力入口时，先单独读取项目总览；找到有效入口后直接进入，不再读取项目事实索引。
3. 项目总览没有登记有效入口，或当前动作需要确定标准落点、首次创建或维护契约时，才读取[项目事实索引](项目事实/README.md)，选择一个直接相关的事实域，再进入对应实际文件或按缺失规则调查现场。

不得为了“可能用到”而在同一批次并行读取项目总览和项目事实索引；索引给出的标准路径也不证明实际文件已经存在或已在当前项目登记。

历史资料、样例事实、完整文档树和未点名的未来动作材料不进入默认读入链。旧聊天、旧日志和旧结论只能作为调查线索，不能替代当前任务与现场事实。

### 1.1 项目或子项目自己的入口

真实项目或子项目可以保留自己的文档入口，例如项目内的 `docs/README.md`。该入口不是 Codex 第一入口，只负责把智能体带到该项目线的当前事实：

- 当前真值面在哪里；
- 当前任务面在哪里；
- 稳定规则、设计或共享契约在哪里；
- 跨线事项和历史证据在哪里；
- 发生变化后应更新哪个唯一入口。

若项目内入口不存在，先使用当前工作台已经点名的实际文件，不让智能体自行遍历文档树，也不为了形式完整立即新建入口。

### 1.2 旧项目的最小映射

旧项目尚未采用模板结构时，不先重建文档体系。只识别现有材料中由哪些位置临时承担：

| 需要恢复的内容 | 临时承载位置 |
| --- | --- |
| 当前主线、状态、阻塞和下一步 | 当前真值面 |
| 当前任务、负责人、边界和验收 | 当前任务面 |
| 跨项目或跨执行线的交接事项 | 接力面 |
| 已完成过程、旧证据和阶段结论 | 历史面 |

同一位置可以暂时承担多个面，但必须能让新智能体直接找到当前主线。只有混写已经造成事实冲突、读取困难或持续维护成本时，才在获得授权后调整承载结构。

### 1.3 任务主面与任务文档族

`任务主面`是单个任务当前契约、状态、证据索引和下一步的唯一责任位置，不等于必须新建一份文件：

- 简单、普通或单轮正式任务，以平台正式任务对话及其初始任务包、正式事件作为任务主面；当前工作台登记真实任务入口，不创建任务卡。
- 跨多个检查周期、需要多人恢复、独立验收或现有任务对话不足以承载的复杂长期任务，才使用项目已有任务系统或按授权创建的任务卡作为文件化任务主面。
- 一个任务同一时刻只认一个任务主面。正式任务对话负责执行时，文件化任务主面保存可恢复的当前真值和证据索引，不能再建立平行任务说明、阶段总结或第二张任务卡。

任务文档按以下关系使用：

```text
当前工作台（只存摘要和入口）
  → 唯一任务主面（控制任务）
      → 复杂设计文档（设计正文）
      → 测试证据位置（单轮验证）
      → 发布/回滚或事故记录（单次生产现场）
      → 交接包（只传当前变化，接收后回到任务主面）
```

任务主面只保存当前可恢复事实、重要控制变化、阶段结论、证据入口和下一步。完整聊天、逐步日志、重复状态快照、长测试输出、监控明细和制品正文留在平台记录或任务登记的证据位置，不复制进任务主面。阶段文档只负责自己的正文，任务主面只登记其路径、版本、当前结论和消费者。

## 2. 缺失处理

文档缺失不等于项目事实不存在，也不自动授权创建文件。先调查现场，再区分“可以从现状确认的事实”和“必须由有权决定者确定的事项”。

| 缺失或异常 | 处理方式 |
| --- | --- |
| 当前工作台缺失 | 从用户当前目标、已有正式入口和现场事实恢复最小当前判断；没有写入授权时只交付缺口与建议落点，不创建文件 |
| 项目总览缺失 | 当前任务事实充足时继续，不把补总览变成前置仪式；确需稳定背景且已获文档写入授权时再创建最小总览 |
| 工作台或总览仍是空白模板 | 不把占位符当项目事实；定点调查能确认的内容，业务目标、验收取舍和真实权限由有权决定者确认 |
| 被点名的正式文件缺失 | 先确认是否已有其他唯一正式承载；没有替代且影响当前结果时，说明最小缺口并按第 4 节处理 |
| Git 不可用或不是 Git 仓库 | 记录事实和受影响的判断，不把 Git 状态补造成“干净”或“已跟踪” |
| 文档链相互矛盾 | 按第 3 节调查和纠偏，不选择最方便的一份继续执行 |

缺失不影响当前安全动作时，继续能够验证的部分；只有缺失会实质改变目标、边界、验收、授权或结果时，才停止受影响的动作。

## 3. 事实冲突与纠偏

不同内容由不同来源决定：

| 内容 | 决定依据 |
| --- | --- |
| 用户价值、目标、业务取舍和验收偏好 | 用户当前明确指令或有权决定者的正式决策 |
| 当前实现、版本、运行状态和实际结果 | 代码、Git、测试、配置、数据、服务和环境的一手证据 |
| 任务范围、写入边界、授权和停止条件 | 当前任务契约与平台真实权限 |
| 已记录的稳定背景、动态状态和历史结论 | 对应项目文档；发生冲突时必须回到前三类来源核验 |

发现文档与现场、文档与任务契约或多份文档彼此冲突时：

1. 明确指出冲突对象、差异和它会影响的当前判断。
2. 围绕当前主要矛盾取得最小充分证据，不为证明某份旧文档正确而选择性调查。
3. 在本轮授权内先按已确认的当前事实处理；无法确认且会改变结果时，只提出一个最小裁决项。
4. 有对应写入授权时，把确认后的变化写回唯一正式入口，并同步必要的引用位置。
5. 没有写入授权时，交付确认结果、证据、建议写回位置和尚未写回的原因，不把聊天结果伪装成已沉淀事实。

写回时分别处理：

- 一手证据确认的事实；
- 有权决定者确认的业务决策；
- 经过实践检验的可复用能力；
- 仍待核对的未知项。

四类内容不能互相替代，也不能把“用户已确认”“模型判断”或“模板可承接”写成“现场已经验证”。

## 4. 数据与文件归位

同一类真值只保留一个正式所有者。现有正式位置能够承载时优先更新，不为同一件事并行建立多份总结、方案、字段表或协作文档。

| 内容类型 | 唯一正式落点 |
| --- | --- |
| 稳定项目目标、业务边界、项目结构和能力入口 | [项目总览.md](项目总览.md) |
| 当前主线、活动任务、动态状态、阻塞、证据索引和下一步 | [当前工作台.md](当前工作台.md) |
| 技术架构、工程基线、测试、环境、发布、安全等稳定能力事实 | [项目事实索引](项目事实/README.md)登记的对应事实文件 |
| 跨任务稳定的产品设计、业务语义、技术架构与核心逻辑 | [项目事实索引](项目事实/README.md)登记的产品设计或技术架构事实入口；已有正式设计保留原位并由事实入口登记链接 |
| 复杂业务任务的活动设计、实施/测试/发布路径和版本变化 | `记录/任务明细/<任务ID>-设计.md`；无正式任务ID的直接用户任务使用`<YYYYMMDD>-<稳定主题标识>-设计.md`，当前工作台或任务卡只登记摘要、版本和唯一链接 |
| API、schema、事件、字段或状态机等共享契约原文 | 现有唯一正式契约文件；产品设计或架构事实只登记业务/架构语义、版本和链接 |
| 单个任务的当前契约、状态、阶段结论、证据索引和下一步 | 唯一任务主面；简单任务为平台正式任务对话，复杂长期任务为项目已有任务系统或按授权创建的任务卡 |
| 单个任务的长日志、原始测试输出、截图、导出和其他详细证据 | 任务契约登记的唯一证据位置；任务主面只保存结论、版本锚点和链接 |
| 跨项目或跨执行线的正式交接 | 当前工作台的接力面或已登记的唯一协作入口；交接包只保存本次移交差异，不复制任务主面 |
| 已完成、取消、废弃或被新结论替代且已无活动消费者的任务主面、长过程与复杂设计 | `记录/历史任务回收/<YYYY-MM>/`或项目原有历史入口；保留原文件名、最终处置、替代入口和最后证据 |
| 格式和空白结构 | `模板/`；模板不承载真实项目事实 |

### 4.1 何时更新

本轮确认的变化会影响后续智能体判断、当前执行或正式验收时，应在已有授权内更新对应唯一入口，例如：

- 当前主线、边界、状态、阻塞或下一步发生实质变化；
- 稳定业务决策、共享契约或数据语义发生变化；
- 代码、环境、测试、发布或运维事实已经改变；
- 原正式入口、文件位置或维护责任发生变化。

普通解释、临时推断、未改变项目事实的对话和可以从代码直接得到的短期过程，不强制写入文档。任何写回都受本轮文件写入授权约束。

### 4.2 新建项目文档

本节只约束项目文档、证据和记录文件；业务源码、测试和配置文件由当前任务契约与对应专业方法约束。

新建项目文档前，任务控制者在上下文中确认：

1. 它解决什么持续存在的问题；
2. 为什么现有正式位置不能承载；
3. 谁会使用和维护；
4. 唯一路径以及从哪里进入；
5. 何时更新、合并、归档或删除；
6. 本轮是否明确拥有该路径的写入授权。

[项目事实索引](项目事实/README.md)已经给出标准路径时，使用标准路径，不把内部文件位置重新交给用户设计。缺少业务取舍、真实权限或其他无法调查的关键信息时，只询问一个会改变结果的最小问题。

没有写入授权、路径越出项目、用途重复或生命周期不清楚时，不创建文件；先交付能够安全完成的结果和明确缺口。创建文件不自动获得 Git 暂存、提交、推送、发布或其他权限。

复杂业务设计命中跨模块、跨执行线、跨检查周期、共享契约/迁移/关键状态，或需要由开发、测试、发布独立消费时，活动设计的模板标准路径是`记录/任务明细/<任务ID>-设计.md`；任务创建时应同时登记计划归档位置`记录/历史任务回收/<YYYY-MM>/<原文件名>`。当前工作台和任务卡只能保存摘要、版本和链接，不能用上下文或几个表格字段替代独立设计正文。同一任务只保留一个活动设计主文档，在原位递增版本；不得创建`最终版/最新版/修改版`形成平行真值。

### 4.3 更新与回收

当前工作台只保留当前判断需要的内容。当旧任务、旧证据或旧阶段结论已经妨碍新智能体直接找到主线时，将长过程移动到已有历史入口，只在当前工作台保留结论、证据位置、遗留风险和仍需执行的事项。

回收不以固定行数、任务数量或屏幕长度自动触发，也不为了文档整齐重建目录。判断标准是：当前入口是否仍能准确、直接地服务当前行动。

任务文档从创建时就登记持续使用者、唯一活动入口和计划归档位置；没有明确使用者或回收方式时不新建。维护期间遵守：

1. 当前状态、边界、版本、阶段结论和下一步原位更新，不按回合重复追加同义快照。
2. 完整事件、长日志、测试输出、截图、监控和制品进入已登记证据位置，任务主面只留稳定锚点和结论。
3. 阶段结束只更新当前阶段结论和下一消费者，不把设计、开发、测试、发布正文复制回任务主面。
4. 用户检查点、跨阶段交接或恢复前，删除已被当前结论替代的临时说明；仍有审计价值的旧内容移到现有历史入口或外部证据，不堆在当前正文。
5. 任务完成、取消或被替代后，先归位稳定事实，形成最终结果、证据、遗留事项和替代入口，再停止向活动文档追加内容。

移动、删除或合并文件必须另有对应授权，并先修正仍然有效的引用；不能用“回收”名义丢弃尚未验收的证据、有效契约或用户仍依赖的历史。

独立设计文档不能在设计阶段结束时立即归档。只要开发、测试、发布或验收仍在消费，它就保留在活动任务明细中。业务任务完成、取消或被正式替代后，先把稳定产品、契约、架构和工程事实归回各自唯一长期入口，在设计文档记录实际结果、差异、证据和替代入口；确认没有活动消费者并修正引用后，才移动到`记录/历史任务回收/<YYYY-MM>/`。归档只冻结历史，不让历史文件继续拥有当前设计权。

文件化任务主面、设计文档、发布/事故记录和交接包在完成消费后使用相同回收门禁：仍有活动消费者时保持原位；没有活动消费者且引用已修正时，按准确路径授权移动到历史入口。暂时没有移动授权时，在原位标记`已关闭，只读历史`并从当前工作台移除活动入口，不继续追加；后续返工建立新的当前任务版本或活动主面并引用该历史，不在归档文件中继续写。

## 5. 离开本文前的检查

完成项目文档恢复或纠偏后，只确认与当前请求相关的事项：

- 当前主线、主要矛盾和下一步是否有事实依据；
- 目标、现场事实、任务契约和文档记录是否仍有未说明的冲突；
- 当前使用的事实是否来自唯一正式入口或一手证据；
- 需要写回的变化是否已在授权内落位，或已明确说明未写回原因；
- 下一步应返回哪个身份或动作路径。

本文检查完成后，返回 [AGENTS.md](../../AGENTS.md) 已选择的身份和动作路径继续，不在本文生成固定接手回执、身份回复或阶段状态。
