## 2. 首次创建授权

正式项目任务实际需要某项能力、对应标准文件尚不存在时，PM 在原业务任务包中直接登记：

```text
允许新建文件：是；类型=标准项目事实文件
目标路径：项目事实索引规定的唯一标准路径
创建原因：初始化当前业务任务必需的项目能力
使用者：对应动作 Skill、后续任务和 PM 验收
入口：本索引 + 项目总览能力台账
回收方式：项目持续保留；事实失效时更新或标历史，不随单任务删除
```

这是使用模板管理正式项目的内部文档动作，不扩大业务源码、Git、服务器、生产、数据、不可逆或外部费用授权；不自动授予`git add/commit/push`。用户明确禁止文档写入，或目标路径越出当前项目时，才形成最小红灯。

## 3. 写入与控制所有权

- PM 在[../当前工作台.md](../当前工作台.md)的项目能力初始化协调表登记唯一初始化责任、依赖和消费结果；任务实例不得直接修改 PM 单写表。
- 任务控制实例只写本任务主面和已授权的项目事实文件，记录事实来源、核验、适用范围和刷新触发；不能把聊天判断写成现场事实。
- 任务控制实例完成最低初始化后可沿原任务继续，不等待 PM 更新稳定台账；同时按任务事件规则回传事实文件和证据锚点。
- PM 消费事件后更新[../项目总览.md](../项目总览.md)中的稳定能力结果状态、正式入口和最后核验，并关闭或刷新动态协调行。
- 其他任务只认 PM 已登记的初始化责任和可读事实文件；发现冲突时发送`shared_conflict`，不另建第二份项目事实。

## 4. 拆分与维护

- 首次只创建当前动作需要的文件，不为完整度一次生成全部空文件。
- 一个能力已有正式文件时持续更新，不按任务复制新版本；历史过程进入记录区。
- 文件过大时可以在同一能力目录下拆分专题文件，但本索引和项目总览只保留唯一主入口。
- 真实代码、Git、测试、服务和环境结果与项目事实冲突时，先按实际结果纠偏，再更新事实文件和刷新状态。
