# 项目事实索引（项目级模板）

> 初始化后，每个业务项目在控制仓`projects/<project-id>/项目事实/README.md`维护自己的正式索引。本文件只提供结构，帮助后续任务找到跨任务复用的稳定知识；它是新PM首次全量接手的默认索引，但不是任务启动许可证或固定文件清单。

项目已有可信的 README、设计、架构、接口、测试或运维文档时，直接登记原路径，不复制到本目录。`../模板/`只提供格式，不承载项目真值。

正文应讲清哪些软件工程内容、如何连接业务与实现，见[工程资料指南](../工程资料指南.md)；固定入口、任务位置及缺失资料的可选目录见[目录怎样组织](../工程资料指南.md#目录怎样组织)。以下类别是内容分工，不要求每类新建文件；大型项目由当前主文档再链接具体专题，不把全部历史和原始证据列为 PM 必读。

## 1. 实际事实入口

真实项目在“项目实际入口”列登记已有文档、适用对象或实现分支及原文章节。一个文件包含多条不同路径时分别定位，保持原文所有者，不另抄通用摘要；单一内容直接链接文件即可。缺少来源如实留空，兜底路径只是建档选项，不要求填满或创建空文件。

实际入口使用从本索引位置可打开的 Markdown 文件/章节链接；按索引所在目录计算相对路径，不按业务项目根计算。文字提及和代码块示例不代表正式入口。登记时区分当前主事实、相关专题与待核对/历史资料。当前主事实包括已确认目标、仍有效的已定方案（含尚未实施）及已核实的当前实现，三者分别标明；新 PM 全局读入其正文，详细专题按需要下钻。

| 事实领域 | 项目实际入口 | 只负责 | 无现成所有者时的兜底路径 / 格式 |
| --- | --- | --- | --- |
| 产品、需求与设计 | <已有模块需求/设计及共享契约入口> | 需求讲用户结果、流程和业务边界；设计讲实现方案；分别标明目标、已定方案与当前实现 | 可选 `模块/<模块>/需求.md`、`设计.md`，小模块可合文件分节；[内容参考](../模板/产品设计与契约基线模板.md) |
| 业务流程与关键决策 | <已有流程、规则或关键决策正文/章节> | 用户到业务结果的完整链路、仍有效的决定及理由、已替代口径的指向 | 优先复用产品/设计正文，不要求独立文件 |
| 产品交互与视觉 | <已有页面清单、交互方案、设计资产入口> | 用户操作、页面状态、角色可见性、业务字段与界面关系、组件和视觉约束 | 优先复用产品正文及设计资产；无界面的项目不适用 |

一个实际文件可以承担多个相近领域；同一适用范围内的同一事实不能同时拥有多个正式正文。表内兜底文件名不是固定路径，已有有效正文继续原位；新建时按指南选所属主题。接口、schema、字段、事件和状态机已有正式契约时，本索引只登记入口和适用范围，宽泛的产品或架构基线不能覆盖更具体的契约。任务引用这些正文的修订、章节和本轮范围；本索引不收录每轮派单、进度和回报。

本索引只组织项目特有事实，不成为第二套运行规则。PM/Worker职责、工作台激活条件、Action Skill方法、通用测试或发布流程继续由对应规则所有者负责，不复制到项目总览、事实索引或领域事实正文。

## 2. 读取与缺失处理

- 新PM首次全量接手时，读取本索引登记的全部当前主事实正文，建立项目全貌；只读当前正式所有者，不扩展历史、归档、候选、全部Worker聊天或原始证据。
- 已有上下文的PM只刷新本轮受影响的事实；正式任务从点名入口沿直接相关依赖补读，足以判断、实现和验收即停止，不重复全量接手。
- 当前动作需要某类事实时，先从“项目实际入口”或其总索引定位当前子项目、模块和专题的正式所有者，再定点读取，不扫描整个目录。
- 当前任务不需要的事实不读取；入口空白或文件不存在也不阻塞普通任务。
- 已被替代或不再适用、标为历史/归档/仅供追溯，以及尚未确认的候选文档，不能因为内容更全而成为当前所有者；仍有效的前期设计和依赖继续按当前范围使用。
- 仍有效的已定阶段方案属于当前设计依据，不能仅因尚未实现而归入历史；其中目标、方案和已实现事实分别标识。
- 技术栈、构建和测试命令以当前依赖清单、源码、配置、脚本、CI和可运行入口为准；说明文档负责索引与补充约定，不能覆盖这些一手事实。
- 实际入口失效时，先调查项目是否已有其他可信承载者，确认后更新索引。
- 没有承载者、当前任务确实需要、内容会被后续任务复用且已有对应写入授权时，才使用兜底路径创建最小文件。
- 无法从用户决定、代码、配置、Git、测试或真实环境确认的内容写`待核对`，不得为了填表猜测。
- 用户禁止文档写入时，只在当前结果中说明已经确认的事实和建议落点。

项目事实没有`未初始化 / 需刷新 / 可用`运行状态。是否能够继续，只看当前任务是否已经拥有必要事实和真实安全条件。

## 3. 事实准入与安全

长期事实必须能够看出适用范围、事实来源、最后核验时间以及什么变化会使它失效；可以在文件或章节统一说明，不要求每条结论重复一套字段。

- 用户确认负责业务目标、语义、取舍和授权，不能替代代码、测试、服务器或生产现场核验。
- 当前分支、提交、候选版本、任务进度、单次测试、单次发布和时间流水不属于长期事实。
- 当前实现与旧技术记录冲突时核验一手事实；实现与已确认业务目标不一致时保留这个差距，不通过改需求文档把缺陷合理化。纠正与渐进维护按[项目文档入口](../00-模板入口.md)执行。
- 密码、私钥、Token、Cookie、验证码和其他秘密值不得写入索引或事实文件；只记录合法来源和使用边界。

## 4. 维护责任

| 真值面 | 维护责任 | 只负责 |
| --- | --- | --- |
| 当前项目`项目总览.md` | PM | 稳定目标、边界、项目结构和长期事实入口 |
| 控制仓`local/当前工作台.md` | PM | 主线、正式任务、负责人、任务状态、进度、阻塞和正式结果 |
| 本索引及其实际事实入口 | 对该事实有写入授权的当前执行者 | 已核验、可复用的稳定知识和入口 |
| Git、测试、任务、发布和运行系统 | 对应任务或系统 | 当前版本、执行过程、单次结果和一手证据 |

执行者确认当前任务所需事实后直接继续业务，不等待为了文档完整而补齐其他领域。变化影响项目方向、其他活动任务或共享契约但仍可继续时留在任务结果；已经形成真实冲突而无法继续时以当前正式任务的暂停 final收口，不另建过程直发路径。

## 5. 更新与历史回收

- 同一事实持续更新同一正式入口，不按任务复制“最新版”。
- 稳定事实只保留当前有效结论和必要依据；候选、过程、失败尝试和旧状态进入任务或历史记录。
- 当前仍生效的阶段目标、实施依赖和决定理由保留在原方案；方案被替代时记录新的正式入口，不把未实现误写成已完成或已废弃。模块需求与设计不随单个任务完成而归档；任务状态不决定工程正文是否仍然有效。
- 文件确实过大且专题有独立消费者或不同更新节奏时才拆分，并由原入口维护索引。
- 入口移动、改名、拆分或失效时，同步更新本索引、项目总览和仍在使用的直接引用。
- 事实变化只复核受影响内容，不全项目重扫。
