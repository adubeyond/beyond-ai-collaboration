# 智能体交接包

> 只在替换任务控制 Worker、跨任务移交复杂成果，或需要保存非 Git运行现场时使用。普通 Skill切换、设计—开发—测试循环、低频进展和同一 Worker连续执行不使用本模板。

优先使用正式任务线程、Git提交和当前工作台。现有入口能够承载时不创建独立交接文档。

## 1. 交接双方

| 字段 | 内容 |
| --- | --- |
| 来源任务 / Worker | <任务、正式 thread> |
| 接收任务 / Worker | <任务、正式 thread或待接收> |
| 交接对象 | <代码、契约、数据、服务、运行现场或其他> |
| 交接原因 | <替换 Worker、跨任务依赖、长观察或其他真实原因> |

## 2. 当前事实

```text
业务目标：
已经完成：
尚未完成：
正式项目与当前 Git提交：
服务 / 数据 / 环境现场：
当前一手证据：
```

只引用原始制品、Git、正式契约和真实运行入口，不复制完整聊天和无关历史。

## 3. 接收边界

```text
接收方要完成的结果：
允许读取和修改：
明确不做：
验收标准：
四类暂停红线：
正式写回位置：
```

交接包不能扩大原任务授权。生产、真实数据、不可逆动作、远端 Git和费用仍需原有明确授权。

## 4. 恢复入口

| 对象 | 当前值 | 接收后的第一项核验 |
| --- | --- | --- |
| 正式项目 / Git | <路径、分支、提交、dirty状态> | <复读 Git和范围> |
| 代码 / 文档 | <文件与版本> | <复读关键差异> |
| 测试 | <命令、原失败和当前结果> | <复测必要路径> |
| 服务 / 环境 | <状态、日志和健康入口> | <健康与业务检查> |
| 数据 | <目标对象、检查点和事务状态> | <只读核验> |
| 临时资源 | <路径、进程、制品或账号> | <归属和生命周期> |

## 5. 接收与关闭

接收方必须先核对当前事实，不把交接摘要当作一手真值。确认可接续后在当前工作台更新负责人和进度。

交接闭环条件：

- 接收 Worker已经明确；
- Git、服务、数据和临时资源现场可解释；
- 新 Worker已完成第一项核验；
- 来源 Worker不再继续写入；
- 最终结果仍回到原任务或明确的新任务正式目标。

如果来源、目标、现场或控制责任冲突，停止冲突写入并交给 PM；不另建平行控制 Worker。
