# 技术架构与核心代码逻辑模板

> 本模板只提供`项目事实/技术架构与核心代码逻辑.md`的可选格式，不保存当前项目事实。实际文件只记录从代码、配置、正式契约、运行证据、既有架构决策或有权决定者核验的跨任务稳定架构事实；未知项保持未知，不把候选方案、当前任务边界或空模板固化成架构。

实际架构入口负责系统边界、架构约束与质量目标、稳定模块职责、核心链路、数据/状态关系以及安全修改必须理解的核心代码逻辑。技术栈、依赖和工程规则归工程开发域；产品行为和共享业务语义归产品设计与契约域；权威测试入口归测试域；环境和部署步骤归各自事实域。本文件只登记相邻真值的链接和当前架构为何依赖它们。

## 11. 维护与使用规则

- 首次创建只写当前任务已经核验且确需跨任务复用的架构事实；已有正式架构或契约时优先登记链接，不复制第二份原文。
- 设计候选、当前任务范围、当前不允许修改、临时实施切片、动态风险和单轮测试结果不进入实际架构事实文件。
- 架构设计按当前风险裁剪；没有涉及的质量维度不必制造内容，但已经涉及的安全、状态、失败、容量或迁移风险不能因为模板可裁剪而省略。
- 实施反馈推翻模块边界、主链路、数据所有权、质量目标或核心逻辑时，先停止依赖旧设计的动作，核对一手事实和影响，再在准确授权内更新唯一正式入口。
- 实际架构文件写入授权不能推导出产品契约、工程基线、源码、测试、Git、环境、部署或其他文件的写入授权。
