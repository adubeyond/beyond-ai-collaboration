# 工程开发基线模板

> 本模板只提供`项目事实/工程开发基线.md`的可选格式，不保存当前项目事实。实际文件只记录已经从代码、依赖清单、配置、脚本、CI、正式文档、工具结果或有权决定者核验的跨任务稳定工程事实；未知项保持未知，不按通用经验补全，也不把空模板整份复制成项目事实。

实际工程基线是工程开发事实域的唯一主入口，但不是所有技术细节的第二份副本。依赖版本、代码、配置、生成脚本、schema和其他已有正式来源继续保有原文；本文件记录适用范围、正式入口、所有者、核验锚点和刷新条件并链接过去。

## 10. 维护与使用规则

- 当前动作已经点名有效工程基线时，只读取直接相关章节；没有明确缺口时不为完整性展开整份文件。
- 实际文件缺失或内容不足时，先从目标代码、直接依赖、相邻实现/测试、配置、脚本和相关CI段定点调查。只有事实需要跨任务复用且准确路径获得写入授权时，才创建或更新实际基线。
- 只记录当前已经核验且会被后续任务复用的部分。未知项保持未知，不创建能力状态机，也不把调查过程、责任任务或动态阻塞写入稳定基线。
- 只有会改变目标实现、写入边界、正式契约、依赖选择或验收的事实缺口才停止受影响开发；其他未知项保留为实现或验证中的定点核对项。
- 现场代码、配置、依赖、Git、工具和运行证据与本文件冲突时，先按当前一手事实处理；获得相应写入授权后只更新受影响事实、来源、最后核验和刷新条件。
- 单次任务的diff、候选提交、当前测试结果、阻塞、实例状态和长日志留在任务主面或证据区，不进入稳定工程基线。
