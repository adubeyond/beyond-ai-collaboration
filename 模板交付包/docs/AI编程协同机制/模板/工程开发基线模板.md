## 6. Git 与工作区约定

| 项目 | 约定 | 事实来源 | 动作前核验 |
| --- | --- | --- | --- |
| 主分支/任务分支/正式工作目录/既有 worktree现场/生成物 |  |  |  |

BEYOND 不创建或推荐 worktree；既有 worktree只作为当前 Git现场记录。同一目录内，任务拥有路径和副作用不重叠时可以并行编辑、测试；共享对象只串行受影响动作。同一 Git工作区的索引、HEAD和历史动作串行，每次精确暂存任务路径。`add/commit/push/merge/清理`分别服从任务授权；本基线不能预授权 Git 写操作。

## 8. 维护规则

- 缺失项先从项目事实自动调查；只有工程取舍或调查后仍不明确的事实才引导用户确认。
- 当前动作必需项未闭合时不得修改业务源码或依赖；完成写回和核验后沿原任务继续。
- 已有可信记录时只刷新命中的版本、模块、命令或 Git 现场，不重复扫描整个仓库。
- 单次任务的提交、diff 和测试结果留在正式任务线程或 Git，不复制进本基线。
