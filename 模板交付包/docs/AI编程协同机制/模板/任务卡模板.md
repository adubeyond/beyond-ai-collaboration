# 任务卡

> 任务卡只服务于确实需要跨多个观察周期恢复、保存非 Git 运行现场或独立审计的复杂任务。普通正式任务使用平台任务线程和[当前工作台](../当前工作台.md)，不创建任务卡。

任务卡不是第二个任务台、权限审批单或事件流水。PM在当前工作台管理团队状态；唯一 Worker维护本卡中的任务事实和证据入口。

## 1. 任务约定

| 字段 | 当前约定 |
| --- | --- |
| 业务结果 | <一个可独立验收的结果> |
| 范围与明确不做 | <允许范围 / 排除范围> |
| 验收标准 | <逐项可判定标准> |
| 正式项目、目标与交付 | <项目路径 / 提交、文档、版本或运行对象> |
| 项目事实入口 | <技术栈、契约、测试、服务器或发布手册；没有则按需调查> |
| 暂停红线 | <业务决定、高风险动作、共享冲突、外部资源> |
| 唯一 Worker / 正式 thread | <负责人 / 平台任务 thread> |
| 业务状态 | 进行中 / 已暂停 / 已完成 |

业务状态只使用三态。当前动作、测试结果、消息、PM采纳和实例存活不形成新状态。

## 7. 历史回收

任务完成后：

- 当前工作台只保留任务摘要、正式结果和证据入口；
- Git、正式设计、测试记录和生产记录各自保存自己的真值；
- 本卡只保留最终约定、关键纠偏、暂停恢复点和完成剖面；
- 逐命令日志、重复摘要和已经失效的中间过程删除或进入既有历史回收位置；
- 不为归档再创建第二份总结文档。
