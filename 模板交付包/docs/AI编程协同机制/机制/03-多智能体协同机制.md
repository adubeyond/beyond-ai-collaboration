# 多智能体共享运行协议

本文只定义 PM、Worker 和协作实例之间的公共接口，用来防止重复控制、共享写入冲突、接力丢失和无意义回调。它不是启动入口，也不负责 PM、Worker 或设计、开发、测试、运维的内部做法；没有真实多智能体关系时不读取。

## 1. 什么时候读取

先由根 [AGENTS.md](../../../AGENTS.md) 判断请求并建立身份，再由身份 Skill 按需进入：

```text
PM：两个以上正式任务、共享对象、跨任务接力、协作资源或跨任务冲突
    → 本协议 → PM多任务协同作业包
Worker：协作实例、独立测试实例、共享写入、跨任务接力或多实例闭环
    → 本协议 → Worker协作与返工作业包
```

下列情况不进入：

- PM 只接手项目、回答问题或建立一个普通任务。
- 同一 Worker 连续设计、开发、测试、运维，或自行调查、修复和复测。
- 用户只纠偏当前任务，或单任务正常领取、暂停、恢复、交付和收口。
- 只是多开窗口、对话或工具，实例之间没有依赖、共享对象或结果接力。

读取本文不会建立身份、创建任务、增加实例或扩大授权。关系结束后回到各自身份路径；本文变化或出现新的协同关系时再读。

## 2. 谁负责什么

任务回答“交付什么”，身份回答“谁对结果负责”，Skill 回答“现在用什么方法”，实例回答“哪个真实对话或环境在执行”。切换 Skill 不产生新任务、新身份或新控制实例。

共同规则：

1. 一个业务任务同一时刻只能有一个任务控制实例，通常是原 Worker。
2. PM 负责多任务关系、共享冲突和主线，不接管 Worker 的任务内执行。
3. Worker 对原任务结果负责，协作实例只做获授权的局部动作。
4. 协作实例不能改变任务目标、边界、验收、授权、检查点或终态。
5. 只有出现独立业务结果才新增正式任务；只有独立证据、隔离或并行收益确实值得时才新增协作实例。

具体规则仍回到唯一所有者：项目事实与文件归位看 [00-模板入口.md](../00-模板入口.md)，PM 内部治理看 [`identity-pm`](../../../skills/identity-pm/SKILL.md)，Worker 生命周期看 [`identity-worker`](../../../skills/identity-worker/SKILL.md)，专业方法看对应 Action Skill，[当前工作台](../当前工作台.md)只保存 PM 已消费的控制快照。本文不重复平台线程创建、Git/worktree、文件创建、发布或回滚步骤。

## 3. 协作与接力接口

### 3.1 正式任务与协作实例

PM 交给 Worker 的信息必须能唯一核对：

```text
任务ID与版本 / 业务结果 / 唯一任务主面 / 唯一控制实例或待领取
工作区与读写边界 / 放行段与检查点 / 验收和证据入口
依赖与共享对象 / PM紧急回源入口 / 停止条件
```

Worker 按自己的接单规则核验；缺少会改变控制权、授权、结果或验收的信息时，只停止受影响动作并返回缺口，不能补造事实。跨实例消息必须带当前任务和版本；旧证据可引用，旧授权和未执行动作不自动继承。

协作实例必须依附已有任务，由原 Worker 启动、核验、采纳和回收。启动前说明：

```text
原任务、版本和控制实例 / 局部目标与明确不做 / 输入与事实来源
读写边界和隔离条件 / 输出与证据要求 / 返回位置与回收条件
```

结果先回原 Worker；未经核验不能进入主线或证明任务完成。只有 PM 能代为启动或关闭时，PM 只完成已授权的资源动作，不接管路由、修复、等待或消息转发。

### 3.2 共享对象与跨任务接力

共享文件、契约、数据范围、环境、服务和生产对象只能有一个正式所有者。开始前明确：

```text
共享对象 / 所有者 / 当前版本或哈希 / 各任务读写边界
兼容义务 / 验证入口 / 合并责任与顺序 / 冲突时停止范围
```

非所有者只引用正式来源。多个任务需要修改同一对象时，先确定唯一写入者或互不重叠的写入边界；未闭合前不得并发写入。

跨任务接力至少包含：

```text
发起与接收任务、版本、控制实例 / 交付目标与输入制品
已确认事实、证据、共享对象与双方边界 / 风险与未完成项
验证入口 / 返回位置 / 关闭条件
```

接收方明确`接受 / 有条件接受 / 拒绝并说明缺口`。接力不转移授权，也不能静默改变任务目标、验收、检查点或共享对象所有权；改变跨任务优先级、共同资源或生产授权时交 PM 或用户裁决。

## 4. 事件、用户指令与 PM 负载

事件只传控制事实，不汇报逐步过程。最少带：

```text
事件ID与类型 / 任务ID、版本、回合和真实来源 / 当前状态
事实与证据入口 / 影响和已采取动作 / 决定者、下一步与停止条件
```

重复事件按 ID 幂等消费；旧版本或乱序事件不能覆盖新事实。

| 等级 | 处理 |
| --- | --- |
| **任务内处理，不回调 PM** | 授权内切换方法、普通调查、实现、失败定位、修复、复测，以及尚无跨任务影响的助手中间结果。 |
| **聚合知会，不等待 PM** | 非阻塞领取或恢复、`yellow/shared_notice`、已闭合接力和协作回收；还包括用户在正式任务对话中已经明确作出的本任务目标、契约、验收、检查点或授权纠偏，前提是不影响其他任务、共享对象、主线、共同资源、安全或生产。 |
| **终态回源，不等待消费回执** | `paused / failed / candidate_completed / completed`是每执行回合唯一终态，不进入普通聚合收件箱。按任务创建时冻结的`定向终态消息 / 平台完成观察器 / 明确人工消费`模式送达来源 PM；送达只证明事件可达，不等于 PM 已消费、裁决或采纳。 |
| **立即回调并停止受影响动作** | 来源不明的阻塞领取或恢复、`cancelled`、重复任务控制实例、`red/shared_conflict`、共享所有权或版本冲突；当前没有有权决定者、无法形成有效任务版本，或影响其他任务、主线、共同资源、安全、生产及不可逆风险。 |

聚合事件进入任务主面、平台事件或正式收件入口，由 PM 批量消费；Worker 不等待纯确认。终态按冻结模式回源后立即释放当前执行回合，不等待消费回执；明确人工消费时，完整终态必须保存在任务契约已经登记的正式任务最终结果或持久终态入口，由已登记消费者按触发和游标读取。立即回调只停止受影响部分，独立且安全的任务继续；PM 应裁决或指出缺口，不回复无意义的“收到”。

用户可以直接在正式任务对话下达指令，不必回 PM 驱动节点：

- 仍在当前版本内：Worker 直接执行。
- 用户已明确改变本任务，且不影响共享现实：Worker 在真实授权内建立新版本、更新正式入口和验证范围后继续，只做聚合知会。
- 仍是建议、决定权或授权不成立：停止受影响动作，请有权决定者确认。
- 影响其他任务、共享对象、主线、资源、安全或生产：立即形成跨任务事件；PM 负责协调，业务取舍和高风险授权仍由用户决定。

## 5. 冲突如何恢复

发生重复控制、共享写入、版本、兼容或接力冲突时：

1. 停止受影响的新写入、合并、发布或扩大动作，保留现场和证据。
2. 核对任务、版本、真实实例、共享所有者、当前哈希和正式入口。
3. Worker 处理任务内恢复；PM 处理控制关系、依赖和共享所有权；用户处理业务取舍与高风险授权。
4. 修正唯一正式来源并复验，只恢复冲突已解除且授权仍成立的动作。
5. 用新事件记录结果，不用重开实例、复制文件、覆盖记录或让 PM 代传话绕过冲突。

## 6. 什么时候退出

以下结果全部成立后退出本协议：

- 协作结果已经回到原 Worker，并被核验、采纳、拒绝或明确留待处理。
- 接力已经由接收方确认，共享对象的所有者、版本、合并结果和证据一致。
- 冲突已经解除，剩余风险、责任和决定者清楚。
- PM 已消费需要进入主线的摘要，无后续责任的协作实例已经释放。

之后 Worker 回自己的任务路径，PM 回项目治理路径；再次命中第 1 节时才重新进入。
