# BEYOND 3.2.14: confirm requirements and design, then deliver continuously

New business development starts with investigation and user discussion, not implementation inferred from a brief goal. Reuse existing requirements and technical-design documents; record the applicable revision, scope and user confirmation. Continue approved slices, ordinary repairs and retests without per-step approval.

Requirements cover end-to-end behavior, data sources, permissions, failure cases and observable acceptance. Technical design explains stack reuse, middleware choices, interfaces, module boundaries and verification. Keep the document scope proportional; do not require three new files or every project template.

New designs normally receive an independent review from one different model, adding a third for consequential disagreement. Repeated targeted fixes without new evidence trigger independent diagnosis. Reviewers analyze rather than write code, and the original implementer retains ownership. Different CLI names or aliases for the same model do not establish independence; reported gateway model IDs cannot independently prove internal backend identity.

Documents evolve with implementation, without rewriting approved acceptance to match a faulty implementation. Shared files have one current writer. Stable architecture links decisions instead of collecting task-by-task approval logs. Unavailable review services do not block discussion; the user chooses an alternative or a precisely scoped waiver.

The release also includes previously completed artifact-retention maintenance: owned temporary test trees are reclaimed, compact reproducible evidence and recovery materials are retained, and scoped backups reuse verified content. No automatic project-wide deletion is introduced.

The sole receipt implementation fix retries its final atomic file replacement when Windows reports transient sharing errors, using the existing helper with 200 attempts and 5ms requested waits. Scheduling affects elapsed time; this is not a fixed wall-clock deadline. Persistent failures remain visible; no delete-and-recreate fallback is introduced. Desktop callback order, receipt format, task states, CLI protocols and the model matrix remain unchanged. Existing projects need no document reinitialization or retrospective approval of already authorized work. This release does not install into business projects.
