# BEYOND v3.2.4 Upgrade Guide

> Comparison: the current public release `v3.2.2 → v3.2.4`. This release also includes the project-owned operations routing fix merged as v3.2.3 but not published separately. It completes real-device regression for multi-result dispatch, terminal recovery, control-root isolation, and lightweight installation without adding identities, business states, Hooks, daemons, or a second scheduler.

## Goal-first continuous progress

1. When one owner message approves several independent results, the PM creates and registers them in the same turn. One failed creation does not block the other independent results; after all creation requests are handled, the PM ends without waiting for, reading, or polling Workers.
2. Required CI, an existing review, or a protected branch remains in progress while it still has an owner, readable state, and normal next trigger. Ordinary queue or review time is not reported as a project pause.
3. Exact literal or byte authorization is preserved without an added newline, BOM, or other content. A user-facing Worker final leads with the business result while commands, commit hashes, and other engineering evidence remain at the formal evidence location.

## Terminal recovery and control-root isolation

1. A formal Worker resolves its terminal runtime only from the current project-root `AGENTS.md` mapping. It never searches, guesses, or falls back to a source repository, template, candidate, or another project.
2. `worker-result.enqueue` and explicit project-scoped `worker-result.list` calls reject a project ID that is not registered in the current control root. Rejection occurs before any pending receipt is written.
3. The native callback remains the primary trigger. If the host does not create a runnable closeout turn for a delivered callback, the next natural PM turn performs one bounded pending read for active tasks and then continues the owner's current goal—without polling, a Hook, notify branch, daemon, or second scheduler.
4. A paused task resumes in the same original Worker. Pause and completion each produce one receipt, one workbench transaction, and one acknowledgement.

## Installation and upgrade

- The project root may be non-Git. Resolve it from the current Codex project directory and root `AGENTS.md`; do not require a successful `git rev-parse` gate.
- On Windows, inventory both sides of a backup with hidden entries included and compare relative paths, bytes, and SHA-256. A changed Hidden attribute on `.git` is not evidence of content loss.
- Upgrade only project-local `beyond-control` product files, six user-level Skills, and the fused root entry. Preserve `local/**`, `projects/**`, `shared/**`, native project rules, and business code.
- No identity Hook, notify branch, background process, extra Codex CLI, or worktree is installed.

## Release acceptance

- Deterministic and model gates cover content, installation, runtime behavior, PM/Worker semantics, Wanshitong scenarios, implementation paths, and public documentation.
- Real Windows validation covers installation, a single Worker terminal chain, two independent concurrent Workers, busy-PM multi-tool boundaries, same-Worker pause/resume, and wrong-control-root rejection with zero pending or workbench writes.
- The official package is `BEYOND-3.2.4.zip` with `BEYOND-3.2.4.zip.sha256` attached to the same Release. Restart Codex after installation and verify the loaded version from a new process.
