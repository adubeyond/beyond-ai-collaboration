# BEYOND 4.0.1: retained-session CLI execution fixes

This complete patch release retains the 4.0 engineering documentation structure and existing CLI compatibility/owner-transfer fixes. It does not overwrite 4.0.0 artifacts or install into an existing project.

- Keep the full goal while declaring each CLI round's deliverable. Save changed requirements for the existing review-and-continuation path instead of injecting them into an active round.
- Connect Codex, Claude Code and ZCode to current requirements, designs and applicable Skills; refresh relevant context when continuing the same session.
- Discover an available Codex executable without moving active processes to a new binary.
- Launch new Windows managers independently of the caller's close-on-exit Job and retain their sessions and results for reconnection.
- Include all three new product scripts and run the seven additional CLI regressions in public Windows/Ubuntu CI.

Desktop Worker callbacks, task states, notification interfaces, six Skills and model policy remain unchanged.

## Known limitations

Gemini's real requests failed with upstream HTTP 503 through all three CLIs. Codex GLM Flash rejected medium through the tested gateway; a machine-local low setting passed, but this private setting is not shipped. One npm Codex 0.160.1 continuation timed out; the currently resolved managed executable completed its separate continuation. Neither result proves every model/CLI combination works.

Lifecycle tests use an isolated owned Windows Job, not a shutdown of the user's actual Desktop. The change applies to newly launched managers only, does not migrate active sessions, and does not add offline notification replay or survive OS shutdown/logoff.
