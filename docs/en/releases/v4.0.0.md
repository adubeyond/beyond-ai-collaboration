# BEYOND 4.0.0: engineering context that remains usable across tasks

This is a complete release, not an incremental patch or a replacement of an existing tag. The major version marks the document-ownership and delivery-quality redesign; Desktop callbacks, task states and the model matrix remain unchanged.

- Separate task objectives, ownership, progress and results from reusable requirements, product design, architecture, data/API contracts, implementation guidance, tests and runbooks. Link current sections and revisions rather than duplicating their contents into task cards.
- Reuse existing project documents in place. Initialize their entry points, fill necessary gaps during real tasks, and maintain the original owners incrementally; do not require every template or bulk-move directories.
- Connect business behavior and data sources to technical decisions and observable acceptance. PMs analyze whether remaining gaps concern requirements, design, implementation or validation; Workers read the underlying documents and report evidence against the original goal.
- Preserve approved but not-yet-implemented designs. Mark only obsolete sections and their replacements; completing a task does not archive still-valid engineering documents or make old history current again.
- Remove Claude's exact-version gate. Replace ZCode's exact-version/full-file-hash gate with dependency, executable integration-position, generated-syntax and runtime-interface checks. Preserve per-run errors, existing sessions, reviews and owner-transfer behavior.

Private upstream interfaces can still become incompatible. This release removes artificial version allowlists, not real compatibility checks or authentication requirements. It does not promise improved model behavior on every business task, nor does publication install into existing projects.

The complete package includes installation, release and validation documents. See the [detailed release notes](../../releases/v4.0.0.md), [installation and upgrade](../../releases/v4.0.0-install.md), and [validation boundaries](../../releases/v4.0.0-validation.md).
