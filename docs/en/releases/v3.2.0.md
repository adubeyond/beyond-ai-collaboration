# BEYOND v3.2.0 Upgrade Guide

> Comparison: `v3.1.7 → v3.2.0`. This release freezes the terminal-result contract and deterministic control plane without adding identities, business states, approval stages, worktrees, or a persistent message system.

## What changes

1. The self-contained final in the formal Worker task is the only task-result truth. A callback wakes the source PM but does not duplicate the result body.
2. After forming a terminal result, the Worker does not inspect PM busy state or wait. It sends one native lightweight wakeup, then writes its formal final.
3. A busy PM finishes the current answer intact. The platform handles the callback after the answer boundary. One callback makes the PM scan every registered Worker and idempotently close all new terminal results.
4. Concurrent Worker completion is accepted and archived exactly once per final. Repeated or coalesced wakeups do not create duplicate tasks, results, or truth sources.
5. Project identity and workbench updates use deterministic runtime actions. During upgrade, active and paused legacy tasks enter the 3.2 machine state, completed rows leave the hot workbench, and prior history plus exact entry backups remain available.

## Removed experimental paths

- BEYOND no longer installs or builds an identity Hook, result inbox, terminal-body replica, notify dispatcher, host adapter, background daemon, or extra Codex CLI.
- Workers do not poll PM state, and the owner's next message is not the normal recovery trigger.
- Existing third-party Hooks, computer-use, user notify configuration, plugins, and Codex features are outside the cleanup boundary.

## What remains stable

- One PM per project control context and one user-visible unique Worker per business result.
- The same Worker continuously selects design, development, testing, and operations methods; ordinary repair, retest, and local commits do not return to the PM for approval.
- Business state remains `进行中 / 已暂停 / 已完成`.
- BEYOND does not create or recommend worktrees; Git index, HEAD, and history changes remain serialized in one working tree.
- Remote Git, production, shared data, deletion, and irreversible actions retain separate authorization boundaries.

## Installation and verification

Stop active PM and Worker tasks, then back up the project `AGENTS.md`, project-local `beyond-control/`, six user Skills, and Codex configuration. Replace BEYOND files once from the immutable `v3.2.0` package, remove only legacy BEYOND experimental components, and fully restart Codex.

In the new process, run installation-integrity verification before project adoption or upgrade. At minimum, verify ordinary Worker development and tests, automatic idle-PM closeout, an uninterrupted busy-PM answer, exactly-once acceptance of concurrent results, automatic return of a real paused final, and lossless legacy-workbench migration.
