# BEYOND 3.2.11: turn progress into outcomes

This patch clarifies nonterminal progress decisions without changing the terminal callback, receipt, acceptance, pause/resume or model-policy protocols.

- Workers continue authorized remaining work after partial handoffs. A dependency blocks only affected actions.
- PMs distinguish actionable work, unchanged dependencies, repeated confirmations, explicit user checkpoints and already-started continuations.
- Consolidate the same known result without dropping different tasks, new faults or released dependencies. Combine necessary handoff facts and progress into one report.
- Handle necessary callback decisions, then return to the foreground request. Do not wait for newly resumed Workers or require all background work to finish before answering.
- Current progress describes what remains, what is actually executing and which owner/input is awaited. An in-progress business state is not proof of a running process.

No new task state, scheduler or message queue is introduced. CLI execution and notification implementations remain at the released 3.2.10 baseline. The rules do not guarantee host message delivery or eliminate model variability.

The full package targets the official 3.2.10 baseline. Preserve and reconcile additional local hotfixes or project-specific control code before upgrading; do not overwrite those extensions merely because their version label matches. Publishing this release does not install it into an existing production project.
