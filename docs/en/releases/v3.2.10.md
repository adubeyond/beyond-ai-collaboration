# BEYOND 3.2.10: visible native CLI conversations

This release adds an opt-in native Codex TUI for third-party API execution. Retain one session, observe real work, notify the Desktop owner after a stable terminal turn and foreground completion, then review and continue the same session. Existing Desktop Worker callbacks and the 3.2.9 model policy are unchanged.

Windows can open an external visible terminal. Linux uses an explicit terminal attachment. Existing profiles without mode retain exec-log behavior. Native mode requires Node.js 24 and a Codex executable with authenticated app-server support, tested with 0.160.0. Loopback-only connections use private short-lived tokens; API credentials remain in a separate CLI home, never in release artifacts.

Native execution uses full access and no per-command approvals, without expanding business or production authorization. Owner review, not CLI completion, determines goal acceptance. The upstream WebSocket interface remains experimental; this is not a universal availability or production-safety guarantee.
