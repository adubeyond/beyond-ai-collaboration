# BEYOND 3.2.7 stable release

This update improves model selection and closeout reliability without rebuilding the collaboration workflow. Whole-project and scoped PMs, continuity of the original Worker, focused context loading and authorization boundaries remain intact.

## Changes

- **Opt-in GPT-6 policy:** `beyond-worker-gpt6-v3` starts bulk work at Luna/high, ordinary implementation, design and high-consequence work at Sol/high, and difficult reasoning at Astra/low. Approved choices are Luna high/max, Sol high/xhigh/max/ultra and Astra low/ultra. PMs choose both fields; older policies remain unchanged and explicit user choices take precedence. Running Workers are not forcibly interrupted.
- **Early callbacks:** distinguish the still-finishing callback turn from a genuinely newer turn by identity, preserving bounded verification of up to one minute and narrowly scoped local recovery. Continue unfinished foreground questions after handling callbacks.
- **Large local records:** stream a fixed file snapshot instead of rejecting it solely for exceeding 256 MiB. Retain thread, directory, turn, completion, consistency and concurrent-change checks.
- **Concurrent receipt safety:** replacement and acknowledgement for the same project/task share exclusion, so an old acknowledgement cannot delete a new receipt. Unrelated tasks are not globally serialized. Listing tolerates a receipt concurrently acknowledged by another PM; corruption and permission errors still fail visibly.
- **Durable acceptance evidence:** recover acknowledgement after bounded operation-cache eviction using a matching completed transaction and unique history entry. Missing or conflicting evidence stays pending, without duplicate acceptance.
- **Consistent approval validation:** reject malformed approval dates or non-text approval evidence both during policy use and installation verification.

## Upgrade

Download `BEYOND-3.2.7.zip` and follow its `INSTALL.md`. The external `.sha256` is optional; absence does not block installation, but a supplied mismatch does. Verify the internal manifest and installed content.

Replace only listed product files and the six matching Skills, merge the project entry, and preserve native rules, `local/`, `projects/`, `shared/`, `.git/` and business files. Installation does not start, resume or close business tasks. Restart Codex after replacing global Skills.

## Validation and limits

Release checks cover real isolated runtime transactions, cross-process races, cache eviction, malformed-record rejection, model policies, large-record recovery, upgrade preservation and real-model PM behavior in an isolated environment. See the [validation record](../../releases/v3.2.7-validation.md).

Model probes use simulated task transport and the real product runtime, not Desktop delivery. Host-supported model parameters are not a promise of every account's availability, and an accepted switch request does not prove the execution configuration changed. This release does not install itself into production or guarantee elimination of context drift, missed host wakeups or model judgment errors.

No Laya/Jev integration, Hook, notify handler, daemon or extra CLI is added.
