# BEYOND v3.0.7 Upgrade Guide

> Comparison: `v3.0.6 → v3.0.7`. This public release is intended for fresh-computer and new-project field testing; it does not mean that Wanshitong has been upgraded.

## Why this release exists

Version 3.0.6 shortened document loading and PM communication, but fresh-project tests still exposed formal work being placed in internal subtasks, one business result being split across conversations, weak Worker continuation, and poor model selection for clear high-volume work. Version 3.0.7 adds no identity, business state, or approval layer. It restores control to one formal Worker while preserving the production, Git, testing, and project-fact capabilities validated in recent releases.

## What changed

| Area | 3.0.6 | 3.0.7 |
| --- | --- | --- |
| Formal task | Could still degrade to an internal container | Must be a fresh user-visible task bound to the formal project; forks, projectless tasks, and internal helpers cannot own the result |
| One result | A design checkpoint could lead to another implementation task | One Worker owns design, implementation, testing, ordinary repair, and authorized delivery |
| Continuation | Could still pause too often or confuse “continue” with automation | Stops only for a real business decision, high-risk authorization, shared-object conflict, or unavailable external prerequisite |
| Subagents | Could be confused with formal Workers | Only accelerate bounded parallel work inside the current Worker |
| Worktree | Could be created by a default platform path | BEYOND neither creates nor recommends one; existing worktrees are merely tolerated and Git mutation remains serialized |
| Model selection | Mostly inherited the default model | An explicitly adopted policy uses Luna for clear repetitive/high-volume checks, Terra for ordinary engineering, and Sol for complex, uncertain, or high-risk work |
| Scope control | Reuse could expand a bounded fix into a generic mechanism | Repeated candidate versions, expanding object sets, or new generic protocols trigger a minimum-complete-path comparison by the same Worker |
| Historical data | A one-off correction could become a product rewrite | A bounded repair may use an auditable transactional one-off path when ownership, impact, authorization, rollback, and validation are closed |

## Preserved capabilities

- One PM per project, multiple independent business results in parallel, and one formal Worker per result.
- Project Markdown remains the owner of technology, testing, server, SSH alias, credential-entry, release, and rollback facts.
- Ordinary implementation, retesting, and task-owned local commits do not return to PM for step approval.
- Precise staging, unrelated-dirty-change protection, complete-candidate release, business verification, and rollback evidence remain intact.
- Design, development, testing, and operations remain professional methods selected by the Worker rather than new agents.

## Upgrading from 3.0.6

1. Obtain the immutable `v3.0.7` tag rather than guessing from a moving branch.
2. Preserve project-specific business documents, technology, servers, credential entries, active tasks, and historical evidence.
3. Update the root entry and all six Skills with their references; do not replace project facts with blank templates.
4. Remove residual rules that place formal work in forks, projectless tasks, internal subtasks, or separate design/development/test conversations.
5. Record the Luna/Terra/Sol policy in the project entry only when the project adopts it; otherwise retain the platform default model.
6. Restart Codex and begin a new task from the project root. Validate a low-risk task's visible Worker, continuation, Git delivery, and callback before expanding use.

## Validation

- 153/153 primary isolated assertions and 31/31 v3.0.5/real-project simulations passed.
- Scope expansion and controlled data repair passed 13/13; model selection passed 8/8.
- P01–P13 completed fresh isolation again after the model policy was confirmed.
- First-hand session metadata confirmed actual Luna-high and Sol-high task execution and callback.
- Control-plane integration passed 24/24 with one Worker and no additional worktree.
- The final strict public candidate, implementation paths, and file-by-file SHA-256 comparison passed.

This evidence covers the tested Windows/Codex environment and declared scenarios. Fresh-computer discovery, a new project, and broader field use remain the purpose of the v3.0.7 installation test.

## Rollback

Restore the v3.0.6 template and six Skills, restart Codex, and preserve the project's own facts, business code, Git history, and runtime evidence. Rolling back BEYOND rules does not roll back project code, databases, or production versions.
