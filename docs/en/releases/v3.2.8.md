# BEYOND 3.2.8

Released 2026-10-02.

One GPT-6.1 Worker policy replaces the old active matrices. Routine work starts with 6.1 Sol medium, denser logic may use high, and polished complex UI, cross-module design, or conflicting evidence may use xhigh. Clear extraction and repetitive work use Luna low or high; demanding architecture, diagnosis, and decisions consider Astra medium, raising effort when justified.

Complete correct delivery and total time precede allowance cost including rework. Adjust the same Worker at normal continuation points; do not inherit effort across models, force cheaper trials, or interrupt useful work. Historical approvals are recognized for upgrade only. Before an explicit current selection, new Workers retain platform defaults and existing threads retain their settings.

Optional PM → Worker → CLI and direct owner → CLI paths retain sessions, notify after each run, and require owner review before continuation or acceptance. Direct CLI tasks have independent records; mediated work still returns through the original Worker. Process completion and notification are not business acceptance. Local profiles supply third-party models and credentials; the package installs neither a CLI nor a persistent service.

The native Desktop callback, pause/resume, and acceptance protocols are unchanged. Fixes cover unversioned-entry override nesting, equivalent Windows execution-root spellings, and credential-home rejection on cold hosts. Desktop authentication reuse and physical directory aliases remain prohibited. Upgrades preserve project knowledge, runtime state, and existing tasks.

See the [validation record](../../releases/v3.2.8-validation.md) for executed checks and evidence boundaries. Offline fixtures are not a universal delivery guarantee or a benchmark of model quality.
