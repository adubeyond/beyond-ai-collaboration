# BEYOND 3.2.13: reconnect business context and engineering documentation

This release brings the 2.0 software-engineering documentation structure into the existing BEYOND collaboration system. It connects project understanding to implementation evidence without adding another task workflow or requiring every template to be completed before work starts.

## What changes

- Business flows, product interactions, architecture, data/API contracts, implementation guides and stage decisions connect to existing testing, operations, release and security documents.
- New PMs read the current main facts to understand the whole project. Workers follow task-specific source documents and direct dependencies instead of loading all project history.
- Existing documents keep their locations and owners. Initialization connects entry points; tasks fill real gaps as needed; verified changes update the original source. Confirmed objectives, chosen designs and current implementation facts remain distinct.
- Initialization supports reference-style Markdown links, rejects unreachable files or sections, and prevents code, quoted or HTML examples from masquerading as real navigation.
- Registration and entry installation retain declared execution clones. Scoped preimages are captured before mutation and cannot be mistaken for whole-directory restore packages.
- Project subdirectories resolve to the correct execution root without losing valid worktrees or declared clones. A non-Git project cannot widen its execution scope to an enclosing Git repository.
- The overview points to the current model policy instead of recommending retired policy names. Model selection behavior does not change.

## What stays

Existing CLI compatibility, command channels, saved-session recovery, process identity, execution-copy routing and lock fixes are preserved. Identity and professional-method guidance changes only for relevant document reading and maintenance. Desktop Worker callbacks, receipts, acceptance, pause/resume and the model matrix remain unchanged.

This is a complete upgrade package, not an incremental patch. Existing projects do not need to recreate their documentation or initialize again. Preserve project facts, runtime state, tasks, CLI sessions, authentication and newer local hotfixes during installation.

## Evidence and limits

Validation covers document structure, reachable reading paths and local isolated runtime regressions. It is not a new live model, Desktop notification or production business acceptance test; readable context does not guarantee a model's delivery quality. Third-party CLI compatibility remains version-specific.

See the [validation record and limits](../../releases/v3.2.13-validation.md), [installation instructions](../../releases/v3.2.13-install.md) and [engineering documentation guide](../../../模板交付包/docs/AI编程协同机制/工程资料指南.md). The detailed engineering templates remain Chinese-first.
