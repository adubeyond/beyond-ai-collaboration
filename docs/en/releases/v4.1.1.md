# BEYOND 4.1.1: result collection and native background notifications

Version 4.1.1 is a focused patch on 4.1.0, distributed as a complete package rather than an incremental overlay. It repairs internal-helper collection and Claude native background-notification boundaries. It does not redesign responsibilities, formal Worker callbacks, or the model matrix. Earlier assets remain unchanged; publication installs nothing into existing projects.

## What changes

- **Collect required helper results before ending the turn.** When the promised delivery depends on an internal helper, its initiating owner first collects and verifies the necessary results. Native completion events may be awaited without polling. An ended parent turn is not assumed to wake automatically. Cross-turn return uses an already authorized CLI or formal-task route, without automatically migrating helpers or creating tasks. Current user questions, pauses, and checkpoints take priority.
- **Recognize current-run Claude background completion.** Structured tool-use/result pairs observed after the current accepted instruction establish associations within the same session and project. The patch handles completion before the first Stop and delayed creation of a new session's transcript. Historical, foreign, duplicate, unpaired, or command-bearing notifications do not gain continuation permission.
- **Separate waiting from completion.** Terminal background records no longer hold Stop indefinitely by themselves. Unknown background state, unavailable observation, and a session cron awaiting its owner use the existing direct-owner attention path. Attention remains separate from final results and does not independently declare success or failure.
- **Preserve authority.** Existing busy-owner protection and serialized notifications remain in place. Attention does not run scheduled prompts, resume paused work, authorize execution, or accept results. No persistent scheduler is added.

## Compatibility and installation

Formal Worker terminal receipts, native callbacks, PM closeout, and the PM's dispatch-and-exit rule remain unchanged. Existing CLI sessions, same-session continuation, model settings and policy, results, reviews, and history are preserved. The patch does not automatically stop, rebuild, or migrate sessions.

The complete package still contains seven Skills. Installation needs separate authorization for the target project and a safe maintenance window. Follow the existing restart and integrity-verification process after updating shared Skills. Replacing files does not prove an existing conversation or CLI manager has hot-loaded new content; do not restart or reconstruct active work without authorization.

Use the [installation guide](../../../模板交付包/docs/en/installation-upgrade-and-project-initialization.md). Public assets contain no private gateway credentials, project identifiers, or local profiles.

## Evidence and limits

The isolated regression tests exercise the real local observer, session state machine, HTTP manager, storage, and notification routing with mocked native-model and Desktop MCP peers. They are not a fresh online model-to-Desktop end-to-end trial. Older native Hooks without a source field still cannot independently authenticate an identically copied manual notification.

The complete validation entry contains 32 groups. Actual results, source identity, and package verification belong to the matching release asset `BEYOND-4.1.1.validation.json` and package manifests; this document does not predeclare a pass. Publication is not installation, business acceptance, or proof that an internal helper wakes an ended parent turn.
