# BEYOND v3.0.8 Upgrade Guide

> Comparison: `v3.0.7 → v3.0.8`. This is a focused patch for field-installation defects, not a redesign of the v3.0.7 runtime.

## Why this release exists

A remote installation reported v3.0.7 while actually combining a v3.0.6 PM Skill, a v3.0.6 managed project entry, selected v3.0.7 files, and a project-local Luna override. That hybrid runtime then applied Worker model routing to a new PM and resumed old work during project takeover.

Version 3.0.8 adds no identity, state, approval, or stage. It makes installation identity executable and narrows two ambiguous runtime rules.

## What changed

- A release manifest and verifier compare every file in the six installed Skills and verify the versioned managed portion of the project `AGENTS.md`; old, missing, residual, or mixed content fails closed.
- Project-specific rules live only in a bounded override block, and model overrides must name the PM or Worker role they apply to.
- Luna/Terra/Sol routing configures newly created Workers only. It does not change the current PM model or authorize a replacement PM.
- A takeover-only request restores the mainline and task state without starting or resuming business work. A task advances only when the same user instruction explicitly requests it.
- The secret-free project entry should be version-controlled after initialization or upgrade so later changes remain attributable.

## Upgrade from v3.0.7

1. Obtain the immutable `v3.0.8` Git tag.
2. Preserve project documentation, facts, workbench state, task records, and Git history.
3. Replace all six Skills with the v3.0.8 copies. Move project-specific root rules into the dedicated override block and update the remaining managed `AGENTS.md` content to v3.0.8.
4. Run from the tagged checkout:

   ```text
   node 模板交付包/scripts/verify-install-integrity.mjs --installed-skills-root "<Codex Skills directory>" --project-agents "<project root>/AGENTS.md"
   ```

5. Treat the upgrade as complete only after exit code `0`, then restart Codex and create a new PM task.
6. First issue a takeover-only request and confirm that old tasks remain stopped; then explicitly resume one task and confirm the original Worker path remains in control.

## Verification

- Installation-integrity regression: 5/5 passed, including controlled failures for an old Skill, an old project entry, and a role-ambiguous model override.
- Implementation-path checks: 203 passed.
- Real isolated Codex model-scope checks: 9/9 passed.
- Takeover with two paused legacy tasks: 4/4 passed; both real processes exited with code 0.
- Strict public candidate: 115 files passed, with zero SHA-256 differences between source and candidate.

These results cover the declared Windows/Codex isolation target. They do not prove that a specific project has upgraded or that any real server or production release has passed.

## Rollback

Restore the v3.0.7 template and six Skills, then restart Codex. Preserve project facts, business code, Git history, and runtime evidence. Rolling back BEYOND rules does not roll back business code, data, or production.
