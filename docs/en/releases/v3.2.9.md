# BEYOND 3.2.9: Sol-first model defaults

Released 2026-10-02. This patch changes model policy, not callbacks, goal progression, foreground protection, or the optional CLI protocol. The 3.2.8 tag and artifacts remain immutable.

Public validation also exposed a transient Windows denial while reading a lock directory during handoff. The fix reuses the existing bounded I/O retry; persistent denials still fail visibly. Ownership and receipt protocols are unchanged.

| Work | Starting configuration |
| --- | --- |
| PM | GPT-6.1 Sol xhigh, selected by the user in the platform |
| Routine engineering and ordinary design | GPT-6.1 Sol high |
| Difficult design, diagnosis, and high-consequence judgment | GPT-6.1 Sol xhigh |
| Explicit structured batches and extraction | GPT-6 Luna high |
| Evidence-backed breakthrough work | Explicitly selected Astra |

These defaults reflect user feedback, not an official performance or quota guarantee. Optimize complete delivery and speed before total consumption. The only active opt-in policy is `beyond-worker-gpt61-v5`; historical approvals are recognized for migration, not silently reinterpreted. Existing threads and the PM's own settings are not automatically reconfigured. Explicit user model locks take precedence; same-Worker stage changes specify both model and effort.

Upgrades preserve native project rules, facts, tasks, history, pending receipts, and existing control-repository Git data. External checksums remain optional; in-package verification remains required.
