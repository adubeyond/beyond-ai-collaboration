# BEYOND v3.2.2 Upgrade Guide

> Comparison: `v3.2.1 → v3.2.2`. This release closes the terminal-result gap in a resumed paused Worker and shortens ordinary execution for a clear business goal without changing identities, business states, task ownership, or model policy.

## Terminal-result reliability

1. PM resumes the original Worker with only the send tool's required fields—currently `threadId + prompt`—and omits optional host, model, and reasoning parameters.
2. Before the native callback, a formal Worker stores the exact frozen final as project-local pending state. PM can close the result by `projectId + taskId` even when the host UI shows the resumed final but control readers cannot read it.
3. PM deletes pending state only after a successful pause or acceptance transaction. A stable operation derived from `receiptId` makes crash recovery idempotent, and stale acknowledgement cannot remove a newer result.

## Goal-first execution

1. A current, explicit, informed, object-specific user instruction overrides BEYOND defaults and historical project preferences. File, remote Git, environment, server, production-data, irreversible-action, and external-cost authorization remain separate.
2. Clear local development that only needs existing tests stays inside `task-dev`; it does not load `task-test` as a second method, and PM does not preselect an Action Skill for the Worker.
3. After a standard tool or dependency entry is rejected, the task makes at most one targeted equivalent attempt that preserves the result and risk boundary. If it still cannot proceed, it preserves authorized reversible work and reports the gap instead of searching the machine, caches, other installers, versions, or the web, or rerunning a test that cannot start.

## Unchanged

- The native callback only wakes PM; the user-visible Worker task still emits the complete final.
- One Worker owns one business result, using only `进行中 / 已暂停 / 已完成`.
- No Hook, notify adapter, daemon, extra Codex CLI, worktree, polling loop, or persistent message inbox is added.
- Normal completion, genuine pause, busy-PM handling, and parallel callbacks retain the verified v3.2.1 path.

## Release validation

Content and installation integrity passed. Real Codex Desktop projects covered normal completion, genuine pause, multi-stage recovery in the same Worker, a busy PM, parallel closeout, and consumed-pending deletion. Goal-first validation also covered an explicitly authorized exact write and deletion, a user-selected browser path, and one formal Worker completing one file change, one test run, one commit, one callback, and one acceptance.
