# BEYOND v3.1.2 Upgrade Guide

> Comparison: `v3.1.1 → v3.1.2`. This patch corrects the default control-repository location without changing the PM, Worker, three-state, Action Skill, Git, test, or release paths.

## Fixes

- Create the independent `beyond-control/` repository under the current project root by default instead of placing it beside the project without an explicit choice.
- Use an external control repository only when the user explicitly wants several independent projects to share one.
- Add `/beyond-control/` and `/.beyond-local-backups/` to the project root `.gitignore` during project-local initialization so business Git cannot accidentally stage the independent control repository or local backups.
- Exclude the control repository itself from project Markdown and repository discovery.
- Normalize Windows short and long paths before comparing the project root, control root, and Git root.
- Use the same entry fusion, Hook, and installation verification in project-local and explicitly external modes.

## Default layout

```text
business-project/
├─ beyond-control/
├─ AGENTS.md
├─ .codex/
└─ <existing code and documents>
```

The package is not scattered over existing project files. Existing `AGENTS.md` and Hooks are still backed up before fusion, and project documents still require the user's migration choice.
