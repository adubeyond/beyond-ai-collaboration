# BEYOND v3.1.7 Upgrade Guide

> Comparison: `v3.1.6 → v3.1.7`. This release adds no identity, business state, approval stage, or worktree workflow. It preserves the v3.1.6 legacy-project initialization loop.

## What changes

1. The formal Worker final and platform task state are terminal truth. A uniquely identified idle source PM may receive one compact reminder.
2. A running, unknown, or conflicting PM is not interrupted, awaited, or retried. The PM recovers missed results with one zero-duration platform snapshot at the next user turn.
3. Ordinary task packets stay compact. Worker models follow the primary work; words such as server, Git, database, or security do not upgrade the model by themselves.
4. Replacing the root entry or Skills waits for active tasks to stop, then requires a Codex restart and new-process verification. Ordinary project-document edits remain restart-free.
5. New formal tasks no longer write result-inbox records. A legacy pending record is deleted only after PM verification and workbench update and is not retained as long-term history.

## What remains stable

- One PM per user and project control context, and one unique Worker per business result.
- The same Worker continuously selects design, development, test, and operations methods.
- Business state remains `进行中 / 已暂停 / 已完成`.
- BEYOND does not create or recommend worktrees; shared Git mutation remains precise and serialized.
- Production, data, remote Git, deletion, and irreversible actions retain separate authorization boundaries.

## Installation verification

Obtain the complete package from the immutable `v3.1.7` tag. Stop existing PM and Worker tasks, replace the project-local `beyond-control`, project entry, and all six user Skills once, then restart Codex. In the new process, verify version/file consistency, ordinary model selection, Worker terminal delivery, busy-PM protection, next-turn result recovery, and verified deletion of legacy pending records.
