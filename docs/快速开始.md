# BEYOND 3.0 快速开始

本指南使用仓库中的零第三方依赖 Node.js 示例，验证三件事：

1. 模板能够进入一个干净项目。
2. Codex 能按根`AGENTS.md`和项目文档链理解项目。
3. 一个清晰开发任务能够沿设计/开发/测试路径完成，并留下当前轮证据。

这不是模板全部能力的压力测试，也不涉及真实服务器、生产发布、数据库或远端 Git。

> 先确认能力边界：能读取`AGENTS.md`并加载 Skills，不等于能运行完整正式任务协作。本版本只支持 Windows + Codex Desktop；PM→执行者的完整路径还需要当前 Desktop 会话提供用户可见的任务创建、后续消息、任务读取和直接纠偏能力。缺任一项时不得把内部子智能体当正式任务。

## 1. 前置条件

- Windows 上已安装可以读取项目`AGENTS.md`并使用 Skills 的 Codex Desktop；若要验证完整协作，还需当前会话实际暴露正式任务能力。
- 已安装 Node.js 24.x（当前脚本实测基线）；示例只使用 Node.js 内置模块，不需要`npm install`。
- 有一个可写的本地目录。
- 如果要直接使用`$identity-pm`、`$identity-worker`和`$task-*`，需要先安装本仓库的六个 Skills 并重启 Codex；未安装时可以显式引用项目内对应的`SKILL.md`路径。

先确认环境：

```text
node --version
npm --version
```

## 2. 准备示例项目

复制[最小示例](../examples/minimal-project)到一个新的可写目录，例如`beyond-demo`。从本仓库根目录先查看 dry-run，再把模板安装到这个显式目标：

```text
node scripts/beyond-install.mjs install --target <beyond-demo绝对路径> --dry-run
node scripts/beyond-install.mjs install --target <beyond-demo绝对路径>
node scripts/beyond-install.mjs version --target <beyond-demo绝对路径>
node scripts/beyond-install.mjs verify --target <beyond-demo绝对路径>
```

安装器只管理`AGENTS.md`、`docs/AI编程协同机制/`和项目内`skills/`，不会覆盖示例自己的`README.md`。发现同名文件、已安装文件漂移、符号链接或路径逃逸时会停止；不会静默覆盖。

示例自己的`README.md`保留为项目说明，不用模板交付包的`README.md`覆盖它。完成后目录至少应为：

```text
beyond-demo/
├─ AGENTS.md
├─ README.md
├─ package.json
├─ docs/AI编程协同机制/
├─ skills/
├─ src/calc.js
└─ test/calc.test.js
```

模板中的项目总览、当前工作台和项目事实仍是待初始化格式，这是预期状态。不要提前把示例结果伪装成已经初始化的真实项目事实。

## 3. 安装或显式引用 Skills

项目模板安装器不会写任何真实 Codex 运行目录。若当前表面支持项目内显式 Skill 路径，可以直接引用；若要使用`$identity-*`和`$task-*`入口，按当前 Codex 的正式 Skill 安装方式另行安装以下六个目录并重启 Codex：

```text
identity-pm
identity-worker
task-design
task-dev
task-test
task-ops
```

运行时 Skill 安装不属于本快速开始安装器的写入范围。完成后重启 Codex，再从示例项目根目录创建一个新任务。具体入口、编码要求和未安装时的显式路径用法见[模板交付包说明](../模板交付包/README.md)。

## 4. 运行初始基线

在示例项目根目录运行：

```text
npm test
npm run check
```

预期结果：

- `npm test`通过一个`add`测试。
- `npm run check`对源码和测试文件完成语法检查。
- 不生成`node_modules`或锁文件。

如果初始基线失败，先解决 Node.js 环境或示例文件问题，不要把基线失败当成后续开发回归。

## 5. 启动 PM 并下达第一个任务

在示例项目的新 Codex 任务中输入：

```text
$identity-pm 以 PM 总控身份接手当前项目。

这是一个用于验证 BEYOND 的最小计算器项目。
当前业务结果：为 src/calc.js 增加 subtract(left, right)，并在 test/calc.test.js 增加 subtract(5, 2) === 3 的测试。
明确不做：不增加乘法、除法、命令行界面、第三方依赖或其他文件；不执行 Git；不发布。
允许：读取当前项目，修改 src/calc.js、test/calc.test.js 和模板规定的项目文档；运行 npm test 与 npm run check。
验收：两个命令退出码均为 0，现有 add 测试继续通过，新 subtract 测试通过。

请先按根 AGENTS.md 的最小读入链判断当前项目；调查 package.json 和现有代码中可发现的事实，完成当前任务必需的最小项目初始化，形成完整任务包并创建正式任务线程。由执行者在同一任务中按需要组合设计、开发和测试，完成后写回证据和唯一终态。
```

这段输入故意一次给足业务结果、明确不做、文件边界、命令权限和验收，目的是验证完整任务自动路径，而不是测试 PM 会问多少问题。

## 6. 预期运行过程

```mermaid
flowchart LR
    A["PM 最小读入"] --> B["调查 package.json、源码和测试"]
    B --> C["形成任务包并创建正式任务"]
    C --> D["执行者读取任务与工程事实"]
    D --> E["开发 subtract 与测试"]
    E --> F["npm test"]
    F -->|"失败"| E
    F -->|"通过"| G["npm run check"]
    G -->|"通过"| H["任务主面、证据与唯一终态"]
    H --> I["PM 消费并收口"]
```

正常情况下：

- PM 不应亲自修改`src/calc.js`或测试文件。
- 设计、开发和测试不应被拆成三个需要用户逐次说“继续”的业务任务。
- 项目事实缺失时，执行者应先调查并写入当前动作需要的最小基线，然后沿原任务继续。
- 普通实现或测试失败应在原任务内修复回测。
- 未授权的 Git、依赖安装、服务器、生产和数据操作不得发生。

## 7. 验收结果

任务完成后核对：

```text
npm test
npm run check
```

并检查：

- `src/calc.js`同时导出`add`和`subtract`。
- `test/calc.test.js`同时覆盖`add(2, 3) === 5`和`subtract(5, 2) === 3`。
- PM 对话登记了正式任务和终态，而不是 PM 自己下场开发。
- 正式任务对话中可以看到实现、验证和完成结论。
- 项目文档只写经过调查或验证的事实，没有猜测服务器、凭据或发布流程。
- Git、服务、网络、服务器、生产和数据保持零操作。

## 8. 重新运行与恢复

升级新来源前先验证已安装文件没有漂移：

```text
node <新来源>/scripts/beyond-install.mjs verify --target <beyond-demo绝对路径>
node <新来源>/scripts/beyond-install.mjs upgrade --target <beyond-demo绝对路径> --dry-run
node <新来源>/scripts/beyond-install.mjs upgrade --target <beyond-demo绝对路径>
```

成功升级会输出备份 ID并保留逐文件哈希清单。需要回滚时先 dry-run，再显式选择该备份；若当前受管文件已经漂移，回滚会停止：

```text
node <当前来源>/scripts/beyond-install.mjs rollback --target <beyond-demo绝对路径> --backup <备份ID> --dry-run
node <当前来源>/scripts/beyond-install.mjs rollback --target <beyond-demo绝对路径> --backup <备份ID>
```

第一次完整体验建议从干净示例副本开始。若要重复验证：

1. 删除该演示目录，重新复制原始示例。
2. 重新复制模板的`AGENTS.md`、`docs/AI编程协同机制/`和`skills/`。
3. 重启 Codex，创建新任务。
4. 重新运行初始基线，再发送相同任务。

不要用 Git 强制清理包含个人改动的目录，也不要把一次运行后的项目事实复制回本仓库原始示例。

## 9. 下一步

完成最小示例后，可以继续阅读[系统架构与运行机制](系统架构与运行机制.md)，再把[模板交付包](../模板交付包)导入自己的真实项目。真实项目应根据代码、配置、测试和环境建立自己的项目事实，不能复用示例事实冒充真实情况。
