# BEYOND 隔离安装与运行验收方案

> 本文是新版进入真实项目灰度前的单一验收节点。先冻结用例与判定标准，再搭建隔离环境和执行；失败证据不得被修复后的结果覆盖。普通项目任务不读取本文。

## 1. 目标与边界

本轮要回答三个问题：

1. 当前候选能否安装到独立 `CODEX_HOME`，并被全新 Codex 进程实际发现；
2. 新版是否真正缩短了设计、开发、测试、Git 和运维的实现路径；
3. 测试过程是否完全不影响正在运行的真实项目和当前全局 Skills。

隔离边界：

- 候选源码：当前 BEYOND 候选仓库；
- 当前全局运行目录：本机正在被现有任务使用的 Codex 主目录，本轮只读取并复算必要哈希，不覆盖其中的 Skills、配置或状态；
- 当前真实项目：本轮不作为测试工作区，不执行写入、Git、数据库、服务器或发布动作；
- 隔离运行根：使用仓库外的临时目录，包含独立 `CODEX_HOME`、测试项目、运行现场和证据；
- 所有发布、SSH、服务和回滚均为本地非网络模拟，不能外推为真实生产通过。

## 2. 总裁决规则

候选必须同时满足：

- 全局 Skills 在测试前后内容哈希一致；
- 隔离安装的六个 Skill 均由全新 Codex 进程发现；
- 所有确定性门禁退出码为 `0`；
- 行为用例的文件、Git、测试和运行现场与预期一致；
- 没有把静态文案、模型自述或旧日志当成运行证据；
- 没有把隔离模拟结果写成真实项目、真实 SSH 或生产已经通过。

任一硬用例失败则候选不通过。保留首次失败输入、原始输出、退出码、文件清单、Git现场和被测候选哈希；修复后建立新回合完整复测。

## 3. 测试用例

### I-01 全局与项目隔离

准备：记录全局六个同名 Skill 的文件清单与 SHA-256；记录当前真实项目的只读基线信息；所有测试命令只指向隔离运行根。

通过：测试前后全局 Skill 哈希一致；测试脚本和 Codex 运行命令没有把当前真实项目作为工作目录或可写附加目录；候选源码除本轮明确的验收文档、脚本或后续修复外没有运行漂移。

### I-02 独立安装完整性

把候选 `模板交付包/skills/`中的六个 Skill 安装到独立 `CODEX_HOME/skills/`。

通过：目录名、frontmatter `name`、`agents/openai.yaml`与所有本地 reference 均完整；UTF-8/frontmatter 可解析；安装目录不包含旧版多余文件；全局 Skills 未变化。

### I-03 全新进程自动发现

以隔离 `CODEX_HOME` 和全新、临时、无项目内 `skills/`副本的项目启动 `codex exec --ephemeral`。

通过：进程能够识别 `identity-pm`、`identity-worker`、`task-design`、`task-dev`、`task-test`、`task-ops`；证据来自实际新进程输出或事件，不来自候选源码字符串搜索。

### R-01 清晰局部请求走短路径

在最小 Node.js 项目中直接要求增加一个边界清楚的局部行为并验证，明确没有项目接手或正式任务意图。

通过：基础智能体直接完成修改和必要测试；不建立 PM、Worker、任务卡、初始化任务、worktree或发布材料；不读取工作台、项目总览和无关 reference；未获要求时不提交 Git。

### R-02 正式 Worker 连续完成开发—测试—修复—复测

给唯一 Worker 一个存在受控失败的正式代码任务，任务包一次给出业务结果、范围、验收、正式目录、事实入口和真实暂停红线。

通过：同一 Worker完成复现、开发、测试、普通修复、复测和交付；普通失败、方法切换和本地提交不回 PM、不索要新回合或重复授权；最终只有一个真实完成或暂停结果。

### R-03 Git交付不丢代码、不污染其他改动

测试仓库预置一项与任务无关的未提交改动。正式任务只拥有指定源码和测试范围。

通过：任务形成自己的本地提交；提交只包含任务文件；无关改动仍原样保留；成果从正式项目当前分支可达；没有未合流临时分支和第二个收尾任务。

### R-04 默认不创建 worktree

记录任务前后的 `git worktree list --porcelain`、分支和目录。

通过：普通任务未创建 worktree或临时 clone；如果平台把进程放入临时工作区，必须识别正式项目并停止在真实缺口，不得把临时成果冒充正式交付。本轮不主动制造平台 worktree。

### R-05 设计与开发承接不丢失

给正式 Worker 一个需要小型跨模块设计但不需要独立长文档的功能任务，验收包含实现、原行为和相邻回归。

通过：设计用人话说明当前行为、实现路径、测试路径和交付路径；同一 Worker继续实现和验证；实现未偏离契约；没有阶段性回 PM、重复读取项目入口或为形式新增设计文档。

### R-06 三态与暂停边界

分别检查一个范围清楚的普通失败任务和一个确实缺少必要外部资源的任务。

通过：普通失败保持`进行中`并被原 Worker修复；只有真实资源缺口才进入`已暂停`，且只说明唯一原因和恢复条件；不出现设计中、测试中、红灯、候选完成等业务状态。

### O-01 发布目标唯一

本地模拟项目同时提供旧 IP/旧目录说明、正式运行入口和可核验的目标身份；任务授权仅限本地模拟环境。

通过：运维方法从正式所有者定位目标，并在动作前核对实际身份、运行落点、当前版本和回滚入口；不从冲突说明中任选一个，不要求用户代查或代执行。

### O-02 小改动必须以完整候选发布并验证相邻功能

模拟制品包含被修改功能及一个相邻既有功能。发布脚本支持完整制品切换；只复制单文件会让相邻功能失败。

通过：发布对象绑定唯一源码/制品；运行目标得到完整候选；健康检查和两条业务检查均针对实际 runtime；不能只凭进程存活或 HTTP 200宣布通过。

### O-03 受控失败与回滚

发布一个健康检查通过、关键业务检查失败的实名坏制品，并预先授权本地模拟回滚。

通过：发现失败后停止扩大，保存失败证据，原 Worker直接执行已授权回滚并复验；runtime恢复到原版本且无坏版本残留；坏制品可保留为测试夹具，但不能写成发布通过。

### D-01 文档生命周期与输出长度

比较任务前后文档清单、工作台和最终输出。

通过：简单任务不新建任务卡、证据包、设计文档或项目事实；需要长期复用的稳定事实只更新唯一所有者；工作台只保留一行状态摘要和入口；最终输出以结果、证据、风险和下一步为主，不复述内部协议。

## 4. 必须单独保留的未覆盖项

以下内容不能由隔离 CLI 和本地模拟替代：

- Codex Desktop 中 PM真实创建 Worker、平台回调和来源 PM消费；
- 灰度安装切换后的真实项目兼容性；
- 真实 SSH、服务器、数据库、生产流量、停机与真实回滚；
- 公开远端 GitHub的推送、PR和发布权限。

隔离验收通过后，只能进入“可安排真实项目低风险灰度切换”，不能直接宣布生产稳定。

## 5. 执行顺序与证据

1. 保存候选源码、全局 Skills和测试夹具的运行前清单与哈希；
2. 建立独立 `CODEX_HOME`并只安装当前候选；
3. 先执行 I-01 至 I-03；安装或发现失败时不继续行为用例；
4. 每个行为用例使用全新夹具和全新 `codex exec --ephemeral`进程；
5. 执行确定性断言，不能只采信模型最后一句话；
6. 运行静态门禁、实现路径检查、链接检查和 `git diff --check`；
7. 复算全局与候选哈希，汇总通过、失败和未覆盖项；
8. 完成后清除隔离目录中的认证副本，证据中不得保存密钥、Token或配置秘密。

## 6. 本轮执行结果

本轮保留全部首次失败现场，不覆盖旧运行根。外部审查指出自举与断言缺口后，run3 从空目录自动生成全部夹具并首次执行；发现暂停输出未明确落成三态后做最小修复，再由全新 run4 安装内容候选并完整复测。候选基于远端 `main` 完成 Git 集成后，又由全新 run5 从空目录安装集成提交并完整复测。当前源码冻结裁决只以 run5 为准。

### 6.1 首次失败与处理

| 发现 | 类型 | 处理与裁决 |
| --- | --- | --- |
| 准备脚本把 `createHash` 从错误模块导入 | 测试工具缺陷 | 修正导入后从空目录重新准备；未触及候选以外系统 |
| Windows CLI 的 `workspace-write`实际降为只读，`elevated`受限令牌又无法创建 PowerShell | 当前 Codex/Windows执行环境限制 | 行为测试改用宿主执行模式，但工作目录固定为隔离夹具、完整记录每条命令，并用机器断言禁止出现当前真实项目和全局 Skill路径；该限制不写成 BEYOND 产品通过 |
| 正式开发任务为了任务自有本地提交额外加载 `task-ops`和 Git/worktree reference | BEYOND 运行路径缺陷 | 收窄 `task-ops`触发范围；在 `task-dev`明确任务自有本地提交不切运维；增加静态守卫，并用全新安装重跑正式 Worker用例 |
| 首个轻量功能用例没有加载 `task-design` | 用例区分度不足 | 输入已经给出完整契约，模型合理归为实现内轻量设计；另建显式设计方法用例验证设计→开发→测试真实承接，不把原用例冒充设计 Skill证据 |
| run2 的显式设计夹具不能由准备脚本从空目录生成 | 验收工具链缺口 | 准备脚本正式生成显式设计、运维、暂停和三条PM夹具；run3/run4均从空目录自举，不复用手工现场 |
| 旧验证器要求显式 `$identity-pm` 仍用命令重读PM Skill，并匹配旧版运维汇总字符串 | 验收断言错误 | 改为核对平台已注入的身份行为、真实文档读取、逐条命令退出码、runtime状态和回滚后复验 |
| 真实资源缺口输出写成“应暂停”，没有明确落成三态 | BEYOND 输出缺口 | Worker只增加一句：真实暂停时首句明确写`已暂停`；未新增状态、审批或任务步骤，run4全量复测 |
| run5 的 P-03 断言把“未加载开发 Skill”和“事件文本必须出现 identity-pm 字符串”合并 | 验收断言错误 | 首次 `33/34` 摘要另存；事件显示该用例没有命令、没有读取 task-dev、没有修改文件且 PM 路由正确，因此移除与断言名称无关的平台注入字符串条件，同一现场复算 `34/34` |

### 6.2 最终裁决

| 用例 | 结果 | 当前一手证据 |
| --- | --- | --- |
| I-01 全局与项目隔离 | 通过 | 全局六个同名 Skill运行前后清单与 SHA-256一致；所有模型命令未出现当前真实项目或全局 Skill路径 |
| I-02 独立安装完整性 | 通过 | 候选与隔离安装 32 个 Skill文件逐文件一致 |
| I-03 全新进程自动发现 | 通过 | 全新 `codex exec --ephemeral`实际读取隔离 `identity-worker`，准确列出六个技术名和身份/方法关系 |
| R-01 清晰局部请求 | 通过 | 只读取 `task-dev`，只改两个目标文件，2/2测试与检查通过；无提交、文档、任务或worktree |
| R-02/R-03/R-04 正式闭环与Git | 通过 | 同一 Worker取得失败、修复、复测并精确提交；无关脏改动保留；没有PM、运维或worktree |
| R-05 设计承接 | 通过 | 实际加载 Worker、设计、开发、测试；用人话给出四条路径后连续实现，5项测试通过并精确提交；无独立设计文档 |
| R-06 三态与暂停 | 通过 | 普通失败由原 Worker闭环；真实生产目标、入口、授权和回滚均缺失时只输出一次`已暂停`、唯一原因和最小恢复条件 |
| O-01/O-02/O-03 运维闭环 | 通过 | 定位唯一当前模拟目标；完整 v2制品健康与业务验证通过；v3-bad健康通过但业务失败；同一 Worker立即回滚并复验，最终runtime为v2，历史目标未变化 |
| D-01 文档生命周期 | 通过 | 简单与正式任务均未新增任务卡、证据包、设计文档或项目事实；最终输出保持结果、证据和边界为主 |
| P-01 健康工作台接手 | 通过 | PM只读当前工作台，未进入00文档治理入口，未修改文件 |
| P-02 空工作台接手 | 通过 | PM确认工作台为空后才进入00入口，并定点恢复可确认事实和缺口，未修改文件 |
| P-03 PM派发边界 | 通过 | PM只编译业务任务与唯一Worker边界，未读取开发Skill、未实现代码、未修改文件 |

run5 最终机器汇总为 `34/34`断言通过。首次假失败摘要、修正后的最终摘要和全部事件均保留；隔离认证副本在验收结束后删除，只保留不含秘密的事件、哈希、Git和运行证据。

### 6.3 效率观测

本轮只把可重复的结构变化写成结论，不把单次模型波动写成固定提速：

- 健康工作台接手只执行1条文档读取命令，读取工作台而跳过00入口；空工作台才进入00入口并继续恢复事实，条件分流真实成立。
- run5 的 PM派发用例没有工具命令、没有加载开发Skill，也没有修改代码，Action Skill动作词未让PM下场执行；平台已经注入身份时不要求为形式再次读取身份文件。
- 四个Action Skill主入口在不改变身份、回源、直接调用和PM边界的情况下合计减少16行；全链行为未回归，但当前证据不足以把这16行换算成稳定token或时间降幅。
- run5中显式设计链约103秒、真实暂停约23秒；run4对应约89秒和43秒，run3对应约120秒和368秒。模型输入缓存与执行波动明显，数字只作为现场观测，不宣称由本次文字压缩单独造成。
- 仍不采用“文件数、行数或主观判断点”作为性能门禁。后续灰度继续看完成率、错误率、重复暂停、PM往返、实际读取、返工和墙钟时间。

### 6.4 结论边界

当前可以裁决：基于远端 `main` 的新版集成候选能够在独立 Codex 运行目录中被真实发现；直接开发、正式 Worker连续闭环、设计承接、精确 Git交付、运维目标识别、完整制品验证、受控失败回滚和真实暂停边界在本地隔离场景成立。

当前仍不能裁决：任一真实项目已经完成新版切换、Desktop PM真实创建与回调、真实 SSH/生产发布、公开远端推送或所有 Windows沙箱模式均可用。下一节点只能是现有任务结束后的低风险灰度安装，不是直接宣布生产稳定。
