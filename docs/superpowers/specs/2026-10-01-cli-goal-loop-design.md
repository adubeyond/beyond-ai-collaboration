# CLI 目标协作设计

日期：2026-10-01。状态：设计待评审，尚未实施。基线：BEYOND 3.2.7。

## 要解决什么

把原生 Codex CLI 接入 BEYOND，作为可选的执行方式。CLI 使用用户配置的第三方 API，在指定项目目录工作，保留会话上下文；直接负责人下发一轮任务后不用陪跑，收到结果通知后再分析、纠正和续跑，直到约定业务目标真正完成。

本次不是把 CLI 限定为审查小工具，也不是用 CLI 替换所有 Desktop Worker。CLI 可以在授权范围内实际修改、测试和交付。默认 Worker 路径继续可用，用户现有项目、登录和生产任务不因启用这条分支被改动。

两条路径共用一套 CLI 启动、保存结果和通知能力：

```text
路径一：PM → Desktop Worker ↔ CLI → Worker 原有回传 → PM
路径二：PM 或 Worker ↔ CLI → 直接负责人核验并继续或收口
```

“直接负责人”指本次向 CLI 下发任务的 Desktop 对话。路径一中是 Worker；路径二中可以是 PM。CLI 只通知这个负责人，不同时接受 PM 和 Worker 两套指挥。

## 当前证据与尚未补齐的部分

本机原型已经展示了保存 CLI 会话、在同一会话续跑、保存运行记录，以及通过 Desktop 原生消息工具唤醒原负责人。已有原型测试记录不能替代本次产品实现的回归测试。

当前原型仍有以下产品化缺口：

- 首次启动没有完整的通知绑定路径；已知会话的续跑和事后绑定成功，不能证明第一次业务运行也能自动回调。
- 通知绑定只面向 Worker，不能直接支持 PM；现行工作台又要求真实 Worker 标识，不能把 PM 或 CLI 会话伪装成 Worker。
- Desktop 插件位置包含固定版本路径，源回合结束判断依赖本机记录格式；这些是本机兼容方式，不是官方跨版本保证。
- 同一会话的并发续跑、旧结果晚到、通知发送结果不明和应用重启需要明确处理，不能默认等于“成功送达”。

原生 CLI 的 JSON 事件、最终输出文件和指定会话续跑是已有能力；“CLI 完成后唤醒某个 Desktop 对话”则是 BEYOND 要接入并实测的能力，不能由前者直接推导。参见 [OpenAI 非交互执行文档](https://learn.chatgpt.com/docs/non-interactive-mode)。

## 方案选择

采用“轻量后台程序等待，原负责人做判断”。不让负责人停留在一个模型回合中定时查看日志，也不为每次 CLI 续跑新增一个 Desktop 对话。独立建立常驻消息服务会增加部署、权限和维护成本，本次不采用。

后台程序只管理当前已授权的 CLI 运行、落盘和通知。它不自动决定下一个业务动作，不自行无限续跑，不安装全局守护进程或 Hook。完成结果保存和一次通知尝试后退出；结果核对标记由负责人写入，通知不明也不让后台程序无限重试或等待。

### 负责人怎样使用

1. 明确目标、执行目录、验收办法、当前授权范围和相关事实入口，选择配置好的 CLI 运行档案。
2. 调用启动入口。入口稳定保存任务绑定并成功启动后台程序后，尽快返回本轮标识；不是等业务执行结束才返回。
3. 负责人继续其他工作，或结束当前回答。此时业务任务仍是进行中；不轮询 CLI，不保持模型等待，不因等待结果向上游制造一次业务暂停。
4. CLI 结束本轮后，后台程序保存结果并通知原负责人。成功、运行失败和异常结束都要形成可核对的记录。
5. 负责人定点读取匹配结果、必要的业务证据和当前用户指令。目标未满足且仍有安全动作时，把具体差距和下一步交给同一 CLI 会话续跑；目标满足后才验收。

源 Worker 为等待 CLI 而结束一个执行回合时，给用户说明“CLI 正在执行，结果将回到本 Worker”。这类明确转交后台执行的回合不再向 PM 发送普通“请续派”进展；否则会把 PM 拉回陪跑或触发重复执行。需要 PM 项目裁决、到达用户检查点、正式暂停或完成时，继续走原有对应回源路径。这个例外只适用于启动回执已确认的 CLI 后台运行。

## 任务、会话与状态

### 不增加第二个业务任务

Worker 把原任务的一部分交给 CLI 时，CLI 运行属于原任务，不登记第二个 Worker 或同名业务任务。Worker 对整体结果负责；最终仍按既有 Worker 协议提交回执、回调来源 PM，由 PM 核对和验收。

PM 直接把一个独立业务结果交给 CLI 时，工作台要登记这个真实执行方式。增加显式 CLI 执行绑定，记录负责人及 CLI 状态入口；不能拿 PM 的 threadId 填现有 Worker 字段，也不能用虚构 Worker 标识满足校验。仅在当前对话内使用 CLI 做一个辅助问题，不强制建立正式任务。

原有记录未声明执行方式时仍按 Desktop Worker 解释。不迁移旧任务，不改变其 Worker 唯一性、回执算法、验收事务和历史定位。

### 一份运行状态

以下是拟实现的语义，不是现行接口承诺。具体字段和命令在实施计划中与既有 runtime 对齐。

| 信息 | 用途 |
| --- | --- |
| 项目与任务标识 | 复用原任务身份，隔离不同项目中的同名任务 |
| 负责人对话标识、源回合标识 | 只回到真实调用者，并识别本次派发回合 |
| 执行方式、执行目录、运行档案引用 | 区分 Desktop 与 CLI，保持真实工作目录及认证来源 |
| CLI 会话标识、本轮序号、启动请求标识 | 同一会话续跑、重复派发去重及旧结果识别 |
| 目标与本轮指令、授权边界 | 保存下发依据，不把旧 CLI 上下文当成新授权 |
| 运行结果与通知处理记录 | 定位命令、文件变化、最终输出、退出状态及负责人裁决 |

当前会话和本轮状态以桥接运行记录为准，工作台引用这个入口，不再维护另一套独立的“当前轮次”。运行记录保存在经确认的控制面位置，与业务目录及其他项目隔离；会话和工程日志按原存储策略保留，不因负责人读取一次而删除上下文。

CLI 运行状态与业务状态分开：CLI 一轮成功退出，业务仍可能进行中；CLI 一轮失败，业务也不自动暂停。工作台沿用既有业务状态，不增加“CLI 成功”业务终态。

### 首次启动和连续续跑

首次启动先保存项目、任务、真实负责人和通知绑定，再启动 CLI；不要求负责人等 CLI 给出会话标识后回来补绑定。收到 `thread.started` 时立即保存会话标识。若启动在此之前失败，也用启动请求和本轮标识把失败通知回原负责人。

后续只能用已确认的会话标识续跑；不使用跨任务不确定的 `--last`，不通过重新 start 偷换上下文。缺少或冲突的会话记录先定点恢复，不能猜测一个会话或重复执行可能已有副作用的动作。

同一 CLI 会话只允许一轮执行。启动与续跑使用排他控制和请求去重；相同请求返回已有运行，不同指令的并发续跑明确拒绝，不能静默吞掉纠偏指令。旧结果可以查看，但不能覆盖新一轮状态或再次验收。不同任务是否能并发，仍由既有共享对象和 Git 操作边界判断，不全项目强制串行。

## 结果怎样回到负责人

### 先保存结果，再通知

后台程序消费 CLI 事件和进程结束信号，确认输出已稳定保存后才通知。成功运行须有匹配的会话、正常结束事件、退出状态和最终输出；异常退出则保存已知现场与原始错误，不能伪造成功，也不能把已发生的改动说成不存在。

通知只是“这一轮结果已就绪”，不表示业务验收完成。通知包含项目、任务、本轮及结果入口；工程明细留在结果记录。负责人据此核对真实文件、测试或运行证据，不只相信 CLI 自述。

CLI 中间结果不进入 `worker-result.enqueue`。路径一只由 Desktop Worker 在整个任务形成正式终态时使用它；路径二由 CLI 类型的验收分支核对运行结果和负责人裁决，复用工作台的幂等收口事务，但不伪造 Worker final、终态 pending 或 ack。

结果消费与业务完成也分开：负责人记录“本轮已核对”后可以继续原目标。只有业务验收成立，才把正式任务完成并归档。

### 保留待处理结果，保护主回答

派发时建立源回合结束观察，避免 CLI 很快结束便把结果插进尚未交付的派发回答。本机记录观察放在独立适配层中，订阅前后核对持久记录，覆盖结果先到、结束信号先到和订阅期间的竞态；不能只依赖一次文件事件。

源回合结束后，如果结果已就绪就发送；否则由后台程序继续等待 CLI 的实际结束事件。通知通过当前已安装且核验可用的 Desktop 消息能力送达原负责人，发现并验证实际插件入口和工具声明，不固定某个用户目录、插件版本或业务项目。

负责人处理 CLI 通知时先识别类型和本轮身份，不把它误当作 Worker 正式终态。若负责人正在处理另一个用户问题，保持那次问题、追加问题和已授权工作完整，在安全边界处理通知后接回原主线；不以一句 CLI 摘要替换主回答。

消息送达不等于负责人已经处理。分别记录送达状态和处理状态。超时或异常造成送达不明时保留结果，不能盲目重发；重复通知或重复处理请求不再次续跑或验收。下一次自然进入负责人对话时，允许定点核对其已登记而未处理的 CLI 结果作为补救，不建立全项目轮询。

Desktop 在忙碌回合尾部收到消息后是否会继续生成可执行回合，必须做真实宿主验证。本次不承诺跨应用重启、未知插件版本或任意宿主的永远自动唤醒；也不以用户手动催促后的处理充当自动回调通过证据。如果支持目标上只能送达却不能自动处理，该场景就是未通过，需要解决后才宣称路径可用。

## 执行能力和授权

CLI 在准确的执行目录启动，按任务相关性读取项目入口、事实和 Action Skill；配置档案需明确提供已安装 Skill 的可读入口，不假定隔离的 CLI 配置目录自动拥有 Desktop 的 Skills。无需为 CLI 再建立一个带 Desktop 回源义务的 `identity-worker` 身份。PM 直接使用这条路径，是让 CLI 执行、自己分析和推进，并非放开 PM 亲自改业务代码或操作生产的边界。

任务指令明确它是受直接负责人管理的 CLI 执行会话，正式任务状态和对外回源由负责人掌握。需要设计、开发、测试或运维时仍使用现有专业方法，避免新建一套重复 Skill。

第三方 API 的地址、模型和凭据通过独立运行档案配置，不复用 Desktop 订阅认证，不在任务、源码或运行命令中携带秘密，不静默回退到其他付费来源。运行档案中的凭据不序列化进结果，显示和共享日志前遮蔽认证信息。完整访问权限不代表获得生产、删除、发布或其他业务授权。

启动前只验证这条 CLI 路径实际需要的目录、档案、可执行程序和通知能力。没有 Desktop Worker 创建路线不应阻断直接 CLI 路径，但项目控制根和工作台写入仍须核对；不能跳过跨项目隔离或搜索任意控制仓。

CLI 普通失败后，负责人判断是调用错误、方法问题还是实际阻断；能安全修复就纠正并续跑。需要新授权、外部资源确实不可用或用户要求停止时，只停止受影响动作，按已有任务规则处理。连续同类失败不机械重复同一指令，也不无限烧额度。

用户停止或关闭任务时，先核对并停止本任务仍运行的 CLI 进程，再收敛任务。只操作保存且核验归属的进程，不能按名称批量结束 Codex。迟到结果不能恢复已关闭任务；用户更改目标或授权后，续跑先更新本轮指令，旧结果不能触发旧动作。

## 人怎样看见 CLI 在干活

保留原生事件、工具执行、文件变化、最终输出、当前状态和同一会话的后续记录。状态与日志入口返回给调用者，用户需要时可以查看；默认负责人不把全部日志再抄入聊天。

“保存了日志”不等于“运行在现有右侧终端”。本次必须如实区分后台执行记录、可以打开的日志视图和原生交互终端。实际终端入口只有在宿主提供相应能力并验证后才展示，不能声称已把命令输入现有侧栏 shell。无需暴露隐藏推理，也不为此建设网页监控站。

## 预计修改范围

| 位置 | 变化 |
| --- | --- |
| 产品根入口 | 增加 CLI 选路入口和唯一机制文档链接；默认 Desktop 路径不变 |
| PM、Worker 及相应 reference | 说明直接负责人、后台等待、结果判断和同会话续跑；仅增加明确选择 CLI 的分支 |
| 控制 runtime 与工作台呈现 | 增加 CLI 执行绑定及类型化核验；保留旧 Worker 记录、事务和回执语义 |
| CLI 桥接与宿主通知适配 | 移植原型中可复用部分，补首次启动、真实负责人、去重和兼容校验 |
| 测试与使用说明 | 覆盖两条路径及失败恢复，说明配置、实际可见性和支持边界 |

本轮仅保存本设计。实施也不直接修改真实业务项目、已安装 Skills、当前正在运行的本机原型、用户登录、模型矩阵或生产环境；先在隔离环境实现并验证。启用 CLI 不强迫其他用户安装它或更换认证。

本次不涉及真实安装与发布。未来启用按项目明确选择，不默认迁移正在运行的任务；停用仅影响后续选路，已有 CLI 运行须先由原负责人稳定现场和交接，不能靠切回 Desktop 掩盖未结束的工作。

## 验收和测试

先用临时项目及可控制的假 CLI、假通知宿主验证状态和竞态，再用真实 CLI、第三方 API 与 Desktop 验证完整路径。真实宿主测试使用隔离业务样例；不改生产数据，不把安装验真当作功能通过。

| 场景 | 必须证明 |
| --- | --- |
| 首次启动，CLI 很快结束 | 不需事后补绑定；启动返回不等待业务完成；原负责人结束派发后自动收到并处理结果 |
| CLI 在负责人空闲后结束 | 无用户催促、无模型等待或轮询，自动唤醒原负责人 |
| PM → Worker → CLI → PM | CLI 回到 Worker；Worker 核验后原有终态回执、回调、accept、ack 各一次，不新增正式 Worker |
| PM 直接与 CLI 协作 | 无中间 Worker；真实负责人和 CLI 执行方式可见，类型化核验和归档正确 |
| Worker 与 CLI 连续协作 | 等待 CLI 不引发 PM 续派；已有会话继续，不把后台执行报告成业务完成 |
| 多轮目标纠偏 | 第一轮部分完成或普通失败，负责人指出缺口并续跑同一会话，最终以文件和测试证明目标完成 |
| 两个任务和忙碌负责人 | 结果分别归属原任务；重复、延迟或回合尾部到达都不丢处理，不遗漏用户主问题 |
| 重复启动或并发续跑 | 一个会话只运行一轮，重复请求不重复执行；旧轮次不能覆盖新结果 |
| 身份及路径错配 | 不同项目、负责人、会话、执行目录或结果入口错配被拒绝，其他任务记录不变 |
| 进程、API 或通知异常 | 失败现场保留，不假完成；送达不明不盲重发；恢复不重复已有副作用 |
| 用户纠偏、停止和关闭 | 新授权生效，旧通知不能续做旧动作，进程停止和记录状态一致 |
| 默认 Worker 回归 | 未启用 CLI 的完成、暂停恢复、非终态进展及前台保护链与基线一致 |
| 可见性和配置隔离 | 看得到实际工作记录；同一会话可追溯；不泄露凭据、不误用 Desktop 认证、不虚构侧栏终端 |

每个测试保存实际动作、事件顺序、状态变化及断言结果。真实自动唤醒、第一次绑定、忙碌主线保护和旧 Worker 回归是放行必需证据；模拟通过只证明相应程序逻辑，不能代替这几项真实验证。
