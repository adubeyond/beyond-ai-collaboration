# BEYOND v3.2.5 候选升级说明

> 当前状态：R6预发布候选。公开稳定版仍为`v3.2.4`；R6通过发布门禁后作为预发布候选公开，不冒充稳定版。

## 新PM先理解项目，再设计任务

- 新PM首次接手时一次性读取根入口、当前项目身份与路由、项目总览、当前工作台、项目事实索引及其登记的全部当前主事实正文，同时建立项目/仓库/模块地图；不要求老板靠固定短句重新介绍项目。
- 已有上下文的PM复用未变化的理解，只刷新工作台、路由和本轮受影响的事实所有者；历史、归档、候选、全部Worker聊天、全仓源码和原始证据不进入默认接手链。
- 老板给出非平凡短提示时，PM先用`task-design`轻量模式收敛业务结果、上下文、边界、验收和唯一真实用户取舍，再形成紧凑任务包。技术设计、实现、测试和发布路径仍由唯一Worker决定。
- 普通任务设计留在PM内部，不新建设计文档、计划、报告或检查点；任务包只链接直接相关的精确事实所有者，不复制整份runbook或项目资料。

R6不修改Worker终态回调、pending回执、`workbench.accept/ack`、唯一Worker、暂停恢复或终态顺序；这些继续沿用已经验证的3.2.5控制链。

## R4-R6补充改进

- 面向老板的第一层答复先说业务结论、影响和下一步；没有明确要求时，不用内部字段、命令清单和工程黑话代替判断。
- 当用户前提与当前项目证据冲突时，先说明真实情况，不为了完成表面动作引入依赖、迁移框架或扩大工程范围。
- 模糊“优化”不会自动制造性能、重构、打包或未来能力目标；有真实缺陷时只做解决它所需的最小完整修改。
- 老板明确关闭不再运行且没有待处理回执的任务时，`workbench.close`保留关闭原因与授权入口，任务以“已关闭”进入历史。

## 安装包校验口径

- ZIP是唯一必需的下载文件；同名`.sha256`是可选验真材料，缺失或下载失败不得阻断安装。
- 若提供了`.sha256`而计算结果不一致，必须停止，不能忽略或伪造通过。
- 无论是否提供外置校验文件，包内65文件清单和安装后的完整性验真仍是硬门槛。

## 项目路由从单目录升级为四根模型

- `canonicalProjectRoot`负责BEYOND正式项目身份；`repositoryRoot`负责本任务登记的仓库或交付根；`executionRoot`负责Worker当前精确checkout；`controlRoot`负责唯一控制仓。
- 单仓本地任务四根可以相同。一个BEYOND项目也可以覆盖多个明确登记的子仓、外置仓和平台已提供的既有worktree，不复制控制仓，也不创建第二个worktree。
- 跨根任务携带由`project.resolve`形成的完整`projectRoute`。runtime复核项目、路径、Git/worktree、remote、host与Codex项目绑定；任何漂移都在写入pending前拒绝，不搜索或猜测另一个控制仓。

## 回执隔离与升级保持性

- 短期终态回执改为`projectId + taskId`命名空间；跨项目同名任务不能互相覆盖、扫描或ack。
- 旧的task-only pending以并发安全方式迁移；重复副本只有回执身份一致时才能收敛，迁移不制造第二份业务结果。
- 安装和升级保留已登记仓库根、remote、host和Codex项目绑定。当前目录变化不能静默改写正式登记。

## 规则唯一所有者

- Worker终态顺序只由`identity-worker/SKILL.md`拥有；PM匹配、验收、暂停和回执消费只由`identity-pm/references/lifecycle-and-closeout.md`拥有。
- 历史回传记录和中英文架构只解释问题与构件关系，不再复制会漂移的执行算法。
- 静态门禁同时核对双语架构、历史记录、版本说明和Changelog，阻止旧的全Worker扫描口径重新进入当前规则。

## R6验收边界

- 本地门禁覆盖项目身份、四根路由、既有worktree、独立clone拒绝、remote漂移、项目级回执隔离、并发迁移、安装、升级和公开内容。
- R6公开前仍需核对候选制品与发布资产一致；真实安装、Codex重启和平台回调属于独立的后续证据，不能由本地门禁替代。
- 候选打包通过不等于已安装、已发布或长期项目稳定；不安装Hook、notify分支、守护进程、额外Codex CLI或第二套调度器。
