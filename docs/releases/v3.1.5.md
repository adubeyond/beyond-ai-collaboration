# BEYOND v3.1.5 升级说明

> 对比范围：`v3.1.4 → v3.1.5`。本版本不改变一个项目一个PM、一个业务结果一个唯一Worker、三态、同一Worker按需使用设计/开发/测试/运维方法、默认不创建worktree以及生产授权分离等主干。

## 解决的问题

### PM回答不再被Worker终态打断

旧路径把Worker的暂停或完成结果直接注入来源PM对话，可能抢占PM正在生成的用户回答。v3.1.5改为项目隔离的本机结果收件箱：

1. Worker只在真实暂停或完成时，用固定脚本登记一条紧凑结果；
2. PM只在用户主动新回合、显式状态查询或要求收取结果时读取一次；
3. PM先回答当前问题，再核对唯一Worker、正式任务线程和主证据；
4. 更新工作台后才确认归档；重复结果幂等，损坏或串项目记录失败可见。

这项变化有意取消“完成结果立即唤醒并打断PM”的行为。PM会在下一个安全用户回合感知结果，而不是后台轮询。

### 新Worker模型策略有唯一所有者

项目初始化会展示两种明确选择：

- `platform-default`：不传模型和推理参数，保留平台默认；
- `beyond-worker-matrix-v1`：普通工程使用Terra/high，大量低风险结构化核对使用Luna/high，复杂架构、疑难故障和生产风险使用Sol/xhigh。

用户确认的长期选择写入项目总览受管块，由固定脚本展示、保存和解析；根入口、工作台和旧聊天不再保存第二份策略。当前PM对话中的临时模型选择仍可覆盖后续新Worker，但不会改变当前PM或既有Worker。

### 工作台和结果事实更可靠

- PM通过固定脚本定点更新普通里程碑，脚本执行结构校验并保留恢复备份。
- Worker结果涉及字段映射、对象归属或前后值时，必须保持“实际是什么、应是什么”的原方向，不能倒置。
- 完成任务从当前工作台收拢到本机月度历史；结果收件箱确认后同样进入本机历史，不形成第二张任务台。

## 升级边界

- 安装或升级后仍需按[安装、升级与项目初始化指南](../../模板交付包/docs/安装升级与项目初始化指南.md)完成项目接入；复制文件不等于老项目已经初始化。
- 旧根覆盖区中的Worker模型策略不会静默继承。初始化会展示实际选项，用户未确认时保持平台默认。
- 本机结果收件箱不通过Git共享，也不替代正式Worker任务、主证据或团队协同文档。
