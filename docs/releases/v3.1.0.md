# BEYOND v3.1.0 升级说明

> 对比范围：`v3.0.9 → v3.1.0`。发布版本不表示任何真实项目已经自动升级或可直接用于生产；安装、融合与实际目标仍需分别验证。

## 本次只增加什么

- 一个与业务项目平级的内部`beyond-control`仓库，同时保存 BEYOND正式文档、项目级文档、团队任务和协同内容；
- `local/`中的个人工作台和本机项目映射，由 Git强制忽略并支持本机备份恢复；
- 团队任务与协同的共享 Markdown、默认分支同步、精确提交、冲突停止和精简归档；
- 新项目初始化与已有项目接入/升级两句明确入口；
- 项目识别、登记、`AGENTS.md`融合备份、同步、汇总和归档的固定动作脚本。
- 项目级Codex身份护栏：会话身份在继续、恢复和上下文压缩后保持，PM业务写入被机械阻断；已有Hook先备份再合并。

## 保持不变

- PM与Worker仍是两个身份，设计、开发、测试和运维仍是同一Worker选择的方法；
- 正式业务任务仍由一个用户可见Worker连续负责；
- 业务状态仍只有`进行中 / 已暂停 / 已完成`；
- 普通个人任务不读取团队共享区，不增加审批、PM往返、reviewer或worktree；
- 业务代码、分支、测试、发布和回滚继续由对应项目原有机制管理。

## 初始化

安装成功后只展示两句带身份入口的提示，不自动扫描或修改项目：

- `$identity-pm`后输入`使用 BEYOND 初始化这个新项目。`
- `$identity-pm`后输入`使用 BEYOND 接入或升级这个已有项目。`

已有项目先调查代码、Git、现有`AGENTS.md`和Markdown，再逐组让用户确认融合与迁移。固定脚本会备份原入口和既有Hook；业务项目只保留融合后的完整根入口及`.codex`身份护栏，不复制整套 BEYOND文档。首次安装或护栏内容变化后，用户在Codex中审核并信任一次。

本地融合不自动取得远端Git权限。固定脚本会建立共享登记、最小项目总览和最小事实索引，避免融合入口断链；需要共享时，用户另行授权后只用`project-registration`范围推送同一项目的这三份基础文件。remote中的HTTP凭据和查询参数不会写入本机或共享Markdown。

## 发布验证

发布前已完成安装完整性、控制仓初始化、项目入口与Hook融合、身份登记/恢复/写入阻断、根入口替换后身份连续性、3.0.9受管入口升级不叠加、跨盘符与带空格控制仓定位、`local/`写前备份与恢复、团队任务和项目登记精确推送、remote脱敏、范围外推送与归档路径穿越拒绝。71个真实Codex隔离场景聚合断言200/200通过，完整PM派发、唯一Worker执行、终态回传和PM收口控制链24/24通过，并完成真实长上下文压缩恢复验真与人工冻结。结论只覆盖本次Windows/Codex测试环境及声明场景，不外推为所有平台、真实业务项目或生产环境已经通过。
