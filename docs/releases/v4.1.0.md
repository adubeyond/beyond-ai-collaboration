# BEYOND 4.1.0：协作与交付层更新

4.1.0 将已完成的协作与交付候选整理为完整发行版，不是增量补丁。本次发布整理不再新增一轮业务流程改造；保留 4.0.1 工程资料体系、原 CLI 会话能力和此前 CLI 修补。旧发行资产不覆盖，发布也不自动安装到任何业务项目。

## 主要变化

- **三种职责，按需要组合。** 项目 PM 管理整体主线、取舍与真实依赖；产品交互负责人形成可体验的原型并说明业务行为；模块负责人兼顾规划与实施，可自行开发，也可按需使用助手或 CLI。职责不强制对应三个对话，也不要求模块负责人再派一个执行者。
- **以小目标交付，不把整体目标拆丢。** 一个目标对应可验收的业务结果。前后端按耦合和并行收益决定是否拆分；拆分后由一个已有负责人组合，验证实际页面、接口和数据链，而不是汇总两份组件自测。
- **原型与工程资料相互补充。** 新交互先用原型讨论，保留需求、数据来源、权限、异常、接口和验收设计。复用已有文档、交接与合适的 UI 技能，更新原入口，不批量迁移资料。纯后台任务和既定流程局部修复不强加原型前置。
- **当前设计对应当前验收。** 可选交付契约绑定设计修订、接口版本和真实成果引用，防止旧验收跨改版收口。机器检查只核对关联和状态，不认证用户授权，也不判断证据内容是否真实。
- **通知只交给直接负责人。** CLI 结果按当前负责人定点送达，处理负责人移交前后的旧通知竞争。不广播给其他 PM，不把协同建议当成用户指令，不借通知自动恢复暂停目标。
- **归档后仍能保全与清理。** 正式 CLI 的原负责人可查询归档结果和受管清理空闲管理器，不能借此续跑、新建会话或接管活进程。管理器退出与旧窗口状态分别报告；身份不足时保留未知。

## 保留什么

桌面 Worker 终态回执存储与收口顺序、模型矩阵保持原底座。既有 CLI 阶段交付、资料读取、同会话续跑、程序定位、兼容性检查、受管停止和回收能力保留，不重写 CLI 引擎。

完整包增加 `identity-product`，共七个 Skill。安装保留项目资料、配置、原会话、历史结果、审查记录和成果，不自动配置第三方认证、转换旧任务或恢复业务。

## 验证边界

既有隔离测试覆盖契约修订、组合、通知归属、归档查询和回收等行为；双负责人直接交接试验复用了已完成实现，是现有功能的组合复验，不是从零开发的完整自主交付试验。已有通知后的网络连接超时记录不因一次后续通过而消失。

本版不宣称已证明业务交付质量提升、固定额度节省、所有模型可用或长期无人值守稳定。最终正式检查以对应源码、CI 和发行附件为准。详见[验证与限制](v4.1.0-validation.md)。

安装与回退见[4.1.0 安装说明](v4.1.0-install.md)；产品入口见[完整交付包](../../模板交付包/README.md)。
