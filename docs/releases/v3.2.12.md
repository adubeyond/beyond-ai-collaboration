# BEYOND 3.2.12：三种 CLI 助手，共用一条目标协作路径

保留桌面 Worker 默认路径，在已授权的可选 CLI 分支中加入 ZCode 和 Claude Code。负责人可以把开发、核查或审查交给原生 CLI，继续自己的工作；CLI 本轮结束后主动通知，负责人核验结果，再决定继续原会话还是验收。

## 本次变化

- **真实可见会话**：Codex、ZCode、Claude Code 保留原生终端、工具过程和会话上下文；不是把日志伪装成聊天。
- **并发完成不抢前台**：同一负责人的通知串行发送；重新核对其最新回合已结束，再通知下一份结果。失败与未知结果也保留并回传，不冒充完成。
- **按任务换档**：每轮明确模型与推理强度，任务之间相互独立。结束并核验当前轮后，可以换档续接保存的同一会话，不更改共享默认配置。
- **明确执行权限**：已获完全访问授权的路径使用 Codex never/full-access、ZCode yolo 或 Claude bypassPermissions，避免逐命令等待人工批准；系统权限、目录信任和服务端模型授权仍须如实处理。
- **修复实测问题**：处理进程退出竞态；补齐 ZCode 设置强度的原生调用参数；保留被界面后续错误遮盖的原始模型错误。
- **保留已安装的权限纠偏**：明确策略拒绝不能换入口绕过；无关临时文件清理被拒时如实保留，不因此卡住未受影响的任务。
- **通用 CLI 负责人移交**：按用户指令移交已经稳定结束的正式 CLI 任务，保留同一会话及历史；接手人独立复核，移交中断可以恢复，不重开任务。
- **业务验收回归项目文档**：不在通用 runtime 写死特定项目、站点或日期窗口；历史自定义字段和证据保留，仍按项目原有验收标准判断成果。

## 不改什么

不改变六个 Skill、桌面 Worker 的终态回调、短期回执、验收、暂停恢复、任务状态及模型矩阵。不新增常驻服务，不安装第三方 CLI，不分发认证、本机配置或测试数据；CLI 不自动获得生产发布权限。另一批 PM 规则草稿未并入本包。

## 支持边界

- 实际原生验证版本：Codex 0.162.0-alpha.2、社区 zcode-app-cli 3.14.4-32、Claude Code 2.1.294。
- ZCode 和 Claude 可见终端集成含版本相关私有接口，作为明确可选的试验适配提供；升级这些 CLI 后必须重新核验，不宣称任意版本稳定兼容。
- 实测通知、配置与同会话续跑不等于长期送达保证；本机完全访问不能绕过操作系统或第三方服务拒绝。
- 适用官方 3.2.11 基线。已有本地热修复或定制规则须先比较并保留，不能仅凭版本号相同就整包覆盖。

安装不等于自动启用三个 CLI，也不会替换现有业务执行者。详见[验证结果与限制](v3.2.12-validation.md)、[安装与升级](v3.2.12-install.md)及[CLI 具体用法](../../模板交付包/docs/AI编程协同机制/机制/04-CLI目标协作机制.md)。
