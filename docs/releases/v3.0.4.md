# BEYOND v3.0.4 升级说明

> 状态：已发布 · 2026-08-01
>
> 对比范围：`v3.0.3 → v3.0.4`。当前公开版本为`v3.0.4`；公开发布不表示任一具体项目已经安装或进入生产。

## 为什么继续调整

v3.0.3重建了根入口、PM、Worker和四个专业Skill的真实串联，但真实项目反馈表明，任务版本、执行回合、终态事件、默认worktree和多层文档门禁仍会让普通业务任务绕路，PM也容易被过程回调占用。

v3.0.4不再通过叠加规则修补这些问题，而是缩短默认运行链：PM管理团队，唯一Worker连续完成业务结果，设计、开发、测试和运维仍是Worker或直接调用者选择的专业方法。

## 主要变化

| 维度 | v3.0.3 | v3.0.4 |
| --- | --- | --- |
| 业务状态 | 任务状态与终态事件、消费和裁决并存 | 业务状态只保留`进行中 / 已暂停 / 已完成`；测试和运维裁决不是任务状态 |
| Worker执行 | 已能跨Skill连续推进，但仍保留较重的回合与终态协议 | 一个业务结果只由一个Worker控制；普通失败、修复、复测和任务内提交不返回PM审批 |
| PM职责 | 管理主线并消费正式终态 | 维护低频工作台、任务关系和最终证据裁决，不做日常消息中继或阶段审批 |
| 项目接手 | 默认先进入完整项目文档入口 | 先读当前工作台；只有工作台为空、缺失、冲突或确需文档治理时才进入00入口 |
| 工作区 | worktree曾是常见隔离手段 | 用户指定项目是默认工作区；BEYOND不自动创建worktree，同目录按路径/对象划界并行，共享Git动作串行 |
| 协同机制 | 以多智能体协议和事件隔离为核心 | 03只处理真实跨任务依赖、共享对象、写入顺序和接力，不参与单任务冷启动 |
| 项目事实 | 存在能力状态与初始化倾向 | 技术栈、测试、服务器、发布、回滚和凭据入口继续保留，但不再成为任务启动许可证或能力状态机 |

## 默认运行路径

### PM管理的正式任务

```text
用户 → PM创建用户可见的正式任务与唯一Worker
     → Worker按需选择设计/开发/测试/运维
     → 内部子智能体只做任务内局部协助并返回Worker
     → 普通失败在原Worker闭环
     → 暂停或完成时低频返回PM
     → PM依据正式落点和一手证据更新工作台
```

### 用户直接提出的清晰请求

```text
用户 → 当前基础智能体 → 对应Action Skill → 直接交付
```

直接请求不凭空制造PM、Worker、任务台行、事件或执行回合。正式任务中的Action Skill也不会成为新的控制智能体。

## 保留的生产级边界

- 文件、Git、服务、数据、环境、生产和外部费用仍是不同权限维度，不能互相推导。
- 同一目录内边界不重叠的Worker可以并行编辑和验证；共享对象及Git索引/历史动作串行，无关脏改动必须保留。
- 复杂设计继续使用一个可实现、可测试、可交付并可归档的活动设计文档。
- 测试继续使用`通过 / 不通过 / 不能判断`，并绑定真实命令、退出码和断言。
- 发布继续绑定唯一候选、目标环境、实际运行状态和可执行回滚；健康检查不能代替关键业务验证。
- 只有业务取舍、高风险边界、无法解决的共享冲突或必要外部资源不可用时才能暂停。
- 只有成果进入约定正式目标并由当前一手证据验收后才能写`已完成`。

## 有意替换的旧机制

以下内容不再作为默认运行合同：

- 任务版本、执行回合、事件ID和每回合唯一终态的完整事件协议；
- 领取、启动、候选完成和普通进展等生命周期消息；
- PM对普通阶段切换、失败修复和任务内Git提交的逐步确认；
- 自动为任务创建或切换worktree；
- 为了任务启动而补齐全部项目事实或能力状态。

它们不是被忽略，而是由更直接的真值替代：当前工作台保存低频团队状态，正式任务线程保存过程，Git保存版本与归属，测试和运行现场保存一手证据。

## 从v3.0.3迁移

1. 保留现有项目代码、工作台、任务记录、技术栈、服务器、发布和凭据入口，不要用模板整目录覆盖真实项目。
2. 更新根`AGENTS.md`、PM/Worker和四个Action Skill，再按项目实际情况迁移工作台和00入口。
3. 将仍在使用的旧03机制引用改到“跨任务协同与共享对象机制”。
4. 已经按任务版本/执行回合保存的历史证据继续作为只读历史，不必重写成三态。
5. 正在运行的任务先完成或暂停，再做灰度切换；不要在活动Worker仍会读取或写入旧规则时热替换。
6. 隔离安装通过后，先选择一个低风险真实任务验证读取、Git、测试和回源，再扩大范围。

## 当前验证

发布版本已经完成：

- 94个公开文件的结构、链接、Skill入口和关键规则检查；
- 40项实现路径守卫，其中包含正式Worker显式身份、内部子智能体和直接PM回源的平台边界；
- 全新隔离安装与9条真实Codex路径，机器裁决34/34通过；
- Codex Desktop源码直读任务拓扑探针在保留三次缺陷证据后通过：正式Worker以首行`$identity-worker`落入左侧任务，并只向直接PM回传；
- 直接修改、正式Worker修复、设计→开发→测试、完整制品发布、受控失败回滚、真实暂停和PM冷启动A/B；
- `git diff --check`和隔离认证清理。

这些证据仍不证明本机全局补丁已经安装并被新进程自动发现、真实SSH、生产发布、远端Git合流或所有平台版本均已通过。Desktop源码直读创建与回调已经通过，不能替代安装版验证。
