# BEYOND 4.0.1：CLI 阶段交付、资料读取与独立执行修补

这是基于 4.0.0 的完整修补版，不是增量包，不覆盖旧版发行资产。保留 4.0 的工程文档体系、三种 CLI 能力兼容和负责人移交；本次不安装到任何已有项目。

## 主要变化

- 每轮 CLI 明确本阶段交付，同时保留完整业务目标。新要求可保存，并在本轮结束、审查后按现有接续路径进入原会话，不在忙碌轮中强行插单。
- Codex、Claude Code、ZCode 接入当前需求、设计和必要 Skill；续跑刷新适用资料，不拿旧聊天替代现行文档。
- Codex 自动解析当前可用程序，不再依赖旧安装目录。已运行进程继续使用其绑定程序，不因公共配置更新而迁移。
- Windows 新启动的受管管理进程检查独立于调用宿主的关闭作业；调用端退出后已派发工作可继续，重新接入时读取原结果并续用原会话。
- Windows 进程身份查询直接读取同一 .NET 创建时间，避免已复现的 Get-Process 命令路径停顿；不降低进程归属和 PID 复用检查。
- 新增三份产品脚本全部进入 Git 和完整包；新增七项 CLI 专项接入 Windows/Ubuntu 公开 CI，候选和正式包均绑定干净提交、清单与解压验真。

## 已知问题与边界

1. `gemini-4-argon` 在三种 CLI 的真实调用均遇到第三方网关 HTTP 503；明确错误包括通道 `channel_info` JSON 解析失败。尚未验证 Gemini 首轮成功或续聊，不能宣称所有模型可用。
2. 本次网关拒绝 Codex GLM Flash 的 `medium`；本机默认及公共 profile 改为受支持的 `low` 后，默认启动、读文件和当前 BEYOND 程序同会话续聊通过。这是本机配置修正，不随通用包分发，也不修改模型矩阵或旧任务保存的显式设置。
3. npm Codex CLI 0.160.1 的一次独立续聊等待 150 秒未返回，原因未确定，不算通过；当前受管解析的 0.163.0-alpha.10.2 完成对应续聊。结果不互相替代，也不因此建立版本白名单。
4. 宿主关闭验证使用自有隔离 Windows Job，未关闭用户实际桌面端；不能冒充真实生产关闭重开验收。
5. 独立生命周期仅对新入口启动的管理进程生效，不热迁移旧进程，不保证系统注销、关机、重启或手工关闭 CLI 后继续执行。离线结果保留，但没有新增通知补发或自动唤醒机制。

桌面 Worker 回调、通知协议、任务状态、六个 Skill 和模型矩阵不变。原 CLI 会话、结果与审查记录不迁移、不重建。包不包含项目私有资料、凭据、第三方模型目录或本机 profile。

参见[安装说明](v4.0.1-install.md)、[验证与限制](v4.0.1-validation.md)和[CLI 协作机制](../../模板交付包/docs/AI编程协同机制/机制/04-CLI目标协作机制.md)。
