# BEYOND 3.2.13：接回业务背景与软件工程资料

在现有协作机制上接回 2.0 的软件工程资料体系，让 PM 能理解项目全貌，让执行者能沿任务找到业务依据、工程契约和验证方法。不是另建一套任务流程，也不要求先写完全部文档才能开工。

## 本次变化

- **资料不再只有目录和命令**：补充业务流程与规则、产品交互、架构与核心逻辑、数据接口、专题开发和阶段决策的内容分工，连接已有测试、运行、发布及安全资料。
- **接通读取路径**：新 PM 按现有接手入口读取当前主事实，建立全局理解；执行者从任务点名原文出发，按直接依赖补读需要的专题，不把全部历史资料塞进每个任务。
- **复用与逐步维护**：已有文档保留原位置和内容所有者；初始化接入口，任务中补当前必需内容，核实后写回原文。已确认目标、已定方案和当前实现事实分开，不用错误实现覆盖业务目标。
- **修正入口识别**：支持引用式 Markdown 链接；相对路径和章节必须可达；代码、引用及 HTML 示例不能冒充正式入口。保留已有索引，不覆盖未涉及的项目资料。
- **保护登记与写前备份**：重新登记或融合项目入口时保留已声明执行副本；固定入口在修改相关文件前保存范围明确的前像，拒绝把这种部分备份当成整目录恢复包。
- **修复子目录身份误判**：从项目或仓库子目录进入时，按实际仓库关系解析执行根；合法 worktree 和已登记副本继续可用，错误路径和损坏声明仍被拒绝，非 Git 子项目不能借父级 Git 仓扩大执行范围。
- **清除过期矩阵说明**：项目总览指向当前模型策略，不再推荐已过期的策略名称；模型选择行为不变。

后续修复集中在三个产品文件：`scripts/beyond-control.mjs`、`scripts/runtime/project-identity-provider.mjs` 和项目总览模板；没有借此改造回调或扩大任务状态机制。

## 保留什么

完整保留现有 CLI 命令通道、原生会话恢复、进程身份、执行副本路由及锁竞争修补，包括此前的 Claude Code 兼容调整。身份与专业方法说明仅调整相关资料读取、补齐和维护路径；桌面 Worker 回调、短期回执、验收与暂停恢复、模型矩阵保持不变。

这是完整升级包，不依赖此前的资料增量包；已有项目无需重做初始化。项目业务文档、运行状态、CLI 会话和认证不随通用模板覆盖。

## 支持边界

资料入口可读不等于内容永远正确，也不保证模型一定完整交付；实际业务事实仍须核对来源。本版验证重点是文档结构、读取路径、登记与身份逻辑以及现有功能的本地隔离回归，不是新一轮真实桌面回调或生产验收。
