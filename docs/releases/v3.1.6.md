# BEYOND v3.1.6 升级说明

> 对比范围：`v3.1.5 → v3.1.6`。本版本不改变一个项目一个PM、一个业务结果一个唯一Worker、三态、同一Worker按需使用设计/开发/测试/运维方法、默认不创建worktree以及生产授权分离等主干。

## 1. 解决的问题

旧版在完成最低接入后，没有把“完整初始化”或“先使用、后续按需补齐”保存为可恢复状态。项目文档迁移、事实索引和根入口收敛可能停留在聊天记忆中，最低接入也可能被误报为完整初始化。

v3.1.6在项目总览增加唯一受管状态，并通过控制仓固定脚本完成查看、选择、逐组登记和最终收口。普通任务不读取这段状态。

## 2. 新的初始化路径

1. 安装或升级先完成最低接入和安装验真；
2. PM只向用户询问一次：现在完整初始化，或先开始使用、后续按需补齐；
3. 完整初始化按项目总览、架构、开发、测试、运维、安全和其他资料逐组处理；
4. 正式入口必须真实存在，且除项目总览外必须先进入项目事实索引；
5. 完成时重新核对所有入口和根`AGENTS.md`；
6. 选择按需补齐时，普通任务可以立即继续，之后从首个待处理组恢复。

PM只在用户确认的初始化范围内迁移或登记项目Markdown、更新事实索引和瘦身根入口。该例外不授权业务代码、测试、配置、环境、数据、远端Git或发布操作。

## 3. 升级后的第一步

升级和安装验真完成后，在项目根启动PM并输入：

```text
$identity-pm
使用 BEYOND 接入或升级这个已有项目。
```

PM会从项目总览的固定状态继续，不要求用户记住旧对话，也不会自动启动或恢复业务任务。

## 4. 验证范围

- 隔离老项目完整初始化和按需补齐：34项断言通过；
- 团队控制仓66项、实现路径286项；
- 安装、项目入口迁移、老项目接入和Worker策略回归通过；
- 正式公开候选严格检查和`git diff --check`通过。

这些证据证明源码候选和本地隔离路径，不等于真实项目已经升级，也不证明生产发布或用户可用。
