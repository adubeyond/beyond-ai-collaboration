# BEYOND v3.2.2 升级说明

> 对比范围：`v3.2.1 → v3.2.2`。本版本闭合暂停Worker恢复回合的终态可靠性缺口，并收短明确业务目标的普通执行路径；不改变身份、三态、任务所有权或模型矩阵。

## 终态可靠性

1. PM恢复原Worker时只传当前发送工具的必填字段；当前标准调用为`threadId + prompt`，不附加可选`hostId`、模型或推理参数。
2. 正式Worker在原生回调前把同一份冻结final写入项目内短期pending；平台恢复回合final暂不可读时，PM仍能按`projectId + taskId`收口。
3. 工作台暂停或完成事务成功后立即删除pending；中断时用同一`receiptId`派生的稳定操作号幂等恢复，旧回执不能删除更新后的结果。

## 目标优先与执行收敛

1. 用户当前明确、知情且对象具体的指令优先于BEYOND默认偏好和历史项目约束；文件、远端Git、环境、服务器、生产数据、不可逆动作和外部费用仍分别授权。
2. 清晰本地开发只需运行现有测试时继续由`task-dev`闭环，不为了测试动作额外加载`task-test`，PM也不替Worker预选Action Skill。
3. 标准工具或依赖入口被拒后最多尝试一次不改变结果与风险的定点等价路径；仍不可用时保留已授权可逆成果并准确说明缺口，不再搜索整机、缓存、其他安装器、版本或网页，也不重复运行已知无法启动的测试。

## 保持不变

- 原生回调仍只负责唤醒；用户可见Worker任务仍输出完整final。
- 一个业务结果仍由一个Worker负责，状态仍只有`进行中 / 已暂停 / 已完成`。
- 不增加Hook、notify适配器、后台进程、额外Codex CLI、worktree、轮询或长期消息收件箱。
- 普通新Worker完成、真实暂停、忙碌PM和并行回调继续沿用3.2.1已验证路径。

## 发布验收

已完成内容与安装完整性验真，并在真实Codex Desktop项目中验证正常完成、真实暂停、同一Worker多阶段恢复、忙碌PM、并行收口和pending消费删除。目标优先路径另以明确授权写入与精确删除、用户指定浏览器路径，以及一个正式Worker完成单文件修改、一次测试、一次提交、一次回传和一次验收进行验证。
