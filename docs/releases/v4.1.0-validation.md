# BEYOND 4.1.0 验证范围与限制

本版晋级已有协作与交付隔离候选。历史候选通过记录、此次源码回测、公开 CI、完整发行包和业务项目验收是不同事实，不能互相替代。最终发布结论以对应提交的 CI、完整包清单和发行附件为准，本页不预报尚未完成的测试数量或结果。

## 本次发布检查范围

- 核对根入口、三种职责、七个 Skill、文档链接和安装入口一致；候选身份与正式发行身份不能混用。
- 回归小目标交付契约、设计修订、接口与组合证据关联，包含旧验收跨改版拒绝及错误、缺失、过期关联反例。
- 回归直接负责人通知、并发结果、重复通知、负责人移交、暂停边界以及归档后的查询与空闲清理。
- 核对既有 CLI 会话、模型配置、结果、审查记录及资料传递兼容性；不把运输成功视为模型理解正确。
- 对正式来源打完整包、核对内容清单与字节、解压验真；隔离安装与回退检查保留原工程资料和运行记录。
- 核对桌面 Worker 终态回执及模型策略的保留范围；不以 CLI 测试冒充桌面回调新增验收。

## 已有候选证据如何使用

候选最近一轮修复记录包含 180 项本地测试；安装相关历史记录包含 47 项检查。它们只证明各自当时快照及列明边界，不是本次正式提交的新测试数，更不是 227 个真实业务交付案例。

已有真实隔离场景验证了原型交接、浏览器/API/持久化的小目标，以及双负责人在既有实现上的直接交接与组合复验。后者没有新建原生执行轮或重新完成一次从零开发；不能将其写成全新需求自动完成的全流程证明。早期通知后网络连接超时和人工恢复记录保留，后续通过不抹除其可靠性限制。

外部模型的审查帮助定位问题，但静态审查不能替代执行测试，审查报告也不能自动批准其后发生的修改。

## 未证明的能力

- 任意业务任务的交付质量、交付速度或额度消耗必然改善。
- 任意并发交错、任意宿主版本、所有第三方 CLI 与模型组合均稳定。
- 长期无人值守、网络故障后的必然自动续接，或用户未授权时自动恢复业务。
- 引用、哈希或机器状态能证明需求合理、证据真实或用户已授权。
- 发布成功即代表任一业务项目已升级或已通过业务验收。

现有模型目录与认证来自用户本机配置，不随通用包公开；第三方返回的模型标识也不独立证明网关底层模型身份。平台或工具策略拒绝需保留原始事实，不能统一归因为操作系统权限。
