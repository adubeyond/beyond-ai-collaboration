# BEYOND v3.2.3 升级说明

> 对比范围：`v3.2.2 → v3.2.3`。本版本修复 `task-ops` 在通用运维规则正确、但项目专属 Git/PR/CI 或服务器入口没有被实际消费时可能走到旧副本的问题；不增加身份、业务状态、审批阶段或第二套运行框架。

## 项目运维路由

1. Git、PR、required CI、服务器连接、部署、发布和回滚进入执行前，先读取当前项目根入口，再按项目事实索引定位唯一正式所有者。
2. `task-ops` 的 Git 与运行 reference 只保留通用安全边界，不硬编码项目 IP、账号、远端协议、脚本或 CI 字段。
3. 历史迁入件、候选、镜像和其他工作区不能替代项目声明的受管脚本与 runbook；入口冲突只停止受影响动作并收敛唯一所有者。

## 安装边界

- `v3.2.3` 使用新的不可变 Release ZIP 与 SHA-256；修改后的 Skill 字节不得继续标为官方 `v3.2.2`。
- 升级仍替换完整控制仓候选与六个 Skill，同时保留项目 `local/`、`projects/`、`shared/` 和原生根规则；安装后运行完整验真并在新进程核对实际加载版本。
- 本补丁不授予 Git、服务器、生产、数据、删除或凭据权限，项目专属授权与受保护入口仍由项目自己决定。

## 发布验收

发布候选必须通过公开内容、实现路径、安装一致性和项目路由回归；实际项目验收还要由一个新任务证明它消费的是已安装 `task-ops` 和项目唯一正式入口，而不是只静态搜索源码。
