# BEYOND 3.2.14 安装与升级

使用完整包，不需要叠加旧增量包。项目根无需是Git仓库；本次安装不创建、恢复或续派任务。

1. 确定真实项目根、控制仓与用户Skill根；正在使用相关规则的PM、Worker和CLI先由用户安排结束或停用，不由安装器擅自改任务状态。
2. 核验包内文件集合、字节数、SHA-256和来源版本。外置`.sha256`为可选附件，缺少不阻断包内核验；已提供但不匹配时停止。
3. 比对当前产品定制与CLI修补，避免用通用包覆盖目标中的更新。保存本次覆盖文件、六个Skill、融合根入口及登记文件的新鲜前像，记录原本不存在的文件，不备份无关业务树或历史缓存。
4. 按产品清单精确更新。保留业务资料、`.git/`、`local/`、`projects/`、`shared/`、工作台、pending、CLI会话、认证和其他非产品文件；不整树删除后重建。其他用户Skill不动。
5. 运行原固定融合和验真入口：

   ```text
   node <controlRoot>/scripts/beyond-control.mjs install-project-entry --project-root <projectRoot> --confirm-fusion yes
   node <packageRoot>/beyond-control/scripts/verify-install-integrity.mjs --installed-skills-root <skillsRoot> --project-agents <projectRoot>/AGENTS.md
   ```

   验真器来自本次包，核对实际安装目标；对照清单复核产品内容及保留状态。融合只更新自己的登记、前像和忽略规则，不代表业务授权或验收。
6. 完全退出并重启Codex，确认实际版本与项目身份。无需重新初始化已有文档，也不要求重跑整套发布测试。

## 升级后怎样用

PM重新读取新版入口与相关设计方法，沿原项目总览和事实索引读取当前资料。新业务先讨论确认；已有批准且仍适用的设计继续，不把升级变成全项目重审批。现有设计正文原位维护，普通实现细化由原执行者完成；变更影响范围、契约或验收时只讨论受影响部分。

新方案默认增加一位不同模型的审查者，使用项目已有授权入口。没有模型入口时明确说明，由用户选择替代或豁免，不自动安装、索要凭据或改回调。原有模型矩阵不变。

## 回退

按本次前像恢复覆盖文件，只移除本次安装新建且仍未被后续工作改变的文件。独有成果和必要恢复材料保留；发现后续改动先解决冲突，不整树覆盖。范围前像不是整项目恢复包。
