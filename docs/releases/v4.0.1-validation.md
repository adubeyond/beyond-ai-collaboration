# BEYOND 4.0.1 验证与限制

本版从完整 CLI 候选 R1 晋级。候选此前通过 27 组完整隔离回归、94 个产品文件/100 个包内文件验真及从 4.0.0 的升级回退；正式版更改版本入口和 CI 后重新验证，不拿旧候选结果冒充新提交结果。

## 发布门禁

- 运行 `node scripts/run-product-validation.mjs`，按实际源码指纹保存完整报告；所有组通过且测试中源码未变化才允许发布。
- 原有公开检查和新加入的七项 CLI 专项在 GitHub Windows/Ubuntu 执行；Windows 宿主 Job 专项在 Windows 上执行，在非 Windows 平台明确跳过，不宣称 Linux 验证 Windows 系统能力。
- 在干净已提交源码上打完整包，核对文件集合、字节和 SHA-256，实际解压后运行完整性检查。
- 在隔离项目从 4.0.0 升级并回退，核对原业务资料、工作台、pending、CLI 会话和结果完整保留。
- 比较原基线的六个 Skill、模型策略、Worker 回执、CLI 通知及桌面宿主接口；这些冻结内容不得改变。
- 发布后核对远端 tag、来源提交和正式 ZIP，保留旧正式版和本轮失败证据。最终结果以本版 PR、CI 和发行附件为准。

## 真实调用证据的范围

首轮 Windows CI 的 CLI 检查为 278/279，通过了生命周期专项，但接续入口子进程触发 20 秒测试看门狗。原测试未输出子进程阶段证据，无法据此确定是 Git、PowerShell 启动还是退出问题；本机同一入口单独回测通过。现仅为隔离测试补充不含参数、环境和凭据的阶段耗时及落盘诊断，保留原超时和断言，重新运行完整回归与公开 CI；首轮失败保留，不写成首次全绿或已查明根因。

第二轮 Ubuntu CI 暴露模拟输入文件的非原子写入，以及在管理进程完成会话登记前重放已保存请求的测试竞争。模拟文件改为写完后重命名，只有真实 runner 顺序记录后续 ready 事件后才认为测试输入可用，同时核对原会话和最终成功结果。此修改仅属于隔离夹具，不改变产品锁或回调；真实入口撞到活锁仍会显式拒绝，需要按原请求重试，不宣称消除了全部生产竞争。

Claude Code 的 GLM 读文件对照、ZCode 的 GPT-6.1 Sol 读文件对照通过。Codex GLM 在 low 配置下默认启动、读文件及当前受管程序同会话续聊通过。

Gemini 三种入口均返回上游 503，没有成功首轮或续聊。npm Codex CLI 0.160.1 的一次续聊超时仍未解决；不可写成所有模型和 CLI 组合全部通过。模型返回的名字不证明网关底层权重身份。

宿主关闭测试使用自有 Windows Job，没有关闭用户桌面端、停止正在运行的任务或迁移原会话。没有新增离线回调重放。通用包不分发本机 GLM 默认配置修正。

自动化验证证明已列契约和兼容路径，不保证任何模型在任意业务上的交付质量；隔离升级不等于已经安装到生产项目。桌面 Worker 回调未变，也未以本轮 CLI 测试冒充其新增生产验收。
