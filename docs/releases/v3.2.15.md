# BEYOND 3.2.15：辅助 CLI 可交接，原会话与成果保留

本版只补齐辅助 CLI 的负责人移交。用户明确指定交接对象和新负责人后，未登记为工作台正式任务的辅助 CLI，可以在当前执行轮正常结束、进程状态可核验时移交。它仍然是辅助任务，不伪装成正式执行者，也不新建执行会话。

## 本次变化

- 复用原有 `cli.transfer`，显式选择 `taskMode: "assist"`，一次只移交一项；不接受工作台中已有或归档的同名任务，不绕过正式任务原有负责人关系。
- 保留原任务编号、CLI 会话、模型及推理配置、任务契约、历轮结果和审查记录，不写入或补造工作台登记。
- 移交完成后旧负责人不能继续审查、续跑或控制该任务；新负责人先独立审查已有结果，再在原授权内续跑同一会话。旧审查保留，但不冒充新负责人的判断。
- 重复请求沿原事务恢复或返回原结果；不同目标竞争时不能同时取得控制权。中断期间不允许双方继续执行，先恢复原移交事务。
- 进程异常退出留下锁时，保持阻断；恢复必须核实原进程已退出、身份和状态仍一致，不强删锁或接管仍存活的进程。

## 保留与边界

完整继承 3.2.14 的需求与技术设计确认、工程资料接入、生成物回收、回执写入重试和既有 CLI 修补。六个 Skill、桌面 Worker 回调、短期回执顺序、任务状态与模型矩阵不变；既有正式 CLI 移交仍走原协议。

升级本身不移交、恢复或续跑任何已有任务。辅助移交不是批量迁移工具，也不新增业务、生产或发布权限；真实项目的交接与业务交付需分别核验。本次隔离测试不冒充真实 CLI 会话交接或业务验收。

参见[安装与升级](v3.2.15-install.md)、[验证与边界](v3.2.15-validation.md)及[CLI 协作机制](../../模板交付包/docs/AI编程协同机制/机制/04-CLI目标协作机制.md)。
