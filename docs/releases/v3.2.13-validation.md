发布对比另发现并修复了旧候选遗漏的父仓校验：非 Git 子项目不能将父级 Git 仓冒充自己的 worktree。新反例先确认失败，恢复一行原有边界校验后，身份与路由专项共 50/50 通过；对应场景已包含在上表的 295 项中，不能重复相加。

首次跨平台 CI 暴露了两处测试环境假设：Windows 下测试与产品采用不同的物理路径规范化 API，导致指向同一位置的长短路径被误判；Linux 裸仓默认分支与测试推送分支不同，导致读取远端 HEAD 失败。测试统一物理路径规范化方法，并明确隔离裸仓的初始分支；不修改产品路由、回调或共享 Git 行为，不把该次失败记为通过。

完整 ZIP 的来源提交、产品树、文件清单、字节和解包验真由构建器绑定并核验。最终包升级与回退复演使用官方 3.2.12 及已使用的完整候选两种基线；实际制品验证结果随发布附件提供，不将源码测试代替制品验真。GitHub Windows/Linux 公开检查以发布 PR 对应记录为准，本地结果不冒充 Linux 真机验证。
