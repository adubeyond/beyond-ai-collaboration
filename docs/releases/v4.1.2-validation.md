# BEYOND 4.1.2 验证范围与限制

本页规定复现入口与证据边界，不预报测试通过。源码检查、完整包验真、公开 CI、目标项目安装和真实业务验收是不同事实。公开结果以本版发行附件 `BEYOND-4.1.2.validation.json`、包内清单与对应提交的 CI 为准；构建者另保留本地 `.zip.verification.json`。

## 本次重点

- 请求准备、登记与清理使用不同工具调用，正常登记后可独立清理。
- 注入启动前登记拒绝时不启动运行时，不产生回执，并保留请求。
- 登记成功后清理被拒，不改变既有回执、最终答复或工作台，不重复操作。
- 无效业务输入由真实运行时拒绝，不能误称为平台策略拒绝。
- 真实提交后注入工具响应丢失，以只读查询找回原结果，不自动重放或清理未确认请求。
- 在测试工具边界拒绝旧式“登记加清理”整条调用，不实际执行强制删除。
- 工作台更新成功后清理失败，保留同一操作结果；PM 不重复验收、确认或续派，Worker 保留冻结最终答复与回源顺序。
- 保留原生 Worker 回传、CLI 修补、项目身份、安装融合、内容验真、模型策略和最小示例的既有回归入口。

## 复现命令

在匹配版本的源码根运行针对性检查：

```text
node --test scripts/check-worker-result-receipts.mjs
node --test scripts/check-native-worker-return.mjs
node scripts/check-implementation-paths.mjs
```

完整产品验证从稳定源码建立隔离快照，执行现有 32 组检查，保留快照、紧凑报告与日志，再清理临时树。本轮发布使用每组 480000 毫秒的调用上限，不改变产品超时策略：

```text
node --input-type=module -e "import { runProductValidation } from './scripts/run-product-validation.mjs'; const report = runProductValidation({ timeout: 480000 }); if (!report.passed) process.exitCode = 1;"
```

本地报告位于 `outputs/product-validation/<sourceSnapshotSha256>/`。核对检查结果、源码在验证期间是否变化、清理状态和最终结论；历史通过记录不替代本次快照。

提交并确认工作树干净后，以实际外置产物目录替换占位符，构建完整包，并相对 4.1.1 核对隔离升级与精确回退：

```text
node scripts/build-release.mjs <release-output-directory>
node scripts/check-release-package.mjs <release-output-directory>/BEYOND-4.1.2.zip --baseline-ref v4.1.1
```

公开摘要绑定版本、源码提交和快照、各组结果、CI 及包校验，不包含私人项目、会话标识、本机路径或凭据。构建与验真不授权对真实项目安装。

## 能说明与不能说明的内容

新增用例使用实际本地控制运行时、回执与工作台存储，但策略拒绝及响应丢失由测试注入。它们能复现拆分调用后记录如何保留、未知结果如何读回和重复操作如何避免；不能证明 Codex 策略引擎实际拒绝某命令的原因，也不能证明真实模型一定遵循这些指引。源规则检查证明边界措辞存在，不等于真实模型端到端行为验收。

本版未修改平台审批、安全规则或访问范围，不承诺消除所有 `blocked by policy`。未说明具体原因的历史拒绝仍保留未知归因；不能从完全访问、管理员权限或 `never` 自动推断所有命令应被放行。保留的回传检查仍使用模拟模型与 Desktop 对端，不证明在线模型端到端可用、既有会话热加载或长期无人值守稳定性。发布成功不代表项目已升级、任务已恢复或业务验收通过。
