# BEYOND v3.0.6 升级说明

> 对比范围：`v3.0.5 → v3.0.6`。公开发布不表示任一具体项目已经安装或进入生产。

## 为什么发布这一版

v3.0.5移除了会夺走任务控制权的固定方法流程。随后在真实项目和全新隔离环境中继续暴露出几类效率与读取短路：PM派单和过程沟通仍可能过长；Worker完成后会把工程报告重新复制给PM；用户只问结果时仍可能看到大量技术细节；SSH记录冲突时，模型可能跳过运维reference并再次索要密码。

v3.0.6不引入新的身份或业务状态。它继续压缩既有主链，并把实际读取路径补完整。

## 核心变化

| 维度 | v3.0.5 | v3.0.6 |
| --- | --- | --- |
| PM派单 | 已以业务契约为主，但仍可能展开执行说明 | 只保留业务结果、范围、验收、正式目标、事实入口、真实暂停边界和授权 |
| Worker执行 | 一个Worker连续负责业务结果 | 保持不变；设计、开发、测试和运维仍只是同一Worker选择的方法 |
| Worker回传 | 可能复制完整技术报告 | 默认只返回业务结论、一个主证据入口和影响/下一步 |
| PM沟通 | 已降低回调频率 | 60秒内简单任务不再逐步播报读取、编辑和复核 |
| 用户交付 | 技术证据可能进入默认答复 | 先说明业务结果、能否使用、影响和下一步，技术细节按需展开 |
| Skill读取 | 依赖Skill触发和模型执行 | 显式点名或选中Skill后必须加载主说明；reference仍按场景读取 |
| 服务器事实 | 已有生产上下文 | 规范别名、主机身份、最近解析地址和凭据入口分开记录，旧IP不再成为永久入口 |
| Git并行 | 路径隔离、Git动作串行 | 保持不变；不创建或推荐worktree，精确暂存任务文件 |

## 当前主链

正式团队任务保持一条控制链：

```text
老板提出业务结果
→ PM登记一个任务并派发一次
→ 一个用户可见Worker连续完成设计、开发、测试和已授权本地交付
→ Worker返回一条紧凑结果
→ PM更新原任务并向老板说明业务现实
```

普通修复、测试、复测、方法切换和任务自有本地提交不回PM申请。只有真实业务决定、高风险授权、共享对象冲突或当前无法取得的外部条件才暂停。

## 新项目安装

1. 从Git获取`v3.0.6`，不要从移动分支猜当前版本；
2. 把`模板交付包/AGENTS.md`和`模板交付包/docs/AI编程协同机制/`导入新项目根目录；
3. 把`模板交付包/skills/`下六个Skill安装到该电脑的Codex Skills目录；
4. 重启Codex，并从新项目根目录创建新任务；
5. 首次接手只建立项目目标、正式目录、当前工作台和实际存在的技术栈/测试/服务器/发布入口，不复制空模板或旧项目事实。

安装说明见[快速开始](../快速开始.md)。

## 从v3.0.5升级

- 先保留项目自己的业务边界、技术栈、服务器、凭据入口、发布路径、当前任务和历史证据；
- 更新根入口、六个Skill及其references；
- 清理旧入口中残留的阶段门禁、默认worktree、重复审批、重复任务状态和通用Skill方法副本；
- 同一环境存在多个SSH/IP记录时，保留准确规范别名与凭据来源，由当前配置和现场重新核验主机身份；
- 重启Codex后用一个低风险真实任务验证读取、Git、测试、Worker回传和PM收口，再扩大使用范围。

## 回滚

回滚时恢复`v3.0.5`的模板和六个Skill，重启Codex，并保留项目自己的事实、业务代码、Git历史和运行证据。回滚BEYOND规则不等于回滚项目代码或生产版本。
