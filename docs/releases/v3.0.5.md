# BEYOND v3.0.5 升级说明

> 状态：已发布 · 2026-08-03
>
> 对比范围：`v3.0.4 → v3.0.5`。公开发布不表示任一具体项目已经安装或进入生产。

## 为什么发布这一版

v3.0.4已经把正式任务收敛为PM、一个业务结果一个Worker和三种业务状态，但真实项目继续暴露两类问题：部分从外部方法吸收的固定步骤仍会打断目标推进；生产任务会反复确认同一组目标、制品、授权、验证和回滚事实。

v3.0.5不重新设计系统。它把当前修复冻结为一个可复现版本：任务目标重新高于方法流程，生产上下文在同一发布任务中只建立一次，同时保留v3.0.4已经验证的项目事实、测试、Git、发布和回滚能力。

## 主要变化

| 维度 | v3.0.4 | v3.0.5 |
| --- | --- | --- |
| 工程方法 | 仍残留固定预设计、测试顺序和审查惯性 | Worker按当前事实选择复现、定位、实现和验证，不规定唯一顺序 |
| 独立审查 | 某些路径仍可由风险或收益推断触发 | 只由用户、验收标准或预先登记的项目规则明确触发 |
| 子智能体 | 边界偏紧，也可能按步骤切片 | 只做可分离、可并行的调查、测试、跨模块核对或资料整理；不取得任务身份 |
| worktree | 不再自动创建，但仍残留推荐、规划和收口路径 | BEYOND不创建或推荐；只兼容用户或平台已经提供的既有worktree |
| 并行写入 | 同一正式项目容易被整体串行 | 路径和副作用互不重叠的Worker可并行编辑和验证；共享对象与Git写操作串行 |
| 生产发布 | 安全锚点完整，但可能在每一步重新建立 | 每个发布任务建立一次生产上下文，之后只刷新变化项并连续完成预检、发布、验证和预授权回滚 |
| PM往返 | 普通检查或失败仍可能被转成任务或回调 | 只读检查和普通进展不建正式任务；普通失败在原Worker闭环 |

## 保留的能力

- 一个项目一个PM，一个业务结果一个用户可见Worker；设计、开发、测试和运维仍是原Worker选择的专业方法。
- 业务状态仍只有`进行中 / 已暂停 / 已完成`。
- 技术栈、测试命令、服务器、发布、回滚和凭据入口继续作为项目稳定事实。
- 测试仍绑定真实对象、版本、环境、命令、退出码和断言。
- Git仍要求精确暂存、保护无关修改，并串行处理索引、HEAD和历史动作。
- 生产发布仍要求唯一来源与制品、真实目标、健康检查、关键业务检查和可执行回滚。
- 复杂设计仍使用可实现、可测试、可交付并可归档的独立文档。

## 被移除的固定流程

- 强制brainstorming或预设计仪式；
- 强制RED→GREEN、先制造失败测试或一次一个假设；
- 风险推断自动创建reviewer或独立审查任务；
- 为每个步骤创建助手、切换新任务或回PM审批；
- BEYOND创建、推荐或自动合流worktree；
- 同一生产任务在每一步重复读取和确认未变化事实。

这些流程被结果要求替代：设计必须说清实现、测试和发布路径；代码必须达到任务目标；测试和生产必须留下足够的一手证据。BEYOND不再规定所有任务只能走同一种方法顺序。

## 从v3.0.4升级

1. 先完成或暂停活动任务，不在Worker仍使用旧规则时热替换。
2. 保留项目代码、工作台、项目事实、服务器、发布、凭据和历史证据，不用模板整目录覆盖真实项目。
3. 更新根`AGENTS.md`、PM/Worker和四个Action Skill，并同步当前工作台与03机制中实际使用的入口。
4. 删除三个旧reference，避免旧规则继续被发现：
   - `identity-pm/references/cross-task-coordination-and-review.md`
   - `task-dev/references/implementation-debugging-and-repair.md`
   - `task-ops/references/git-worktree-and-resource-closeout.md`
5. 使用新的`cross-task-coordination.md`和`git-and-resource-closeout.md`。
6. 重启Codex，使新Skill被全新进程发现；先用一个低风险任务观察，再扩大使用。

需要回滚时恢复`v3.0.4`的模板和六个Skill，删除v3.0.5新增的替代reference，重启Codex，并按项目自己的备份记录恢复被替换的项目入口。回滚BEYOND规则不等于回滚业务代码或生产版本。

## 验证边界

发布门禁覆盖公开内容、实现路径、共享Git、最小示例、全新隔离安装、安装后Skill发现和低风险真实项目观察。隔离和真实项目证据只能证明本次对象与环境，不外推为所有Codex平台、真实SSH或所有生产系统均已通过。
