# BEYOND 4.1.1 安装与升级

使用完整发行包 `BEYOND-4.1.1.zip`，不要只覆盖几个运行脚本。发布不等于已安装；每个项目分别确认安装授权、维护范围和安全空档，不因发布强停、迁移或恢复业务任务。

1. 确认目标项目根、控制仓与七个共享 Skill 的实际使用者。活动对话和 CLI 先按既有授权与检查点处理，不将发布授权扩大为停止或恢复任务的权限。
2. 核对版本、来源提交、包内清单和发行附件。外置 `.zip.sha256` 可选；提供但不匹配时停止，未提供仍须完成包内内容与最终安装验真。构建者的本地 `.zip.verification.json` 记录包检查；公开发行附件 `BEYOND-4.1.1.validation.json` 包含包检查与验证摘要，不代替目标项目的安装验真。
3. 为本轮实际覆盖或融合的对象保存精确前像，记录原先不存在的新路径。保留业务代码、配置、Git、项目资料、工作台、待处理结果、CLI 会话、模型设置、结果和审查记录；不备份整个业务仓或用空模板覆盖资料。
4. 按完整包清单更新产品文件，并安装匹配的七个 Skill：`identity-pm`、`identity-product`、`identity-worker`、`task-design`、`task-dev`、`task-test`、`task-ops`。复用既有工程文档和项目登记，不重新创建任务或迁移会话。
5. 使用现有融合入口更新项目根规则并运行安装验真。根入口或共享 Skill 更新后，按既有流程在安全时机重启 Codex，再核对实际加载版本。既有 CLI 管理进程也不能被假定已经热加载替换后的脚本；不要为应用补丁擅自重启或重建它。
6. 安装验真、规则实际加载和业务验收分别报告。提醒不授予执行、定时任务、恢复或验收权限；正式 Worker 回调和模型矩阵不变。

回退只恢复本次精确前像中的覆盖对象，并精确处理原先不存在的产品路径；不得整树覆盖后来新增的业务成果、会话或项目状态。不要混用不同版本的产品文件和 Skill。

完整命令及维护提示词见[安装、升级与项目初始化指南](../../模板交付包/docs/安装升级与项目初始化指南.md)。另见[版本说明](v4.1.1.md)与[验证范围与限制](v4.1.1-validation.md)。
