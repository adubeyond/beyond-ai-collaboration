# BEYOND 3.2.15 安装与升级

使用完整升级包，不需要叠加旧增量包。项目根无需是 Git 仓库；安装不创建、恢复、移交或续跑任务。

1. 确定真实项目根、控制仓与用户 Skill 根。安装前核对相关 PM、Worker 和 CLI 的活动状态，避免替换正在使用的实现；不擅自终止执行或修改任务状态。
2. 核验包内文件集合、字节数、SHA-256 和来源版本。外置 `.sha256` 为可选附件，缺少不阻断包内核验；已提供但不匹配时停止。
3. 比对目标中的产品定制和 CLI 修补，保留更新的现有修复。只为本次实际覆盖的产品文件、六个 Skill、融合入口及登记文件保存新鲜前像，同时记录原来不存在的对象，不复制无关业务目录或历史缓存。
4. 按产品清单更新，不整树删除重建。保留业务与工程资料、`.git/`、`local/`、`projects/`、`shared/`、工作台、pending、CLI 任务、会话、结果、审查、认证和其他非产品内容；其他用户 Skill 不动。
5. 使用既有入口融合并验真：

   ```text
   node <controlRoot>/scripts/beyond-control.mjs install-project-entry --project-root <projectRoot> --confirm-fusion yes
   node <packageRoot>/beyond-control/scripts/verify-install-integrity.mjs --installed-skills-root <skillsRoot> --project-agents <projectRoot>/AGENTS.md
   ```

   验真器来自本次包；核对实际目标中的产品内容与应保留状态。版本一致不等于已有任务已交接或业务已验收。
6. 完全退出并重启 Codex，刷新已加载入口，核对版本与项目身份。已有项目继续复用资料，不重新初始化、不重审批仍有效的既有范围。

## 需要交接辅助 CLI 时

先取得对单个任务、旧负责人、新负责人和交接范围的明确授权，再按[CLI 协作机制](../../模板交付包/docs/AI编程协同机制/机制/04-CLI目标协作机制.md)读取当前会话与状态、提交移交。不要直接编辑负责人字段，不把辅助任务转成正式任务，也不为交接另起执行会话。新负责人独立审查后，才在原授权内续跑。

本版安装不自动执行这一步。现有全局回调、模型矩阵、CLI 配置与认证不因安装而改变。

## 回退

按本次精确前像恢复被覆盖内容；仅移除本次安装新建且没有后续变化的文件。独有成果、CLI 状态与必要恢复材料保留。发现后续更改先处理冲突，不整树覆盖；安装前像不是业务项目整包回滚材料。

参见[版本变化](v3.2.15.md)和[验证边界](v3.2.15-validation.md)。
