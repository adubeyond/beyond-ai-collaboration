# BEYOND v3.1.3 升级说明

> 对比范围：`v3.1.2 → v3.1.3`。本补丁移除默认运行链对 Codex Hook 的依赖，不改变 PM、Worker、三态、Action Skill、Git、测试和发布主链。

## 为什么升级

v3.1.1–v3.1.2 的身份 Hook 需要额外信任、运行探针、工具名兼容和重启。在部分 Codex Desktop 环境中，这些控制动作反而会阻断安装、PM 接手或正式 Worker 创建。v3.1.3 将身份与任务控制重新交还给 BEYOND 自身的显式入口和任务关系。

## 主要变化

- 默认安装、初始化、PM 接手和验真不再安装或依赖 BEYOND Hook。
- PM 与 Worker 身份由显式 Skill、当前用户可见任务和来源关系共同确定。
- 安装验真直接核对入口、六个 Skill、版本清单和项目融合结果，不要求 Hook 信任、运行探针或强制重启。
- 升级旧项目时只清理引用 `beyond-runtime-guard.mjs` 的旧 BEYOND handler 和已知运行状态；其他 Hook、`.codex` 配置和无法确认归属的同名文件保持不变。
- 项目内 `beyond-control/` 仍是默认布局，跨项目外置控制仓仍需用户明确选择。

## 验证结果

- 静态实现路径、安装完整性、旧入口迁移、团队控制、公开内容和 Git 差异检查通过。
- 隔离环境完成 71 个真实 Codex 用例，全部退出码为 0，运行时未启用 Hook。
- PM 派发、Worker 修改代码与测试、本地提交、终态回源和 PM 收口的完整链路 24/24 通过。

## 升级方式

按[安装、升级与项目初始化指南](../../模板交付包/docs/安装升级与项目初始化指南.md)执行目标版本安装与老项目初始化。已有项目会先备份受影响文件，再做精确迁移；不需要先进入 `/hooks`，也不需要为 BEYOND Hook 单独重启 Codex。
