# BEYOND 4.0.0：让任务建立在可读、可维护的工程资料上

4.0 将本轮文档体系改造与 CLI 兼容修补合并为完整发行版，不覆盖旧版本，也不是需要逐层叠加的增量包。版本跨入 4.0，主要标记任务与工程资料的职责重整；没有改写已经稳定的回调协议、工作台状态或模型矩阵。

## 这次改变什么

### 任务和工程文档各司其职

任务记录目标、范围、负责人、过程、差距和结果；需求、产品设计、架构、数据/接口、开发、测试、运行资料保存可跨任务复用的正文。任务卡引用当前适用的路径、章节与修订，不再代替需求和设计，也不复制一套相互漂移的正文。

已有项目优先登记和复用原有文档，不批量搬目录、不要求补齐全部模板后才能开工。文档入口和工程资料指南说明建议布局、正式所有者、读取顺序及缺失处理；初始化接好入口，任务中补齐必要事实，交付时维护真正变化的稳定内容。

### 业务规格、技术方案和验收互相对应

设计不仅列模块或技术栈，还要把用户操作、字段和数据来源、筛选排序与条件恢复、权限、异常、预期结果讲清楚。技术设计继续说明实现边界、接口数据约束和验证入口；不能用技术步骤替代业务要求，也不虚构尚未确认的性能数字。

需求和设计的确认沿用既有机制，绑定适用范围与修订。普通已批准实现连续推进，不增加逐命令审批或新的身份。

### PM 实质分析，执行者按原目标回报

PM 结合项目全貌与当前证据判断缺口是在需求、设计、实现还是验证；多轮未收敛时给出针对性分析与下一步，而非只转发、催促或拒绝完成。执行者实际读取任务对应正文和必要依赖，报告原目标、已实现结果、剩余差距、实际输入输出及证据，不把“构建通过”当成业务完成。

这没有把 PM 变成所有业务代码的并行写入者，也没有将已完成的子任务自动扩成无限任务。共享正文仍由当次明确写入者维护。

### 资料逐步更新，不让历史冒充现状

已确认但尚未实现的设计仍可作为当前目标；现有错误实现不能自动覆盖它。局部章节过期只处理相应部分和替代关系，仍有效部分保留可读。任务结束只回收任务过程，不因此归档有效的需求、设计或架构。

后续任务复用当前正文和修订，旧历史保留追溯价值但不自动进入默认判断。删除、迁移或扩大业务范围仍需要各自授权。

### CLI 升级按实际兼容性判断

- Claude Code 不再按精确版本或版本范围拒绝启动；可执行文件与实际握手、消息通道检查继续生效。
- ZCode 取消精确包版本和整文件哈希门禁，改查依赖、真实代码接入位置、生成副本语法及会话实际接口。注释、字符串和无关同名函数不冒充接口。
- 能力检查失败沿用当前轮的错误记录，保留具体原因；原会话续跑、结果、审查、模型选择、负责人移交及已有错误保护不回退。
- 私有宿主接口仍可能随上游变化而不兼容。本版消除的是人为的版本白名单，不是承诺任何未来版本都能运行。

## 保留与升级边界

完整保留既有 CLI 修补和辅助任务负责人移交；桌面 Worker 回调、回执顺序、工作台状态、模型矩阵保持原样。升级不自动恢复、交接或续跑历史任务，不迁移业务目录，不改认证或用户模型配置。

发行版本升级为 4.0.0，清单数据格式仍为 schemaVersion=3。验真器分开检查二者，双语安装入口指向本版完整包；历史发行包保持原样。

完整 ZIP 仅包含通用产品与公开说明，不包含真实项目资料、会话、凭据或内部测试记录。老项目无需重新初始化；安装后让 PM 刷新入口与当前资料索引，沿原资料逐步维护。
