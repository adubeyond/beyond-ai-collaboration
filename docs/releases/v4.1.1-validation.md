# BEYOND 4.1.1 验证范围与限制

本页规定复现入口与证据边界，不预报测试通过。源码检查、完整包验真、公开 CI、目标项目安装和真实业务验收是不同事实。公开结果以本版发行资产 `BEYOND-4.1.1.validation.json`、包内内容清单及对应提交的 CI 为准；构建者另保留本地 `.zip.verification.json` 原始包检查记录。

## 本次重点

- 内部助手依赖结果在父回合结束前收取；不把正式 Worker 的派单退出规则套到内部助手，也不假定空闲父回合会自动被助手完成事件唤醒。
- Claude 当前轮结构化工具调用与结果配对、首次 Stop 前完成、观察与 Hook 到达交错、新会话转录稍后创建；拒绝旧轮、异会话、异项目、未配对、重复、冲突关联及带额外命令的通知。
- 已终止后台记录不独自阻塞正常 Stop；未知状态、观察缺失与会话定时任务向现有负责人发出提醒，提醒不改变正式结果或扩大授权。
- 原始结果与提醒分别校验；负责人忙碌时沿已有保护等待，多个 CLI 的提醒与结果串行投递。暂停、转移、同会话接续和原模型配置的既有边界保持不变。
- 保留正式 Worker 回执及 PM 收口、其他 CLI、项目身份、工作台事务、安装融合、内容验真和最小示例的回归入口。

## 复现命令

在匹配版本的源码根运行针对性检查：

```text
node --test 模板交付包/scripts/cli/claude-background-return.test.mjs
node scripts/check-cli-claude.mjs
node scripts/check-implementation-paths.mjs
```

完整产品验证从稳定源码建立隔离快照，执行现有 32 组检查，保留快照、紧凑报告与日志，再清理临时树。本轮发布使用每组 480000 毫秒的调用上限；这不是对运行脚本默认值或产品超时策略的修改：

```text
node --input-type=module -e "import { runProductValidation } from './scripts/run-product-validation.mjs'; const report = runProductValidation({ timeout: 480000 }); if (!report.passed) process.exitCode = 1;"
```

本地报告位于 `outputs/product-validation/<sourceSnapshotSha256>/`，包含 `latest.json.gz`、对应成功或失败报告和源码快照。检查结果、源码在验证期间是否变化、清理状态及最终 `passed` 都应核对；历史通过记录不替代本次快照。

提交并确认工作树干净后，以实际外置产物目录替换下方占位符，构建完整包并相对 4.1.0 核对：

```text
node scripts/build-release.mjs <release-output-directory>
node scripts/check-release-package.mjs <release-output-directory>/BEYOND-4.1.1.zip --baseline-ref v4.1.0
```

发布摘要 `BEYOND-4.1.1.validation.json` 应绑定版本、实际源码提交与快照、各组结果及最终结论，并引用对应包的校验材料；公开摘要不包含私人项目、会话标识、本机路径或凭据。构建、解压和包验真不授权对任何真实项目安装。

## 测试能说明什么

新增后台回传测试使用真实本地观察器、会话状态机、HTTP 管理入口、存储和通知逻辑，但原生模型与 Desktop MCP 对端是模拟实现。这能检查当前关联、通知路由、拒绝条件与状态边界，不能证明在线服务、真实模型行为或特定 Desktop 版本的端到端可用性。

旧版原生 Hook 缺少来源字段时，完全相同的手工复制通知仍无法仅凭该 Hook 独立认证来源；结构化同轮关联不应被描述成对所有伪造来源的保证。已恢复或后续轮次缺少转录时，不接纳迟到历史内容来补造本轮关联，而是提示负责人观察不可用。

## 未证明的能力

- 真实模型到 Desktop 的新一轮在线端到端完成与唤醒。
- 父回合结束后，内部助手必然自动开启新的父回合。
- 旧会话、全局 Skill 或已运行 CLI 管理进程在替换文件后热加载。
- 任意宿主、模型、网关、并发交错或长期无人值守均稳定。
- 定时提示、提醒或机器状态自动产生用户授权、业务终态或验收结论。
- 发布成功代表项目已经升级、任务已经恢复或业务验收已经通过。
