# BEYOND v3.0.9 升级说明

> 对比范围：`v3.0.8 → v3.0.9`。这是控制内核和实战回归补丁，不增加身份、业务状态、审批阶段或worktree流程。

## 为什么发布这一版

3.0.8解决了混合安装和模型作用域问题，但异机与真实项目继续暴露出控制面漂移：正式任务可能走fork、projectless或内部助手，PM可能在派单后持续等待和转播，Worker普通final可能被误当成已经回源，模型分档也可能只看任务大小而忽略工作性质。

3.0.9不通过叠加更多流程解决这些问题，而是把正式任务创建、PM退出、Worker回源和模型选择收敛为一条可验证路径。

## 核心变化

- PM先按规范化项目路径和`hostId`取得唯一项目身份；零个或多个匹配都停止，不降级到错误项目。
- 正式Worker只能建立为绑定正式项目、用户可见的全新顶层任务；不用fork、projectless、内部助手或新worktree承载正式结果。
- 创建成功以平台返回真实`threadId + hostId`为准；排队ID、标题失败和首次路由失败都不能触发第二条补建路径。
- PM创建任务后只取一次零时长快照并结束当前回合，不等待、轮询或转播普通过程。
- Worker在真实暂停或完成时，先向平台注入的直接来源发送一次终态，再结束自己的任务；普通final不冒充已回源。
- 项目明确采用模型矩阵时，普通代码工作用Terra/high，大量低风险非代码核对用Luna/high，复杂架构、疑难故障或生产风险用Sol/xhigh；模型配置只作用于新Worker。
- 工具过程沟通由根入口统一拥有，PM和Worker不再复制平行的频率规则。

## 保持不变

- PM负责主线与团队，Worker连续负责一个业务结果，设计、开发、测试和运维仍是按需方法。
- 业务状态仍只有`进行中 / 已暂停 / 已完成`。
- 普通开发、修复、测试、复测和任务本地提交不回PM。
- BEYOND仍不创建或推荐worktree；Git写动作保持精确、串行和可追溯。
- 远端Git、生产、数据、停机、不可逆动作和费用继续分别授权。

## 从3.0.8升级

1. 保留项目特有覆盖、项目事实、工作台、任务记录、业务代码和Git历史。
2. 从不可变标签`v3.0.9`更新模板受管入口与六个Skill的全部文件，不保留旧版残留。
3. 运行安装验真：

   ```text
   node 模板交付包/scripts/verify-install-integrity.mjs --installed-skills-root "<Codex Skills目录>" --project-agents "<项目根>/AGENTS.md"
   ```

4. 只有退出码为0才算安装内容一致；随后重启Codex，并在新PM任务中验证项目接手和正式Worker创建。
5. 正在执行的旧任务先完成或暂停，不在运行中热替换规则。

## 验证结果

- 实现路径221/221、安装完整性5/5、严格公开候选120个文件通过。
- R2核心隔离验收172/172、模型矩阵9/9、真实业务语言12/12、项目问题模拟30/30通过。
- 范围膨胀13/13、正式控制面串联24/24通过。
- 重启后五个原超时案例在同一短序列中首轮全部完成，退出码均为0；冻结候选与源码身份无漂移。

这些结果证明当前Windows/Codex隔离对象与声明场景通过，不表示任何具体项目已经升级，也不外推为真实服务器或生产发布通过。

## 回滚

恢复`v3.0.8`的模板受管入口和六个Skill，运行安装验真并重启Codex；保留项目事实、业务代码、Git历史和运行证据。回滚BEYOND规则不等于回滚业务代码、数据或生产版本。
