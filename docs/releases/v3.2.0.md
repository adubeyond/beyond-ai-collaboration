# BEYOND v3.2.0 升级说明

> 对比范围：`v3.1.7 → v3.2.0`。本版本冻结终态结果契约与确定性控制面，不增加身份、业务状态、审批阶段、worktree或常驻消息系统。

## 这次解决什么

1. Worker正式任务中的自包含final是任务结果唯一真值；回调只负责唤醒来源PM，不复制结果正文。
2. Worker形成终态后不判断PM忙闲、不等待，只发送一次平台原生轻量唤醒，再输出正式final。
3. PM正在回答时，当前回答必须完整结束；平台在回答边界后处理回调。一次回调会触发PM扫描全部已登记Worker，并幂等收敛所有新终态。
4. 多个Worker并发完成时，每个final只验收、归档一次；重复或合并通知不会制造重复任务、重复结果或第二份真值。
5. 项目身份解析与工作台更新下沉为确定性运行入口。旧项目升级时，活动和暂停任务迁入3.2机器状态，已完成项退出热工作台，旧历史和原始入口保留备份。

## 删除的实验路径

- 不再建设或安装BEYOND身份Hook、结果收件箱、终态正文副本、notify dispatcher、host adapter、后台守护进程或额外Codex CLI。
- 不依赖Worker临场轮询PM状态，也不把下一次老板发言当作正常回收入口。
- 项目原有第三方Hook、computer-use、用户notify、插件和Codex能力不属于清理范围。

## 保持不变

- 一个项目控制上下文一个PM，一个业务结果一个用户可见的唯一Worker。
- 原Worker连续使用设计、开发、测试和运维方法；普通失败、复测和本地提交不反复回PM。
- 业务状态仍只有`进行中 / 已暂停 / 已完成`。
- BEYOND不创建或推荐worktree；同一Git工作区的索引、HEAD和历史动作继续串行。
- 远端Git、生产、共享数据、删除和不可逆动作继续分别授权。

## 安装与验真

停止当前项目的活动PM和Worker后，备份项目根`AGENTS.md`、项目内`beyond-control/`、六个用户级Skills和Codex配置。使用不可变`v3.2.0`发布包一次性替换BEYOND文件，只精确清理旧BEYOND实验组件，然后完整重启Codex。

新进程必须先运行安装完整性验证，再接入或升级项目。至少验证：普通Worker开发与测试、空闲PM自动收敛、忙碌PM回答不被截断、多个终态各验收一次、真实暂停自动回传，以及旧工作台迁移不丢活动任务和历史。
