# BEYOND 4.1.2：请求清理与策略拒绝处理修补

4.1.2 是基于 4.1.1 的窄范围补丁，以完整发行包交付。它修正调用方式和失败处理指引，减少附带清理导致的整条登记拒绝，以及清理失败后重复登记的风险；不修改平台安全策略，也不能消除所有 `blocked by policy`。

## 修复什么

- **登记与清理分开。** 准备请求文件、独立执行并核对受管结果、单独清理使用不同工具调用，不合进同一 shell、管道或 `finally`。登记被拒或结果未确认时保留请求；普通删除不默认加 `-Force`，但也不一刀切移除其他用途的参数。确需强制操作时使用平台允许的审批，不绕过拒绝。
- **根据证据判断失败。** 区分明确未启动、启动后失败和结果未知。只有明确未启动才报告未执行；响应丢失或结果未知时先定点核对已有结果，不盲目重放可能已产生副作用的动作。`never` 只表示不弹审批，不表示全部放行或已通过自动审查；完全访问和管理员权限不能覆盖平台明确禁止。
- **清理不改业务结果。** 清理失败如实保留残留，不把它当成登记失败，不重发既有通知。Worker 在回源前单独说明残留，保留已冻结的最终答复与通知顺序；PM 以受管结果判断事务成败，不因残留重复验收、确认或续派。

## 保留什么

运行时实现、正式 Worker 回调、模型矩阵和既有 CLI 修补不变。原有会话、结果、审查、工程资料与成果不迁移、不重建；发布本身不安装项目，也不恢复业务任务。完整包仍包含七个 Skill，旧发行资产保持原样。

## 证据与限制

新增隔离用例围绕真实本地运行时验证请求与清理分离、拒绝后保留请求、提交后清理失败、无效业务输入及提交后响应丢失。策略拒绝与响应丢失通过测试注入，不是执行 Codex 策略引擎，也不是对真实模型遵循规则的验证。仅有泛化拒绝文本时，具体原因仍可能未知，不能归因于删除参数或用户权限。

完整验证沿用 32 组检查；实际源码快照、通过与失败、CI 和包验真以发行附件 `BEYOND-4.1.2.validation.json` 及包内清单为准。本页不预写待执行检查为通过。
