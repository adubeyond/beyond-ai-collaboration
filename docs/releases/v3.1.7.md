# BEYOND v3.1.7 升级说明

> 对比范围：`v3.1.6 → v3.1.7`。本版本不增加身份、业务状态、审批阶段或worktree流程；保留v3.1.6的老项目初始化闭环。

## 这次解决什么

1. Worker暂停或完成后，以正式任务final和平台状态作为终态真值；来源PM明确空闲时只发送一次紧凑提醒。
2. PM正在回答、状态未知或来源异常时不插入、不等待、不重试；PM在下一个用户回合通过一次零时长平台快照恢复漏送结果。
3. 普通任务包保持短小，模型按主要工作选择，服务器、Git、数据库或安全等词语本身不触发升级。
4. 根入口或Skills替换必须等待活动任务停止，安装后重启Codex并从新进程验真；普通项目文档修改不强制重启。
5. 新任务不再写结果收件箱。旧版pending记录只在PM核验并更新工作台后删除，不进入长期历史。

## 保持不变

- 一个用户、一个项目控制上下文只有一个PM；一个业务结果只有一个唯一Worker。
- 原Worker连续使用设计、开发、测试和运维方法，普通修复和本地提交不反复返回PM。
- 业务状态仍只有`进行中 / 已暂停 / 已完成`。
- BEYOND不创建或推荐worktree；共享Git写动作仍精确且串行。
- 生产、数据、远端Git、删除和不可逆动作继续分别服从当前授权。

## 安装验证

从不可变`v3.1.7`标签取得完整交付包。停止现有PM和Worker后，一次性替换项目内`beyond-control`、项目根入口和六个用户级Skills，随后重启Codex。新进程中先核对版本与文件一致，再分别验证：普通任务模型选择、Worker终态、忙碌PM不被打断、下一用户回合结果恢复以及旧pending记录的核验后删除。
