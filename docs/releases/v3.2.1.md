# BEYOND v3.2.1 升级说明

> 对比范围：`v3.2.0 → v3.2.1`。这是终态收口与项目接入备份的补丁版本，不改变3.2的身份、三态、任务模型或控制面架构。

## 修复内容

1. Worker必须先结束全部业务工具和仍会改变现场的进程、形成完整final草稿，再把轻量回源作为本轮最后一次工具调用；回源后只能输出final并结束。
2. PM不再把回调当成线程已经结束。Worker仍在运行且没有final时保持`进行中`；平台明确显示回合已经结束但没有可读final时，一次转为可恢复的`已暂停`，不提前验收、不无限等待、不另建替代任务。
3. 同一业务结果缺少启动脚本、发布、修复或复验步骤时恢复原Worker，不再按动作名称拆出新任务。
4. 项目调查和本机状态备份跳过`.codex-pytest`、`.pytest-tmp`、`.pytest_cache`与`.beyond-local-backups`，避免临时测试现场或历史备份被递归扫描、复制和放大。

## 保持不变

- Worker正式final仍是任务结果唯一真值，回调只负责唤醒PM。
- 一个业务结果仍由一个用户可见Worker连续负责；业务状态仍只有`进行中 / 已暂停 / 已完成`。
- 不增加Hook、notify适配器、后台进程、额外Codex CLI、worktree或长期消息收件箱。
- 项目身份与工作台仍由3.2确定性运行入口管理。

## 升级

停止目标项目的活动PM和Worker后，用`v3.2.1`发布包精确替换项目内`beyond-control/`和六个用户级Skill，融合项目根`AGENTS.md`并重启Codex。重启后运行安装完整性验证，再进行一个正常完成和一个真实暂停的Worker回传验证。
