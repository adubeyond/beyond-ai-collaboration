# BEYOND v3.0.7 升级说明

> 对比范围：`v3.0.6 → v3.0.7`。本次公开发布用于另一台电脑和新项目实战验证，不表示万事通已经升级。

## 为什么发布这一版

3.0.6缩短了文档读取和PM沟通，但全新项目实测仍出现正式任务被放进内部子任务、同一业务结果拆成多个对话、Worker连续推进不足，以及规则明确的大批量工作没有使用合适模型等问题。3.0.7不新增身份、状态或审批，而是把控制权重新交给一个正式Worker，并保留最近版本已经验证的生产、Git、测试和项目事实能力。

## 核心变化

| 维度 | 3.0.6 | 3.0.7 |
| --- | --- | --- |
| 正式任务 | 规则已要求用户可见，但真实入口仍可能降级 | 只能建立绑定正式项目的全新左侧任务；fork、projectless和内部助手不能承载正式结果 |
| 一个业务结果 | 设计检查点后仍可能另开实施任务 | 一个Worker贯穿设计、开发、测试、普通修复和已授权交付 |
| 连续推进 | “继续”可能被误解成自动化或仍频繁停顿 | 只在真实业务决定、高风险授权、共享冲突或客观外部缺口暂停 |
| 子智能体 | 容易与正式Worker混淆 | 只为当前Worker做可并行局部加速，不接管业务结果 |
| worktree | 可能被平台默认创建 | BEYOND不创建、不推荐；已存在时仅兼容，Git写操作保持串行 |
| 模型选择 | 主要依赖默认模型 | 已确认策略的项目按工作性质选择：Luna处理清晰重复和大批量核对，Terra处理普通工程任务，Sol处理复杂、高未知和高风险任务 |
| 范围控制 | 复用通用能力可能越做越大 | 出现重复候选版本、对象持续增加或通用协议扩张时，原Worker重新比较最小完整路径 |
| 历史数据 | 容易把单次修复扩大成通用产品改造 | 对象、归属、影响、授权、事务和回滚闭合时，可走受控一次性修复；未来防复发另行判断 |

## 保留不变的能力

- 一个项目一个PM，可并行建立多个独立业务结果；每个结果只有一个正式Worker。
- 项目技术栈、测试、服务器、SSH别名、凭据入口、发布和回滚事实继续由项目Markdown承载。
- 普通开发、复测和任务自有本地提交不回PM逐步审批。
- 精确暂存、保护无关脏改动、完整候选发布、业务检查和回滚证据继续保留。
- 设计、开发、测试和运维仍是Worker选择的专业方法，不是新的智能体。

## 从3.0.6升级

1. 从Git取得不可变标签`v3.0.7`，不要从移动分支猜版本。
2. 保留项目自己的业务文档、技术栈、服务器、凭据入口、当前任务和历史证据。
3. 更新根入口、六个Skill及其references；不要把旧项目事实替换成空模板。
4. 清理仍把正式任务放入fork、projectless、内部子任务或按设计/开发/测试拆对话的旧规则。
5. 若项目采用Luna/Terra/Sol策略，在项目入口明确登记；未登记时继续使用平台默认模型。
6. 重启Codex，从项目根目录建立新任务；先用低风险任务确认左侧正式Worker、连续执行、Git和结果回源，再扩大使用。

## 验证结果

- 全量隔离主断言153/153通过；3.05与万事通问题模拟31/31通过。
- 范围膨胀和受控数据修复13/13通过；模型分档8/8通过。
- 模型规则确认后P01–P13再次冷启动，13/13自然完成。
- 真实平台会话元数据证明Luna高推理和Sol高推理任务实际运行并完成回源。
- 控制面集成24/24通过；一个Worker贯穿，没有额外worktree。
- 最终严格候选公开文件、实现路径和逐文件SHA-256对账全部通过。

这些证据覆盖本次Windows/Codex环境和声明场景。另一台电脑、新项目自动发现和更广泛实战仍由3.07安装测试继续验证。

## 回滚

恢复`v3.0.6`的模板和六个Skill并重启Codex；保留项目自己的事实、业务代码、Git历史和运行证据。回滚BEYOND规则不等于回滚项目代码、数据库或生产版本。
