# BEYOND v3.2.4 升级说明

> 对比范围：当前公开发布 `v3.2.2 → v3.2.4`。本版本同时包含已合入主线但未单独发布的 `v3.2.3` 项目专属运维路由修复，并完成多结果派发、终态恢复、控制仓隔离和轻量安装路径的真机回归；不增加身份、业务状态、Hook、守护进程或第二套调度器。

## 目标优先与连续推进

1. 同一条老板消息明确批准多个互不依赖结果时，PM在同一回合逐个创建并登记；单个创建失败不阻断其他独立结果，全部创建请求处理后立即结束，不等待、读取或轮询Worker。
2. required CI、既有审查或保护分支仍有责任实例、可读状态和正常下一触发时保持“进行中”，不把正常排队或审查时间误报成项目暂停。
3. 用户明确要求精确字面值或字节时，不自行追加换行、BOM或其他字符；面向用户的Worker结果先回答业务结果，测试命令、提交哈希等工程证据留在正式证据入口。

## 终态恢复与控制仓隔离

1. Worker终态runtime只允许从当前正式项目根`AGENTS.md`映射解析，不搜索、猜测或回退到源码仓、模板、候选包或其他项目。
2. `worker-result.enqueue`和显式项目范围的`worker-result.list`会拒绝当前控制仓未登记的项目编号；拒绝发生在pending写入之前。
3. 原生回调仍是主触发；若宿主没有为已送达回调建立可执行收口回合，下一次自然PM回合只补读一次活动任务的pending并继续老板当前目标，不引入轮询、Hook、notify、守护进程或第二套调度器。
4. 暂停任务继续由同一原Worker恢复；暂停和完成各自只形成一次回执、一次工作台事务和一次ack。

## 安装与升级

- 项目根可以不是Git仓库；以当前Codex项目目录和根`AGENTS.md`确定目标，不把`git rev-parse`成功作为安装前提。
- Windows备份前后使用相同的隐藏文件感知清单，按相对路径、字节和SHA-256核对；`.git`目录Hidden属性变化不等于内容丢失。
- 升级仍只替换项目内`beyond-control`产品文件、六个用户级Skill并融合根入口；保留`local/**`、`projects/**`、`shared/**`、项目原生规则和业务代码。
- 不安装身份Hook、notify分支、后台进程、额外Codex CLI或worktree。

## 发布验收

- 本地确定性与模型门禁覆盖内容、安装、运行时、PM/Worker语义、万事通场景、实现路径和公开文档。
- Windows真机完成真实安装、单Worker终态、双Worker独立并发、忙碌PM多工具边界、同一Worker暂停恢复，以及错误控制仓项目编号拒绝且零pending/工作台写入。
- 正式安装包为`BEYOND-3.2.4.zip`，同一Release附带`BEYOND-3.2.4.zip.sha256`；安装后必须重启Codex并在新进程核对实际加载版本。
