# BEYOND v3.0.8 升级说明

> 对比范围：`v3.0.7 → v3.0.8`。这是针对异机安装实测问题的小补丁，不重构3.0.7主路径。

## 为什么发布这一版

另一台电脑声称已经升级到3.0.7，但实际同时存在3.0.6的PM Skill、3.0.6的项目通用入口、局部3.0.7文件和一条项目本地Luna规则。混合环境随后把Worker模型分档错误用于新PM，并在接手项目时恢复旧任务。

3.0.8不增加身份、状态、审批或阶段。它让安装结果可以由程序证明，并收窄两条存在歧义的运行规则。

## 核心变化

- 新增版本清单与安装验真脚本：六个已安装Skill逐文件对账，项目根`AGENTS.md`核对版本和通用内容；旧版、缺失、残留或混合内容任一存在即失败。
- 项目特有规则只放在专用覆盖区；模型覆盖必须明确适用于PM还是Worker。
- Luna/Terra/Sol分档只用于PM创建的新Worker，不改变当前PM模型，也不授权建立替代PM。
- 单独“接手项目”只恢复主线和任务状态；只有同一条用户指令明确要求时才启动或恢复具体任务。
- 根入口不保存秘密，初始化或升级完成后应纳入项目版本管理，以便追溯规则变化。

## 从3.0.7升级

1. 从Git取得不可变标签`v3.0.8`。
2. 保留项目业务文档、项目事实、工作台、任务记录和Git历史。
3. 用3.0.8更新六个Skill及其全部文件；把项目特有根规则迁入`AGENTS.md`专用覆盖区，其余通用部分更新到3.0.8。
4. 从该标签运行：

   ```text
   node 模板交付包/scripts/verify-install-integrity.mjs --installed-skills-root "<Codex Skills目录>" --project-agents "<项目根>/AGENTS.md"
   ```

5. 只有退出码为0才算升级完成；随后重启Codex并创建新PM任务。
6. 首次只说“接手项目”，确认旧任务没有自动启动；再明确恢复一个任务，确认原Worker路径继续生效。

## 验证结果

- 安装完整性回归5/5通过，包括旧Skill、旧项目入口和无角色模型覆盖的受控失败。
- 实现路径静态验证203项通过。
- 真实隔离Codex模型作用域9/9通过。
- 两个已暂停旧任务的纯接手用例4/4通过，两次真实进程退出码均为0。
- 严格公开候选115个文件通过，源码与候选逐文件SHA-256差异0。

这些结果证明当前Windows/Codex隔离对象与声明场景通过，不表示任何具体项目已经升级，也不外推为真实服务器或生产发布通过。

## 回滚

恢复`v3.0.7`的模板和六个Skill并重启Codex；保留项目事实、业务代码、Git历史和运行证据。回滚BEYOND规则不等于回滚业务代码、数据或生产版本。
