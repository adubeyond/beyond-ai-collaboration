# BEYOND 90 秒图文短视频脚本

## 视频定位

这是一条面向视频平台的图文解释短片，不要求重新模拟或录制一次完整任务。

视频负责让陌生用户在 90 秒内看懂 BEYOND 解决什么问题；真实运行证据继续由仓库中的测试记录、正式案例、发布验真和可选界面截图承担。图文动画不能冒充行为测试，但也不需要把宣传视频拍成测试录像。

## 视觉形式

- 画幅：竖版 `1080 × 1920` 为主，同时保留横版安全区；
- 风格：深色背景、白色大字、蓝紫强调色、少量绿色表示“证据闭环”；
- 构成：大字标题、简化流程图、任务卡片、状态变化和 2–3 张脱敏证据截图；
- 节奏：每 3–6 秒更换一个视觉重点，不连续展示终端滚屏；
- 字幕：所有旁白必须有完整字幕，关闭声音也能看懂；
- 音乐：轻节奏电子音乐，音量低于旁白；
- 品牌尾屏：使用 `.github/assets/social-preview.png` 中的现有视觉语言。

## 旁白全文

> AI会写代码，但项目一复杂，你是不是又开始不停追问？新对话失忆，Worker完成后没人收口，测试和发布混成一件事，并发任务还可能互相覆盖。BEYOND把这些关系放回本地项目：一个PM管主线和验收，每个Worker只负责一个业务结果。用户只说明结果、验收和权限边界。目标清楚，PM直接派发，不持续轮询陪跑。Worker根据需要完成设计、开发、测试或运维，但始终围绕同一个结果连续负责。完成或真正暂停时，Worker留下正式结果和短期回执，再把终态送回PM。缺少真正的业务输入就暂停；输入到位后，仍由原Worker继续，不重新开一个任务。代码写完、测试通过、已经提交、已经发布和生产可用，从来不是同一件事。BEYOND，让Codex超越对话，抵达结果。

## 建议图卡

### 图卡一：传统困扰

```text
昨天做到哪了？
任务完成了吗？
测试通过是不是已经发布？
为什么又创建了第二个执行者？
```

### 图卡二：BEYOND关系

```text
项目负责人
    ↓ 结果 / 验收 / 权限
   PM
  ↙  ↘
Worker A  Worker B
  ↓          ↓
结果与证据 → PM验收 → 项目主线
```

### 图卡三：证据分层

```text
代码已修改 ≠ 测试已通过
测试已通过 ≠ 已创建提交
已创建提交 ≠ 已推送或发布
已发布       ≠ 生产业务可用
```
