## 20 位种子用户规则

- 邀请正在使用 Codex Desktop 做真实项目的人；
- 不要求必须 Star；
- 只要求完成一次安装、一次小任务或说明失败位置；
- 失败必须保留第一手错误，不由邀请者代写“成功”；
- 不接收任何生产凭据、客户数据或私有仓内容；
- 记录是否看懂定位、是否找到下载、是否完成重启、是否成功建立 PM。

## 归因纪律

- GitHub Traffic 只保留近期窗口，每周固定时间采集一次；
- Release 资产下载量按 ZIP 统计，不把 SHA-256 下载再算一次；
- Gitee 数据与 GitHub 数据分开记录；
- 不用 Star、Clone 或页面浏览证明安装成功；
- 文章发布后至少观察 7 天，不因当天数据为零立即改产品；
- 某渠道连续两次发布都没有带来独立访客或有效反馈时，停止复制内容，先更换选题或受众。

## 第一轮裁决

30 天后只回答三个问题：

1. 是否有人从 GitHub 以外发现 BEYOND；
2. 到访者是否能理解产品并完成下载或安装；
3. 安装后的真实阻力来自定位、文档、平台能力还是产品缺陷。

如果外部访客仍接近零，优先修正分发渠道；如果访客增加但下载不动，修正首屏和演示；如果下载增加但安装失败，才优先修正安装体验。
