# 我给 Codex 两个任务后离开了，它们完成后自己回到 PM 验收

> BEYOND 3.2.4：一套面向 Codex Desktop 本地项目的开源 AI 工程协同系统。

很多人第一次使用 AI 编程工具时，最惊喜的是“它真的能写代码”。

可当项目开始持续几天、同时出现多个任务以后，问题很快就变了：

- 新对话不知道昨天做到哪；
- 一个任务被拆成设计、开发、测试、运维，用户需要反复输入“继续”；
- Worker 已经完成，PM却不知道结果已经回来；
- “测试通过”“已经提交”“可以发布”经常被混成一句“完成了”；
- 两个任务并行时，责任边界和写入范围越来越难追踪；
- 缺少一个业务输入时，任务要么乱猜，要么彻底丢失。

这些问题不是“模型不会写代码”，而是项目缺少一条稳定的协作与验收链。

这正是我做 BEYOND 的原因。

## BEYOND 不是另一个聊天机器人

BEYOND 运行在 Codex Desktop 的本地项目里。它把协作关系分成两个清晰角色：

- PM 管理项目主线、任务组合、责任边界和最终验收；
- Worker 对一个业务结果连续负责，根据需要完成设计、开发、测试或运维动作。

它不要求用户先学会一套复杂流程。用户只需要说明：

1. 最终要得到什么结果；
2. 怎样才算完成；
3. 哪些动作已经授权，哪些没有。

目标清楚时直接执行；真正会改变业务结果的歧义才询问。

## 一个真实的并发任务

为了验证这套机制，我在一个本地 Node.js 项目中让 PM 同时建立两个互不重叠的任务：

- A 读取当前 Node.js 版本；
- B 运行一次项目现有测试。

PM 为两个结果分别登记唯一 Worker，随后结束当前派发回合。它没有等待 Worker，没有主动读取线程，也没有轮询进度。

两个 Worker 分别执行自己的任务。完成后，每个 Worker：

1. 冻结一份与正式 final 一致的终态文本；
2. 保存短期回执；
3. 回调来源 PM；
4. 输出正式 final 并结束。

PM 收到各自回调后，分别读取一次正式结果，完成一次验收、一次历史归档和一次回执确认。最终两个任务的活动记录都归零，历史记录各一条，pending 回执清零。

重要的是，这里没有把两个结果合并成一个模糊的“都完成了”。每个结果都有自己的负责人、正式 final、证据和验收事务。

## 任务暂停，不等于任务丢了

真实项目里并不是所有任务都能一次完成。

如果一个任务必须知道测试确认代号，而这个代号没有提供，Worker 不应该猜测。它应该形成真实暂停终态，说明：

- 唯一暂停原因；
- 已经保留的事实；
- 恢复所需的最小输入；
- 仍负责恢复的原 Worker。

用户后来提供代号时，PM恢复同一个 Worker，而不是创建第二个任务重新开始。最终历史中仍然只有一个业务结果。

这让“暂停”成为可恢复状态，而不是失败后的上下文丢失。

## 证据比“完成了”更重要

BEYOND 刻意把几个经常混淆的结论分开：

- 修改了代码；
- 测试运行并通过；
- 创建了本地提交；
- 推送到远端；
- 部署到测试环境；
- 发布到生产；
- 生产业务真实可用。

它们不是同一件事，也不共享同一份权限。

如果用户只授权修改和测试，Worker就不能因为“顺便”而推送或发布。反过来，用户当前已经明确授权的动作，也不应该被框架的一般偏好无故阻止。

## 3.2.4 解决了什么

BEYOND 3.2.4 重点强化了真实项目长期运行中的几个问题：

- 一条指令包含多个独立结果时，PM可以在同一回合逐个派发；
- 控制面只接受当前项目根已经登记的项目编号，错误项目在写入 pending 前被拒绝；
- 非 Git 项目也能作为正式安装目标；
- Windows 备份统一包含隐藏文件，并按路径、字节和哈希核对；
- 用户当前明确目标和授权优先于普通默认偏好；
- 宿主没有形成可执行回调回合时，下一次自然 PM 回合可以进行一次有界终态恢复。

BEYOND 不承诺平台永远没有偶发行为，也不把一次测试包装成普遍真理。它要做的是：即使出现暂停、回调延迟或执行失败，责任、事实、证据和恢复入口仍然清楚。

## 适合谁

BEYOND 更适合：

- 已经使用 Codex Desktop 维护真实本地项目的人；
- 一个人同时推进功能、缺陷、测试和发布工作；
- 希望 AI 少靠人工续推，但又不能越过生产权限的人；
- 需要任务暂停、恢复、验收和长期项目事实的人。

如果只需要一次性问答或写一段临时代码，BEYOND 可能没有必要。

## 三步开始

1. 下载正式发布包并核对 SHA-256；
2. 在目标项目中让普通 Codex 任务完成备份、安装和验真；
3. 重启 Codex Desktop，使用 `$identity-pm` 初始化或接入项目。
