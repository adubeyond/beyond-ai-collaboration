# BEYOND 实现路径审计与修复记录

> 本文是本轮“恢复执行效率”的唯一审计主文档。它只在机制审查与版本冻结时使用，不进入普通任务运行链。结论必须来自当前源码路径和真实场景验证，不继承旧记录中的通过判断。

## 1. 目标

保留项目文档带来的快速定位能力，同时删除普通实现路径上的无效治理步骤。规则只有在能够保护真实业务边界、共享资产、生产安全或结果证据时，才允许成为默认门禁。

默认原则：

```text
业务结果、范围和明确不做已经确定
→ 范围内可逆本地动作连续执行
→ 只在真实风险命中时暂停
```

## 2. 审计场景

| 场景 | 预期最短路径 | 不应默认发生 |
| --- | --- | --- |
| S1 普通局部 BUG | 子项目入口 → 定位/复现 → 修改 → 自测与相邻回归 → 本地提交 → 交付 | PM续派、设计文档、任务卡、worktree、项目事实初始化、完整运维规则 |
| S2 需要设计的新功能 | 子项目入口 → 必要设计/契约 → 同一Worker开发 → 测试/修复/复测 → 本地提交 → 交付 | 按设计/开发/测试拆任务、阶段回PM、重复接手、平行设计文档 |
| S3 已授权生产发布 | 正式运行入口 → 核对唯一制品/目标/回滚 → 发布 → 健康与业务验证 → 必要观察/回滚 → 收口 | 重复索要同一授权、要求用户代SSH、默认worktree、临时换发布路径、只验HTTP 200 |

## 4. 发现与裁决

| 编号 | 发现 | 裁决 |
| --- | --- | --- |
| P-01 | 复杂设计reference无条件回到完整项目文档入口，正式任务会重复读工作台/总览 | 改为正式任务复用已注入的子项目入口；只有直接请求缺入口或入口冲突才读总入口 |
| P-02 | 开发写成“任务授权包含正式测试时”才切测试，正常代码验收可能再次等待授权 | 明确正式代码任务的验收天然包含必要测试；只有测试真实触及高风险对象时核对该维权限 |
| P-03 | Worker与开发列出全部权限维度，可能诱导模型逐项补字段 | 只核对当前动作实际触及的维度；未触及维度不检查、不补字段、不暂停 |
| P-04 | 测试资产修改要求“明确授权的测试文件范围”，模块级代码任务可能被误判为缺授权 | 当前任务已有文件写入范围包含相邻测试；真正越界时才核对新增写入 |
| P-05 | 测试/运维输入把独立证据位置写成必填，简单任务可能为留痕创建新文件 | 没有独立记录时由当前任务结果承载；需要长期留存才使用既有记录入口 |
| P-06 | 生产五锚点保留任务起始基线和授权目标主线，单一正式提交发布仍走多分支治理 | 普通发布收敛为四项真实事实；只有生产与正式来源存在额外差异时才追查分支/热修 |

保留的默认门禁：最小并发写入检查、任务范围和契约、相邻回归、任务自有提交、生产目标/制品/回滚、真实高风险授权和当前一手证据。它们直接保护共享改动、用户结果或可恢复性。

问题按以下标准处理：

- **删除默认步骤**：没有直接风险收益，只增加读取、文档、状态或回调；
- **改为按需规则**：只在特定复杂度、共享冲突或高风险对象出现时有价值；
- **保留核心门禁**：保护真实业务语义、其他改动、生产/数据安全、可恢复性或一手证据；
- **等待用户裁决**：会改变PM/Worker职责、项目组织方式或安全取舍。
